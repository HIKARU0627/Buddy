# UI-05 の記録（段階 1: 自動の区切りと要約のつなぎ）

[ADR 0068](../adr/0068-ui05-stream-segments-auto-boundaries.md) の段階 1（Issue #97、親 #92）の記録です。**製品の試験の合格ではありません。** UI-03 の最小の縦断（区切り 1 つ）に、30 分・日付の変更の自動の区切りと、前の区切りの要約（由来と期限）のつなぎを足しました。記録しない会話・保存モードの変更・区切りの指示・知らせの運搬・表示のリース・端末の移動は未着手です。

記録は 3 つに分けます。

- **模擬**: Electron を起動しない試験（`pnpm test`）。127.0.0.1 の Core の統合を含む。
- **実機相当の確認**: UI-05 では実施していません（UI の見た目を変えないため）。
- **未実施**: 確かめていないこと。

## 作ったもの

| 場所                             | 内容                                                                                                                                                                    |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/domain/src/canvas.ts`  | `SEGMENT_IDLE_TIMEOUT_MS`（30 分）と `automaticSegmentBoundary`（30 分・日付の変更の判定。先に来ていた方を理由にする）                                                  |
| `apps/core/src/canvas-stream.ts` | 区切りの自動の切り替え（直列・切り替えの後の再確認）、`nextCarriedSummary` による要約の由来と期限の引き継ぎ、発言の期限の記録（再送は二度数えない）、作れないときは 503 |
| `apps/core/src/core.ts`          | `createStreamRoutes` に本人の時間帯（`utcOffset`）を渡す 1 行                                                                                                           |

端末から見える差は、`POST /v1/stream/turns` の応答の `segment`（区切りの ID・`open_reason`・`opened_at`・`carried_summary`）だけです。キャンバスの版・イベント・WSS の知らせは変わりません。端末に会話の ID・区切りの ID・保存モードを渡さない方針も変わりません。

## 模擬

| 試験                                                                                                                                                                                                  | 結果 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 29 分 59 秒 999 ミリ秒では同じ区切りで答え、直前の発言から 30 分ちょうどで新しい区切り（`idle_timeout`）になる                                                                                        | 合格 |
| 新しい区切りの `opened_at` は評価した時刻。つないだ要約は前の区切りの ID と、発言の最も早い期限（手で数えた UTC）だけを持つ（本文を持たない）                                                         | 合格 |
| 本人の時間帯（+09:00）で 0 時ちょうど（15:00Z）に日付が変わると、30 分前でも `date_changed` で切る                                                                                                    | 合格 |
| 何回区切りをまたいでも期限は由来の最も早い発言のままで、期限の切れた要約は材料にせず、期限内の発言だけから作り直す                                                                                    | 合格 |
| 区切り（会話）を作れないときは 503 で、古い区切りで答えない（発言の処理もしない）                                                                                                                     | 合格 |
| 純粋関数: 30 分ちょうど・1 ms 前、発言がまだ無いとき（区切りの始まりから測る）、0 時ちょうど・1 ms 前、30 分と 0 時が同時刻（`idle_timeout`）、負の差（-05:00）、形の違う差・読めない時刻では切らない | 合格 |
| 既存の UI-03 の試験（区切り 1 つの縦断・配置・版・知らせ・認可）が、そのまま通る                                                                                                                      | 合格 |

期待値は手で書いた値で、実装の関数から作っていません。時計は注入しています。
