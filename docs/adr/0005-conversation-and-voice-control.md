# ADR 0005: 会話・委譲・音声制御・出力先の契約

- 日付: 2026-10-19
- 状態: B00-04（#19）の判断。端末の音声処理・Live 接続・中枢の配信処理は未実装。
- 根拠: 設計 10 §1・§1A（F03）・§2・§2A・§3〜§8、07 §2・§5、02 停止、01 いつも見える状態、決定事項 D06・D14。原本の参照手順は docs/design/README.md。下の 3 点は本人の回答（2026-10-19、いずれも推奨案）で決定。
- 追記（2026-10-23、ADR 0038）: stop_playback の再開は、`playback_queue`（再生キューと現在の output_epoch の照合。表のとおり変更なし）に加えて、どの接続で再開するかを決めた（既定は新しい Live 接続、同じ接続は設定を実機で検証して有効にしたときだけ）。close_voice_session に `consent_revoked`（外部への送信の同意の取り消し）を足した。音声レンダラーの限定 IPC・制御接続の遷移・リースの更新・input_kind の受付・同意の契約を足した。

## 決めたこと

| 対象                           | 決定                                                                                                                                                                                                                                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 世代（epoch）の担当            | io_epoch・output_epoch は端末が停止時にその場で進めて中枢へ報告し、audio_epoch・control_epoch・session_epoch は中枢が Live の開始・再接続・端末交代で発行する。どれも中枢の再起動で巻き戻さず、受け取った側は小さい値に戻さない                                     |
| 原本に対応表がない結果表示     | query_mail はメール一覧の行（本文は開いたときだけ取得）、query_memory は記憶の行、research は受付の 1 行（完了は気づき）、consult・dev_status は吹き出し、handoff_screen は状態の 1 行、undo_action は取り消し一覧を開くボタン、記憶の保存・訂正・忘却は完了の 1 行 |
| 委譲の結果の「構造化した事実」 | 結果表示の種類に対応した項目（ResultFact）の配列にする。読み上げ用の文はコードの定型文（template_id と版）だけから作り、モデルの自由文を入れない。1 回 400 トークン以内・最大 3 回で、超える分は画面に出す                                                          |

## 停止の 3 つの操作と再開条件

`AudioControl` の action は stop_playback・close_voice_session・suspend_io の 3 つで、理由は action ごとに重ならない列挙です。会話の終了（end_conversation）は close_voice_session の conversation_ended として Live を閉じ、会話も終えます。処理の取消（cancel_workflow）は音声を止めない別の命令です（10 §1A）。理由ごとの動作と再開条件は `packages/domain/src/audio.ts` が持ちます。

| action              | 理由                                                                                                          | 動作                                                              | 再開条件                                                       |
| ------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------- |
| stop_playback       | user_stop、barge_in                                                                                           | 再生だけ止める。マイク・Live・VAD は維持                          | 再生キューと現在の output_epoch を照合して再開                 |
| close_voice_session | silence                                                                                                       | Live を閉じる。入出力の許可が有効なら KWS・③は使える              | 次の呼びかけで新しい Live（同じ会話）                          |
|                     | output_mode_text                                                                                              | 同上                                                              | 返し方を声に戻すまで③                                          |
|                     | budget_reached                                                                                                | 同上                                                              | 会話予算の予約ができるまで③                                    |
|                     | private_conversation                                                                                          | 同上                                                              | 記録しない会話が終わるまで③                                    |
|                     | conversation_ended                                                                                            | 同上。会話（session_id）を終える                                  | 次の呼びかけで新しい会話                                       |
|                     | device_move                                                                                                   | 同上                                                              | 移動先の端末の呼びかけ                                         |
|                     | provider_failure、sideband_lost                                                                               | 同上。同じ接続は復活させない                                      | ③は使える。①は次の呼びかけで新しい接続                         |
|                     | consent_revoked（ADR 0038 で追加）                                                                            | 同上                                                              | 外部への送信の同意を取り直すまで③                              |
| suspend_io          | device_io_stop・os_lock・device_revoked・core_lease_lost（local）、guest_mode（guest）、global_stop（global） | 収音元・KWS / ASR・再生を止め、PCM とリングを破棄し Live を閉じる | 登録済み・解除済み端末の画面で明示再開し、許可とリースを再検査 |

停止が重なったときは強い方（suspend_io ＞ close_voice_session ＞ stop_playback）を優先します。理由と対象範囲（scope）の組は domain の表で検査します。

## 遅着と出力先

- 出力先は入力時に固定し、入力の種類だけで決めます（文字・③は文字、①は音声）。音声の接続が開いていても文字の依頼は文字で返します（D14）。`InteractionMode` は①②③の 3 通りだけを schema で受け付け、④（文字→音声）は拒否します。
- `DelegationResult` は音声の出力先だけに使えます（意味検査）。
- 遅れて届いた結果・音声・ACK は、端末・各世代が現在の値と一致するときだけ受け入れます。音声で返す結果を使えないとき（別の端末、古い世代、文字の依頼、入出力停止、リース無効）は画面の一覧に回し、それ以外（ASR の結果、停止の ACK、Live の開始）は破棄します。現在より新しい世代も、発行元が確かめられないため拒否します。

## その他の契約

- `ConversationContext`（buddy.context.v1）は 10 §4 の項目どおりです。直近の発言は 6 件まで、承認待ちなどの項目は 10 件まで。`store_generation` は ADR 0003 の UUID です。端末名は合成値で試験します。
- `PendingClarification` は対象の workflow と版・足りない引数・元の引数・期限を持ち、記録しない会話では ram_only にします。
- `LiveControlState` は close_requested / close_confirmed / close_unconfirmed を分け、使用秒数が確認できるまで予約を精算済みにしません（10 §2A）。
- `DeviceIOState` は、ロック状態が不明・ロック中・停止中のときに入力を許可しないことを意味検査します（07 §2）。
- `Lease` の heartbeat 2 秒・期限 6 秒は設計初期値で、値そのものは固定しません（heartbeat が期限より短いことだけを検査）。
- `VoiceEvent` は音声の制御イベント（サイドバンド接続済み、委譲の処理中・背景化、読み上げ要求、停止）で、本文・文字起こしを持ちません。
- `SessionControlPhrases` は会話の操作の照合表です。短い発話の全体が言い回しに一致したときだけ操作にし、「終わりの時間教えて」のような依頼は意図判定へ回します（X58）。
- 旧名の ResponsePlan は WireResponse / Interpretation / ActionReadiness に分けました（ADR 0004）。
