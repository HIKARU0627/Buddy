# ADR 0107: B10-04 P2b 声で返す定型文の追加・追記の上限

- 日付: 2026-11-14
- 状態: B10-04（親 #18、Issue #246）P2b の判断。声（Live）で返す結果の定型文と、追記の上限を足す。1.5 秒のつなぎ・8 秒の背景化・調査/相談の受付の経路（裏のジョブ）・遅着は P3。実音声・実 API・実請求・実機は未実施。
- 根拠: 設計 10 §5（つなぎ・即時ジョブの上限・裏のジョブ・事実文と定型文・変更を伴う依頼）、設計 09 X33・X49、ADR 0005・0052・0066・0105・0106。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。
- 対象: `packages/domain/src/voice-commentary.ts`、`apps/core/src/live-conversation.ts`（`#deliver`）、各試験。契約（`packages/contracts`）・マイグレーションは変えていない（`DelegationResult` は `template_id` を自由な文字列、`commentary_parts` を最大 3 つとして元から持つ）。

## 決めたこと

| 対象                     | 決定                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 定型文の範囲             | **原本に言い回しがあるものだけ**を足す（原本の不足を推測で補わない）。つなぎ「確認しますね。」、背景化「少し時間がかかるので、できたら知らせます。」、調査・相談の受付「受け付けました。終わったら知らせます。」、完了。他の結果の種類（用事・メール・記憶の一覧など）は、生む経路がまだなく言い回しも原本にないので、従来どおり「画面で確認してください。」のまま。版は `1` のまま（既存の文は変えず、足すだけ）     |
| つなぎ・背景化・受付     | `bridgeCommentary`・`backgroundCommentary`・`acceptedCommentary`。事実（件名・宛先・本文）を含まない 1 部の文。**受け付けていない依頼には使わない**（受付は裏のジョブが受け付けたときだけ。経路は P3）。この PR は文だけで、送る時間制御は P3                                                                                                                                                                         |
| 完了                     | `completionCommentary({ kind, executed })`。`executed` がちょうど `true` のときだけ「登録しました」系の文を返し、それ以外（false・未指定・真に見えるだけの値）は承認待ちの案内（画面で確認してください）にする。完了を告げてよい条件をコードで固定するための規則で、**今の経路には呼ぶ所がない**（実行の完了を確認して声へ返すのは自動実行を持つ B13）。音声の「はい」を承認にしない（変更しない）                    |
| 追記の上限               | `fitCommentary`: 1 回の追記は 3 部以内・各 200 文字以内（400 トークンの安全側の近似。ADR 0052 のまま）。空の部分は載せない。超える部分は**切らずに載せない**（切ると意味が変わる）。超えた分があるときは、Core がその結果を画面へも置き（置けたかは確かめない）、声には「ほかは画面で確認してください。」を足す（3 部に満たなければ末尾、満杯なら最後の部分を置き換える。3 部を超えない）                             |
| 画面に出したとは言わない | 声に載せなかった文が画面にそのまま載るとは限らない（画面が持つのは結果の種類ごとの表示）。このため、**確認を頼む案内だけ**を声で足し、「画面に出しました」とは言わない。予定の一覧の残りの件数も、画面に載るのは先頭 50 件と件数だけで残りは見えないので、従来どおり「ほかに○件あります。」のまま（画面に出したと言わない。Codex の P2 指摘で、結果を画面へ置いたかを返す口と「画面に出しました」の案内を取り下げた） |
| 閉じた接続への追記       | 変えない（`appendCommentary` は接続が開いて準備済みのときだけ送る。閉じた接続・失効した依頼には送らない。X29・X33 の「閉じた接続への追記 0」は P3 の時間制御と合わせて確かめる）                                                                                                                                                                                                                                      |

## 試験（模擬だけ）

- `scripts/voice-commentary-limits.test.mjs`（手書きの期待値）: つなぎ・背景化・受付の文と template_id・事実を含まないこと。完了は `executed === true` のときだけ 5 種類の文、false・undefined・null・1・"true" では承認待ちの案内。完了以外の文が「しました」で終わらないこと。予定の残りの件数は件数だけで、画面に出したと言わないこと。追記の上限（3 部ちょうど・4 部以上・200 文字ちょうど・201 文字・サロゲートペア・空の部分・載せられる部分がない場合）。案内の文を足しても 3 部を超えない。
- `apps/core/src/live-conversation.test.ts`: 53 件の予定を声で返すと「予定は 50 件です。ほかに 3 件あります。」で、画面へは何も置かない（既存の試験。変更なしで通る）。

追記の上限を超えた場合の Core の配信（`fitCommentary` の超過 → 結果を画面へも置き、案内を足す）は、今の定型文が 3 部・200 文字を超えないため、Core の試験では起こせない（最終の防御）。domain の規則だけを試験した。

**模擬のみ**。実音声・実 API・実請求・実機は未実施で、合格扱いにしない。

## 残ること

- P3: 1.5 秒のつなぎ（1 回だけ）・8 秒の背景化・調査と相談を最初から裏へ回す経路（受け付けたときだけ受付の文）・完了の気づきと次回の文脈・遅着・訂正と別件。
