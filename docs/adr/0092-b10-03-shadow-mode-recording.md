# ADR 0092: B10-03 P3 影モードの記録（比較・300 件の上限・保存期限・既定 OFF）

- 日付: 2026-11-03
- 状態: B10-03（親 #18、Issue #200）P3 の判断。影モードの比較の実行と記録の規則を Core に足す。**SQLite への保存（`intent_shadow` の命令・由来の辺・忘却の閉包）と起動時の設定の読み込みは未実装**（下の「残ること」）。実 API・API キー・実請求・実機は未実施。
- 根拠: 設計 10 §5・§6A、設計 09 X48・X57、設計 05 の影モードの運用（P05）、ADR 0008・0040・0070・0090・0091、本人の決定 D4（2026-11-01、既定 OFF）。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。
- 対象: `apps/core/src/shadow-mode.ts`、`turn-ports.ts`（判定時間 `elapsed_ms`）、`api-turns.ts`（`onInterpreted` の入口）、`core.ts`（`CoreTurnOptions.onInterpreted`）、`packages/ai/src/candidate-comparison.test.ts`。契約・マイグレーションは変えていない（`intent_shadow` の表と `IntentShadowRecord` は既存）。

## 決めたこと

| 対象               | 決定                                                                                                                                                                                                                                                                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 既定               | **OFF**（D4）。`ShadowSettings` が無ければ、比較モデルも保存先も呼ばない。評価のときだけ設定を渡して ON にする。起動時の設定の読み込みは実 API の承認（B15）まで配線しない                                                                                                                                                                           |
| 会話への影響       | `observe` は同期で戻り、比較は裏で動く。比較の遅延・失敗・例外は本線に伝えず、`used_for_execution` は常に `false`。比較の入口（`onInterpreted`）は、保存した新しい発言の解釈だけに呼ぶ（再送・会話の操作・Live では呼ばない）。入口の例外は発言の結果を変えない                                                                                      |
| 走らせない条件     | 記録しない会話（`storageModeStateEffects` の `record_shadow` が偽、または保存期限が決まらない）・音声の接続中・余力がない（P0/P1/P2 の仕事がある）・予算の口が拒否・campaign の停止。走らせなければ記録も **0 件**。記録しない会話は、比較モデルへ文字を送らないことにもなる                                                                         |
| 300 件の上限       | 開始前に保存先の件数で `updateShadowCampaign`（件数・実費・日数の最初の到達で停止）を確かめ、保存側でも `save(record, limit)` が件数と同時に原子的に判定する。上限は `min(設定, 300)`。299 件から同時に 2 件走っても保存は 1 件で、300 件に達した後は比較モデルを呼ばない                                                                            |
| 保存期限           | 保存した発言の `expires_at`（通常 7 日、拡張 30 日）と**同じ時刻**にそろえる。`onInterpreted` が発言の期限を渡し、比較の完了時刻からは数えない（比較が遅れても期限は延びない）。比較が終わる前に発言が失効していたら記録を残さない                                                                                                                   |
| 記録の内容         | 契約の `IntentShadowRecord`（本線と比較モデルの意図・引数・遅延）。発話の本文を持たず、`input_id` で参照する。拒否・打ち切り・形式不正・timeout・利用不可は `outcome` で分け、「意図なし」に読み替えない。契約に合わない記録は保存しない                                                                                                             |
| 複数の比較モデル   | `targets` のすべてを同じ入力で並行して判定し、1 入力の記録の `shadows` にまとめる。予算の口が拒否した対象は黙って欠落させず `skipped` で記録し、予算の口が例外を投げた対象は `unavailable` で記録して他の対象の結果を残し、全部が拒否されたときだけ走らせず記録も作らない                                                                            |
| 未送信の入力       | 本線と同じ入力の検査（空・2,000 文字超など）を受付の前に行い、通らない発話は受付（予約）も作らず skip する。万一送らなかった場合は精算せず `release` する（使用量不明の予約を残さない）                                                                                                                                                              |
| campaign の再確認  | 件数・実費・日数の停止条件は開始前に加えて、予算の受付を待った後の送る直前にも保存先の件数と実費の口から読み直す。停止済み（または実費を取得できない）なら送らず予約を解放する。受付を同時に待つ比較どうしが、互いの保存より前に送り出す分は防げない（上限を超える記録は保存側の原子的な上限で防ぐ）ので、超過しうる呼出しは同時数の分だけに限られる |
| 音声の接続の再確認 | 観測時の `live_session_open` に加えて、`liveSessionOpen` の口で今の状態を、予算の受付の前と受付後の送る直前に読み直す。接続が開いていれば送らず予約を解放して skip する（`live_session_open`）。口は省略できるが、省略すると観測時の値だけになるので、本番の配線では必ず渡す                                                                         |
| 送る直前の再確認   | 設定（OFF・campaign の入れ替え・対象の取り外し）と余力（P0/P1/P2 の仕事がないこと）は、予算の受付の前と、受付の後で送る直前にも読み直す。受付を待つ間に無効化された比較は送らず、`ModelCallAdmission.release` で予約を解放する（B10-03 P3 で `release` を口に足した）。全部が無効なら記録を作らない                                                  |
| 費用               | 比較は会話専用枠ではなく、自発的な解析と同じ側（`origin: shadow_mode`）の予算の口で受け付ける。口は `ModelCallGuard`（ADR 0091）。拒否なら走らせない。実費の合計は `spent` の口から受け取り（**必須**。取得できない・不正な値のときは比較を始めない。上限を迂回させない）、金額は設定の外に置く                                                      |
| 候補比較（X57）    | 候補モデルは同じ指示・基準日・入力を受け、結果を候補ごとに分けて残せる（`candidate-comparison.test.ts`）。意図だけ合格した候補を他の用途へ転用しない規則、評価セット・採点・採否は既存の domain の規則と B10-07                                                                                                                                      |

## 試験（模擬だけ）

- `apps/core/src/shadow-mode.test.ts`: 既定 OFF で呼出し 0・記録 0。通常の会話で 1 件・本文なし・`used_for_execution: false`・7 日。拡張の会話は 30 日。X48: 記録しない会話（と未知のモード）は呼出し 0・記録 0。音声の接続中・余力なし・予算なしは skip。遅い比較モデルでも `observe` が待たない。比較の各失敗が outcome で記録される。299 件から同時 2 件で 1 件だけ保存、300 件の後は呼出し 0、設定が 300 を超えても 300。実費・日数の上限での停止。実際の発言の経路で、比較モデルが timeout でも本線の応答が同じこと、再送・会話の操作で記録が増えないこと、既定 OFF で呼出し 0。
- `packages/ai/src/candidate-comparison.test.ts`: X57 の同じ条件の比較。

**模擬のみ**。実 API・実請求・実機・実 endpoint の能力確認・モデルの採否は未実施で、合格扱いにしない。

## 残ること

- `intent_shadow` の保存（DB worker の命令、`derivations` の辺による忘却の閉包、期限の掃除との接続）。マイグレーションは不要（表は 0001 にある）。この PR の保存先は口（`ShadowRecordStore`）とメモリ上の偽。
- 起動時の設定（campaign・比較モデルの配備 ID・endpoint・認証）と、`planModelCalls` による余力の判定の配線は B15 と本人の承認に合わせる。
- 比較の集計（`ShadowCampaignSummary`）、採否は B10-07。
