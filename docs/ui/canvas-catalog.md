# UI-07 部品のカタログの記録（9 つの部品・本文を取る経路・持ち越しの P3）

[ADR 0032](../adr/0032-ui-canvas-stream-and-window-roles.md) の部品のカタログ（Issue #99、親 #92）の記録です。**製品の試験の合格ではありません。** 既定のデスクトップは今の 1 つの窓（従来の窓）で、開発用のフラグ（`--buddy-ui=canvas`）のときだけキャンバスの窓を使います。規則は [ADR 0032 の「UI-07 の部品のカタログ」](../adr/0032-ui-canvas-stream-and-window-roles.md)に先に書き、その後で実装しました。

記録は 3 つに分けます。

- **模擬**: Electron を起動しない試験（`pnpm test`）。127.0.0.1 の Core と main の部品の統合、サーバー描画、happy-dom の文書での描画を含む。
- **撮影用の起動での描画**: ビルドした画面を、本物と同じ CSP の index.html で、画面に出ないブラウザ（Playwright の headless shell。本人のブラウザとは別の一時のプロセス）に読み込み、撮影用の模擬の限定 API で決まった記述と本文を渡して撮った。main・Core・OS の窓・物理の入力は通っていない。
- **未実施**: 確かめていないこと。

**中身（行・セル・予定・メール・出典など）はすべて合成の模擬のデータです。** 実データの取得は B08（予定）・B09（メール）・B11（記憶・出典）で作ります。実在の人名・メール・URL・予定を含みません。

## 撮影用の起動での描画（2026-10-23）

ビルドした画面（`apps/desktop/dist/renderer`）を一時のディレクトリへ写し、撮影用の模擬の限定 API（キャンバスの窓として決まった状態欄・記述・本文を返す）を読む index.html にして、127.0.0.1 から画面に出ないブラウザで開いた（CSP は本物の index.html の meta のまま。違反は 0 件）。9 種類の部品（chart は 2 通り）を、ライトとダーク × 狭いカード（幅約 180）と広いカード（幅約 680）で撮り、全部の部品を 1 枚に並べた画面（1920 × 1080・1280 × 800・幅 480 の 1 列）、メールを開いた状態、フローティングウィンドウと通常のカードの比較も撮った。**どのカードも本文が箱からあふれない**（本文の領域の scrollHeight・scrollWidth が箱の中に収まる）ことを DOM の値で確かめた。スクリーンショットはスクラッチの場所（リポジトリには入れない）。

- list: 状態は形（線の円・塗った円とチェック・三角と！）で分かれ、期限は右（狭いカードでは題名の下）。入りきらない行は「+数」。
- table: 見出しの行と本文の行。狭いカードでは 1 列だけ描き、「+行数」「→列数」の札。
- schedule_timeline: 縦の時間の軸。重なる予定は横に並び、重ならない予定は全幅。
- mail_card: 差出人・時刻・件名・ラベル（狭いカードではラベルを省く）。開いた 1 通の下に本文。
- compare: 同じ値の行は 1 つの広いセル、違う行は列ごとに分かれて左に太い線。狭いカードでは列が減り「→1」。
- progress: 名前・帯・「済み / 全部」。終わったものはチェック。
- chart: 棒と折れ線。2 つ目の棒は斜線、折れ線は点の形と線の種類で区別。凡例は同じ形。狭いカードでは項目の名前を 1 つおきに間引く。
- source_list: 題名・ホスト名・外へ出る矢印。
- text: プレーンテキスト。改行を生かす。
- ダークでも同じ構図で、トークンの色だけが変わる。
