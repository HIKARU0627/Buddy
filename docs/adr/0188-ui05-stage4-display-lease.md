| 止める                     | 条件を外れたら（窓が隠れた・ロック・停止・接続が切れた・キャンバス表示でない・終了）更新をやめる。待っている更新の応答・予約した更新は使わない。**リースを返す経路は契約にない**ので、中枢では `ttl_ms`（6 秒）で切れる（U472）。これは「失った」ではなく、理由は出さない（記述は今までどおりロック・停止・切断・隠れたことで捨てる）                                                                                                                    |

### 状態の移り（`DisplayLeaseKeeper`）

| 状態        | 意味                                 | キャンバスの窓                                  |
| ----------- | ------------------------------------ | ----------------------------------------------- |
| `idle`      | 条件が揃っていない（取りに行かない） | 記述を捨てる。理由は出さない                    |
| `acquiring` | 最初の取得を待っている               | 何も描かない（理由は出さない。取れたら読む）    |
| `held`      | 持っている                           | `GET /v1/canvas` で取り、検査を通った記述を描く |
| `lost`      | 失い、間隔を置いて取り直している     | 物を描かず、理由の 1 文だけ                     |

`lost` は取り直しが失敗し続けても 1 回だけ知らせる（取り直しのたびに出し直さない）。`lost` の間に条件が変わって取り直しても、取れるまでは `lost` のまま。

## 契約

- `DesktopIpcNotification` の `desktop.canvas_changed` に、理由つきの形 `{channel, canvas: null, withheld_reason: "display_lease_lost"}` を足した（`oneOf` のもう 1 つの形。今までの形 `{channel, canvas}` はそのまま）。理由つきの形は `canvas` が必ず null で、記述と理由を同時に持たない（Schema で拒否する）。理由の種類は今は 1 つ。
- `packages/contracts/fixtures/canvas-stream-cases.json` に、正しい形 1 件と、拒否の形 3 件（記述と理由の両方・知らない理由・理由が null）を足した。
- `LeaseRenewalRequest`・`LeaseRenewalResponse` は変えていない。端末の `LeaseRenewalBody` の `kind` を `'audio' | 'display'` にした（音声と表示で同じ型）。
- `@buddy/client` の `LinkState` に `ioEpoch`（bootstrap の `io_state.io_epoch`）を足した（契約の型は変えていない）。

## 画面

- キャンバスの窓は、理由があるとき物を描かず、上の中央の島の下へ 1 段だけを出す（`CanvasWithheld`）。記号と文言は tones.ts の約束どおり `warning` の `○`（「接続し直し待ち」と同じ。自動で取り直すので本人の操作は要らない）と、文言「中枢との表示の確認が途切れたため、キャンバスの物を隠しています（確認し直せたら戻ります）。」の 1 文。記号は読み上げず（`aria-hidden`）、段は `role="status"`。
- 枠は shapes.ts の共通の枠 `FRAME_CLASS`（`rounded-box`・`border-separator`）、地はキャンバスの地（`bg-background`）のまま（新しい色の組を作らない）。文字はキャンバスの地の上の `text-foreground` と `text-warning-soft-foreground`（ADR 0024 の 4.5:1 の組）。
- ロック中・停止中は今までどおり地の中身ごと描かない（理由も出さない）。画面の状態（`desktop-state.ts`）は、理由のない通知・ロック・停止で理由を消す。
- 撮影（Electron なし、Playwright の chromium、合成の値）: 理由を出した状態のライト・ダークを撮って目で確かめた（下の「撮影」）。

## 試験（模擬だけ）

期待値は手で書いた値（送った時刻・期限・nonce の連鎖・状態の移り・取り直しの間隔・通知の形・文言）。検査対象の関数から作っていない。リースの時計とタイマーは手で進め、実時間を待たない。

- `apps/desktop/src/main/display-lease-keeper.test.ts`（9 件）: 条件が揃うまで送らない・最初の取得の本文（`display`・新しい ID・前の nonce なし・中枢の世代 3・2000／6000・期限は送った時点から）、2 秒ごとに期限より前に同じ ID で更新し nonce をつなぐ、隠れる・ロック・停止・切断（条件が null）で止めて応答と予約を使わず、見えたら新しい ID で取り直す・終了で止まる、更新の拒否ですぐ失い 2 秒後に新しい ID で取り直して held に戻る、失敗が続くと 2・4・8・16・30・30 秒で取り直し失った知らせは 1 回だけ・条件が外れたら取り直しもやめる、答えのない更新で期限（7000 ちょうど）に失う、最初の取得の結果不明・例外で失い持っている間の結果不明では期限まで持つ、更新の数の上限・nonce の食い違いで今のリースを保ったまま 1 回だけ取り直し、取り直しも拒否されたら失う、違う nonce の成功を使わない・接続範囲と世代が変わったら取り直す。
