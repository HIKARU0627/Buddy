- 根拠: 設計 11 §3・§5A・§5B、設計 09 X39・X62・X63・QA09〜QA11・QA45、ADR 0007・0070・0082・0100。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。
- 対象: `packages/ai/src/extraction.ts`・`extraction-evidence.ts`・`validation.ts`・`index.ts` と各試験、`docs/b00/contract-map.md`（U242・U243）。契約（`packages/contracts`）は変えていない。

## 決めたこと

| 対象                     | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 実行の流れ               | 入力の組立て（P1）→ 1 回だけ送る → schema（契約の `ExtractionWire`）→ 意味 → 根拠の照合と `ExtractionResult` v2。timeout・不正な出力・途中終了の後に、自動の再送・JSON 修復・上位モデルでの再試行をしない（ADR 0070）。検証層（`modelOutcomeFromAdapter`）は出力の型を型引数にし、意図の判定の既定は変えない                                                                                                                                                                                           |
| 結果の 3 状態            | `extracted`（結果を得た）・`not_sent`（入力が組み立てられず送らなかった）・`failed`（送ったが使えない。原因の種類と usage を保つ）。失敗を「依頼 0 件の成功」に混ぜない（設計 11 §5B）                                                                                                                                                                                                                                                                                                                 |
| 位置と照合               | 引用は、**実際に送ったソースの text** を `source_id`・`part`・`source_revision` で引き当て、コードポイント単位で探す。重なる一致も数え、**一意でなければ照合できない**（QA11）。文字の正規化はしない（分解形と合成形は不一致）。対になったサロゲートの途中から始まる一致は境界でないので除く。照合できない理由は `source_unknown`・`part_mismatch`・`revision_mismatch`・`not_found`・`ambiguous` に分けて数える（診断用。本文・引用は含めない）                                                       |
| 根拠の状態               | 引用が 1 つも無い・全部照合できない → `missing`。一部だけ照合できない → `conflicting`（照合できた引用だけを refs に残す）。全部照合できた → `explicit`。照合できない根拠を `explicit` にしない（U242）                                                                                                                                                                                                                                                                                                 |
| confidence               | 根拠の照合に失敗した依頼（引用の照合失敗・根拠なし・期限の原文を照合できない）は、自己申告が高くても `low` に下げる。**上げない**。観測値で、認可に使わない（ADR 0007）。照合に失敗した依頼は、domain の共通検査（`candidateCommonReasons`）が `confidence_low` と `evidence_*` で拒否するので、4 種類の自動実行の対象にならず、承認待ちも作らない（X39）                                                                                                                                              |
| 期限と年                 | 原文（`original_text`）が照合できた引用の中か、送ったソースの中に一意にあるときだけ `explicit`。照合できなければ `missing` で `low`。**確定した年が、同じ依頼の引用・原文にある年の数字、または受信年を基準にした「今年・来年・再来年・昨年・去年」で説明できなければ、`unresolved`（`missing_year`）へ下げる**（年を推測した出力を確定値にしない。X63・QA09）。日付だけの期限に時刻を補わない                                                                                                         |
| 期限なし                 | 全て読めているときは期限の項目を作らない（返信の下書きを止めない）。未読・切詰めがあるときは `unread` の項目を作り、「期限なし」を確定しない（X39・QA10）                                                                                                                                                                                                                                                                                                                                              |
| 意味の検証               | 期限の欄の組み合わせが矛盾する出力・暦にない日付・範囲外の時刻は、直さず `invalid_semantics`（失敗）にする（ADR 0007）。組み立ては、この検証を通らない出力では例外で止める                                                                                                                                                                                                                                                                                                                             |
| 引用                     | モデルの `in_quoted_text` と、照合できた根拠が本文の引用の範囲（P1）に重なるか、**どちらかが引用なら引用**として扱う（自動実行の対象外の方向。U241）                                                                                                                                                                                                                                                                                                                                                   |
| コードが決める項目       | 位置、未読・切詰め・版（P1 が確定した `completeness` をそのまま使う）、`addressed_to_me`・`from_automated_sender`（ヘッダーから Core が決めた値を引数で受ける）、依頼 ID（`null`）。モデルが返せる項目の schema（`additionalProperties: false`）にこれらは無く、余分な欄は `invalid_schema`                                                                                                                                                                                                            |
| 変更（取消・完了・訂正） | 対象と変更の根拠を同じ規則で照合する。依頼 0 件でも変更を返す。**対象と変更の内容の両方の根拠が照合できたうえで、注入された解決関数（Core の 5A の規則）が一意に返したときだけ `resolved`**（変更の根拠が空・不一致・版違い・一部だけの取消・完了・訂正は `unresolved`。根拠のない取消で有効な依頼を止めない）。0 件は `unresolved`、2 件以上は `ambiguous`。`uncertain`・根拠の照合に失敗した対象は解決関数を呼ばず `unresolved`。`new` は対象なしで `resolved`。変更の新しい期限にも年の規則を当てる |
| 関連解析への写し         | `analysisStateOfExtraction`: `analyzed` になるのは、結果を得て、**未読も切詰めもないときだけ**。依頼が 0 件でも未読があれば `unread`（空の結果で ready にしない。QA45）。読める内容がない入力は `unread`、入力の誤りは `failed`。timeout・利用不可・予算・中断は `pending`、拒否・打ち切り・schema／意味の不正は `failed`。どれも関連解析を ready にしない（`analysisReadiness`）                                                                                                                      |
| 出力の上限               | 出力の文字数の安全上限を 16,000 とする。profile の出力上限（暫定の `background-low` は 500 トークン）に収まらない出力は `truncated`（失敗）で、部分の出力を使わない（U243）                                                                                                                                                                                                                                                                                                                            |
| 置き場所                 | domain は contracts に依存しない（ADR 0010）ので、契約の型を使う根拠の照合と結果の組立ては `packages/ai` に置く。依頼 ID の解決・保存・候補の生成は別の層（B11）                                                                                                                                                                                                                                                                                                                                       |

## 試験（模擬だけ）

`packages/ai/src/extraction.test.ts`（手書きの期待値。契約の JSON Schema を正本にし、自動実行の可否は domain の共通検査と操作別の検査で確かめる）:

- X39・QA11: 引用が見つからない・版違い・参照元違い・part 違い・一意でない・結合文字・サロゲートの境界。照合できない根拠は explicit にならず、4 種類の自動実行の理由に `confidence_low`・`evidence_missing:summary` が出る。引用の中の依頼は引用として扱う。
- X62・QA10: 添付の引用が正しい添付の中にあるときだけ照合できる。別の添付にしかない引用は照合できない。読取失敗・未取得の添付と本文の切詰めは入力のコードが確定し、モデルが未読の欄を返すと `invalid_schema`。自動配信の用事・下書きの既存の制限は残る。
- X63・QA09: 年の記載のない日付・翌年へ繰り上げた日時・本文の年と食い違う年は確定せず `unresolved`。「来年」「年の数字」は確定する。過去の期限は過去のまま。日付だけの期限に時刻を補わない。
- 矛盾する期限・暦にない日付は `invalid_semantics`（usage を保つ）。
- QA45（抽出の部分）: 期限のない取消を依頼 0 件で抽出し、解決関数が 1 件のときだけ `resolved`。0 件・2 件以上・`uncertain`・照合できない対象は未解決・曖昧のまま。未読のある空の結果は `analyzed` にならず、`analysisReadiness` が ready にならない。
- 失敗（timeout・利用不可・中断・拒否・打ち切り・途中の JSON）は別の状態で、送信は 1 回だけ。

検証層を型引数にした変更は、既存の試験（意図の判定）が変わらず通ることで確かめた。

**模擬のみ**。実 API・実メール・実請求・実機・モデルの採否は未実施で、合格扱いにしない。

## 残ること

- 抽出前フィルターと判定の記録は P3、関連集合の計画と実行直前の照合は P4。
