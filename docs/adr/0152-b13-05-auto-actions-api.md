# ADR 0152: B13-05 自動実行の一覧と安全停止の解除の API

- 日付: 2026-11-26
- 状態: B13-05（親 #24）の Core の API の部分。自動実行の一覧（`GET /v1/auto-actions`）と安全停止の解除（`POST /v1/safety/resume`）の処理を作る。取り消し（`POST /v1/auto-actions/{id}/undo`）の経路、補償の操作の中身、画面は未着手。実データ・実機・実 API は未実施。
- 根拠: 設計 03「取り消しと安全停止」、設計 07 §2、設計 08 §9、J12、設計 06 B13、ADR 0009・0018・0074・0147。原本の参照手順は `docs/design/README.md`。
- 対象: `packages/domain/src/approval.ts`（取り消しの状態の規則）、`packages/storage/src/safety-store.ts` と worker の通り道（`db-protocol.ts`・`db-worker.ts`・`db-client.ts`）、`apps/core/src/api-auto-actions.ts` と `core.ts` の配線、それぞれの試験。契約（`packages/contracts`）とマイグレーションは変えない。

## 背景

B13-03（ADR 0147）で、安全停止の件数・自動実行の一覧（`auto_actions`）・取り消しの記録（`undo_records`）・停止の解除（`resumeSafetyBreaker`）を保存層に作った。契約には一覧・取り消し・解除の 3 経路があり、経路の検査（`ROUTE_CHECKS`）も決まっているが、Core に処理が無く、経路は 404 のままだった。

## 決めたこと

| 対象             | 決定                                                                                                                                                                                                                                                                                                                         |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| worker の通り道  | 一覧の照会と解除の書込みを、新しい通り道 `safety` で受ける。書込みの扱い（止めた worker は書かない・耐久設定の照合・成否不明は broken）は音声・予算の通り道と同じ。操作の命令（`DbCommand`）は操作の状態の遷移だけに使うので、そこへは足さない                                                                               |
| 一覧の中身       | 安全停止の状態と自動実行した操作を一つの読み取り transaction で返す。項目は完了の新しい順で、操作の今の版（`state_revision`）、実行した確定 intent の内容版と hash（`undo_target`）、取り消しの期限を付ける。確定 intent の本文は読まない・返さない。件数は新しい順に 200 件まで（U309）                                     |
| 取り消しの状態   | 有効な取り消しの記録が `undone` なら `undone`、`in_progress` か `unknown`（補償の結果の確認中）なら `in_progress`。有効な記録が無く（失敗だけを含む）期限を過ぎていれば `expired`。期限ちょうどはまだ期限内（取り消しの開始と同じ比べ方）。取り消しの経路が無い間は、それ以外を `unavailable` にし、取り消せるように見せない |
| 外部の対象の変化 | `target_changed` は提供元の現在値を読まないと決められないので、一覧では出さない。取り消しの経路を作るときに、補償の直前の照合とあわせて決める                                                                                                                                                                                |
| 解除の版の照合   | 経路の検査の `expected_revision` は DB の現在の安全停止の版と本文の `expected_safety_revision` を比べる。読めなければ 503。解除の transaction の中でも同じ値で照合し直す                                                                                                                                                     |
| 解除の応答       | 成功は 200 で解除の後の `SafetyState`。版の不一致・停止していないは 409 `conflict`、照合の後に失効した端末は 401、成否不明と想定外の失敗は 503。解除した端末は `resumed_by_device_id` に残す（設計 07 §2）                                                                                                                   |
| 同じ要求の再送   | 解除は版を進めるので、同じ `request_id` の再送は 409 になり二重に効かない。入出力の再開（`resumeIo`）・取得対象の変更と同じ扱いで、画面は読み直して確かめる                                                                                                                                                                  |

## 原本に決めがない項目

- 一覧の件数の上限と、古い項目の見せ方は書かれていない（U309）。契約の `AutoActionList` にページ送りが無いので、取り消しの期限（30 日）の範囲を想定して新しい順に 200 件までにした。

## 対象外

- 取り消しの経路（`undoAutoAction`）、補償の操作の中身と対象の現在版の照合、照合で拒否した操作の後始末。
- 自動実行の一覧・安全停止・取り消しの画面（B13-05 の残り）。

## 試験（模擬だけ）

- `packages/storage/src/safety-store.test.ts`: 期待値はすべて手書き。一覧の順序・各項目（版・時刻・期限・内容版・hash）、取り消しの状態（取り消し済み・取り消し中・結果不明・失敗・期限ちょうど・期限切れ）、一覧に載らない操作（画面で承認したもの・未完了）、通り道での状態の読み取りと解除（停止していない・版の不一致・未登録の端末・版の形式・書込みを止めた worker・成功の後の状態）、worker を介した一覧と解除。
- `apps/core/src/api-auto-actions.test.ts`: 端末トークン・自宅・ロック解除・画面の操作の拒否、一覧が契約の形に合うこと（本文を含まない、取り消しは `unavailable`）、解除の版の照合・成功・再送の 409・解除した端末の記録。

**模擬の期待値だけ**。画面・実データ・実機・実 API は未実施で、合格扱いにしない。
