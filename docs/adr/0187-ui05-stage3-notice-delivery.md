# ADR 0187: UI-05 の段階 3 期限切れ・忘却の知らせの運搬（WSS の notice）とキャンバスの物の後始末

- 日付: 2026-11-27
- 状態: UI-05（#97、親 #92）の段階 3（ADR 0068 の段階の表）の判断と実装。`apps/core/src/notice-relay.ts`（新規。知らせの中継）、`apps/core/src/event-stream.ts`（購読へ `notice` を送る）、`apps/core/src/canvas-stream.ts`（`CanvasHub.removeItems`・`StreamRoutes.applyNotice`）、`apps/core/src/core.ts`（配線と `CoreHandle.notices`）、`packages/client/src/connection.ts`（`ClientConnection.onNotice`）、`apps/desktop/src/main/core-link.ts`（受け取り）、契約（`EventStreamMessage` に `notice` を足した。JSON Schema・OpenAPI の説明・`api-cases.json` の `streamEvents`）と模擬の試験だけ。マイグレーションは足していない。忘却の公開ゲート `FORGET_PUBLIC_GATE_OPEN` は閉じたまま。画面への表示（本人への知らせ）は作っていない。実機の Mac mini・Windows・macOS の端末、実データ・実 API・実請求は未実施。
- 根拠: ADR 0032（流れ・キャンバス・窓の役割。版の知らせ・ロック中は取りに行かない・要約の由来と期限・忘却は要約をつながない）、ADR 0058（期限処理と知らせのポート `NoticeSink`。消せた物だけ・配信の失敗は掃除の失敗にしない。元情報の知らせの ID は元サービスの ID）、ADR 0068（UI-05 の段階分け・段階 2-i の忘却の区切り・U168）、ADR 0180（忘却の Core の経路と `ForgetLedgerNotice`・U383 の残り）、ADR 0182（端末の忘却台帳の複製と受け取り口 `forgetLedgerNotice`・U403）、ADR 0186（U464）。**本人の決定（2026-11-01、U168）**: WSS の `notice` を開いている購読だけへ流し、再送・永続はしない（表示は版と `getCanvas` で収束させる）。非公開の原本（設計 01・03・07）はこの環境になく、参照していない。決めのない点は、本人の「試験と見直しは後でまとめて行う」に従って聞かずに暫定で決め、`docs/b00/contract-map.md` の U465〜U468 に記録した。
- 番号: ADR は 0187、未決事項は U465〜U468 と、見直しで足した U469。

## 運搬の設計（どの知らせを誰にどう送るか）

| 知らせ                           | 出す所                                             | 端末へ                                                                                                                   | Core の中                                                              |
| -------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `RetentionNotice`（`expired`）   | 掃除の job（消せた物だけ。ADR 0058）               | 開いている購読すべて（端末ごとに絞らない。1 人の利用者の端末）。`source_item` の項目を除き、除いて空なら送らない（U467） | キャンバスの物を閉じる。要約をつないだ区間が消えたら要約を外す         |
| `RetentionNotice`（`forgotten`） | 忘却の経路（ADR 0180。製品ではゲートが閉じている） | 同上                                                                                                                     | 同上に加え、要約を外し、次の発言で `forget_requested` の区切り（U466） |
| `ForgetLedgerNotice`             | 忘却の経路                                         | そのまま                                                                                                                 | 何もしない                                                             |
| `StorageBoundaryNotice`          | 保存境界の保持者（起動の途中）                     | そのまま（ただし起動の途中で出るので、今は購読がなく届かない）                                                           | 何もしない                                                             |

- **購読していない端末・切れた接続**: 中継は「そのとき登録されている購読」にだけ渡す。登録は、接続範囲を確かめて配信を始めた後（`start` の中）で、閉じる・切れる・自宅判定の不成立・接続範囲の失効・端末の失効で外れる。溜めない・cursor に入れない・後から開いた購読に前の知らせを送らない（U168）。取り逃した端末は、表示は版（`canvas`）と `getCanvas` で、忘却台帳は次の接続の同期（ADR 0182）で収束する。
- **検査**: 既存の購読の検査に合わせた（端末トークンと自宅判定は切り替えの前。接続範囲は開始と ping ごとの確かめ直し。端末の失効と自宅判定の不成立は即時に閉じる）。**ロック中も送る**（`event`・`canvas` と同じく本文を持たない。U465）。端末はロック中はキャンバスを読まず、台帳だけ追いつく（台帳の配信はロック中も返す。U387）。表示の権限（`management_only`）で知らせを分けることはしていない（U465 で本人に確かめる）。
- **中身**: 今の知らせの型の範囲（ID と理由と番号）。発言・記憶の ID は Core の DB の行の ID（UUID）、`carried_summary` は区間（会話）の ID で、どちらも端末が応答で既に受け取る種類の ID。元サービスの生の ID（`source_item`）は送らない（U467）。台帳の知らせは系譜・世代・`entry_hash`（項目の hash。HMAC ではない）だけ。
- **順序**: 表示の後始末を先に当て（版の知らせ `canvas` が先に購読へ出る）、その後に `notice` を送る。`notice` を受けた端末が取る `getCanvas` は、閉じた後の記述になる。

## キャンバスの物の消し方

| 対象                 | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 記録 |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 結び付き             | (1) その物を置いた・最後に中身を変えた発言（発言の結果の束を当てたときに Core の RAM に覚える。保留を捨てた知らせの物は発言に結び付けない）、(2) 物の参照の `screen_result`（声で返せなかった答えの物。参照の ID は発言の ID）、(3) 物の参照の `memory`（記憶の ID。今の配置者は置かないが、置いたときに同じ規則で消す）。どれかが知らせの項目に当たれば閉じる                                                                                                                            | U468 |
| 閉じ方               | Core が `close` の束を作り、AI の束と同じ Schema・domain の検査（`applyCanvasBatch`）を通して当てる。残る物の関係がその物を指していれば、先に `update` で外す。1 つの束は 12 操作（`CANVAS_OPS_LIMIT`）までなので、多ければ束を分け、束ごとに版を 1 進める。閉じた物の本文（`#texts`）・置き場所の版（`placedAt`）・結び付きを捨てる。当たる物がなければ版を進めない（知らせも出ない）                                                                                                    | U468 |
| 再送                 | 消えた発言の同じ要求の再送は、前の束を返さず `canvas: null`（消えた物の束を端末に返さない）。配置済みの印は残し、置き直さない                                                                                                                                                                                                                                                                                                                                                             |      |
| 区切りにつないだ要約 | 期限切れでは区切らない。要約をつないだ区間（`carried_summary` の項目。今の区切りか要約の由来の区間）が消えたら、今の区切りの要約を外す（区切りは変えない）                                                                                                                                                                                                                                                                                                                                |      |
| 忘却の後の区切り     | 忘却の知らせ（`kind: forgotten`）では、どの忘却でも今の区切りの要約を外し、次の発言で `forget_requested` の区切りを始める（ADR 0068 の段階 2-i と同じ印。要約はつながない）。Core は忘れた内容が今の文脈・要約に入っているかを確かめられないので安全側にした。ADR 0180 の U383 の残り（画面の経路の忘却の後の流れの区切り）を、この形で埋めた。新しい区切りの会話を作っている間（自動の区切り・保存モードの切り替え）に忘却の知らせが来たら、作る前に決めた要約を新しい区切りにつながない | U466 |
| 保存                 | 結び付きはキャンバスと同じく Core の RAM（再起動で作り直す。U169）                                                                                                                                                                                                                                                                                                                                                                                                                        |      |

## 試験（模擬だけ）

期待値は手で書いた値（版・物・関係・区切り・知らせの中身・送った同期の世代・読み取りの回数）。検査対象の関数から作っていない。

- `apps/core/src/notice-relay.test.ts`（3 件）: 端末へ送る形（`source_item` を除く・空なら送らない・ほかの知らせはそのまま・契約に合う）。表示 → 購読 → 受け取り口の順、購読がない間の知らせを後から送らない、外した購読に送らない。契約に合わない知らせ（本文の欄）を送らない、表示と購読の失敗で他を止めない、受け取り口の拒否を呼び出し側へ返す。
- `apps/core/src/canvas-notice.test.ts`（4 件）: `removeItems` が 14 操作を 12 と 2 の束に分けて版を 2 つ進め、関係を先に外し、本文・置き場所の版を残さず、ない物では版を進めない。`applyNotice` が置いた発言・`screen_result`・`memory` の参照で物を閉じ、関係のない知らせ・台帳の知らせでは版を進めず、消えた発言の再送に束を返さない（消えていない発言の再送は従来どおり）。要約をつないだ区間の期限切れで要約を外し（区切りは同じ）、忘却で次の発言が `forget_requested` の区切りになり、印は一度だけ使う。新しい区切りの会話を作っている間に忘却の知らせが来たら、その区切りに要約をつながない。
- `apps/core/src/notice-core.test.ts`（2 件。製品の Core を HTTPS で起動）: 流れへの発言で置いた用事のカードが、8 日後の掃除（発言の期限切れ）で閉じて版 2 になり、ロック中の開いている購読へ `canvas`（版 2）→ `notice`（項目は発言の ID だけ）の順で届く。閉じた購読には届かず、後から開いた購読は次の知らせ（台帳）からだけ受け取る。本文・予定の見出し・予定の ID を含めない。自宅の外で 4403 で閉じた購読には届かず、開き直しは 403、自宅に戻って開き直した購読には前の知らせが届かない。`source_item` だけの知らせは送らず、混ざった知らせは `source_item` を除いて送る。
- `packages/client/src/connection.test.ts`（1 件）: 契約に合う知らせを受け手へ渡し、知らない・本文の欄を持つ・欄の欠けた知らせは渡さずに購読を保ち、cursor を進めない。受け手の例外で他の受け手を止めない。知らせ以外の形の違いは従来どおり接続し直す。
- `apps/desktop/src/main/notice-link.test.ts`（1 件。製品の Core と main の部品）: 接続したまま保存層で忘れた後、台帳の知らせで世代 0 の head を 1 回だけ送って世代 1 を保存する。持っている head の知らせでは尋ねず、次の知らせ（世代 2）でだけ尋ねる。期限切れの知らせ（当たる物がない）でキャンバスを 1 回読み直す。ロック中は期限切れの知らせで読まず、台帳の知らせで追いつく。複製とログに元サービスの ID・台帳の中身を出さない。
- `packages/contracts/fixtures/api-cases.json` の `streamEvents`: `notice` の正しい形 3 件、拒否の形 5 件。
- 実装を壊して落ちることを確かめた（いずれも元に戻した）: 端末へ送る知らせから `source_item` を除かない（`notice-relay.test.ts` 2 件と `notice-core.test.ts` 1 件が落ちる）、物を置いた発言との結び付きを見ない（`canvas-notice.test.ts` 1 件と `notice-core.test.ts` 1 件）、知らない `notice` で接続し直す（`connection.test.ts` 1 件）、`DesktopCoreLink` が台帳の知らせを受け取り口へ渡さない（`notice-link.test.ts` 1 件）、区切りを作る間の忘却で要約を外さない（`canvas-notice.test.ts` 1 件）。
