## 残ること

- DB の列（予算月ごとのタイムゾーンと月の実際の始まり（monthStart）・始まりを決めたタイムゾーン（monthStartTimeZone）の記録、承認の表、手での精算の印）と単一 transaction での受付（B07-03）。
- 設定ファイルの置き場所と起動時の読み込み、処理をどの葉の枠に計上するかの門、時計の戻りを状態の「予算保留」に出すこと（B07-04）。
- 承認・確認・手での精算の経路の処理と、承認の consumed への更新（B07-05）。
- クレジットの区分（B07-07）、実請求との照合（B15）。
- 課金され得る期間の終わり（応答の期限）の決め方は profile の timeout に依存し、B07-04 で決める。
- **B07-04 の必須の項目**: 起点（`BudgetOrigin`）から計上する葉の枠を決める関数と、超過枠へ回せる枠の許可リスト（本人の依頼の枠）を設定から作ること。domain の `admitWithOverage` は許可リストを受け取るだけで、起点と枠の対応はまだ持たない（レビュー P3-2）。
- 時計が進んでから戻ったとき（誤って未来の月へ進んだ後に正しい時刻へ戻った場合）、`clock_regressed` の保留を本人が解く経路（予算月を戻す操作と、その間に受け付けた予約の扱い）。B07-04 で扱う（レビュー P3-5）。
- タイムゾーンの正規化（`Intl.DateTimeFormat().resolvedOptions().timeZone` の値で記録するか）と、`Etc/*`・旧別名（`Asia/Calcutta` など）の扱い。いまは IANA の名前の形と Intl が受け付けるかだけを見る。B07-04 で扱う（レビュー P3-6）。
