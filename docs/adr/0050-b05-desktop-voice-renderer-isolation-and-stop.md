## 3 層の停止（設計 10 §1、X30・QA43）

- **第 1 層**: 音声レンダラーが、停止の命令を受けたその場で再生・送信・収音を止め、PCM とリングを消す（ACK・session.close を待たない）。
- **第 2 層**: main は ACK の期限（suspend_io と stop_playback は 300 ms、close_voice_session は 1500 ms）を見て、ACK がない・適用に失敗した（failed・rejected_invalid・ignored_stale_epoch）・受け付けない ACK しかないときは、音声レンダラーを強制終了する（`forcefullyCrashRenderer` と窓の破棄）。強制終了したら、この端末の入出力も止める（「ACK が返らないときは、全部止める」。画面の明示の再開まで再開しない。U92）。再生停止の ACK がなければ全停止（suspend_io の device_io_stop。ADR 0041）へ上げ、入力の中断を画面で知らせる（`notice: input_interrupted`）。開始の ACK がなければ（3000 ms）provider_failure で閉じる。
- **第 3 層**: main は止めるときに中枢へ閉じる要求を送る（`VoiceCorePort.closeLive`）。中枢のサイドバンドからの終了と使用量の照合は ADR 0046 の Core が持つ。
- **判別できないとき**: 音声レンダラーの無応答（`unresponsive`）・クラッシュ・読み込みの失敗は、会話中でなくても強制終了し、この端末の入出力を止める。止める・ロック・作り直しの後に届く ACK、前の音声レンダラーからの ACK、世代の合わない ACK は使わない。
- **再開しない**: ロックの解除・再接続・呼びかけでは自動で再開しない。画面で明示再開すると、音声レンダラーが残っていれば呼びかけ待ちに戻り、強制終了していれば新しい音声レンダラーを用意するだけで、会話は「続ける」で新しく始める。

## 「音声を外部へ送っている」の印（U93）

- `external_send` は、開始の命令を出した時点から、閉じる・停止の ACK を受けるか強制終了するまで true。停止した直後（ACK を待つ ≦ 300 ms）は、状態が「停止中」でも印を消さない（送っている側へ倒す。印を早く消さない）。
- 外部へ送る状態は、**会話中・読み上げ中（音声の通知も Live の接続を開く。10 §7）・聞き取り中（文字で返す）**とした。聞き取り中は 10 §6A の③では端末の中で文字にするが、③と KWS が実際につながって確かめられるまでは、外し方を誤ったときに「送っていない」側へ倒れる害のほうが大きいので、送っている側に数える（PR #160 のレビューの司令塔の判断。ADR 0032 の読み取りは変えない）。外すかどうかは、③と KWS を実際につないで確かめたときに見直す。
- 停止中の音声の 8 項目の記号は ■（入出力の停止と同じ形）にした。

## 画面（本人の方針: 文字ではなくレイアウトで）

状態の層のパネルの入出力の段の下に、音声の段を置いた。1 段目は左から、マイクの記号・音声の状態（記号＋短い文言。停止中は入出力の段と重ねないよう ■ だけで、文言は読み上げの名前だけ。会話中は面の色と印で示すので ⚠ を重ねない）・「音声を外部へ送っている」の印（つまみの専用の記号と同じ形。送っていれば塗った面、送っていなければ線だけ、値がなければ点線）・「続ける」（文字だけ。押せるのは呼びかけ待ちで送っていないときだけで、そのときだけ塗った面。押せない間は枠だけで、位置は変えない。始めている途中は回る記号）。2 段目は、印の列の右端にそろえて「同意を取り消す」（枠つき・高さ 32px。同意しているとき、または取り消しを保存できなかったとき）。2 段目の高さはいつも取っておき、取り消しが出入りしても下の 8 項目が動かない。停止中は入出力の段の「再開」を主のボタン（塗った面）にした。会話中は段の面を警告の色で塗る。文言のない状態は列挙の値を出さず「不明」にする。ロック中・不明は段の位置だけを灰色の面で残す。知らせ（入力の中断・始められなかった）と拒否の文言は段のすぐ下。理由のコード・API の名前・送り先の名前は画面に出さない（送り先の会社名は同意のダイアログにだけ出す）。HeroUI の Button・Tooltip・Spinner を使った。

## 契約の変更

- `DesktopIpcChannel` に `desktop.get_voice`・`desktop.voice_continue`・`desktop.voice_consent_revoke`（状態の層だけ。従来の窓・キャンバス・入力バーは使えない。`DESKTOP_ROLE_CHANNELS`）。`voice_continue` は画面操作（ロック解除済み・前面）、`get_voice` と `voice_consent_revoke` はいつでも（取り消しは送らない側の操作）。
- `DesktopIpcNotification` に `desktop.voice_changed`（状態の層だけ）。拒否の理由に `voice_unavailable`。
- `DesktopVoiceView`: hidden（ロック中・不明）か、`voice_state`・`external_send`・`consent`（`granted`・`required`。表示と確認を出すかの判断だけで、送ってよいかの正本ではない）・`can_continue`・`notice`（`input_interrupted`・`not_started`・`consent_not_saved`）。`can_continue: true` は Schema で、呼びかけ待ちかつ外部へ送っていないときだけに限った。
- 音声レンダラーとの IPC は既存の `VoiceRendererRequest`・`VoiceRendererAck`（ADR 0038）のまま。7 つ目の IPC は足していない。

## Electron での確認（このマシン・模擬のレンダラー。実機の音声ではない）

`--buddy-ui=canvas --buddy-voice=mock` で起動し、CDP で音声レンダラーの窓の中から確かめた（スクラッチパッドの道具。リポジトリに置かない）: `require`・`process`・`buddyDesktop` がない、`buddyVoice` は 3 つの鍵だけ、https・http・UI のスキーム・data: の fetch、WebSocket、外部の画像、`window.open` はすべて失敗、`getUserMedia({ audio })` は `NotAllowedError`。状態の層から「続ける」→ 同意のダイアログ（差し替えて同意）→ 会話中 → 停止 → 停止中 → 同意の取り消し → 再開（会話は始まらない）→ OS のロックの通知（音声の段を隠す）を通し、ライトとダークの画面を撮った。故障の注入 `--buddy-voice-fault=hang=suspend_io` では、会話中に停止すると音声レンダラーが本当に固まり（イベントループを止める）、main が ACK の期限で `voice_ack_missing:voice.suspend_io` を出して強制終了し、音声レンダラーの窓が消えて、状態は停止中・印は消えた。OS の確認ダイアログそのもの・前面の判定は差し替えた模擬で、実際の操作ではない。時間（300 ms）はこの確認では測っていない（模擬の試験の手で進める時計で確かめた）。

## 判断が要る点

1. **ACK が返らないときに、この端末の入出力まで止めること**（U92）。close_voice_session の ACK 欠落や、会話していない間の無応答でも止める。止めすぎなら「音声レンダラーの作り直しだけ」にする案がある。
2. **同意の端末側の記録**（U90）。中枢の同意の経路（HTTP・`voice_consents` の表）ができたら、端末の記録は表示用の写しに戻す。
3. **聞き取り中（文字で返す）を外部へ送る状態に残したこと**（U93。PR #160 のレビューで司令塔が決めた。③と KWS を実際につないで確かめたときに見直す）。
4. **製品の起動では音声を始めないこと**（U91）。中枢の Live の provider・SDP offer の経路・世代の突き合わせが揃うまで。
5. **ショートカットの「続ける」**: 本人の判断（#15）は「ショートカットでも起動」だが、この作業は状態の層のボタンだけにした（同意のダイアログの親がパネルなので）。ショートカットは UI-08 か次の B05 の作業で足す。

ADR に書いて持ち越すもの:

- **結果不明の後の nonce の連鎖**（P3-1）: 更新の応答が分からないとき、端末は次の更新で受け付けられた最後の nonce を `previous_nonce` に入れる。中枢がその要求を受け付けていた場合は連鎖が合わず拒否される（リースは期限で切れ、止まる側）。中枢の側（ADR 0046）で、直前の 2 つを許すか、同じ nonce の再送を冪等にするかを決める。
- **WebRTC は `session.webRequest` の対象外**（P3-2、U89）: 実際の Live の接続を作る作業で接続先を確かめる方法を足す。
- **Electron の組み立ての自動試験**（P3-7）: main.ts（窓・セッション・ACK の受け口）は Electron を起動しない試験の対象外。今回はこのマシンで CDP を使って手で確かめた。自動の試験は後の作業。
- **同意の偽造**: 端末の記録は表示のためだけで、送ってよいかは中枢が決める（ADR 0038）。中枢が Live の受付で同意を必ず検査することを、B05 の後続の作業の完了条件にする。
