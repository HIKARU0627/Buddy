# ADR 0089: B08-02 取得対象の Core の経路（一覧・読み取り・変更）

- 日付: 2026-11-03
- 状態: B08-02（Issue #201、親 #16）の P2b。`apps/core` のハンドラと配線まで。中枢の画面（P3）は未着手。実 API は未実施。
- 根拠: 設計 04 取得する対象・接続・権限（J13・J16）、設計 07 §1・§3、設計 11 §1A、ADR 0020・0071・0086〜0088、本人の決定 D5・D8（2026-11-01）。原本の参照手順は `docs/design/README.md`。
- 対象: `apps/core/src/api-connections.ts`、`apps/core/src/core.ts` の配線、`apps/core/src/api-connections.test.ts`。

## 決めたこと

| 対象           | 決定                                                                                                                                                                                                                                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 経路           | 新しい経路は作らない。`listConnections`（GET /v1/connections）、`getConnectionTargets`（GET …/targets、ADR 0071）、`updateConnectionTargets`（PUT …/targets）に処理を付ける。`getConnectionSync` は B08-05 まで処理を付けない（検査の後に 503）                                                                    |
| 検査           | 端末トークン・自宅判定・ロック解除・画面の操作・接続範囲・版の照合は `ROUTE_CHECKS`（api-server の admission）のとおり。ハンドラは通った要求だけを処理する。音声など画面以外からの変更は 403、入力の出どころの申告が無い要求は必須ヘッダーの欠落で 422                                                             |
| 応答           | `ConnectionSummary` の項目だけを返す。`credential_ref`（トークンの参照）・保存の状態（`targets_state`）は返さない                                                                                                                                                                                                  |
| 版の照合       | `expected_revision` の照合は保存済みの許可版と本文の `expected_permission_revision` の比較（core.ts が環境の `revisionMatches` を切り替える）。読めなければ例外にして 503 で閉じ、「内容が変わりました」と見せない。保存層の compare-and-swap が最終のガードで、admission を通った後に変わっていても二重に効かない |
| 拒否の対応     | 許可版の不一致・存在しない接続・切断済み → 409 conflict。契約の上限超過・欠落・余計な項目・未知の種類 → 経路の検査が JSON Schema で 422、前後に空白のある ID などの意味の不正 → 保存層が拒否して 422。成否不明・書込みの停止・想定外の保存の失敗 → 503                                                             |
| 存在しない接続 | 契約に 404 は無いので、`getConnectionTargets` は 422 invalid_input、`updateConnectionTargets` は版の照合が合わず 409                                                                                                                                                                                               |
| 再送           | 同じ `request_id` の再送は、成功済みなら許可版が進んでいるので 409 になり、二重には効かない。画面は読み直して確かめる。受付（command_receipts）は作らない（外部への変更ではなく、保存層の版の照合で足りる）                                                                                                        |
| 範囲の既定値   | 経路は既定値を補わない。古い行（4 項目が無い）は空の選択として返し（ADR 0088）、本人が選んで保存したときだけ書く                                                                                                                                                                                                   |

## 試験（模擬だけ）

- `node --test apps/core/dist/api-connections.test.js`（9 件）: 未認証 401・ロック中 403・自宅外 403、古い行を空の選択として返しトークンの参照を出さないこと、存在しない接続・不正な ID が 422、画面の操作での変更（応答・保存・両方の版が 1 つずつ上がる・別の接続は不変）、古い許可版・同じ `request_id` の再送・存在しない接続・切断済みが 409 で何も書かないこと、同じ選択の再送は版を上げないこと、設計の上限を超える値・欠落・余計な項目・空白付きの ID の拒否と上限ちょうど／下限ちょうどの受理、音声からの変更の拒否、変更で当該接続の走査だけが abandoned になり別の接続は変わらないこと。期待値は設計の値と D5・設計 11 §1A から手で書き、実装の表から作らない。
- `apps/core/dist/api-routes.test.js` ほか: 経路の表と OpenAPI の一致（変更なし）。

**模擬の期待値だけ**。画面・実 API・実アカウント・実データは未実施で、合格扱いにしない。
