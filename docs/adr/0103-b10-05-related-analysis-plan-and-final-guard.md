# ADR 0103: B10-05 P4 関連集合の解析計画と実行直前の照合

- 日付: 2026-11-14
- 状態: B10-05（親 #18、Issue #244）P4 の判断。関連集合（同じ provider・アカウント・thread）の解析計画（純粋な関数）と、実行直前の照合（最終ガード。DB を読む口は注入）だけ。DB の保存・transaction への配線は B11・B13、同期の公開 transaction での計画の無効化は B08-06。実 API・実メール・実機は未実施。
- 根拠: 設計 11 §5A・§5B（F05）、設計 08 §3 F05、設計 09 QA32・QA45・X64・X65、ADR 0007・0101・0102。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。
- 対象: `apps/core/src/related-analysis.ts`・`related-analysis.test.ts`。契約（`packages/contracts`）と `packages/domain/src/analysis.ts` は変えていない（`analysisReadiness`・`analysisStillCurrent`・`resolveEntityState`・`autoCreationReasons` をそのまま使う）。

## 決めたこと

| 対象                 | 決定                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 計画の入力と出力     | 入力は、集合の ID・公開世代・列挙が終わったか・必要ソース（メールの ID・版・解析の状態・変更）・前回の記録。出力は domain の `AnalysisState` と契約の `RelatedAnalysis`（`status` は ready・pending・blocked）と、次回へ渡す記録                                                                                                                                                     |
| ready の判定         | domain の `analysisReadiness` をそのまま使う（列挙の完了・必要ソースが解析済みか規則 ID 付きの除外・未解決の変更なし・現在の公開世代）。条件を足さず、緩めない。必要ソースが 1 つも無い集合は、列挙できていないものとして ready にしない（空で完了にしない）                                                                                                                         |
| status               | ready でない理由に、未読・失敗・規則 ID なしの除外・未解決の変更があれば `blocked`（待つだけでは進まない）。それ以外（列挙の途中・解析待ち・予算待ち・世代の変化）は `pending`                                                                                                                                                                                                       |
| 同じ記録から同じ結果 | 必要ソースは ID の昇順に並べ、配列順・解析の到着順・変更の並びに依存しない。`source_set_hash` は必要ソースの ID と版（状態を含めない）から作る。再起動は記録から計画を作り直すだけで、途中の状態を ready にしない（QA32・QA45 の crash の観点）                                                                                                                                      |
| 版番号               | `analysis_revision` は前回の記録と**指紋**（集合・世代・計画完了・各ソースの状態と規則 ID・未解決の数・**解決した変更の内容（関係・対象の依頼 ID・解決の状態。並びに依存しない）**）が同じなら進めず、変わったときだけ 1 進める。記録が無ければ 1。同じ入力を二度計画しても版が進まないので、同じ判定を二重に失効させない                                                            |
| 未解決の変更         | 取消・完了・訂正の対象が不明・曖昧、訂正か追加か不明（`uncertain`）は未解決として数え、集合を ready にしない。曖昧な取消は依頼の状態を変えない                                                                                                                                                                                                                                       |
| 依頼の状態           | `entityOutcome`: 確定した取消・完了を、変更の並び・解析の到着順によらず同じ有効状態へ（`resolveEntityState`）。取消済み・完了済み・再作成の抑止中・同じ操作を作成済みなら、4 種類の自動作成を止める理由を返す（`autoCreationReasons`）                                                                                                                                               |
| 実行直前の照合       | `finalGuard`: 判定に使った版（group・revision・source_set_hash・公開世代）が DB の現在値と同じか、現在の集合が ready か、依頼の版（`request_revision`）が同じで有効か、作成済み・抑止中でないかを一括で見る。**読めなかったもの（集合・依頼・使った版が無い）は拒否**し、推測で通さない。判定後・送出前に取消・新着が公開された競合は、版・集合の hash・未解析ソースの理由で拒否する |
| 失効後の再判定       | 版が変わった旧資格は、集合が ready に戻っても通らない（再判定が要る）。別のスレッドの失敗は別の集合の ready に影響しない（集合ごとに計画する）                                                                                                                                                                                                                                       |
| 配線                 | DB を読む口（`AnalysisReader`・`EntityReader`）は注入する。LocalCommand の変更 transaction・RemoteMutation の送出直前の transaction から呼ぶ配線は、自動実行（B13）と候補の保存（B11）で行う。この PR では呼び出し口と規則までで、既存の実行担当へはつないでいない                                                                                                                   |

## 試験（模擬だけ）

`apps/core/src/related-analysis.test.ts`（手書きの期待値。hash は別に計算した固定の文字列）:

- 版と hash、必要ソースの順序・到着順・変更の並びで結果が変わらないこと。
- QA45: 取消のメールが解析待ち・予算待ち・未読・失敗のあいだ ready にならず、空の結果で通らない。A 先・B 先・並び替えで同じ状態になり、取消が確定した依頼は 4 操作とも止まる。対象が曖昧・不明な取消は状態を変えず ready を止める。
- X64・X65: 作成済み・再作成の抑止中は作らない。
- QA32: 列挙の途中・必要ソースが空の集合は ready にならない。規則 ID なしの除外は止める。
- 版が進む条件（集合・状態・変更の内容・世代）と進まない条件（同じ入力・再起動・変更の並び替え）。解析のやり直しで変更が [] から確定した取消に変わる・対象が変わる・関係が変わるときは、未解決の数が同じでも版が進み、旧版の最終ガードが失効する。
- 最終ガード: 全部が現在のときだけ通る。判定後に新しいメールが公開された場合は旧版を拒否し、解析が終わって ready に戻っても旧版は通らない。世代・集合・依頼の版・取消・作成済み・抑止中・読めない場合の拒否。別のスレッドの失敗は影響しない。
- 要点（集合の hash・依頼の版・読めない場合・列挙の完了・未解決の数）を壊した実装で試験が失敗することを確認した。

**模擬のみ**。DB の transaction・同期の公開・実メール・実機・実請求は未実施。独立した 2 依頼の ID の発行・統合しないことの検査は、依頼 ID の解決（5A）を持つ B11 で行う。
