## 1. 先に結論

**設計の第一候補どおり Brave Search API を推奨する。ただし保存の扱いに条件がある。**

Brave は Tavily より単価が安く（約 1.02 円/検索）、価格がリクエスト単位で固定なので B07 の R／M の門にそのまま載る。円換算では Mojeek のほうがさらに安いが、GBP 建て・カード登録必須で、日本語の質が不明という代償がある（§3.1・§3.4・§7）。一方で、**Brave の規約は検索結果の保存を許していない**（動作に必要な一時的な保存を除く）。Buddy は出典を後から確認できる形で残す設計なので、Brave を選ぶなら次のどちらかにする必要がある。

- (推奨) **検索応答を永続保存しない。** 出典は、その場で表示する URL・取得時刻・Buddy が自分で取得した本文からの抜粋・自分の要約で作り、**保存してよいかの確認が取れるまでは永続化しない**。本文の取得は B12-04 で自前に行うため、この形は設計と両立する。ただし検索応答に含まれる URL も規約上の「Search Results」に含まれると読めるため、**URL の保存可否も B12-02 で確認する**（§3.2）。
- 検索結果そのものを残したい場合は、保存権を明示している **Mojeek の Business プラン**が対抗候補になる（§7 の選択肢 B）。

Tavily は API と料金の面では使いやすいが、**クエリ（入力）に提供・改善のための広い利用許諾**があり（9.2）、**生成 AI 機能の入力と出力は学習に使いうる**（6.5）。6.5 が通常の Search に及ぶかは規約本文からは**未確認**だが、9.2 だけで既定にしにくい理由になる（§3.6）。

**DeepSeek を加えても、第一候補は Brave のままにする。** DeepSeek は Search と Fetch の API を持ち、料金は **$0.75 / 1,000 成功リクエスト（約 0.15 円/検索）**で 4 社で最も安い。検索結果に本文・日付・権威度まで含められ、保存を禁じる条項も確認できない（§3.1・§3.2・§3.5）。しかし、**プライバシーポリシーが入力と出力を「機械学習モデルやアルゴリズムなどのトレーニングおよび改善」に使うと定めており、API 固有の除外規定を確認できない**（§3.6・§3.7）。本人が重視する「学習に使われないこと」に照らすと、公開情報の範囲では既定の検索先にできない。加えて、収集した情報は**中国本土のサーバーに保存**され、準拠法は中国本土の法令、管轄は杭州の裁判所と定められている（§3.7）。

したがって DeepSeek は、**「選択前の確認で『API の入力と出力を学習に使わない』旨を文書・設定で確かめられ、かつ中国本土への保存を本人が許容する場合の最有力候補」**として並べる（§7 の選択肢 D）。**学習に使わないことの確認は必須**で、確認が取れないまま D を選ばない（本人の重視点）。その条件が満たされれば、料金・保存・本文の 3 点で Brave を上回る。**推奨は変えないが、条件付きで最有力になりうる候補として記録する。**

- 設計は「無料クレジットを予算計算に入れず、安全側に見積もる」としている。上の「月 300 円で賄える検索」も無料枠を数えていない。無料枠を数えるなら Brave（約 1,000 回分）と Tavily（1,000 回分）は月 300 円分を超えるが、**無料枠は予告なく変わりうる**ので、B07 の門では数えない扱いを維持するのが安全。Mojeek の無料クレジットの量は公開ページからは不明。
- Mojeek は GBP 建てで、設計の試算（USD）と通貨が違う。円換算には為替の仮定が要るため、上の円は**比較のための概算**であり、B07 の price_version に入れる値ではない。
- Tavily の `auto_parameters` を有効にすると、リクエストが自動で advanced（2 クレジット）に上がることがある。M を固定するため、**明示的に basic を指定し、auto_parameters を使わない**。
- Tavily の Research は 1 リクエストのクレジットが `model=pro` で 15〜250、`model=mini` で 4〜110 の幅を持つ。B12 では使わない（M を固定できない）。
- DeepSeek の課金は**成功したリクエストだけ**。失敗・検索結果 0 件・タイムアウトは課金されない（ガイドの Billing）。ただし B07 の予約は試行回数で計上する（§4）。
- 課金は **2026-10-31 16:00 UTC（北京時間 2026-11-01 00:00）から始まっている**。DeepSeek Harness・Claude Code・Codex 経由のサーバー側ツール呼び出しは無料と記載されているが、Buddy は API を直接呼ぶため対象外。
- モデルのトークン料金にはピーク・オフピークの差があるが、**Search と Fetch は定額**で、時間帯による差の記載はない。
- `need_content` の有無で単価が変わるという記載はない（明示されているのは `count` が単価に影響しないことだけ）。本文の有無による差は**不明**として残す。

**Buddy への影響（重要）**

- 設計は「検索結果と根拠の短い抜粋・取得時刻・URL を対応させる」としている。Brave を選ぶ場合、**Brave が返したタイトル・スニペットをそのまま保存することはできない**。
- Brave の規約は「Search Results」を API からの全出力と定義している（1.10）。検索応答に含まれる **URL もこの定義に含まれる**と読めるため、URL だけを残すことが許されるかは**未確認**。B12-02 で Brave に確認するか、法務確認が済むまで永続保存しない。
- 保存を減らす候補は「保存するのは取得時刻・**B12-04 で自分が取得した本文からの抜粋**・自分の要約だけにし、Brave の URL・`description`／`extra_snippets` はその場の表示にだけ使う」形。ただし URL も保存できないとなると出典の再表示が難しくなるため、**この形を採るかは URL の保存可否の確認後にする**。本文を取得できなかったページ（会員限定・PDF・失敗）は、その場では URL と「本文未取得」を表示する（B12-04 の区別をそのまま使う）。
- Mojeek の Business の保存権は**料金ページの FAQ の説明**で、規約本文には Startup の制限と Enterprise の別条件だけが書かれている。契約時に「Business で無期限の保存ができる」ことを書面で確認する。
- Tavily は保存を禁じていないが、§3.6 のクエリと AI 機能の利用と表裏なので、保存の可否だけでは選ばない。
- DeepSeek も保存を禁じていない点では Tavily と同じ。明示の保存権をうたう Mojeek Business とは根拠が違い、**「禁止がないだけ」**である。出典を後から再現する設計とは相性がよいが、保存のしやすさだけで選ぶと本人の重視点（§3.7）と衝突する。
- DeepSeek の検索結果に含まれる第三者コンテンツの権利について、明示の記載は確認できない（**不明**）。保存・再表示の可否は B12-02 で確認する。

## 4. B07 の予算の門（R／M）との整合

B07（#12）で、有料の要求は受付の transaction で **予約額 R** と **最大負担 M** の両方を検査する。M を有限に制限・検証できないものは p95 予約を使えない。検索の枠は月 300 円で、LLM（1,700 円）・音声（4,000 円）と融通しない（設計05、ADR 0006・0042、`docs/b07/README.md`、`packages/contracts/schemas/buddy.schema.json` の `BudgetServiceRoutes.search`）。

| 観点               | Brave                                                         | Tavily                                                                                                 | Mojeek                                           | DeepSeek                                                                      |
| ------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------ | ----------------------------------------------------------------------------- |
| 1 回の費用が固定か | **固定**（$0.005/リクエスト。結果数・本文の有無で変わらない） | **固定**（basic 1・advanced 2 クレジット）。`auto_parameters` を使わなければ固定                       | **固定**（プランの 1,000 リクエスト単価）        | **固定**（$0.00075/成功リクエスト）。件数・本文の有無で変わらない             |
| R と M             | R = M = 単価 × 回数。p95 は不要                               | 同じ。basic を明示する                                                                                 | 同じ。プランと通貨（GBP）を price_version に持つ | 同じ。R = M = 単価 × **試行回数**（失敗も含める）                             |
| 3 検索/依頼の M    | 約 3.06 円                                                    | basic 約 4.90 円／advanced 約 9.79 円                                                                  | Business 約 2.16 円（£1 = 200 円の仮）           | **約 0.46 円**                                                                |
| 応答喪失時         | B07 のとおり R・M を保持し、0 円にしない                      | 同じ（`request_id` は応答に含まれるため、喪失時の照合は usage／logs の口で可能かを B12-02 で確認する） | 同じ                                             | 同じ。失敗は課金されないが、応答が不明なら 0 円にしない                       |
| 価格の版           | USD。為替は設計の試算値を使う                                 | USD。プランにより単価が変わるので版を分ける                                                            | **GBP**。為替の扱いを B12-02 で決める            | **USD。Search と Fetch を別の単価として持つ。ピーク・オフピークの区別はない** |
| 無料枠             | 予算計算に入れない（設計の扱い）                              | 同じ                                                                                                   | 同じ                                             | 同じ（公開の額がないため、なおさら数えない）                                  |

- **検索は LLM と違い、1 回の費用が完全に固定**なので、B07 の M の検査と相性がよい。p95 の実測を待たずに B12-03 を始められる。
- M が固定できなくなる要因は、Tavily の `auto_parameters`（advanced へ自動で上がる）と Research（15〜250 クレジットの幅）だけ。どちらも使わなければ M は固定できる。
- Mojeek は通貨が GBP のため、B07 の price_version に currency を持たせ、為替の仮定を明示する必要がある。設計の試算（170 円/米ドル）をそのまま GBP に当てない。
- 予算の門は「検索の枠 300 円」で見る。LLM の 1,700 円や音声の 4,000 円から補填しない（B07 の既存の規則）。
- DeepSeek は「成功したときだけ課金」なので、実際の請求は R を超えない。それでも B07 の規則どおり、予約は試行回数で計上する（応答喪失時に 0 円へ戻さない）。
- Search と Fetch は単価が同じでも別の API として回数を持つ。Fetch を使うと 1 依頼の M は 3 検索 + 5 ページ = 約 1.22 円になる。
- 為替は設計の試算（170 円/米ドル）をそのまま使える。GBP のような通貨の追加は要らない。

## 5. 上限の案

設計の初期値（1 依頼 3 検索・本文 5 ページ・1 ページ 2MB／15 秒・リダイレクト 3 回）を維持する。そのうえで、**月 300 円の枠と両立する日次の目安**を足す。

| 項目           | 案                                                                               | 根拠・計算                                                                             |
| -------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 1 依頼の検索   | **3 回**（設計の初期値を維持）                                                   | 1 依頼 = 1 回の調査。3 回で足りない場合は追加せず、結果に「検索 3 回で打ち切り」を示す |
| 1 依頼の本文   | **5 ページ**、1 ページ 2MB・15 秒、リダイレクト 3 回（設計の初期値を維持）       | 処理と費用の上限。品質の保証ではない                                                   |
| 1 日の検索     | **9 回（= 3 依頼）を目安**                                                       | Brave で 9 × 1.02 × 30 日 = 約 275 円。月 300 円に収まる                               |
| 月の検索       | **300 円を上限（hard）**                                                         | B07 の検索の枠。超える予約は拒否                                                       |
| 予算不足のとき | **保留**（完了と表示しない）。検索回数を減らせる場合は減らし、その旨を結果に残す | Issue #27 の完了条件「失敗を完了と表示しない」                                         |
| 個別承認       | 本人が画面で承認した依頼だけ、超過枠 500 円の範囲で実行                          | B07 の既存の規則。自発の処理には使わない                                               |

**DeepSeek を選ぶ場合**

- 設計の初期値（1 依頼 3 検索・本文 5 ページ）と月 300 円の hard は変えない。**単価が安いことは上限を上げる理由にならない。**
- 日 9 回の目安は Brave 前提の値。DeepSeek なら 9 回/日で月約 41 円にしかならない。日次の目安を上げるかは運用の判断で、費用の制約ではない。
- 本文を Fetch API で取る場合、1 依頼あたり +約 0.77 円（5 ページ）。3 検索 + 5 ページで約 1.22 円/依頼、月 300 円で約 245 依頼。
- 失敗は課金されないが、B07 の予約は試行回数で計上する（§4）。

**設計の例と枠の食い違い（B12-02 で直す）**

- 設計05 の費用の表には「標準試算: 検索 300 回/月」の例がある。Brave の単価で 300 回は **約 306 円**となり、検索の枠 300 円をわずかに超える。
- これは「標準試算」が LLM と検索を合わせた利用の目安であり、**検索の枠の上限値ではない**と読むべき。B12-02 で、上限の説明と試算の例を混同しないように書き分ける。
- 月 300 円で賄えるのは Brave で約 294 回（3 検索/依頼で約 98 依頼）。日 9 回の目安は、この範囲に収まるように置いた。

## 7. 選択肢と影響（本人が選ぶ）

### A. Brave Search（推奨・条件付き）

- 料金: 約 1.02 円/検索。月 300 円で約 294 検索（約 98 依頼）。毎月 $5 の無料クレジットがあるが、予算には数えない。
- 保存: **検索応答（URL を含む）の永続保存は未確認**。確認できるまで保存しない運用を条件にする。出典はその場の表示と、自前取得の本文抜粋で作る。
- 利点: Tavily より安い（Mojeek は円換算でより安いが、GBP・カード必須・日本語の質が不明。DeepSeek はさらに安いが、学習利用の条件で既定にできない）。固定単価で R／M が単純。独立インデックスで、本文を自前取得する設計と合う。表示は任意。
- リスク: 検索結果を残せないため、**取得元のページが後で消えると出典の本文を再現できない**（その場の表示と、自分の抜粋しか残せない。保存可否は未確認）。URL の保存可否も未確認で、保存権が要るなら Enterprise の個別契約を問い合わせる必要がある。
- 移行: アダプターで隔離するため、後から他社へ替える影響は小さい（設計の前提）。

### B. Mojeek Business

- 料金: £3 / 1,000（税別）。£1 = 200 円の仮で約 0.72 円/検索、月 300 円で約 416 検索（約 138 依頼）。**カード登録が必要**。
- 保存: **無期限の保存権**があり、検索結果をそのまま残せる。表示義務なし。
- 利点: 保存の制約が最も緩い。EU のインフラでサブプロセッサなし。90 日保持で ZDR は相談可。
- リスク: **日本語のインデックスの質が不明**（欧州中心の独立インデックス）。GBP 建てで為替の扱いが要る。Business の保存権は料金ページの説明で、規約本文の裏付けを契約時に確認する必要がある。
- 向く場合: 「検索結果そのものを保存して出典を後から再現したい」ことを優先する場合。

### C. Tavily

- 料金: $0.008/クレジット（basic 1・advanced 2）。basic で約 1.63 円/検索、月 300 円で約 183 検索（約 61 依頼）。毎月 1,000 クレジットの無料枠。
- 保存: 禁止されていない。本文（markdown/text）も返す。
- 利点: 実装が最も短い。本文と日付まで 1 回で返る。レートが高い。
- リスク: **クエリに提供・改善のための広い利用許諾（9.2）**があり、**生成 AI 機能の入力と出力は学習に使いうる（6.5。通常の Search への適用は未確認）**。Search に 6.5 が及ぶかは未確認だが、9.2 だけで既定の検索先にはしにくい。保存を許す代わりに、事業者側の利用が広い。
- 向く場合: クエリの広い利用と AI 機能の学習利用を許容できる用途に限る。Buddy の既定にはしない。

### D. DeepSeek（Search＋Fetch。条件付きの最有力対抗）

- 料金: $0.75 / 1,000 成功リクエスト（= 約 0.15 円/検索）。月 300 円で約 1,960 検索（3 検索/依頼で約 653 依頼）。**4 社で最も安い。** 毎月の無料枠は公開の料金表に記載がない（不明）。
- 保存: 保存を禁じる条項は確認できない。出力の権利は顧客に譲渡される（Open Platform 規約 4.2）。明示の保存権ではない点は Tavily と同じ。
- 利点: 最も安い。検索応答に本文・日付・権威度まで含められる（Fetch API もある）。固定単価・USD・成功時のみ課金で、R／M が最も単純。保存の制約が緩い。
- リスク: **入力と出力が学習・改善に使われうる（API 固有の除外なし。§3.7）**。**中国本土のサーバーに保存**され、準拠法は中国本土の法令、管轄は杭州の裁判所。名称・ロゴの無断使用が禁止され、AI 生成の明示を求められる。公開から日が浅い（2026-10-17）。国コードの指定がなく、日本語の地域化は IP 指定に頼る。第三者検索 API へのキーワード共有の記載がある（Search API への適用は不明）。
- 向く場合: **決定より前の「選択前の確認」で「API の入力と出力を学習に使わない」旨を文書・設定で確かめられ、中国本土への保存を許容できる場合。** 学習に使わないことの確認は**必須**で、確認が取れない場合は D を選ばない。条件が満たされれば、料金・保存・本文の 3 点で Brave を上回り、第一候補になる。
- 既定にしない理由: 本人の重視点（学習に使われないこと）を、公開情報だけでは満たせないため（§3.7）。料金の安さだけでは既定にしない。**確認が取れるまでは D を選ばない。**

### E. 保留（B12 を後回しにする）

- 影響: B12-03 以降は始めない。B12-02 も検索サービスの選択を前提にするため、保留の間は契約を確定しない。他の工程（B10・B11・B13・B14）には影響しない。
- 向く場合: 日本語の質を先に測りたい、または保存の扱いを法務的に確認したい場合。ただし実 API の費用と同意が先に要る。

## 8. 未確認・未実施

- **実 API は呼んでいない。** 日本語の検索品質、レイテンシ、実際の応答の形は未測定。
- **実請求は未実施。** 為替は試算用の仮定（170 円/米ドル、£1 = 200 円）で、実際の請求額ではない。
- **法務確認は未実施。** 規約の解釈（特に Brave の「一時的な保存」の範囲、**検索応答に含まれる URL が Search Results に含まれるか**、Tavily の 6.5 が通常の Search に適用されるか、Mojeek の Business の保存権、**DeepSeek の API 入力が学習に使われない設定・契約の有無**）は本人または専門家の確認が要る。
- Brave の保存権（Enterprise）への問い合わせはしていない。料金ページの FAQ には「結果を保存できるか」の項目があるが、回答本文は取得できなかった。判断は規約 3.2(i) を根拠にしている。
- Exa は料金（$4 / 1,000 の lite 検索、毎月 $10 の無料クレジット）だけ確認した。規約が PDF で本文を取得できず、**保存条件が不明**のため比較表に入れていない。
- Google Custom Search JSON API は**新規受付を終了**しており、既存の顧客も **2027-01-01 で終了**する（公式ページ）。新規の候補にしない。
- Bing Search APIs は **2025-08-11 で退役**した（公式の告知）。候補にしない。
- Google Search Grounding は、モデル内の検索件数と費用の境界を独立したリクエストとして制御できないため、設計で初期採用しないと決めている。この判断は変えていない。
- 検索結果をスクレイピングで返すサービスは、Google 等の規約に反しうるため候補にしない。
- DeepSeek の Search／Fetch API は **2026-10-17 に公開されたばかり**。障害・仕様変更の実績は未確認。料金も 2026-11-01 から課金が始まった段階で、請求の実績はない。
- DeepSeek の API 入力が学習に使われない設定・契約・申請の有無は**未確認**。公開のFAQ（`https://static.deepseek.com/faq/`）は本文を取得できなかった。
- プライバシーポリシーの「検索サービスを提供するためにサードパーティの API を統合し、入力キーワードを共有する」記載が **Search API に当たるかは不明**（自社エンジンという説明との関係）。
- DeepSeek の日本語の検索品質、`lang:ja` の可否、`localization` に IP を渡した場合の地域化の効き方は**未測定**。
- DeepSeek の Fetch の本文サイズ上限・タイムアウト値は、公開の記載が見当たらない（**不明**）。
- 中国の越境移転の法令（PIPL 等）の要件と、日本の個人情報保護法上の「外国にある第三者への提供」の整理は**未確認**。
