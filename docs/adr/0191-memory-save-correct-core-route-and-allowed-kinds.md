# ADR 0191: 記憶の保存（memory_save）と訂正（memory_correct）の Core の経路、保存してよい記憶の種類の設定

- 日付: 2026-11-27

- 状態: B06-07（Issue #143・#180 の残り、親 #11）の判断と実装。本人が忘却の公開ゲートを開く条件（U431）の 1 つ「記憶を保存する経路と保存してよい種類の設定ができること」の土台。保存層（マイグレーション 0024・`memory.settings_*`・`memory.admission_facts`・`memory.save` と発言の記録の最後の保証）、Core（`memory-save.ts`（新規）・`api-turns.ts`・`api-memory.ts`・`api-routes.ts`・`core.ts`・`turn-ports.ts` の模擬の解釈）、契約（JSON Schema・OpenAPI・fixture・生成型）、デスクトップ（main の中継・IPC のチャネル・画面の欄）、B06 の模擬の統合（X59）と模擬の試験・撮影だけ。**忘却の公開ゲート `FORGET_PUBLIC_GATE_OPEN` は false のまま**。自動の抽出からの保存は作っていない。実機の Mac mini・Electron の実画面・Windows／macOS の実機・実データ・実 API・実請求は**未実施**。
- 根拠: Issue #143・#180 の「現状」と本人の決定（Q3: memory_correct も忘却の確認の画面を使う、Q4: U111 からの導線、Q10: 保存してよい記憶の種類の設定。2026-11-27 U431: ゲートは閉じたまま）、ADR 0004（意図表: memory_save・memory_correct は LocalCommand・承認なし・Live の文字起こしからは進めない）、ADR 0008（保存直前の検査・明示の保存は内容の禁止では止めない）、ADR 0040（台帳の鍵と用途別の鍵 `buddy/memory/dedupe/v1`）、ADR 0054（`memory.save` の最後の保証・U111）、ADR 0180（忘却の経路・U389）、ADR 0183（忘却の画面・U432・U436）、ADR 0190（記録しない会話では保存を伴う依頼を決まった文で断る）、ADR 0024・0181（画面の約束と形の規約）。非公開の原本（設計 03・08・09・11）はこの環境になく、参照していない。決めのない点は、本人の「試験と見直しは後でまとめて行う」に従って聞かずに暫定で決め、`docs/b00/contract-map.md` の U488〜U497 に記録した。

## 決めたこと

### 設定（Q10、U432）

- 保存先は中枢の DB の 1 行の表（`memory_settings`）。正本は中枢。変えるのは本人の画面操作だけ（音声・チャット・発言・島・キャンバスからは変えない。経路の検査と IPC の窓の役割で二重に止める）。
- 既定は空。**本人が許可するまで、明示の依頼でも自動の抽出でも何も保存しない**（U496）。
- 許可から外しても、保存済みの記憶は消さない（忘れるのは忘却の画面。U493）。
- 設定はバックアップに含める。**復元の後は、許可が 1 つでもあれば全部 off にして版を 1 進める**（見直しで変えた。バックアップの後に本人が取り消した許可が復元で戻らないように。ADR 0038 の「取り消した同意を復元で戻さない」と同じ考え。本人は画面で選び直す。U494）。
- 変更に OS の確認ダイアログを挟まない（選んだらすぐ送る。前面の画面操作だけ。U492）。

### 保存の流れと最終ガード（本人の明示の依頼）

1. 発言の解釈が `memory_save`（または `memory_correct`）。Live の文字起こし（方式 C）・確定前の入力は記憶にしない（全文の確定へ戻す。ADR 0004 の `liveTranscript: false`）。
2. 記録しない会話の間は、発言が RAM の経路（ADR 0190）へ分かれ、保存を伴う依頼として決まった文で断る（DB・鍵・保存層に触れない）。RAM の経路で記憶の計画ができても持たない（重ねた守り）。`planExplicitMemory` も記録しない会話なら鍵・保存層を読む前に断る（重ねた守り）。
3. 本文を整える（Unicode の NFC、続く空白を 1 つ、前後の空白を除く。空・80 文字超・見えない文字（制御文字・書字方向の制御文字・ゼロ幅の文字）は保存しない。縮めない。U495）。種類がなければ保存しない（推測しない）。
4. 台帳の鍵を読む。なければ保存しない（**鍵を作らない**。U385 と同じ考え。U489）。
5. 保存の前の検査の材料を読み、`memoryAdmission` で判定する（記録しない会話・許可していない種類・設定の版・台帳との関係（欠けた世代・忘れた由来）・重複（同じ内容の HMAC）・同じ種類・同じ対象キーの食い違い（U111））。
6. 保存するなら、本文と対象キーをデータ鍵で封じ（所有者は `memories`・記憶 ID・版 0）、発言と同じ transaction（`turn.record` の `memory`）で保存する。保存層はその transaction の中で、設定（種類・版）・台帳の全件との照合・由来の期限・重複・食い違いをもう一度確かめる（最後の保証）。
7. 発言の保存の直前に、保存境界の区切り（ID と世代）が処理を始めた時と同じかを確かめる（ADR 0190 の照合のまま）。違えば 409 で何も保存しない。
8. 保存層が記憶を拒否したら、発言も書かれていないので、理由の応答で発言だけを記録し直す（記憶は保存しない。自動では保存し直さない）。COMMIT の成否が分からないときは 503 で、端末の再送は受付で照合される（二度保存しない）。

予算: 保存は外部の有料の呼び出しを伴わない（解釈の予約は解釈の差し込み口が行う）。世代: 忘却の台帳の世代（処理を始めた時点の世代と欠けのない台帳）と、保存境界の区切りの世代の両方を照合する。

### 内容・対象キーの HMAC（U488・U489）

- 内容の HMAC（`dedupe_key`。忘れた記憶の台帳の `blocked_content_keys` と比べる値）と対象キーの HMAC（`target_key_hash`）は、台帳の鍵から HKDF で導いた `buddy/memory/dedupe/v1` の鍵（ADR 0040）で、`buddy/memory/content/v1`・`buddy/memory/target/v1` ‖ 0x00 ‖ 種類 ‖ 0x00 ‖ 本文 を HMAC-SHA256 にした値。復元の後も同じ鍵で求められる。
- 明示の依頼の引数（IntentArgs）に対象キーはない。**対象キーは本文そのもの**にした（暫定。U488）。同じ種類・同じ本文は重複として保存しない。内容の違う同じ対象の食い違い（U111）は、明示の保存からはふつう起きない（起きたときの返事は作ってある）。

### 返事（保存した・保存しなかった）

- 返事は決まった文（モデルの文ではない）で、記憶の本文と記憶 ID を含めない（応答は平文の列 `turn_responses` に残る。U497）。結果の表示は `completion_line`。保存した・同じ内容があったは `ready`、保存しなかった（本人の対応が要る）は `needs_review`。
- 例: 「「好み」の記憶として覚えました。「記憶と忘却」の欄で確かめられます。」「覚えませんでした。「好み」の記憶は、保存してよい記憶の種類で許可されていません。「保存してよい記憶の種類」の欄で変えられます。」「同じ内容をすでに覚えています。新しくは保存しませんでした。」「覚えませんでした。中枢が今は記憶を保存できません（バックアップの設定がまだのときも保存しません）。」ほか（`api-turns.ts` の `memoryReplyText`）。

### 訂正（memory_correct、Q3・U436・U490）

- **新しい内容を新しい記憶として保存し（保存の流れは memory_save と同じ）、古い記憶は残す。古い記憶を忘れるのは忘却の画面（計画と確認の帯・OS の確認ダイアログ）に導く。** ゲートが閉じている間は「古い記憶を忘れる操作は、まだ使えません（「記憶と忘却」の欄で記憶を見ることはできます）」と返す。ゲートが開いたら「古い記憶は「記憶と忘却」の欄で選び、忘却の計画を確かめてから忘れてください」と返す（ゲートは読むだけ）。
- 理由: (1) Q3（訂正も忘却の確認の画面を使う）に合わせると、古い記憶を消すのは画面の計画と確認だけで、発言からは消さない。(2) ゲートが閉じている間に訂正を保存しないと、本人の言い直しが失われる。(3) 今の Core には記憶を判定・返事に使う処理がないので、古い記憶と新しい記憶が並んでも、どちらかを黙って使うことは起きない。記憶を使う処理を作るときに、訂正の後の古い記憶を利用保留にするかを決める（U490）。
- 解釈の `target_candidate_id` は使わない（解釈に記憶の候補を渡していないので、メールの候補の ID と取り違える。古い記憶は画面で本人が選ぶ）。
- ほかの案（訂正の保存を忘却の実行の後にする・訂正を承認待ちの操作にする）は、ゲートが閉じている間は保存できない・操作の記録（U389）を先に決める必要がある、ため採らなかった。

### 保存しなかった食い違い（U111、Q4）からの導線

- 同じ種類・同じ対象キーで内容の違う記憶があって保存しなかったときは、「覚えませんでした。同じことについて、内容の違う記憶がすでにあります。」に、訂正と同じ古い記憶の忘却への導線（ゲートの開閉で言い分ける）を続ける。保存しなかった理由を API の応答で本人に返すことは、これで U111 の引き継ぎを満たした。既存の記憶の利用保留（U111 の (b)）は記憶を使う処理と一緒に決める。

### memory_forget の操作（U389）

- 変えない（暫定 (a) のまま: 忘却は画面の計画と確認の経路だけ）。memory_save・memory_correct も承認の記録（LocalCommand の操作）を作らない（意図表の承認は none。記憶そのものと発言・受付が記録になる）。

## 画面

- 従来の窓の本体、「家計簿」と「記憶と忘却」の間に「保存してよい記憶の種類」の欄（`Section`、カードを使わない。ADR 0024）。
- 欄の頭に 1 文（「ここで選んだ種類だけを、記憶として保存します。…」）と状態の行（「○ 今は何も選んでいないので、記憶は保存しません。」／「● 今は n 種類を保存します。」）。
- 6 種類を枠（`FRAME_CLASS`、ADR 0181 の形の規約）で囲んだ行に並べ、行ごとに選択（HeroUI の `Checkbox`）と説明（U491）。選んだらすぐ送り、送っている間は全部の選択を無効にする（同じ欄の頭に「変えています…」）。
- 欄の下に「選ぶのをやめても、保存済みの記憶は消えません。忘れるときは、下の「記憶と忘却」の欄を使います。」
- 中枢から読めていない間は選択を置かず「まだ中枢から読めていません。「記憶と忘却」の欄の「読み直す」を押してください。」（「何も許可していない」と言わない。押せないボタンを置かない。ADR 0024 の約束 7）。
- 別の画面で変わった（409）・結果が分からないときは、欄の中に理由を出し、送り直さずに main が今の設定を読み直す。
- 会話の欄の返事は既存の表示（`completion_line` は返事の文をそのまま出す）。
