# ADR 0064: 会話の操作に使った発話を委譲の対象の候補から外す（U151）

- 日付: 2026-11-01
- 状態: 本人の決定（U151、(b)）。B05-07（#131）の模擬の統合試験で観測した未決事項を決め、`packages/domain` の `resolveDelegationTarget` と中枢の `LiveConversation` に反映する。実機・実 API・実請求は**未実施**。
- 根拠: 設計 07 §5、10 §5・§5A・§6、09 の X51・X58、ADR 0005・0038・0052。`docs/b00/contract-map.md` の U151。本人の判断（2026-11-01、#131 の引き継ぎ）。

## 背景

設計 10 §5・§6 は、委譲の対象のターンを 1 つに決められないときは聞き返すと定めます。会話の操作（「読み上げを止めて」「ちょっと待って」など）に使った発話が、その後の委譲の対象の候補に残るかは原本に決めがありませんでした。

B05-05（ADR 0052）の `resolveDelegationTarget` は、先の委譲がすでに使ったターン（`claimed`）だけを候補から外し、会話の操作に使ったターン（`controlled`）は外していませんでした。そのため、操作の発話の直後（委譲の窓 2 秒以内）の依頼は、操作の発話と並んで「対象が複数」と判定され、1 回聞き返しになっていました。依頼は実行されない安全側の挙動ですが、操作の直後に話した依頼も届きません。B05-07 の統合試験 `X58-request-right-after-a-control-phrase` が、この挙動を既知の制約として記録していました。

## 選択肢

| 案  | 内容                                                                                           | 影響                                                                                           |
| --- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| (a) | 今のまま。操作の発話を候補に残し、直後の依頼は対象が複数として聞き返す                         | 依頼は実行されない（安全側）。ただし操作の直後の依頼が届かず、聞き返しが 1 回増える            |
| (b) | 会話の操作に使った発話を候補から外す（`resolveDelegationTarget` に `controlled` を渡して除く） | 操作の直後の依頼も、操作の発話と並ばずに通常どおり解釈される。操作の発話は依頼の対象にならない |

## 決定

**(b) を採ります。** 会話の操作に使った発話は、依頼の対象ではなく、委譲の対象の候補から外します。操作の発話を外しても、承認・実行権限は生まれません（操作は依頼ではないため）。

- `resolveDelegationTarget` に `controlled`（会話の操作に使った発話の連番）を渡し、`claimed` と同じく候補から除く。
- 中枢の `LiveConversation` は、追っている `context.controlled` をそのまま渡す。解決の後に置いていた「対象が操作の発話なら依頼にしない」重複の検査は、解決の時点で除外されるため取り除く（確定の直前に照合する `#checkControl` の検査は残す）。
- 操作の発話かどうかを決めるのは、これまでどおり `#checkControl`（`resolveSessionControl` の照合表）です。確定より前に操作と分かった発話だけが `controlled` に入るため、操作と依頼が同時に確定するような場合は、従来どおり安全側（対象が複数なら聞き返し）に倒れます。

## 試験

- `packages/contracts/fixtures/voice-interaction-cases.json` に `a-turn-used-by-a-control-phrase-is-not-a-target` を足した（操作のターンを `controlled` で外すと、直後の依頼だけが 1 つの対象になる）。`scripts/voice-interaction.test.mjs` が `controlled` を渡して確かめる。
- 統合試験 `X58-request-right-after-a-control-phrase` の期待値を (b) に合わせた。直後（窓 2 秒以内）も窓の外も、依頼（丁寧な形なので操作ではない）は通常どおり解釈され、LLM を 1 回呼び、操作は作らず、会話は開いたままです。
- 既存の X58（操作の言い回しが LLM を呼ばず操作ごとに別の効果で届く）・X51（入力の確定）の期待値は変えていない。
- 証拠 `tests/integration/evidence-b05-simulated.json` は、B05 の対象のソース（`resolveDelegationTarget`・`LiveConversation`）が変わるため作り直した。模擬の範囲で、実機・実 API・実請求ではありません。

## 変えないこと

- 委譲の窓（2 秒）・確定待ちの上限（5 秒）・断片の安定（300 ms）の値は変えない（ADR 0052 の仮の値のまま。実機の T04 で再評価する）。
- 操作の発話の効果（`SESSION_CONTROL_EFFECTS`）・照合表・`claimed` の扱いは変えない。
- 承認・実行権限・処理状態の正本は中枢のコードのまま。発話の除外は候補の選び方だけで、実行可否を広げない。

## 残ること

- 実機（#132）・実 API（#133）・実請求は未実施です。`X58-request-right-after-a-control-phrase` の観測は模擬の Live と手で進める時計によるものです。
- 操作の発話と依頼が同時に確定する場合の聞き返しは、安全側のままです。実機の遅延分布（T04）で、必要なら確定の順序を再評価します。
