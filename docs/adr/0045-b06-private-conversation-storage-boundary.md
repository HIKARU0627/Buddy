## 原本に書いてあること（読み取り）

- 03 記録しない会話の境界: Buddy 内に保存しない（クラウドへ送った情報まで保存ゼロにはならない）。開始時に開いている音声（Live）の接続は閉じ、その会話の間は呼びかけ語でも開かない。③（端末内で文字にする）は使える。影モードの比較記録は作らない。再開用の文脈の要約も終了時に捨てる。外部変更は、会話本文を保存せず、必要な操作記録を残す独立した確認画面へ切り出し、その記録内容を示して一度承認を得る。要約メモとして黙って保存しない。
- 03 データの分離: 記憶（明示の memory_save を含む）・影モードの記録は記録しない会話では作らない。「今回は」の指示は会話の終了とともに捨てる。
- 09: X17（永続保存 0 件・独立確認で許可された最小操作記録だけ・Live の接続 0 回・呼びかけ語は③で受け付ける）、X36（記録しない会話でも同じ流れで永続保存 0 件・Live 0 回）、X44（抽出の時点）、X48（記録しない会話では比較記録 0 件）、X59（記録しない会話では保存 0 件）。

- **判別できない値**（U66）: 知らない保存モードでは、③・一時のキャンバス・予算の予約を含めてすべて禁止する。知らない行も禁止する。承認済みの印は真偽値の `true` だけを認める（`"true"`・`1` は未承認）。
- 「禁止（RAM）」の行は、記録しない区切りの間は RAM にだけ持ち、出るときに捨てる（`PRIVATE_RAM_KINDS`）。RAM にも持たない行（記憶・抽出・影モード・「今後は」・発言のイベント・通常の操作の記録）は拒否する。

## 遷移（`applyStorageBoundaryEvent`）

事象を 1 つずつ当て、Core が行う命令を順に返す純粋な関数。状態は保存モード・区切りの ID・Live の段階（`closed`・`connecting`・`open`・`closing`）・RAM に持つ物・承認を待つ確認だけ。

- **入る**（`enter_private`）: 命令は ①開いている・開きかけの Live を閉じる（`close_voice_session`、理由は `private_conversation`。ADR 0005・0038 と同じ理由）②一時のキャンバスを始める ③要約をつながない記録しない区切りを開く（`private_started`・`carried_summary: null`）の順。閉じる途中なら閉じる命令を重ねない。既に記録しない区切りなら拒否（`already_private`）。判別できない保存モードからは、入ることだけを許す（記録しない側へ倒す）。
- **出る**（`exit_private`）: 命令は ①RAM を捨てる（発言・要約・入力の版・聞き返し・「今回は」・一時のキャンバス・承認前の確認。捨てた確認の ID を命令に載せる）②一時のキャンバスを終える ③前の要約を持ち込まない区切りを開く（`private_ended`・`carried_summary: null`）の順。出る先が normal・extended のどちらか判別できなければ出ない（U66）。Live は開き直さない（次の呼びかけで、通常の受付を通す）。
- **記録しない区切りの間**: Live の要求・Live の文字起こしの入力は拒否する。入った後に届いた接続（X31 の SDP の answer の後の接続など）は使わずに閉じる（閉じる命令を出し済みなら重ねない）。文字と③の入力は RAM に持つ。
- **区切りの ID**: 入る・出るで開く区切りは、今の区切りと別の ID でなければ拒否する。

## 独立した確認の中身（`privateConfirmationErrors`・`privateApprovalErrors`。U42 の内訳）

ADR 0040 の「残すもの」を、許可リストの 7 欄にした（U67）。

| 欄                | 中身                                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `operation_id`    | 操作の ID（UUID v4）                                                                                                                        |
| `content_version` | 内容版（10 進の文字列）                                                                                                                     |
| `content_hash`    | 内容の hash（小文字 16 進 64 桁。確定 intent の JCS＋SHA-256。依頼 ID を混ぜない）                                                          |
| `intent`          | 意図の名前（RemoteMutation の意図だけ。U64）                                                                                                |
| `account_id`      | 外部サービスのアカウント（ADR 0040 の「接続の ID」。`OperationIntent` の名前に合わせた）                                                    |
| `target`          | 元サービスの対象（`remote_id` は `OriginalSourceId` と同じ文字種・`source_revision`）か null（予定の作成など対象のない意図）                |
| `change`          | 元サービスへ実際に渡す内容。キーは意図の許可引数から `target_candidate_id` を除いたもの。必須の引数の欠けは拒否（`checkIntentArgs` を使う） |

- **持たないもの**: 上にない欄は、名前によらずすべて拒否する（会話の本文・文字起こし・音声・要約・解釈の結果・LLM の出力・発言・会話・区切り・依頼・入力の版・依頼の版・影モード・記憶の由来など）。`change` の中に許可引数でないキー（`transcript` など）や候補の番号（`target_candidate_id`）を入れることも拒否する。`target.remote_id` に空白・日本語の文は入れられない。
- **確認の画面**: 上の 7 欄と `conversation_saved: false`（「会話の内容は保存されない」こと）を出す。`conversation_saved` は Core が足し、下書きでは名乗れない。
- **承認**: 画面での一度だけ（`route` は `screen`、端末の ID と UTC の時刻だけ）。声の「はい」・方針による自動承認は使わない。通常は自動実行のラベル変更・下書き・自分だけの予定も、記録しない会話からは画面で一度承認する（03 の「その記録内容を示して一度承認」。U64）。
- **最小の操作記録**: 承認の後に、7 欄・承認・`record_kind: 'private_minimal'`・`workflow_id: null` だけを残す（ADR 0040 の `operations.record_kind` の案と同じ形）。呼び出し側が後で下書きを書き換えても、確認と記録は変わらない（写しを持つ）。
- **出るときの確認**（U65）: 承認の前に出たら確認を捨て、出た後の承認では記録も外部変更も作らない。承認済みの記録は出ても変わらない（操作の状態機械で続く）。

## 原本に決めがない項目と判断（U63〜U67）

| ID  | 項目                                     | 判断（この ADR）                                                                                                                      | 理由                                                                                                                     |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| U63 | 記録しない会話での「今後は」の指示       | 保存しない（RAM にも持たない）。設定は通常の会話か設定画面で行う                                                                      | `UserDirective` は会話と発言の ID を必須にしていて、記録しない会話にはその行がない。設定として残すと会話の内容が永続する |
| U64 | 独立した確認に切り出せる意図と承認の経路 | RemoteMutation だけ。用事・メモ・記憶（LocalCommand）と参照は切り出さない。承認は画面で一度（自動実行の意図も）                       | 03 は「外部変更」と「一度承認」だけを定める。LocalCommand は Buddy 内に内容を残す                                        |
| U65 | 承認の前に記録しない会話を出たときの確認 | 確認を捨てる。出た後の承認は `confirmation_not_found`                                                                                 | 確認は記録しない区切りの RAM にある。捨てる側が安全（外部変更も記録も作らない）                                          |
| U66 | 判別できない保存モード・出る先           | すべて禁止。出る先が判別できなければ出ない。判別できない状態からは記録しない側へ入ることだけを許す。Live が開いていれば閉じる         | 安全の境界で、記録しない側・禁止の側に倒す                                                                               |
| U67 | 独立した確認の中身の欄                   | 上の 7 欄の許可リスト（知らない欄は拒否）。ADR 0040 の「接続の ID」は `account_id`、対象は `target.remote_id`・`source_revision` の形 | 本文の混入を名前の禁止表で防ぐと、新しい名前で抜ける。許可リストなら知らない欄はすべて落ちる                             |

## 試験

`scripts/storage-mode.test.mjs` がビルド後の domain を、手書きの `storage-mode-cases.json` と照合する。期待値は実装から作っていない。

- **許可表**: 17 行すべてに許可側と拒否側のケースがあること（normal・extended・private と判別できない保存モードを各行に書いた）、各升目の判定、知らない行、契約の `StorageModeState` の `const` と表から作る `effects` の一致。
- **確認の中身**: 正常 3 件（ラベル・対象のない予定・送る本文）と、本文の混入・会話への ID・LocalCommand・参照・知らない意図・候補の番号・許可引数でないキー・対象の余分な欄と文の ID・必須の引数の欠け・形の違う ID の拒否。承認は画面だけ（声・方針・発言の欄・形の違う端末と時刻を拒否）。
- **遷移の順序**: 入る→RAM→出る、Live が開いている・開きかけ・閉じる途中に入る、外部変更の承認→出る、出る→承認（捨てた確認）、頼む前の承認・声の承認・二度目の承認、Live を閉じる途中の外部変更、通常の会話からの外部変更、入る・出るの重複と判別できない出る先、判別できない保存モード。加えて、入る・頼む・承認・出る・遅れて届く接続の 5 つをすべての順序（120 通り）で当て、記録・確認・Live を閉じる回数・最後の保存モードが、実装を通さずに書いた規則どおりかを確かめる。
- **既存の規則との整合**: `admitLiveStart`（409）・`SESSION_CONTROL_EFFECTS`・`AUDIO_CONTROL_RULES`・`INPUT_KIND_RULES`・`shouldExtractMemories`・`memoryAdmission`・`turnRetentionRule`・`streamSegmentErrors`・`nextCarriedSummary` と食い違わないこと。

**模擬の期待値だけ**。StorageModeGate（Core）・DB の制約・UI-05 の画面・音声の実機は未実施。`tests/test-map.json` の X17・X36・X44・X48・X59 の `product_test` は `not_run` のまま（契約 fixture の合格を製品試験の合格として扱わない）。

## 未解決

- Core の StorageModeGate（B06-07）がこの関数をどこで呼ぶか（発言の保存・イベントの outbox・スナップショット・ログの各所）と、命令の実行が途中で失敗したときの扱い（Live を閉じる命令の失敗は voice.ts の close_unconfirmed と同じく予約を保持）。
