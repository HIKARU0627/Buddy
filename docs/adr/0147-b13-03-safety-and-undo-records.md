# ADR 0147: B13-03 方針による自動承認の件数・安全停止・自動実行の一覧・取り消しの保存

- 日付: 2026-11-26
- 状態: B13-03（親 #24）の保存の規則。最終ガードと送出の配線（B13-04）・画面（B13-05）は未着手。実データ・実機・実 API は未実施。
- 根拠: 設計 08 §9、設計 03（取り消しと安全停止、保存期限）、設計 11 §5A、J12、ADR 0010・0074・0146。原本の参照手順は `docs/design/README.md`。
- 対象: `packages/storage/src/safety-store.ts`（新規）、`packages/storage/src/operation-store.ts`・`operation-commands.ts` の方針による自動承認と取り消しの経路、`packages/domain/src/approval.ts` の定数と `autoActionKindFor`。表は 0001 の `safety_breaker`・`safety_window_counts`・`auto_actions`・`undo_records` を使い、マイグレーションは足さない。契約（`packages/contracts`）は変えない。

## 背景

ADR 0074 は 10 分・20 件の時間窓と安全停止の判定（`autoApprovalAllowed`・`autoExecutionEnabled`）を domain に置いたが、件数を DB に数える処理、停止の記録、自動実行の一覧、取り消しの記録は無かった。B13-04 の最終ガードがこれらを 1 つの transaction の中で読み書きできるよう、保存の口を先に用意する。

## 決めたこと

| 対象                     | 決定                                                                                                                                                                                                                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 方針による自動承認の対象 | `task.create`→`create_task`、`mail.labels.change`→`label_mail`、`mail.draft.create`→`draft_reply` の 3 種類だけ。ほかの操作は `operation_kind_not_auto` で断り、件数も数えない。自分だけの予定の作成（`create_event`）は操作の種類がまだ無いため載せない                              |
| 件数の数え方             | 作成時の自動承認（`auto_approval`）と、承認の命令の `policy_auto` の両方で数える。全体の窓（10 分・20 件）と、同じ対象の窓（60 分）の 2 つ。対象の鍵は命令の `safety_target_key` で渡す（外部 ID の形）。窓が過ぎた行は消して、その時刻から新しい窓を始める                           |
| 上限を越えたとき         | 全体の 21 件目は `rate_exceeded`、同じ対象の 3 件目は `same_target_repeated` で断り、安全停止にする（U300）。命令は断るが、停止の記録は残す（transaction は巻き戻さず、拒否の応答を返して確定させる）。停止中の自動承認は `safety_stopped` で断る                                     |
| 停止前の承認             | 停止の前に記録した方針による承認は、停止中は送出の前（`applyLocal`）で `safety_stopped` として止める（08 §9「停止中の承認は保留」）。画面での承認は止めない                                                                                                                           |
| 自動実行の一覧           | 方針で承認した操作が成功したときだけ `auto_actions` に載せる。取り消しの期限は完了から 30 日（J12）。画面で承認した操作は載せない                                                                                                                                                     |
| 取り消し                 | 取り消しは新しい補償の操作として作り、`undo_of` で元の自動実行に結び付ける（03）。元が一覧に無ければ `undo_target_not_auto`、期限を過ぎれば `undo_expired`（期限ちょうどは許す）、進行中の取り消しがあれば `undo_in_progress`。補償の操作は方針で承認できない（`undo_auto_approval`） |
| 補償の連続失敗           | 補償の結果を `undo_records` に記録し、確定した結果（取り消し済み・失敗）の直近 3 件がすべて失敗なら `compensation_failures` で安全停止にする。結果が不明のものは数えない                                                                                                              |
| 再開                     | 登録済みで失効していない端末からだけ、停止中の現在の版を指定して再開できる。再開で版を 1 つ上げ、時間窓の件数を消す（U301）                                                                                                                                                           |

## 原本に決めがない項目

- 同じ対象の反復は 03 の初期案「1 時間に 3 回以上」を、3 回目を記録せずに停止すると読んだ（U300）。3 回目まで記録して 4 回目で止める読み方もある。
- 再開で時間窓の件数を消すか残すかは書かれていない。残すと、再開の直後に同じ理由で止まり続けるため消した（U301）。
- 補償の連続失敗の「連続」は、確定した結果の並び（要求の時刻順）で数え、結果が不明のものを飛ばした。

## 対象外

- 候補の判定（ADR 0146 の `judgeAutoExecution`）を最終 transaction で呼び直す最終ガード、connector の書込み、補償の操作の中身の組み立て（B13-04）。
- 安全停止と取り消しの画面、停止・再開の知らせ（B13-05）。
- 自分だけの予定の作成の操作の種類（予定の書込みを足すときに `create_event` を対応表へ加える）。

## 試験（模擬だけ）

- `packages/storage/src/safety-store.test.ts`: 期待値はすべて手書き。20 件までは通り 21 件目で停止、10 分ちょうどで新しい窓・1 ms 手前は同じ窓、同じ対象の 3 件目で停止と 60 分ちょうどの窓の切り替え、対象外の種類は数えない、承認の命令の経路、一覧と 30 日の期限、停止前の承認を送出前で止める、取り消しの結び付け・二重の取り消し・期限ちょうどと 1 ms 後・方針による承認の禁止、補償の 3 回連続失敗（不明は数えない、成功で数え直す）、再開の端末と版の検査と件数の消去。

**模擬の期待値だけ**。最終ガード・送出・画面・実データ・実機・実 API は未実施で、合格扱いにしない。`tests/test-map.json` の X21〜X24・X39〜X41・X61〜X65 は、B13-04 の統合試験で更新する。
