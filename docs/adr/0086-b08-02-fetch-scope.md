# ADR 0086: B08-02 取得範囲の選択（カレンダー・ラベル・期間・添付の種類）

- 日付: 2026-11-03
- 状態: B08-02（Issue #201、親 #16）。P1（`packages/domain` の純粋な規則）まで。Core の API と保存（P2）・中枢の画面（P3）は未着手。取得そのもの（B08-03）・添付の抽出（B08-04）・実 API は未実施。
- 根拠: 設計 04 取得する対象・接続・権限（J13・J16）、設計 06 B08、設計 11 §1・§1A、ADR 0007・0024・0032・0071、本人の決定 D5・D8・D11（2026-11-01）。原本の参照手順は `docs/design/README.md`。
- 対象: `packages/domain/src/fetch-scope.ts`、`scripts/fetch-scope.test.mjs`、`docs/b00/contract-map.md` の U204〜U206。

## 決めたこと

| 対象                 | 決定                                                                                                                                                                                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 上限と初期値         | 設計の値を**設定できる最大値**かつ初期値にする。メールは過去 90 日、カレンダーは過去 30 日〜今後 90 日、添付は PDF とテキスト系（txt・md・csv）で 1 件 10,000,000 バイトまで。設定は上限より狭くだけでき、上限を超える値は `validateFetchScope` が拒否する（D5）。広げる既定値は作らない        |
| 初期の選択           | 受信トレイは選択済み（J13）、カレンダーは本人が選ぶまで空、添付は PDF とテキスト。受信トレイの ID が分からない provider は空で始める（Outlook は B09-05）                                                                                                                                       |
| 自動で足さない       | `reconcileDiscoveredTargets` は選択を変えずに返し、新しく見つかったものを「未選択の候補」、選択済みで一覧から消えたものを「見当たらない」として分けるだけにする。足せるのは本人の更新要求だけ                                                                                                   |
| 権限が広くても閉じる | 取得の可否は選択とこの規則で決め、OAuth の権限や provider の応答では広げない。選択外のカレンダー・フォルダー／ラベル、期間外、選択外の種類、上限超過、サイズ不明、種類の食い違い、不正な範囲の設定は、いずれも取得しない                                                                        |
| 窓の数え方           | 24 時間 × 日数を UTC で数える（夏時間・タイムゾーンに依らない）。カレンダーは Google の `timeMin`／`timeMax` と同じく窓と重なる予定だけ取り、端に接するだけの予定は取らない。メールの受信は両端を含む。UTC 以外の時刻表記は推測せず拒否する                                                     |
| 添付の種類           | MIME と拡張子の両方で決める。食い違い、拡張子が対象外、画像・Office・圧縮は決めない（取らない側に倒す）。一般的な MIME（`application/octet-stream`）は拡張子で決める。サイズが申告されない添付は取らない                                                                                        |
| 版                   | 選択に変更があれば許可版と取得範囲の版を 1 つずつ上げる。変更が無ければ（並び順だけの違いを含む）上げない。期待する許可版が違えば拒否する。古い版での取得要求は `fetchRequestStale` が拒否し、走査中の batch は既存の `scanCurrentReasons`（`sync.ts`）が `scope_revision` の不一致で無効にする |
| 拒否の語             | 拒否の理由は固定の語だけにし、件名・本文・ID の値を載せない                                                                                                                                                                                                                                     |

## 契約の変更が要ること（P2 の前提）

現行の `ConnectionTargets`（B03）は `calendar_ids`・`mail_container_ids`・`attachment_kinds` だけで、期間と添付サイズの上限を持たない。D5 の「設定で狭められる」には保存先が要るため、契約に項目を足す必要がある（contract-map U204、提案 (a)）。新しい経路は作らず、ADR 0071 の `GET`／既存の `PUT /v1/connections/{connection_id}/targets` で扱う。契約（`buddy.schema.json`・`generated.ts`・fixture）の変更は別 PR にし、他工程の契約作業と直列にするため、変える前に司令塔へ知らせた。

保存は `connections.targets`（JSON）と `permission_revision`・`scope_revision` 列に収まる見込みで、マイグレーションは要らない見込み。

## 試験（模擬だけ）

- `node --test scripts/fetch-scope.test.mjs`: 初期値、狭める設定と上限超過の拒否、メールの窓の端（ちょうど 90 日前と 1 ミリ秒前）、カレンダーの窓の端と重なり、選択外のカレンダー／フォルダー、UTC 以外の時刻、添付の種類の分類、サイズの境界（10,000,000 と 10,000,001）、新しいカレンダー／フォルダーを足さないこと、版の上がり方と古い版の拒否。期待値は手で書き、実装の表から作らない。

**模擬の期待値だけ**。実 API・実アカウント・実データは未実施で、合格扱いにしない。
