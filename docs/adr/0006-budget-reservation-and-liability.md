# ADR 0006: 予約 R・最大負担 M と精算の契約

- 日付: 2026-10-20
- 状態: B00-05（#20）の判断。DB の transaction・provider の usage 取得・価格計算は未実装。
- 根拠: 設計 05「予約と最大負担の区別」（F02）と冒頭の追補、03 データ表（budget_reservations / usage）、10 §2・§3、決定事項 D09・J17、09 の QA42・QA20・X18・X26・X34・X53・MA03〜MA06。下の 3 点は本人の回答（2026-10-20、いずれも推奨案）で決定。

## 決めたこと

| 対象                 | 決定                                                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 追加予約             | 同じ予約行の R と M を増やす。予約行は版（reservation_revision）を持ち、追加分だけを受付検査する。精算は 1 行・1 回で済む |
| 通常枠と超過枠の分割 | 初期版は分割しない。1 つの依頼は通常の枠か個別承認の超過枠のどちらか一方だけに計上する                                    |
| 未送信の予約の解放   | provider へ送っていないことが記録上確実な場合だけ解放（released）できる。送った可能性があれば usage 不明として保持する    |

## 予算の枠の木

個人の金額を契約に入れないため、予算を枠の木（`BudgetConfig`）で表し、金額は実行時の設定に置きます。枠の構造は J17 のとおりです。

- LLM・検索の合計 ─ LLM（会話はここに計上）─ 自発的な解析（会話の保護分を除いた枠）─ 比較 campaign
- LLM・検索の合計 ─ 検索
- 音声（独立。LLM・検索とは融通しない）
- 個別承認の超過枠（独立。承認 ID のある予約だけ）

予約は葉の枠に計上し、受付時は経路上のすべての枠を検査します。会話を親の枠（LLM）に計上するので、自発的な解析の枠が尽きても会話は LLM の上限まで続けられます（J17）。比較 campaign を一つの枠にしたことで、台帳の未決事項 U09 は解決しました。予算の検査はクレジット適用前の通常料金（actual_gross）で行います（05 冒頭の追補）。

## 受付と精算の規則

`packages/domain/src/budget.ts` が持ちます。

- **受付**: 経路上の各枠で、精算済み額＋未精算の R＋今回の R と、精算済み額＋未精算の M＋今回の M の両方が上限以下のときだけ受け付けます。R が収まっても M が超えれば予算不足で、出力上限を無断で削りません。価格が確認されていない版・通貨違い・R が M を超える要求・承認 ID のない超過枠・同じ request_id の再受付も拒否します。
- **使用量の数え方**: 精算済みは実費、未精算（reserved / usage_unknown）は R と M、解放済みは 0 です。予約は受付時の元の予算月だけに数え、月が替わっても動かしません。前の月の usage 不明は前の月に残り、今月の受付には数えません。
- **精算**: request_id と provider の照合 ID で一度だけ適用します。同じ値の再適用は変化なし（duplicate）、異なる値は競合（settlement_conflict）です。予算月と枠は元のままです。R を超えても M 以内なら通常の精算です。
- **M 超過**: 実費を切り捨てずに全額記録し、確認済み（overrun_reviewed）になるまで、その枠と子孫の枠への新規受付を止めます（overrun_hold）。他の枠は止めません。
- **usage 不明**: 応答喪失・timeout・結果の破棄では R と M を保持したまま usage_unknown にし、解放しません。
- **追加予約**: 予約行の版が一致し、状態が reserved のときだけ受け付けます。

`price_version` は設定で決める不透明な単価の版の ID で、順序比較しません。

## 期待値

`packages/contracts/fixtures/budget-scenarios.json` に、合成設定（通貨は ISO の試験用コード XTS、上限は合成値）で 6 つのシナリオを手書きしました。QA42 は合成上限 100 に縮めて、M による拒否・R 超過 M 以内の精算・M 超過の保留・元の月への精算・追加予約・未送信の解放を再現します。実装から期待値は生成していません。

## 残ること

- DB の単一 transaction での受付、精算の一意制約、価格・為替・安全係数による M の算出、provider の usage の取得は未実装です。
- 付帯クレジットを Claude の profile にだけ充当する規則（MA06）と、残高の取得方法は、公式仕様の確認後に決めます。CreditObservation は観測の記録だけです。
- 実請求との照合（T08）は模擬検証と分けて行います。
