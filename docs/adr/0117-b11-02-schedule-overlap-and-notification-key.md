## 決めたこと

| 対象                   | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入力                   | `findScheduleOverlaps(予定, 期間, zone)`。予定は取得側（connector）が繰り返しを個別の回へ展開したもの。カレンダー ID・予定 ID・iCalUID・繰り返しの回の識別・状態・本人の出欠・busy/free・時刻（時刻付きは UTC、終日は日付）だけを受ける。題・参加者・本文は受けない。繰り返しの展開そのものは connector の仕事で、ここでは行わない                                                                                                                                                                                                                                                                                                    |
| 区間                   | 開始を含み終了を含まない。終了と次の開始が同時なら重複にしない（T05 の境界）。重複する時間帯は 2 つの区間の共通部分。1 秒の重なりも重複                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 除く予定               | 取消（`cancelled`）・辞退（`declined`）・空き時間扱い（`busy: false`）。理由を `excluded` に返す。時刻が読めない・終了が開始以前・暦にない日付は推測せず `time_invalid` で除く。仮の予定・仮の出欠・未回答は除かない（原本が除くのは前の 3 つだけ）                                                                                                                                                                                                                                                                                                                                                                                   |
| 同じ予定               | iCalUID があれば iCalUID と繰り返しの回の識別（`ical:<uid>#<回>`）を、無ければカレンダー ID・予定 ID・繰り返しの回の識別（`id:<calendar>/<event>#<回>`）を参照にする。どちらも回の識別を含めるので、iCalUID が無くても同じ予定の別の回を同じ参照にして重複を見落とさない。各部分は URI 成分として符号化し（`#`・`/` は `%23`・`%2F`、`@` は `%40`、`:` は `%3A`）、区切りを含む識別子（`a#b` と `c`、`a` と `b#c` など）が連結で同じ参照にならない。参照と時間帯が同じ写しは 1 つに畳み、参照が同じ予定どうしは時間帯が食い違っても重複にしない（自分自身との重複を作らない）。繰り返しの別の回は別の参照で、時間が重なれば重複になる |
| 同一性を確かめられない | どちらかに iCalUID が無い組は `identity: 'unconfirmed'`（重複候補として根拠を示す）。両方にあって違えば `distinct`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 終日                   | 日付のまま持ち、時刻付きの短い予定へ変換して保存しない。比べるときだけ、本人のタイムゾーンの日付の 0 時から翌日の 0 時として扱う（夏時間の日は 23 時間・25 時間のまま）。終了の日付は含まない。終日どうしの重複は日付（`all_day`）、時刻付きとの重複はその時刻付きの区間                                                                                                                                                                                                                                                                                                                                                              |
| 期間                   | 重複する時間帯が期間 [開始, 終了) と交わるものだけを返し、時間帯は期間で切らない。期間の終わりちょうどに始まる重複と、期間の始まりちょうどに終わる重複は含まない。期間をどう決めるか（現在から先だけにするなど）は B11-04                                                                                                                                                                                                                                                                                                                                                                                                             |
| 組の単位               | 重なる 2 件の組ごとに 1 つ（U277）。結果の並びは入力の順に依存しない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 候補の期限             | `scheduleOverlapDeadline` が重複の始まりを `Deadline` にする（時刻付きは現地の時刻、終日どうしは日付）。P1 の表示順が今日・明日の見出しで先頭に出す                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 識別子の材料           | `notificationKeyMaterial` が、版の見出し行（`buddy.notification-key.v1`）と種類ごとの固定の行を作る。メールは種類・アカウント・依頼エンティティ・依頼の版・期限、予定の重複は昇順の参照（JSON の配列）・時間帯（UTC の始まり/終わり。Z と .000Z のような書き方の違いは正規の形にそろえる。または終日の日付）、調査は workflow ID・完了の版。期限の原文・件名・本文・宛先は材料にしない。取得時刻・再接続・端末の違いは材料にならない                                                                                                                                                                                                  |
| 識別子の部品           | 識別子の部品は短い記号の列だけ（メールアドレス・空白・改行・制御文字は拒否）。予定の参照は `calendarOccurrenceRef` が作る符号化した形（`ical:…#…`・`id:…/…#…`）だけを受け、符号化していない `@`・区切りの余分な `#`・参照の形でない文字列は拒否する。Google の iCalUID（`…@google.com`）は符号化した形（`%40`）で通り、材料に生のメールアドレスの形は残らない。依頼の版は 0 以上の整数の文字列（先頭の 0 なし）。時刻付きの期限は秒を補って正規化し、タイムゾーンを添える。作れない入力は `null`                                                                                                                                      |
| ハッシュ               | SHA-256 は Core（`node:crypto`）が計算する。`notificationKey(材料, sha256)` は計算結果が 64 桁の小文字の 16 進でなければ `null`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 候補を作るか           | `candidateIntakeDecision`: 同じ識別子の候補が残っていれば、状態が何でも（却下・解決の後も、97 日で行が消えるまで）作らない。識別子の形が違えば拒否                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| 通知を出すか           | `candidateAlertDecision`: 配信の記録の重複・再接続・再取得・端末移動・reminder_id の取り違えは既存の `deliveryDecision` に従う（ACK を失った `delivery_unknown` も配信済みとして数え、鳴らし直さない）。その上で、却下・解決の候補、初回取り込みの新着（U279）、根拠が `valid` でない再通知は出さない                                                                                                                                                                                                                                                                                                                                 |

## 原本に決めがない項目

- 3 件以上の重なりの単位（U277）、返信要否の解決結果を識別子の材料にするか（U278）、初回取り込みの個別の通知（U279）。いずれも暫定の置き方を試験で固定した。本人が決めたら変える。U278 の (b) は契約を変えるので、決まったら直列で行う。
- B11-01 の fixture（`candidate-cases.json` の `notification_key_parts`）は材料の構造を示すだけで、予定の重複の時間帯は現地の時刻で書かれている。生成する識別子は UTC の時刻（夏時間・タイムゾーンの変更で変わらないため）を使う。fixture は変えていない（契約の変更を伴わない）。

## 試験（模擬だけ）

- `node --test scripts/schedule-overlap.test.mjs`（16 件）: 基準を日本時間の 2030-10-09 に固定し、期待値は手で数えた。区間の端（ちょうど・1 秒）、包含、3 件の組、別のカレンダーの同じ予定と食い違う写し、繰り返しの回（iCalUID が無い回を含む）、iCalUID なし、取消・辞退・空き時間・読めない時刻の除外、終日（日本時間・UTC・ニューヨークの夏時間の日の 23 時間）、期間の端、入力の順の独立、不正な期間・タイムゾーン、表示順との接続を確かめた。
- `node --test scripts/candidate-notification.test.mjs`（9 件）: 材料の文字列は手で書き、ハッシュは別に計算した値と照合した。同じ意味は同じ識別子（原文・秒・並び）、意味のある変更は別の識別子、拒否する材料（メールアドレス・改行・不正な版や日付・2 件未満の予定）、候補の重複の作成の拒否、再接続・再取得・端末移動で出さないこと、再通知の条件を確かめた。
- 区間の端・同じ予定・除外・材料の項目・並び・初回取り込みの条件を一時的に壊して、試験が失敗することを確かめた（結果が変わらない等価な変更を除く）。

**模擬の期待値だけ**。実際のカレンダー（Google・Outlook）の応答・保存・画面・OS 通知・実機は未実施で、合格扱いにしない。
