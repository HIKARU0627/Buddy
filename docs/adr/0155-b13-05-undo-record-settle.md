# ADR 0155: B13-05 補償の操作が止まったときの取り消しの記録

- 日付: 2026-11-26
- 状態: B13-05（親 #24）の保存層の部分。U313 を暫定で決め、補償の操作の取消・置き換え・本人のやり直しに合わせて取り消しの記録を動かす。**模擬の試験だけ**で、実データ・実機・実 API は未実施。
- 根拠: 設計 03「取り消しと安全停止」、設計 08 §3（取消は送出の前だけ確定する）、ADR 0074・0147・0153・0154。原本の参照手順は `docs/design/README.md`。
- 対象: `packages/storage/src/safety-store.ts`（`syncUndoForTransition`、補償の失敗の数え方）、`operation-store.ts`（状態を進める処理から呼ぶ）、`safety-store.test.ts`。契約・マイグレーション・Core の API は変えない。

## 背景

ADR 0153 では、取り消しの記録（`undo_records`）は補償の操作の結果（成功・未実行・結果不明）でだけ動いた。補償の操作が送出の前に取消・置き換えで止まると、記録は `in_progress` のまま残る。同じ自動実行を取り消し直せず、一覧は「取り消し中」のままになる（U313）。安全停止の間は補償の送出も止まるので、本人が補償の操作を取り消して、解除の後にやり直す道も必要になる。

## 決めたこと

| 対象                 | 決定                                                                                                                                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 取消・置き換え       | 補償の操作が `cancelled`・`superseded` になったら、同じ transaction で取り消しの記録を `failed` にする。同じ自動実行を一覧から取り消し直せる。取消は送出の前だけ確定するので（08 §3）、結果不明の記録（`unknown`）は動かさない |
| 失敗の連続に数えない | 補償の失敗が 3 回続いたときの安全停止（設計 03）は、本人が取消・置き換えで止めた補償を数えない。補償の操作の今の状態で見分ける（記録の状態の種類は増やさない。マイグレーションを足さない）                                     |
| 本人のやり直し       | 未実行（`not_executed`）の確定の後に本人が補償の操作をやり直すと、記録を `in_progress` に戻す。結果は ADR 0153 のとおり記録へ写る                                                                                              |
| 二重の補償を防ぐ     | その間に同じ自動実行の別の取り消しが始まっていれば、やり直しを `retry_not_allowed`（409）で拒否し、何も変えない                                                                                                                |
| 内容の版を上げたとき | 送出の直前の照合で内容版が上がり承認待ちに戻った補償の操作は、記録を `in_progress` のまま残す。本人が操作の画面で承認するか取り消す（取り消せば上の規則で記録が外れる）                                                        |

## 原本に決めがない項目

- U313 は上の決定を暫定の (a) とする。

## 試験（模擬だけ）

- `packages/storage/src/safety-store.test.ts`（3 件追加）: 期待値はすべて手書き。送出の前の取消で記録が `failed` になり、同じ自動実行を取り消し直して成功すること。未実行・取消・未実行・未実行の順で、取消を数えずに 4 回目で安全停止になること。未実行の後のやり直しで記録が `in_progress` に戻り成功で `undone` になること、別の取り消しが始まっていればやり直しを拒否し状態を変えないこと。

**模擬の期待値だけ**。実データ・実機・実 API は未実施で、合格扱いにしない。
