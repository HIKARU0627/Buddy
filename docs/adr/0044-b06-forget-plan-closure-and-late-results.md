# ADR 0044: B06 の忘却の計画（対象の解決・派生の閉包・台帳のエントリ）と遅着の検査の一般化

- 日付: 2026-10-24
- 状態: B06-03（#139、親 #11）の判断と実装。domain の純粋な規則（`forget-plan.ts`・`late-result.ts`）と、既存の `memoryAdmission`・`commandGuard` の共通化だけ。忘却の transaction（行の削除・台帳への追記・知らせ）・系譜の表（`derivations`）・DB worker の配線・復元の「忘却の適用」・Core の経路は未実装（B06-06・B06-07・B06-05）。**模擬の期待値だけ**で、実機・実 API・実請求は未実施。
- 根拠: 設計 03（データの分離・忘却と再取り込み・バックアップ・復元・記録しない会話の境界）、08 §6（「忘れた後に AI 結果が戻る」競合）、09（X15・X44・X59・QA34・T06）、ADR 0008・0010・0032・0040、本人の判断（2026-10-24、#11 のコメント J1〜J6）と司令塔の判断（同日、#11 の 2 つ目のコメント。下の「司令塔の判断の反映」）。原本は権限のある接続で読み取りだけ行い、全文は写していない。原本に決めがないことは「原本に決めなし」と書いた。ADR 0008・0010・0040 で決めたことは変えていない（追加と、0040 が B06-03 に残した名前の合わせ直しだけ）。
- 番号: ADR は 0044、contract-map の未決事項は U58〜U62（B06-02・B06-04 の並行作業と重ならない割り当て）。

## 原本に書いてあること（読み取り）

- 03 忘却と再取り込み: 記憶は source_item・turn・別記憶との由来関係を必ず記録する。忘却時に対象と派生要約を削除し、元の由来 ID に再登録禁止を付ける。全文が保存期限内に残っていても、対象部分を文脈選択と自動要約から外す。判別が不確かなときは、同じ元メッセージ全体を自動記憶化から除外する保守的な扱いにする。本文なしの元 ID と HMAC 等で同じ情報の再取り込みを検出する（言い換えまでは保証しない）。
- 08 §6: 非同期処理へ由来 ID と忘却世代を渡し、結果の保存・自動表示・後続送信の直前にも最新の許可・期限・忘却を検査する。関連する由来が忘却済みなら結果を破棄し、新しい記憶として保存しない。進行中の承認・結果不明の状態を、記憶の削除と一緒に消して再実行を誘発しない。
- 03 データ表: `memory_sources`（由来の系譜）・`intent_shadow`（入力 ID で発言を参照）・`async_context_guards`（由来 ID・忘却世代）。

**原本に決めなし**: 派生物の系譜をどの表・どの種類で持つか、閉包を広げる範囲（「判別が不確か」の具体）、台帳に派生物をどう書くか、HMAC の入力と鍵の持ち方（ADR 0040 が決めた）、「〇〇を忘れて」の発言の扱い（司令塔の判断で確定）、進行中の操作の確定内容に忘れた内容が含まれるときの扱い。下はこの ADR の設計判断。

## 決めたこと

### 1. 対象の解決（不明・複数なら聞き返す）

`resolveForgetTarget(request, known)`。`known` は Core が DB から読んだ今ある対象の参照。

- ID を指定: 今ある行にあれば確定。なければ `target_not_found` で聞き返す。
- 検索語: **domain は検索語を受け取らない**。Core が RAM で検索語を当てた結果（一致した対象の参照）だけを渡す（ADR 0040 U41）。今ない対象への一致は数えず、重複は 1 件にまとめる。0 件は `no_match`、2 件以上は `multiple_matches` で、候補（参照だけ。本文は表示の権限の範囲で Core が付ける）を返して聞き返す。確定するのは、ちょうど 1 件に決まるときだけ。
- 確定する操作の内容 `forgetOperationContent` は解決した対象の種類と ID だけ。検索語・本文・候補の文は入れない。

### 2. 派生の閉包（`planForget`）

Core は系譜（`derivations`。ADR 0040 の案）を読んで `ForgetGraph`（派生物から由来への辺・由来を引けない派生物・発言と会話の対応・今ある記憶と内容の HMAC・memory の操作の状態）を渡す。domain は次の規則で、忘れる物・除外する由来を固定点まで求める。

| 派生物の種類（`FORGET_ARTIFACT_KINDS` と `memory`・`turn`）                                                                                           | 規則                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 記憶（`memory_sources` の派生）・会話の要約（`session_summary`）・つないだ要約（`carried_summary`。永続のものを含む）                                 | 忘れる物から作られていれば消す                            |
| 気づきの題・抄録（`notification_candidate`）・依頼の抽出結果（`request_entity`）・関連解析（`related_analysis`）                                      | 同上                                                      |
| 永続のキャンバスの物（`canvas_item`。`item_refs` が由来）・影モードの記録（`intent_shadow`。入力 ID で発言を参照）・非同期処理の参照（`async_guard`） | 同上                                                      |
| memory の操作の確定内容（`operation_content`。memory_save・memory_correct・memory_forget の暗号文）                                                   | 同上。ただし操作の状態で扱いを分ける（下の「4」）         |
| 派生した発言（忘却の指示への Buddy の返答など。`turn`）                                                                                               | 忘却の指示の発言から作られていれば消す（Core が辺を足す） |

規則（A〜D を、増えなくなるまで繰り返す）:

- **A（下流）**: 忘れる物（対象・指示の発言・消す派生物）から作られた派生物は、種類によらず消す。派生物の派生物（再要約・それを表示するキャンバスの物）も届く。
- **B（上流の除外）**: 消す記憶の**元の発言・元情報**は、消さずに再登録を禁じる由来にする（03「元の由来 ID に再登録禁止」）。別の記憶が由来のときは広げない（本人が一覧で確認して消せる）。
- **C（由来を共有する派生物すべてを広げる。U59、Codex の P1 で改めた）**: 除外する由来（上の B）から作られた派生物は、**種類によらず**（要約・気づき・依頼・関連解析・キャンバスの物・影モード・非同期処理の参照・操作の確定内容・別の記憶）消す。忘れる記憶と同じ元から作られた物が、その記憶と同じ内容を含むかは、部分ごとの由来が記録されないので証明できない。「忘れた内容が残らないこと」を「関係のない通知が消えないこと」より優先する（本人の意図）。広げて消した記憶の元は、さらには広げない（連鎖して全体が消えるのを防ぐ）。広げた物から作られた物は下流として消す。部分ごとの由来が記録できるようになったら緩める。消した要約・気づきは、除外した由来を外して作り直す（B10）。到着の順序で結果が変わらないこと（忘却の前に届いた派生物は消え、後に届いた派生物は台帳の `blocked_source_hmacs` で破棄される）を試験で確かめる。
- **D（由来を引けない派生物）**: 系譜が書かれていない派生物は、属する範囲（会話・元情報）だけを渡す。範囲が**忘れる物**に触れるなら消し、範囲全体（同じ会話の全発言・同じ元情報）を除外する（03「同じ元メッセージ全体」）。範囲が**除外する由来**に触れるだけなら、種類によらず消す。
- **知らない種類は計画を作らない**: 辺の種類が表にないときは `unknown_artifact_kind`・`unknown_source_kind` で拒否する（見落とすより閉じた側）。

結果は次の形（`ForgetPlan`）。**操作の取消・失効・再送の項目は持たない**。

- `deletions`: 物理削除する行（記憶・派生物・対象の発言・対象の元情報の本文）。`FORGET_DELETE_ORDER`（参照する側から先）の順。操作の行は入らない。FK の最終の順序は B06-06。
- `operation_contents`: 確定内容（暗号文）を今消す操作と、触れずに残す操作（下の「4」）。
- `ledger`: 台帳に書く内容（下の「3」）。
- `notice`: 知らせ（`RetentionNotice` の `forgotten`＝本人が選んだ対象と指示の発言、`derived_from_forgotten`＝そこから作られて消えた物。種類は発言・元情報・記憶・つないだ要約だけ）。ID だけで、本文・検索語を持たない。1 件の上限 256 を超えるときは `chunkNoticeItems` で分ける。

### 3. 台帳のエントリの組み立て

`buildLedgerEntry(plan.ledger, {entry_id, previous_generation, recorded_at})`。入力は解決済みの対象から作った計画と HMAC だけで、**文字列を直接受ける口はない**（ADR 0040）。

- `forgotten`: 消す発言・記憶（Buddy 内の ID）と、消す元情報の HMAC（`source_id_hmac`）。派生した記憶も入れる（ADR 0040 U43）。元情報は**生の ID を書かない**。
- `blocked_source_hmacs`: 除外する由来（上の B・D）の HMAC。元情報に加えて**元の発言も同じ HMAC の欄に入れる**（下の「判断が要る点」。ADR 0040 の文は元情報だけを挙げていたが、HMAC の入力に種類が入っているので同じ関数で足りる。発言を `forgotten` に入れると復元で発言そのものが消えるため、再登録の禁止だけにしたい元の発言は別の欄が要る）。
- `blocked_content_keys`: 消す記憶（派生を含む）の内容の HMAC（`memories.dedupe_key`）。
- **HMAC は注入された関数で求める**（`SourceHmac`。入力は種類と ID）。domain は鍵を持たない。関数の戻り値が 64 桁の小文字 16 進でなければ（生の ID を返すなど）、計画を作らない（`source_hmac_malformed`）。台帳の組み立てでも同じ検査と、重複・空の `forgotten`・世代の不正を拒否する。
- 世代は直前の世代の次（1 件ごとに 1 つ進める）。連続性の最後の保証は DB の trigger（0001）。

### 4. 進行中の承認・結果不明の操作は消さず、再実行を誘発しない

- 計画に操作の行の削除・取消・承認の失効・状態の変更・再送の項目はない。memory の操作の**確定内容（暗号文）だけ**が対象で、`operationContentPurgeable` が決める。
- **消してよいのは終端の 3 状態だけ**（`succeeded`・`cancelled`・`superseded`。`operationContentPurgeable` が明示して列挙する。Codex の P2: 以前は `OPERATION_TRANSITIONS[state]` の長さで判定し、継承された名前の `toString` などを終端と誤認した）。`awaiting_approval`・`approved`・`preparing`・`dispatching`・`reconciling`・`unknown_held`、そして再試行できる `not_executed` は `retained`（`in_flight`）として**何も触れない**。操作の状態にない名前（継承された名前を含む）と、状態の記録が見つからない操作は、消さずに残す（`state_unknown`）。
- 例外は、**この忘却を今まさに適用している memory_forget の操作**（`executing_operation_id`）。同じ transaction で完了するので、確定内容（対象の ID）を消してよい。
- 残した操作の確定内容に忘れた内容が含まれ得る（U61、Codex の P1 で改めた）。終わってから J5 の削除（完了の 7 日後）に任せる。その間は次を守る。
  - **残す操作ごとに、送出禁止の印と、本文を持たない由来を返す**（`retained[].send_blocked`・`provenance`。由来は発言・記憶の ID と元情報の HMAC）。Core は操作に送出禁止の印を付け（承認・試行・状態は変えない）、送出の直前の検査（`dispatch_intent`・LocalCommand の適用）で拒否する。`async_guard` を消しても、送出の検査に使う由来は残る（`commandGuard` の `options.forgetting` に、この由来を渡せる）。
  - 承認・試行・結果不明の記録は消さず、再送もしない。操作を勝手に取り消さない。
  - 実行の直前の検査は、判明している由来を**必ず**台帳と照合する（由来の全体が不明でも）。外部へ送る命令は、由来が不明なら拒否する（下の「6」）。LocalCommand の `memory_save` は適用時の `memoryAdmission` が止める。
- 試験: 10 の状態すべての確定内容が同じ記憶を由来にする世界で、終端 3 つだけが消え、残りは `in_flight`・`state_unknown` で何も変わらないこと。計画の項目名が `deletions`・`ledger`・`notice`・`operation_contents`・`targets` だけであること。

### 5. 遅着の検査の一般化

`lateResultCheck(result, context)`（`late-result.ts`）。要約・記憶の候補・自動表示・後続の送信を、保存・表示・送信の直前に同じ規則で見直す。

- 理由の並び（`memoryAdmission` と同じ）: 記録しない会話（保存だけ）→ 由来を引けない（`provenance_unknown`。閉じた側）→ 許可版 → 台帳 → 期限。
- **台帳との関係**は `ledgerRelationReasons`（`memory.ts`）に切り出し、`memoryAdmission`・`lateResultCheck`・`scopedForgettingReasons` が共有する。ADR 0040 の「忘却の関連の判定」の表のとおり、世代の新旧ではなく**由来が忘却と関係するか**で決める（世代が同じでも忘れた由来は通さない。無関係な忘却で世代が進んだだけでは破棄しない。開始の後の世代が台帳に揃わなければ破棄。開始の世代が今より大きければ破棄）。
- **照合する側でも HMAC の形を検査する**（Codex の P1）: 注入された関数の戻り値が 64 桁の小文字 16 進でなければ（生の ID・大文字・桁数不足・空）、「台帳と一致しない」と読んで通さず、`source_hmac_malformed` で拒否する。計画を作る側（`planForget`）と同じ検査を、共通の `ledgerRelationReasons` に入れたので、保存（`persist`）・表示（`display`）・送信（`send`）・命令の再検査・記憶の保存直前のすべてに効く。
- 記録しない会話は**保存だけ**を止める。表示・送信は一時の文脈のまま判定できる（X59。保存の禁止は `StorageModeGate` の責務で、遅着の検査は二重の保証）。
- 内容の禁止（`blocked_content_keys`）は `content_key` を持つ自動抽出の候補だけを止め、明示の保存・表示・送信は止めない（ADR 0008）。
- 忘却と遅着の**すべての順序**を試験で入れ替える（開始 S・到着 A・関係する忘却 F1・無関係な忘却 F2。S が A より前の 12 通り）。到着が F1 より後なら破棄、前なら保存した後で F1 の閉包が消す。どの順序でも、忘れた発言から作った結果は残らず、無関係な結果は残る。

### 6. commandGuard の忘却の世代の検査を、関係する由来のときだけに絞れるか

**絞れる。ただし opt-in にし、storage への配線は後続にした**（案 A）。

- 今の `commandGuard` は、命令の忘却世代が DB の最新の世代と違えば拒否する。無関係な忘却（別の記憶を忘れた）でも、進行中の命令がすべて `forgetting_generation_changed` で拒否される。ADR 0040 の「関連の判定」と食い違う。
- `commandGuard(command, current, { external, forgetting })` に、命令の由来（`sources`・`provenance`）・台帳・HMAC の関数を渡したときだけ、世代の検査を `scopedForgettingReasons`（`ledgerRelationReasons`）に置き換える。**渡さなければ従来どおり**（この PR で既存の動作は変わらない）。拒否の理由は従来と同じ `forgetting_generation_changed` のまま（Core の応答の分類 `CONFLICT_REASONS` を変えない）。
- 安全側の条件: **判明している由来は、由来の全体が不明（`provenance: 'unknown'`）でも、必ず台帳と照合する**（Codex の P1。以前は不明なら照合せず、世代が同じなら通っていた）。由来を把握していない命令は、世代が違えば拒否する（従来どおり）。**外部へ送る命令（`options.external`）は、由来が不明なら世代が同じでも拒否する**（理由に `provenance_unknown` を足す）。台帳に開始後の世代が欠けていれば拒否。世代が同じでも忘れた由来から作った命令は拒否（従来は通っていた。**絞った検査のほうが厳しい場合がある**）。台帳との照合に使う HMAC が形（64 桁の小文字 16 進）を満たさなければ拒否する（`source_hmac_malformed`。次の「5」）。状態版・依頼版・許可版・安全停止・予算予約の検査は変わらない。
- 配線しなかった理由: 命令の由来を DB から引く（`async_context_guards.source_refs` の読み取りと、送出直前の transaction の中での台帳の全件読み）は DB worker の変更で、承認・送出の最終ガードに触れるため、B06-07 以降で Codex のレビューを重くして行う。そのとき、`DbCommand` が由来の参照を持つか、worker が `async_context_guards` を引くかを決める。

### 7. 司令塔の判断の反映（ADR 0040）

- **「〇〇を忘れて」という発言**: `instruction_turn_id` を対象に加える。台帳には発言の ID だけが残り（`forgotten` の `turn`）、発言と、そこから作られた物（影モードの記録・Buddy の返答の発言）を、忘却と**同じ transaction で消す**。返答の発言は、Core が「指示の発言から作られた」辺を足すと A で消える（返答に〇〇が含まれ得るため）。Live の文字起こしも同じ扱い。
- **記憶・派生物は物理削除**: `deletions` は行ごと消す一覧で、`status = 'deleted'` の行を残さない。台帳が消した記録の正本。

## 判断が要る点（司令塔へ）

1. **元の発言を再登録の禁止にする欄**（U59）: 消す記憶の元の発言を、`forgotten`（復元で発言そのものを消す意味になる）ではなく、`blocked_source_hmacs` に発言の HMAC として入れた。ADR 0040 は `blocked_source_hmacs` を元情報の HMAC と読める書き方で、発言を入れるのは拡張。反対なら、元の発言も `forgotten` に入れて消す（会話の全文が 7 日で消えるので、被害は小さいが、同じ発言から作った別の記憶も閉包で消える）案に変える。
2. **広げる範囲は、除外する由来を共有する派生物すべて**（U59。司令塔の判断で、要約だけから広げた）: 同じ元から作られた別の記憶・気づき・依頼・関連解析・キャンバスの物・影モード・確定内容も消す。関係のない通知・別の記憶が消える代わりに、忘れた内容が残らない。**判断が要る点**: 生きている**用事の正本**（`user_tasks`・`user_notes`。ADR 0040 の「用事の正本」）は、派生物の種類に入れていない（本人が確定保存した用事は本人の削除操作を正とする。03）。同じメールから作った用事が、忘れた内容を含み得る場合に消してよいかは、本人の意図の確認が要る。決まるまでは、用事の正本は計画に入らず、残る。
3. **忘れた内容を含む進行中の操作の確定内容は、終わるまで残し、送出を禁止する**（U61）: 進行中の承認・結果不明を消さず再実行を誘発しない（08 §6）ことを優先し、確定内容に忘れた内容が含まれたままになる間は、送出禁止の印と本文なしの由来を残して、実行の直前の検査で拒否する。**判断が要る点**: 送出禁止の印は Core（B06-06）が操作の行に付ける。印を付けた承認待ちの操作は、本人が取り消すまで進まない（勝手には取り消さない）。
4. **commandGuard の絞り込みの配線**（U62）: 判断が要るのは、DB worker の変更を B06-07 で行うか、それ以降に回すか。
