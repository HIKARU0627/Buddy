## 判断（原本に決めがないこと）

1. **送出前の取り消しを門に足さない**（U84）。送出意図を記録した予約・Live の記録を作った予約は解放できないという DB の保証（0007・0006）を変えず、受付の途中で拒否する窓を狭める。予約を取った後、送出意図を記録する**前**に、停止・交代・リースの期限切れ・所有者の変更を排他の列の中で再確認し（2 段目と同じ判定）、断るなら予約を解放する（送っていないことが確実）。残る窓は、送出意図の記録の応答を待つ間に停止が来た場合だけで、使用量不明として予約を保持する（本人の手での精算。送り直さない・自動で解放しない）。窓の間に取り消しの記録を足す案（`dispatch_cancelled_at`・trigger の緩和・マイグレーション）は、送出意図の「送った可能性がある」の意味をコードの申告に頼ることになり、B07 で固めた最終ガードを弱めるので採らない。二重の予算の最終ガードは省略しない。
2. **金額の式**（U85）。追加予約は M と同じ式（量 × 単価 × 為替 × 安全係数を切り上げ。最低課金量は接続ごとに 1 回で開始の予約が済ませている・版の 1 要求の最大量は追加を重ねるので見ない）、実費は 15 秒との大きい方 × 単価 × 為替（安全係数は M の見積もりだけの余裕）。単価は、予約の窓（予約の受付から 2 時間）にかかる版のうち、額が最も高いものにする（開始の M の `estimate` と同じく、期間の途中で版が切り替わっても少なく数えない側。予約に固定した版だけで求めるのではない）。
3. **予算到達の扱い**（U86）。結果不明の追加予約も予算到達として扱い、同じ券で送り直さない（追加が済んだかもしれないので、閉じて精算で余りを戻す）。発話の終わりのイベントは provider の実装が決める抽象（`onModelUtteranceEnded`）。
4. **時計の逆行**（U87）。単調時計の逆行は通常起きないが、起きたら会話の長さを数えられないので、継続できる側に倒さず閉じる。
5. **終了後の照合**（U88）。provider への読み取りの照会（`lookupSession`）は、原本に決めのない境界で、OpenAI にそのような照会の API があるかは未確認（実 API の作業で決める）。照会の間隔 60 秒・期限 5 秒・精算の試し直し 3 回は仮置き。

## レビューで残した点（P3。この PR では文書だけ）

- **P3-1（発話の終わりと指示の対応）**: いまはモデルの発話の終わりを、予算の上限を伝える指示への応答かで区別していない。provider の実装（実 API の作業）で、指示に対応する応答 ID を使って区別する。
- **P3-2（確認済みにした後の精算）**: 精算する前に Live の記録を確認済みにするので、その間に Core が落ちると自動の照合が効かない。後続の作業で、保存済みの `usage_seconds` から再起動の照合で精算する。
- **P3-3（解放した request_id の取り直し）**: 解放した `request_id` を同じ値で取り直すと 503 になる。端末は毎回新しい `request_id` を作る、という契約にする（端末の実装と契約の試験で確かめる）。
- **P3-5（孤児を閉じるまでの遅れ）**: 孤児・終了未確認のセッションを閉じるまでの遅れは、provider の照会 API があるかに依存する。実 API の作業の最初に、照会の手段と遅れを確かめる。

## 判断が要る点

1. **送出前の取り消しを足さない**こと（U84）。足す場合は、0007 の trigger（送出意図の記録・解放の拒否）の緩和とマイグレーションが要り、B07 の最終ガードの再レビューになる。
2. **実費に安全係数を掛けない**こと（U85）。安全係数を掛ける設計なら、実費が M を超えやすくなる。
3. **provider の照会の API**（U88）。OpenAI にセッションを live_session_id で照会する手段があるかは未確認で、なければ孤児・終了未確認の照合は本人の手での精算（`settle_manual`）に頼る。provider の実装（実 API の作業）で決める。

## 残ること

- provider（OpenAI の Live）の実装（`createSession`・`connectSideband`・`lookupSession`・`appendInstructions`・発話の終わりのイベント）と、実 API の 2 段階の試験（合成の音声、その後に本人の声）。
- 会話の予約額が 3,000 円（予約上限 3,600 円の 8 割程度）に達した日の残り時間の常時表示と、その日の最初の会話で一度だけ伝える通知（10 §3。J17）。予約額の見え方（状態欄・設定の画面の「今日の会話回数と合計時間」）は UI-08（#100）。
- 同意の経路・返し方の正本・端末の失効の中枢の音声への反映など、ADR 0046 の残りのうち B05-04 の対象でないもの。
- 送出意図の記録の応答を待つ間の停止（残る窓）で使用量不明になった予約の、本人の手での精算の案内（画面）。
