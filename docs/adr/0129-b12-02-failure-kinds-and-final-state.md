# ADR 0129: B12-02 失敗の区別と最終状態の決め方（読めたページが無ければ完了にしない）

- 日付: 2026-11-14
- 状態: B12-02（親 #27、Issue #264）の P2。契約と規則だけ。実 API は呼んでいない。
- 根拠: 設計 05「公開Web調査」（「取得失敗・会員限定・PDF 等で本文を解析できない場合は、読めたものと検索要約だけのものを区別します」）、Issue #27 の完了条件（「失敗を完了と表示しない」）、計画 B12-03（失敗と 0 件を区別する）・B12-04（読めない場合の区別）・B12-05（失敗・会員限定を完了にしない）、ADR 0125・0128。
- 対象: `packages/contracts/schemas/buddy.schema.json` の `WebSearchFailureCause`・`WebPageOutcome`・`WebResearchSummaryOutcome`、`packages/domain/src/web-research-limits.ts` の `webResearchFinalState`・`webResearchOutcomeErrors`・`webResearchConfirmedLabel`、fixture `web-research-attempts-cases.json`。

## 決めたこと

### 検索の結果の区別

| 結果                       | 意味                                                                                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hits`                     | 検索は成功し 1 件以上                                                                                                                                 |
| `zero_hits`                | 検索は成功し 0 件。**失敗ではない**                                                                                                                   |
| `failed`＋`failure_cause`  | 検索が失敗した（`timeout`・`http_error`・`rate_limited`・`unauthorized`・`invalid_response`・`network_error`）。0 件ではない。件数は 0 で、原因が要る |
| 断った（`search_denials`） | 送らなかった。`search_limit`（上限）・`budget_denied`（予算の門）・`query_rejected`（検索語の検査。ADR 0127）                                         |

### ページの取得の結果の区別

| 結果                                           | 意味                                                                   | 根拠になるか |
| ---------------------------------------------- | ---------------------------------------------------------------------- | ------------ |
| `read`                                         | 本文を読めた。出典の ID を持つ                                         | **なる**     |
| `unreadable_format`                            | 取得できたが読めない形式（PDF 等）                                     | ならない     |
| `login_required`                               | 会員限定・認証が要る（回避しない。設計 05 の対象外）                   | ならない     |
| `empty_text`                                   | 取得できたが本文が空                                                   | ならない     |
| `blocked_target`                               | 接続の前に拒否した（ローカル・プライベート・リンクローカル等。B12-04） | ならない     |
| `too_large`・`timeout`・`redirect_limit`       | 2MB・15 秒・3 リダイレクトの上限で止めた                               | ならない     |
| `redirect_loop`・`http_error`・`network_error` | リダイレクトの循環・HTTP のエラー・接続の失敗                          | ならない     |

読めなかった理由が違っても、画面の完了にはならない。理由の種類は B12-05 が本人への説明に使う。

### 最終状態の決め方（`webResearchFinalState`）

これ以上試せないとき（上限・取得する件の尽き・要約まで済み）の状態を、試行の記録から決める。手で書いた表が fixture にある。

| 試行の記録                                                                              | 最終状態                                                                                                              |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 成功した検索が無く、検索語の検査で断っただけ                                            | 保留 `held`／`query_rejected`                                                                                         |
| 成功した検索が無く、予算で断った                                                        | 保留 `held`／`budget_held`                                                                                            |
| 成功した検索が無く、失敗した                                                            | 失敗 `failed`／`search_failed`                                                                                        |
| 成功した検索は全部 0 件で、失敗した検索が無く、追加の検索を予算で断ってもいない         | `no_results`／`zero_hits`                                                                                             |
| 成功した検索は全部 0 件だが、追加の検索を予算で断った（検索の枠が残っている）           | 保留 `held`／`budget_held`（取りこぼしがありうるので 0 件と確定しない）                                               |
| 件数が 0 だが、別の検索が失敗した                                                       | 失敗 `failed`／`search_failed`（0 件と言い切れない。U296）                                                            |
| 件数があり、読めたページが 0 件（予算で検索を断った場合を除く）                         | 失敗 `failed`／`no_readable_page`（検索の件数だけで完了にしない。U293）                                               |
| 件数があり、読めたページが 0 件で、予算で追加の検索を断った（5 ページの枠が残っている） | 保留 `held`／`budget_held`。5 ページを使い切っていれば、検索を足しても本文は取れないので `failed`／`no_readable_page` |
| 読めたページがあり、要約を予算で断った                                                  | 保留 `held`／`budget_held`                                                                                            |
| 読めたページがあり、要約が失敗した                                                      | 失敗 `failed`／`summary_failed`                                                                                       |
| 読めたページがあり、要約が成功した                                                      | **完了 `completed`**（`unread_count`・`scope_reduced` を付ける）                                                      |
| まだ試行が足りない（検索が無い・取得がまだ・要約がまだ）                                | 結論なし（null）。呼び出し側が続ける                                                                                  |

- `scope_reduced` は、検索の一部が失敗した・上限や予算で断った・5 ページに達して未取得の件が残った、のどれかのとき true。
- 予算で断った記録（`budget_denied`）は、**検索の枠がまだ残っている間だけ**保留の理由になる。再開して 3 検索を使い切った後は、古い断りで保留を続けず、結果（失敗・0 件・読めない）で終える。断りの一覧は現在も有効なものだけを持つ形が望ましく、再開時に解消した断りを取り除くのは B12-05。
- 取消（`canceled`）は試行の記録に依らず、いつでも起こりうる。

### 応答と記録の突き合わせ（失敗を完了と表示しない）

`webResearchOutcomeErrors` は、まず応答と記録が**同じ依頼**（`workflow_id`・`request_revision`）であることを確かめる（別の依頼の記録で確認済みにしない。取消も同じ）。そのうえで、完了・0 件・失敗・保留の応答が、試行の記録から決まる最終状態と同じかを検査する。状態・理由・読んだ出典の ID の集合・読めなかった件数・範囲を減らしたかが 1 つでも違えば拒否し、`webResearchConfirmedLabel` は `unconfirmed`（確認できない）を返す。応答の整合・記録の整合・記録との一致の**3 つがそろったときだけ**、状態どおりの見出し（`completed` など）を返す。

## 原本に決めがない項目

- 設計 05 は「読めたものと検索要約だけのものを区別」と書くが、検索要約だけで完了にするかは書かない。Issue #27 の完了条件と B12-05 の完了条件に合わせ、**読めたページが無いものは完了にしない**（U293）。検索要約は検索結果なので保存もできない（ADR 0077）。
- 検索の一部が失敗したときに 0 件と言い切らない（U296、暫定）。「0 件でした」と本人に言うのは、取りこぼしの可能性がある限り誤りになりうる。
- 予算で断ったとき、保留にするか範囲を減らして完了にするかは、読めたページの有無で分けた（U297、暫定）。設計の「予算不足では範囲を減らすか保留します」に沿う。読めたページがあっても、要約を作る予算が無ければ保留にする。

## 試験（模擬だけ）

- `scripts/web-research-limits.test.mjs`: 最終状態の表 27 通り、記録の整合 20 通り、応答と記録の突き合わせ 19 通り（完了の見出しになるのは記録と一致したものだけ）を、手で書いた期待値と照合した。失敗・0 件・読めないの 3 つの終わり方が互いに違う状態・理由になること、保留にならないことも検査した。
- 規則を壊す（読めたページが無いのに 0 件扱い）と試験が落ちることを手元で確かめた。
- 実 API・実際のページ・実請求は未実施。会員限定・PDF の実際の判定は B12-04、検索の実際の失敗（レート制限・認証）は B12-03 で確かめる。
