# 設計資料の扱い

公開リポジトリには一般化した設計と機械可読契約を置き、設計原本は非公開 Notion で管理します。

## 公開できる概要

- Node.js / TypeScript の独立 Core と Windows / macOS の Electron クライアントを分離する。
- contracts / domain を OS 非依存にし、通信境界を OpenAPI / JSON Schema で検証する。
- 承認、状態、予算、忘却、同期世代の正本は Core が持つ。LLM と端末が実行権限を作らない。
- B00 で入力・解釈・実行条件・承認・操作結果・イベントの契約を固定する。
- 合成データで試験し、模擬・実機・実 API の結果を区別する。

[B00 の手順](../b00/README.md)と[契約対応表](../b00/contract-map.md)は原本の節番号と試験 ID を参照します。原本全文の代替ではありません。

## 非公開の原本を読む

権限のある Notion 接続で、変更に関係する設計 01〜11、決定事項、レビュー記録を確認してください。
作業用の写しは `.local/design/notion/` に置きます。Git・書式検査の対象外ですが、強制追加した場合は公開情報検査で拒否します。

以前のスナップショットと manifest は公開対象から移し、今回の作業環境ではこのローカル領域に保持しています。新しい clone には配布されません。
原本を取得できない場合は不足を明記し、必要な部分の実装を保留します。要約から原本を推測しません。

manifest がある環境では `pnpm run design:check` で取得時点の SHA-256 を確認できます。Notion の更新検知ではなく、公開 CI に含めません。

公開する契約に、個人の端末情報、実際の費用設定、アカウント、メール、予定、Notion 内部 URL をコピーしません。設定は実行時入力へ、検証例は合成データへ置き換えます。
設計の意味が変わる判断は原本へ反映し、公開契約・試験と整合させます。更新履歴の旧例を現行仕様と混同しません。

[情報管理と公開前確認](../public-release.md)も参照してください。
