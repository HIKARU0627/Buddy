# ADR 0029: 発言から操作の作成までの経路と、preview の発行・無効化

- 日付: 2026-10-22
- 状態: B04-03（#83）の判断と実装。`createSession`・`postTurn`・`previewOperation` の経路、会話の DB worker の命令、解釈と対象の解決の差し込み口、模擬の解釈、試験用の方針表、内容版の更新（D1）の保存、preview の照合（`previewValid`）を作った。実行（B04-04）・画面（B04-05）は対象外。試験は同じプロセスの模擬（127.0.0.1 の HTTPS、模擬の KeyStore、試験の中で作る合成の provider）だけで、実機・実 API・実請求は未実施。模擬 provider のアダプター（#87）は main に入っていないため、差し込み口の形だけを合わせ、接続していない。
- 根拠: Issue #83 の要約と本人の判断 D1〜D6（2026-10-22）、ADR 0004・0009・0018・0019・0023・0026・0027、`tests/test-map.json`（X02・X03・X04・QA27）。設計本文（07 §1〜3、08 §3、09 §1〜3、10 §5・§6A、01）は今回の作業環境に取得できず、Issue と ADR の要約に基づく。原本との照合はレビューで行う。

## 試験

- storage（`conversation-store.test.ts`、4 件）: 会話の作成と再送・照合値の違い・失効した端末、発言の一つの transaction（行・期限・暗号文の持ち主・入力スナップショットの値）と再送・知らない会話で何も書かないこと、依頼から作った操作と preview 用の暗号文の照会、D1（承認待ち・承認の後・内容が同じ・版の食い違い・古い状態版・実行中の試行）。 レビューの後: 発言と同じ transaction での操作の作成・別の操作 ID を計画した再送で増えないこと・作成の途中の失敗で何も書かないこと、`turn.find`。
- Core（`api-turns.test.ts`、7 件）: 重なりの計算、X02（「follow-up を付けて」で依頼 1・操作 1・外部変更 0、2 端末のスナップショットに同じ操作 ID・内容版・hash、別の端末の preview での承認は 409、同じ端末なら 202）、QA27 の Read 側（予定の照会で承認 0・試行 0、重なり）、聞き返し（知らない文・題名なし・候補なし・変更なし・読み取りだけの接続）と用事の LocalCommand の作成、会話の再送、X03・X04（古い接続範囲は 410、新しい接続範囲・ロックの後・許可の版の変更の後・内容の変更の後・再起動の後の古い preview は 409、新しい preview なら 202）、接続の終了と置き換えでの preview の無効化。 レビューの後（4 件、直す前に失敗することを確かめた）: 照会を止めた間のロック・置き換えで previewValid が false、送る直前の照合で preview_valid を false にすること、同じ要求の同時の 3 件と、対象・接続が変わった後の再送で同じ応答・操作 1 件、期限の地域日時（うるう日・不正な日・時刻の境界を手で書いた期待値で）。
- hash の期待値は、試験に手で書いた正規形の文字列（キーの辞書順・空白なし）の SHA-256 で、実装の正規化を使っていない。provider は試験の中の合成の読み取り専用の模擬で、書込みの命令を持たない。

## 残ること（B04-04 以降）

- 試行の状態 `superseded`（0001 の CHECK にない）と、preparing の操作の内容版の更新。LocalCommand の成功（`approved → succeeded` の一つの transaction、試行の `dispatch_intent_at` の CHECK）。どちらもマイグレーションと命令が要る（B04-04）。
- 操作に連携の接続の列がない（0001）。作成・承認の命令は connection_id を null で送り、接続と許可の版は意味検証と preview・承認の照合で確かめている。送出の直前の照合は B04-04 で接続を持たせる。
- #87 のアダプターを `ProviderReader` につなぐ。候補の正本（同期、B07）。スナップショットの sessions は空のまま（発言の表示は B05）。
- preview に期限を設けていない（原本に定めがあれば合わせる）。
