## 記憶と忘却

`packages/domain/src/memory.ts` が持ちます。

- **2 段階**: モデルの生の出力 `MemoryCandidateWire`（種類・80 文字以内の文・由来の発言 ID・対象キー）と、Core が検証した `MemoryCandidate`（由来の種類、重複判定の HMAC、処理開始時の忘却世代・許可版）を分けます。抽出（11 §3）と同じ形です。
- **保存直前の検査**（08 §6）: 遅れて返った結果も、記録しない会話・許可していない種類・許可版の変化・期限切れの由来を拒否します。忘却した由来と、そこから作った記憶（台帳は派生した記憶も記録する）を由来に含む候補は、台帳の世代の新旧によらず保存しません。処理開始後の世代が台帳に揃っていなければ（`forget_ledger_gap`）判定できないので保存しません。
- **同じ内容の再取り込み**: 忘れた記憶の HMAC を台帳の `blocked_content_keys` に残し、自動抽出では同じ内容を保存しません。本人が新しい発言ではっきり頼んだ保存（memory_save）は、この内容の禁止だけでは止めません。03 の「自動記憶化の禁止を黙って解除しない」を自動抽出の範囲と読みました（レビュー対象）。由来が忘却済みなら、明示の依頼でも保存しません。
- **重複と矛盾**: 同じ HMAC の記憶があれば二重に保存せず、期限も更新しません。同じ種類・同じ対象キーで内容が違えば、両方を見直し待ちにします（J15）。
- **期限**: 保存から 90 日で見直し待ち、見直し待ちから 30 日で削除します。別の記憶から作った記憶は、由来の見直し日より後にしません。時計が巻き戻ったときは、期限内に見えても自動で使いません（`clock_regression`）。
- **抽出の時点**（X44）: 会話の終了時・30 分の無発言時に、memory_save で処理した往復を除いて 4 往復以上ある場合だけ抽出します。記録しない会話では抽出しません。
- **復元**: 最新の台帳世代が分からない、完全な台帳の複製が最新世代に届かない、バックアップが台帳より新しい、のいずれかなら記憶・会話を戻しません（X16）。
- **本人の指示**: `UserDirective` は「今回は」（this_time）と「今後は」（from_now_on）を分けます。

## モデルの配備と評価

`packages/domain/src/evaluation.ts` が持ちます。

- **区別する単位**: モデル ID（要求した ID と応答が返した ID）、版（不変の snapshot・可変名・ローカルの digest）、profile（provider・endpoint・API 版・思考設定・構造化出力の方式・出力上限・単価の版・予約方式・検証済みの能力）、用途、評価条件（セットの版・分割・基準時刻・schema / prompt の hash・成果物の digest・cold / warm）、証拠（模擬 provider・実 API・実機、実行 ID・コミット）を別々の項目にしました。
- **採否は配備×用途ごと**（`adoptionReasons`）: 根拠にできるのは同じ配備・同じ用途の `EvaluationResult` だけです。意図判定の合格を他の用途へ流用できません（X57）。全用途をまとめた値は置いていません。採否は本人が決め（`decided_by: user`）、判断のない用途は未評価です。
- **評価として数えないもの**: 模擬 provider だけの結果、調整用の分割、本人の確認済みが 0 件、用途ごとの必須の指標の欠け、評価後に条件（prompt・schema・応答モデル ID など）が変わった配備です。ローカル・音声・端末内の認識は実機の測定だけを証拠にします。同じ用途の評価で必須境界例の違反が 1 件でもあれば不採用です（X66）。単価の版がないクラウドの profile は有効にしません。
- **影モード**（U11）: `IntentShadowRecord` は本文を持たず、`used_for_execution` は常に false です。集計 `ShadowCampaignSummary` は一致率と遅延だけで、正答率・合否・採用の欄がなく、採否の根拠に書いても評価として数えません。campaign は件数・実費・日数の最初の到達で止め、記録しない会話・音声の接続中・空きがないときは動かしません（skip）。記録しない会話では比較記録も作りません。
- **段階**: downloaded→integrity_checked→contract_tested→evaluated→active を一つずつ進め、active にするには採否の検査が通っている必要があります。応答モデル ID・API 版の変化や検証済みの能力の後退を検知したら suspended にし、回帰試験の後に evaluated へ戻します（QA21）。成果物の欠け・大きさの違い・digest の不一致があれば検証済みにしません（QA26）。可変名を同じ名前で指定し直すことは戻し先になりません。
- **用途ごとの必須の指標**は、05 の用途別評価の表と 09 の X57・X66 の評価項目を指標名にしたものです。音声と端末内の認識は B05 の実機試験で指標を決めるまで採用できません。
- `measured_p95` の予約は意図判定の profile だけに使います（05 質問132）。

`ModelEvaluationPlan`（`model-evaluation.json`）は候補一覧のままで、配備の記録ではありません。

## 評価セットの書き出し形式

`IntentEvalCase` が `tests/eval` の 1 例の形式です。採否の集計に使えるのは、本人の確認済みで判定用に分けた例だけです。同じ元例の言い換えは同じ group_id にし、調整用と判定用にまたがらせません（`splitLeaks`）。変換は `scripts/eval-tools.mjs` が行い、試験は合成の行だけを使います。評価セットの本文はリポジトリに置きません。

評価セットの配列の値（ラベルなど）の書き方は確認できていないため、推測で区切らずに変換の失敗にしています。対応表のキーも、確認できた date_from・date_to と IntentArgs の項目名だけです。B10 で評価セットを書き出すときに、実際の行で対応表を確定します。

## 版の型

`api_version`・`sdk_version`・`runtime_version`（provider・runtime の版の文字列）と `suite_version`（評価セットの版）は、一致だけを見る不透明な文字列にしました（ADR 0003 の対応表に追加）。

## 残ること

- 記憶・忘却台帳の保存、台帳の端末への複製、バックアップと復元の手順、期限処理の実行は B06 で実装します。
- 記憶抽出のプロンプト・モデル、HMAC の鍵管理は B06・B10 で決めます。
- モデルの呼出し、評価の実行、配備の記録の保存、変化の監視は B10 で実装します。評価セットの確認済みは 0 件のため、現時点ではどの用途も採用できません。
- 有料 API の比較・実機の測定は行っていません。
