## 決めたこと

DB の台帳（`forget_ledger`・`forget_ledger_items`）が正本で、`forget-ledger.json` は DB から作り直せる写しである（ADR 0054）。Core は、ファイルが壊れている・DB より進んでいる・食い違っているとき起動しない。この CLI は、本人が中枢の前で、DB が「知っている最新」であることを確かめてからファイルを作り直す。

| 対象                      | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 材料                      | 中枢の DB の台帳、`forget-ledger.json`、バックアップ設定（`backup-config.json`）の置き場所にある封筒（`*.buddybackup`）の `ledger_id`・`forgetting_generation`・`ledger_head_hash`。端末の複製（B06-07）はまだ使わない。                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| DB が最新であることの確認 | 同じ系譜の封筒について、封筒の世代が DB の head 以下で、その世代の DB の `entry_hash` が封筒の `ledger_head_hash` と一致すること。世代が DB より先の封筒があれば DB が古い（`backup_newer_than_ledger`）。同じ世代の hash が違えば分岐（`backup_ledger_hash_mismatch`）。どちらも作り直さず、復元（`restore check`／`restore run`）に進ませる。                                                                                                                                                                                                                                                                                                              |
| ファイルの扱い            | DB と一致する（同じ head・同じ hash）なら何もしない（`no_change`）。欠落・壊れ・遅れ・食い違いで、DB が最新であることを封筒で確認できたなら、既存ファイルを同じディレクトリの `forget-ledger.json.repair-<時刻>-<UUID>` に退避してから、DB の全件で作り直す（`rebuilt`）。退避したファイルは消さない（本人が確かめられるようにする。本文・HMAC だけの写しで、秘密ではない）。書きかけの一時ファイル（`.forget-ledger-*.tmp`）も Core の起動時の同期と同じ材料として照合し、新しい・分岐・読めないものがあれば本体を退避する前に拒否する（`ledger_file_ahead`・`ledger_file_diverged`・`ledger_file_invalid`。退避しても Core は起動できないため）。          |
| 進んだファイル            | ファイルの世代が DB より先なら、DB が古い疑いがあるので作り直さない（`ledger_file_ahead`）。復元に進ませる。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| DB が読めない             | DB がない・台帳の連鎖が壊れている（`ForgetRejection`）ときは何もしない（`hub_db_missing`・`hub_ledger_invalid`）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 封筒が読めない            | バックアップの置き場所の封筒が読めない・設定が壊れているときは、新しい世代を持ち得るので確かめられないものとして止める（`backup_unreadable`・`backup_config_invalid`）。置き場所がない（初回）ときは封筒なしとして扱う。封筒の `manifest` は、系譜による除外より先に `BackupManifest` の契約検査と意味検査へ通す（`backup_manifest_invalid`。`ledger_id` の欠落・型違いなど形が違う封筒は、新しい世代を持っていた可能性を排除できないので読み飛ばさない）。封筒の確認は DB の系譜の有無にかかわらず行う（系譜のない DB は初回だけでなく忘却の前へ戻された DB でも起こる。世代 1 以上の封筒があれば `backup_newer_than_ledger` で拒否し、成功と報告しない）。 |
| 排他                      | 復旧の間は Core のロックを取る（Core が動いていれば `core_running`）。データディレクトリを先に用意する（`data_dir_unavailable`）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## 何をしないか

- 同じ `ledger_id` で共通の世代の `entry_hash` が DB とファイルで違う（分岐）ときは、どちらが正しいか決められないので退避も再生成もしない（`ledger_file_diverged`。`restore check` の `ledger_chain_invalid` と同じ扱い）。分岐の前の古い封筒と一致することは、DB 側の分岐が正しい証拠にならない。

- ファイルを先に消して DB に合わせるだけの手順にしない（進んだ台帳の知識・再登録の禁止を捨てるため。U129 で (b) を採らないと決めた）。
- DB が古いときに、ファイルや封筒から DB を作り直さない（復元の段階 3 で台帳を当てる経路を使う）。
- 端末の複製（B06-07）を材料にしない（まだない。増えたら、同じ「最新の連鎖」の選び方に加える）。

## 試験（模擬のみ）

`apps/core/src/restore-repair.test.ts`。本物の Core の設定とバックアップで封筒を作り、次を確かめる。

- 壊れたファイル（`{broken`）を退避し、DB の台帳（空の系譜）から作り直す。退避したファイルが残る。
- DB と一致するファイルは触らない（`no_change`）。
- ファイルが DB より進んでいる（1 件の正しい連鎖）ときは作り直さず、`ledger_file_ahead` で止める（ファイルは残る）。
- DB の台帳が読めない（DB を空にする）ときは `hub_ledger_invalid` で何もしない。
- 同じ系譜で世代 1 の hash が DB とファイルで違う（分岐）ときは、`ledger_file_diverged` で拒否し、ファイルを変更・退避しない。
- `ledger_id` が数値の壊れた封筒を置くと `backup_manifest_invalid` で拒否し、ファイルを変更しない。
- 系譜のない DB（空の DB）に世代 1 の封筒を置くと `backup_newer_than_ledger` で拒否し、台帳のファイルを作らない。
- 書きかけの一時ファイルだけが DB より進んでいるときは、本体が壊れていても退避せず `ledger_file_ahead` で拒否する。
- 退避の後に書き込みが失敗すると `ledger_file_rebuild_failed` と `aside_kept: true` を返し、壊れた本体は退避名に残る。

実機・実際の破損・Mac mini は B15 で未実施。`tests/test-map.json` の X15〜X17 は `not_run` のまま。
