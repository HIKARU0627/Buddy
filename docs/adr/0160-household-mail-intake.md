# ADR 0160: 同期したメールからの利用通知の取り込み（家計簿 段階 1 の一部）

- 日付: 2026-11-26
- 状態: 家計簿の段階 1 の部分。同期で公開したメールのうち未確認のものを取り出し、ADR 0159 の規則で利用通知を読み、ADR 0158 の家計簿に記録する。Gmail だけを対象にする。**模擬の試験だけ**で、実在のメールでの確かめは未実施。
- 根拠: 本人の依頼（本人の手間を減らし、できるだけ早く取り込む）、ADR 0158、ADR 0159。
- 対象: `packages/storage/migrations/0017_household_mail_checks.sql`、`packages/storage/src/household-store.ts`、`apps/core/src/household-mail-intake.ts`、`apps/core/src/sync-scheduler.ts`、`apps/core/src/core.ts`。

## 背景

メールの同期は、受信したメールの識別子と版だけを `source_items` に置き、本文を保存しない。公開の結果も件数だけで、どのメールが新しいかは分からない。利用通知をできるだけ早く記録するには、同期の公開の直後に、まだ確かめていないメールだけを読む仕組みが要る。一方で、初めて接続したアカウントの過去のメールを全部読むと、通信が多く、古い利用を一度に記録してしまう。

## 決めたこと

| 対象               | 決定                                                                                                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 確かめ済みの記録   | `household_mail_checks` に、確かめたメールの識別子と時刻だけを置く。通知だったか、どの会社かは置かない。元のメールが同期から消えたら一緒に消える                                                       |
| 基準               | アカウントごとに初めて取り込むときに `household_mail_baselines` へ基準の時刻を置き、その時点で同期済みのメールをすべて確かめ済みにする。過去の利用は読まない。過去の分は段階 1 の CSV の取り込みで補う |
| 呼び出しの時       | 同期の予定が対象を公開した直後に、メールの対象だけについて待たずに呼ぶ。失敗は記録に残し、同期は止めない。同じアカウントで走っている間は二つ目を始めない                                               |
| 読む順と量         | 未確認のメールを新しい順に一度に 50 件まで読む。残りは次の公開の後に読む                                                                                                                               |
| 掃除のゲート       | 保存期限の掃除が済むまで読まない（ADR 0053・0058）。ゲートの確認から記録の終わりまで掃除の貸し出しを持ち、取れないときは読まずに次の公開の後に読む                                                     |
| 本文を読む前の確認 | まず見出しだけを読み、送り主の確かめ（ADR 0159）と件名の種類で通知の候補でないと分かれば、本文を読まずに確かめ済みにする                                                                               |
| 認証結果           | Gmail の受信サーバーが付けた一番上の Authentication-Results だけを使い、その識別子が `mx.google.com` でなければ使わない。それより下の見出しは途中のサーバーや送り主が付けられるため使わない            |
| 本文               | text/plain の部分を優先し、なければ HTML を文字にして使う。添付の部分は読まない。文字コードは部分の Content-Type に従う                                                                                |
| 記録               | 一通の各利用を、出所（Gmail・アカウント・メールの識別子・メールの中の順番）付きで記録する。同じ出所の二つ目は ADR 0158 の規則で作られないため、確かめ済みの記録が消えても二重には記録しない            |
| 失敗               | 見出し・本文の読み取りや記録に失敗したら、そのメールを確かめ済みにせずに止める。次の公開の後に読み直す                                                                                                 |
| 対象外             | Microsoft のアカウントは、本文を読む口がまだないため読まない。データ鍵か Gmail の読み取りの口がないときも読まない                                                                                      |

## 原本に決めがない項目

- U326: Gmail の接続があれば、本人の操作なしに利用通知の取り込みを始めること。
- U327: 初めて取り込むときに過去のメールを読まないこと。
- U328: メールが通知だったかどうかを保存しないこと。
- U329: Outlook のメールを段階 1 では読まないこと。
- U330: 一番上の認証結果だけを信じること。

## 試験（模擬だけ）

- `packages/storage/src/household-store.test.ts`: 基準の作成と過去のメールの確かめ済み、新しい順、範囲の絞り込み、件数の上限、二度目の確かめ、ないメール、元のメールの削除で一緒に消えること、別のアカウントの基準、形の誤り。
- `apps/core/src/household-mail-intake.test.ts`（7 件）: 一時の DB と偽の Gmail の読み取りで、基準の後の通知を一度だけ記録すること、知らない送り主・認証の不合格・偽の一番上の見出し・請求の件名・速報の件名で本文を読まないこと（請求の件名は、ADR 0176 で請求予定として読むようになり、この試験は件名を変えて確かめている）、HTML だけの通知の二つの利用、確かめ済みの記録を消しても二重にしないこと、読み取りの失敗でやり直すこと、Microsoft・鍵・読み取りの口がないときに読まないこと、掃除のゲートが閉じている・貸し出しが取れないときに読まないこと、補助の関数。送り主はすべて合成の `example.invalid` のドメイン。

**模擬の期待値だけ**。実在のメールでの読み取りは未確認で、合格扱いにしない。

## 残ること
