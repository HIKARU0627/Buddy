# ADR 0158: 家計簿の記録の保存と月の集計（家計簿 段階 1 の一部）

- 日付: 2026-11-26
- 状態: 家計簿の段階 1 の部分。本人の決定で、外部の家計簿サービスの代わりに Buddy の中に家計簿を持つ。この ADR は記録の保存・暗号化・月の集計・分類の規則までで、利用通知メールからの取り込み・画面・CSV の取り込みは後の ADR で足す。**模擬の試験だけ**で、実データ・実機・実 API は未実施。
- 根拠: 本人の依頼（外部の家計簿サービスを使わずに済むよう Buddy の内部機能に置き換える。本人の手間を減らし、できるだけ早く取り込む）と、段階 1 の計画への本人の了承。ADR 0010・0016・0017・0051・0055。原本の参照手順は `docs/design/README.md`。
- 対象: `packages/domain/src/household.ts`、マイグレーション 0016、`packages/storage`（`household-store.ts`・`household-content.ts`・DB worker の `household` の経路）、`apps/core/src/household-ledger.ts`、バックアップの対象の表。

## 背景

原本は家計の情報を外部の家計簿サービスに置く前提で、Buddy 自身は家計の記録を持たない。本人は外部のサービスをやめ、Buddy の中で家計簿を付けたいと決めた。銀行やカード会社の口座を直接読む仕組みは事業者との契約が要るため使わず、段階 1 では各社の利用通知メールを主な取り込み口にする。この ADR はその受け皿となる記録の保存と集計を作る。

## 決めたこと

| 対象                     | 決定                                                                                                                                                                                                                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 記録の性質               | 家計の記録は Buddy 自身の記録で、外部を変えない。操作・承認・自動実行の経路は通さない。本人は画面で分類を変える・消すだけ                                                                                                                                                             |
| 平文に置くもの           | 出所の種類、出所の鍵（SHA-256）、月（`YYYY-MM`）、状態、内容版、時刻だけ。金額・日付・時刻・分類・店名・メモ・支払い手段は暗号文（`sealed_blobs` の目的 `household_entry`、所有者は記録と内容版）に入れる                                                                             |
| 分類                     | 大項目 16 個（一般的な家計簿の分け方にそろえた）に「その他」「未分類」「収入」「振替」を足した 20 個。支出の分類は支出の記録だけ、「収入」は収入だけ、「振替」は振替だけに使える                                                                                                      |
| 振替                     | カードの引き落としや口座間の移動は向きを `transfer` にし、支出・収入の集計から外す（カードの利用と引き落としを二重に数えない）。月の集計には振替の合計だけを別に出す                                                                                                                  |
| 同じ出所                 | 出所（メールの提供元・口座・メール ID・同じメールの中の順番、書き出しの行、手入力の ID）から鍵を作り、同じ鍵の記録は二つ作らない（`duplicate` を返す）                                                                                                                                |
| 削除                     | 行は残し、状態を `deleted` にして月と暗号文を消す。同じ出所から作り直さない。行の削除・出所の変更・内容版の飛ばしは DB の trigger で拒否する                                                                                                                                          |
| 変更                     | 本人の分類の変更は内容版を照合して暗号文を差し替える（古い版は `revision_mismatch`）                                                                                                                                                                                                  |
| 店名からの分類           | 本人が分類を変えると、店名から分類を覚える（本人の規則）。次から同じ店の「未分類」の利用に、向きが合うときだけ当てる。店名は NFKC・小文字・空白の詰めで正規化し、データ鍵から作った HMAC の値で保存する（店名の平文を DB に置かない）。取り込みで覚えた規則は本人の規則を上書きしない |
| 月の集計                 | Core が復号してから計算する（支出・収入・差額・件数・分類ごとの支出・振替）。読める範囲は 24 か月まで、一度に 5000 件まで（超えたら古い記録を切ったと返す）。復号できない記録は数だけ返し、集計に入れない                                                                             |
| 中身の検査               | 金額は 1〜9,999,999,999 円の整数、日付は 2000〜2099 年。店名・メモ・支払い手段は長さと制御文字を検査し、12 桁以上の数字の並びは拒否する（カード番号・口座番号を記録に入れない）                                                                                                       |
| 保存の期間とバックアップ | 記録は本人が消すまで残す。規則は置き換えまで残す。どちらもバックアップの対象に入れる                                                                                                                                                                                                  |

## 原本に決めがない項目

- U318: 家計の正本を Buddy に置くこと（原本は外部のサービスを前提にしている）。
- U319: 分類の一覧。
- U320: 月を平文に置くこと。
- U321: 振替を集計から外すこと。
- U322: 店名の HMAC の鍵の作り直し。

## 試験（模擬だけ）

- `scripts/household.test.mjs`（7 件）: 分類の一覧と向き、中身の検査（長い数字の並び・制御文字・範囲）、月の計算、集計（振替を外す・分類ごとの並び）、出所の鍵の材料、店名の正規化、規則の上書きの可否。
- `packages/storage/src/household-store.test.ts`（8 件）: 記録と同じ出所の `duplicate`、内容版の照合と古い暗号文の削除、削除した出所から作り直さないこと、月の範囲の読み取り、規則の上書きの可否、形の誤りと安全停止、DB の trigger、DB worker の往復。
- `apps/core/src/household-ledger.test.ts`（7 件）: 店名の規則を覚えて次の未分類の利用に当てること、分類済みの利用には当てないこと、月ごとの並びと集計、向きの違う分類・古い内容版の拒否、削除の後の `duplicate`、別のデータ鍵の記録を復号できない数として返すこと、店名の鍵の値。
- 既存の試験の DB の版を 16 に、表の数を 59 にそろえ、バックアップの対象の表を足した。

**模擬の期待値だけ**。実データ・実機は未実施で、合格扱いにしない。

## 残ること

- 利用通知メールからの自動の取り込み（家計簿 段階 1 の次の部分）。
- 端末の画面と API（月の一覧・集計・分類の変更・削除）。
- 外部の家計簿サービスの書き出し（CSV）の一度だけの取り込み。
- 固定費・予算（段階 2）、レシートや会話からの補い（段階 3）。
