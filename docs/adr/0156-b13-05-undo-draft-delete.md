# ADR 0156: B13-05 自動で作った返信の下書きの取り消し（下書きの削除）

- 日付: 2026-11-26
- 状態: B13-05（親 #24）の部分。U310 のうち下書きを本人の決定で (a) にし、Buddy が作ったままの下書きを取り消しで削除する。用事・予定は ADR 0153 の暫定 (b) のまま。**模擬の試験だけ**で、実データ・実機・実 API は未実施。
- 根拠: 設計 03「取り消しと安全停止」（下書き・予定の取り消しは作成物の削除）、J12、設計 07 §2、設計 08 §3、設計 11 §6（本人が手を加えた作成物）、ADR 0030・0075・0151・0153・0155。原本の参照手順は `docs/design/README.md`。
- 対象: 契約（`OperationKind`・`OperationStepKind`・`DraftDeleteOperationIntent`）、`packages/domain/src/connectors.ts`、`packages/storage/src/operation-commands.ts`、模擬の提供元とアダプター（`packages/connectors`）、Core の差し込み口・実行担当・取り消しの経路、端末の文言。マイグレーションは足さない。

## 背景

ADR 0153 では、契約に下書きの削除の種類が無いため、自動で保存した返信の下書きは取り消せない（`unavailable`）と見せた（U310 の暫定 (b)）。ADR 0075 は完全削除の操作の種類を作らないとしている。本人に確かめ、下書きについては削除を足すと決まった。消してよいのは、Buddy が作り、その後に変わっていない下書きだけとする。

## 決めたこと

| 対象                   | 決定                                                                                                                                                                                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 操作の種類             | `mail.draft.delete`（RemoteMutation、工程は `delete_draft`、照合は `exact_target` で下書きの id を読む）。target は下書きの id と版、action は下書きを作った操作と内容版（`created_by`）。外部の相手へは送らない。`created_by` が自分自身を指せば意味検査の誤り（`created_by_self`） |
| 使える場面             | 自動実行の取り消しの補償だけ。取り消しに結び付かない作成は保存層が `undo_only_kind` で拒否する。方針の自動承認では作らない（ADR 0153 の `undo_auto_approval`）。ADR 0075 の「完全削除の種類を作らない」はこの種類だけを除いて続く（fixture の検査もこの種類だけを除く）              |
| 取り消しの押下の時     | 元の操作の作成物の id（試行の `external_id`）で下書きを読み直す。下書きのままで、目印（`buddy-op:<操作>:<内容版>`）・返信元・宛先・CC・件名・本文がすべて保存した内容と同じときだけ補償を作る。送った・手を加えた・別の目印・見つからない下書きは 409 `target_changed` で消さない    |
| 送る直前               | 実行担当が下書きをもう一度読み、下書きのまま・目印が同じ・版が押下の時と同じこと、許可の版が同じことを確かめる。違えば送らず準備のまま残す（内容版は上げない。削除の承認画面は無いので、承認待ちに戻すと本人が承認できない）                                                         |
| 送り方                 | 版を条件にした削除を 1 回だけ送る。提供元は版が違う・送信済みなら 409 で断り、未実行として記録する。結果不明は下書きを id で読み、無ければ消えた、あれば未適用とする（再送しない）                                                                                                   |
| 取り消せるように見せる | 提供元が下書きを id で読める口を持つときだけ、下書きの行を取り消せると見せる。端末は取り消せる下書きの行に「取り消すと、Buddy が作った下書きを削除します。」と添える                                                                                                                 |
| 模擬の提供元           | 下書きに版（作成で `d1`、本人の編集で進む）を持たせ、id での読み取りと、版を条件にした削除（範囲 `mail.drafts.delete`）を足した。削除の真の結果は受付の記録と状態の変化の数で確かめる                                                                                                |

## 原本に決めがない項目

- U310: 下書きは本人の決定で (a)。用事・予定は暫定 (b) のまま。
- U317（新規）: 押下の後に下書きか許可が変わったときは、暫定 (a) で送らず準備のまま残す。本人が操作の画面で取り消すと、ADR 0155 の規則で取り消しの記録が外れる。

## 試験（模擬だけ）

- `packages/connectors/src/mock-provider.test.ts`: 下書きの読み取り、編集で版が進むこと、古い版での削除が 409 で状態を変えないこと、無い下書きは 404、削除の成功と受付の記録、送信済みの下書きは 409。
- `packages/storage/src/safety-store.test.ts`: 取り消しに結び付かない下書きの削除は `undo_only_kind` で作らないこと、取り消しの補償としては作れること。
- `apps/core/src/api-auto-actions-undo-draft.test.ts`（5 件）: 作ったままの下書きが押下で作った補償で版つきで削除され、取り消し済みになること。本文・宛先を変えた・送った・目印が違う・無い下書きは 409 `target_changed` で消さないこと。押下の後に版が変われば実行担当が送らず準備のまま残すこと。id で読めない提供元では取り消せると見せないこと。純粋な判定（取り消せる種類、作ったままの判定、削除の照合）。
- `scripts/contracts.test.mjs`・`scripts/operation-kinds.test.mjs`・`scripts/approval-required-operations.test.mjs`: 新しい intent の正誤の例と意味検査、種類と intent の対応、完全削除の除外がこの種類だけであること。
- 端末の `AutoActionsPanel.test.tsx`: 取り消せる下書きの行だけに削除の説明が出ること。

**模擬の期待値だけ**。実データ・実機・実 API（Gmail・Microsoft の下書きの削除）は未実施で、合格扱いにしない。

## 残ること

- U310（用事・予定）・U313〜U317 の本人の確認。
- 実際の提供元（Gmail・Microsoft）で、下書きの版として何を使い、条件つきの削除をどう送るかの確かめ。
- 準備のまま残った補償を、自動実行の欄から取り消せるようにするか。
