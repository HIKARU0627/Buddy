# ADR 0159: 利用通知メールの送り主の確かめと本文の読み取り（家計簿 段階 1 の一部）

- 日付: 2026-11-26
- 状態: 家計簿の段階 1 の部分。カード会社の利用通知メールから家計簿の記録の内容を作る規則（domain）だけを足す。メールの取得・本文の平文化・同期の後の呼び出しは次の ADR で足す。**模擬の試験だけ**で、実在のメールでの確かめは未実施。
- 根拠: 本人の依頼（本人の手間を減らし、できるだけ早く取り込む）、ADR 0158。各社の公式の案内（利用通知の項目、送信元のドメイン）。
- 対象: `packages/domain/src/household-notice.ts`。

## 背景

銀行・カードの口座を直接読むには事業者との契約が要るため、段階 1 は各社の利用通知メールを主な取り込み口にする。本人がすることは、各社の会員サイトで利用通知メールを有効にすることだけにしたい。そのためには、届いたメールが本当にカード会社のものかを確かめ、各社の書式の違いを吸収して金額・日付・店名を読む規則が要る。

## 決めたこと

| 対象           | 決定                                                                                                                                                                                                                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 送信元の一覧   | カード会社ごとに、公式の案内に載った送信元のドメインだけを持つ（ビューカード・楽天カード・三井住友カード・JCB から始める）。一覧のドメインか、その下のドメインだけを通知の候補にする                                                                             |
| 送り主の確かめ | 差出人の表示は偽れるため、受信サーバー自身が付けた認証結果で、DMARC が差出人のドメインで合格しているか、DKIM が合格して署名のドメインが同じ会社の一覧に入るときだけ信じる。途中のサーバーが付けた認証結果は呼び出し側が渡さない                                  |
| 件名           | 利用のお知らせ・利用通知の件名だけを読む。請求・明細・引落し・ポイント・本人確認・ログイン・不正・キャンペーンなどの語がある件名は、利用通知としては読まない（ADR 0176 で、請求のお知らせの件名は請求予定として別に読むようになった。利用通知の記録にはしない）  |
| 速報と確定     | 同じ利用を速報と確定の二度知らせる会社（ビューカード・楽天カード）は、確定の通知だけを記録する。速報だけを送る会社はその通知を記録する                                                                                                                           |
| 本文の読み取り | 本文を NFKC にし、項目名（利用日・ご利用日時・ご利用先・ご利用加盟店・利用金額など各社の表記の揺れ）と値の組を順に読む。値が同じ行にある書式と次の行にある書式の両方を読む。同じ項目が二度目に出たら次の利用とみなし、一通の中の複数の利用を分ける（100 件まで） |
| 金額           | 円の印（円・¥・JPY）のある金額だけを記録する。外貨・取消（負の金額・取消の語）・読めない金額は記録せず、理由を返す                                                                                                                                               |
| 日付           | 年月日と時刻を読む。年のない書式は受信日の年とし、受信日より後の月日なら前の年とする。本文に日付がなければ受信日を使う                                                                                                                                           |
| 記録の内容     | 支出・未分類・店名（12 桁以上の数字の並びがあれば空にする）・支払い手段にカード会社の名前。分類は ADR 0158 の店名の規則が後で当てる                                                                                                                              |

## 原本に決めがない項目

- U323: 速報と確定の二度の通知のうち、確定だけを記録すること。
- U324: 送信元の一覧を Buddy に組み込むこと（本人が足す手段は画面を作るときに決める）。
- U325: 外貨・取消の利用を段階 1 では記録しないこと。

## 試験（模擬だけ）

- `scripts/household-notice.test.mjs`（10 件）: 組み込みの送信元の一覧の形、差出人のドメインの取り出し、送り主の確かめ（合成の送信元の一覧で。DMARC・同じ会社の DKIM は通し、別のドメインの DKIM・不合格・認証結果なし・一覧にないドメインは通さない）、件名の種類、金額・日付の書式、同じ行と次の行の書式、一通の複数の利用と外貨・取消の除外、日付のない通知と長い数字の店名、記録しない通知。本文はすべて合成で、各社の項目名の表記だけを再現した。

**模擬の期待値だけ**。実在のメールでの読み取りは未確認で、合格扱いにしない。

## 残ること

- メールの取得・本文の平文化・同期の後の呼び出し（次の ADR）。
- 実在の通知メールで項目名の一覧を確かめ、足りない表記を足すこと。
- 送信元の一覧に他の会社（電子マネー・銀行のデビットなど）を足すこと。
