## 決めたこと

| 対象                       | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 保持者                     | `StorageModeGate`（`apps/core/src/storage-gate.ts`）。今の保存モード・区切りの ID・世代を RAM に持ち、domain の `applyStorageBoundaryEvent` の返す命令を順に実行する。入る・出る（`enterPrivate`／`exitPrivate`）は直列にする。読み取り（`mode`・`privateConversation()`・`origin()`・`originRejection()`）は同期                                                                                                                                                                                                                                                                                                                                                                    |
| 永続する欄                 | `clock-state.json` の `storage_boundary`。`{ segment_generation, private_open }` の 2 欄だけ（世代の番号と、その世代が記録しない区切りとして開いているか）。区切りの ID・発言・要約を持たない。厳格な検査（知らない欄・先頭 0・19 桁を超える数・真偽値以外を拒否）で読み、壊れた形は読み替えない                                                                                                                                                                                                                                                                                                                                                                                     |
| ファイルの共有             | 同じファイルを掃除の job（最終確認時刻・epoch）と保持者（世代）が書く。`createClockStateFile` が読んで書き換える処理を 1 つずつ行い、掃除側の保存は渡された内容の `storage_boundary` を**ファイルにある今の値で置き換える**（古い控えで世代を巻き戻さない）。世代の書き込みは版・最終確認時刻・採り直しの記録を変えない（採り直しの照合値を動かさない）                                                                                                                                                                                                                                                                                                                              |
| 世代を書く場所             | 世代を書けるのは、すでに存在して形が正しいファイルだけ。無い・壊れているファイルは作らない・直さない（初めての起動のファイルを作るのは掃除の job。既存の DB でファイルが消えている状態を黙って作り直さない）                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 入る                       | 世代を書けたときだけ入る（書いた後に RAM を進め、命令を実行する）。書けなければ入らない（`persist_unavailable`・`persist_failed`）。命令は domain の順（Live を閉じる → 一時のキャンバス → 区切りを開く）                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 出る                       | 世代を書けたときだけ出る。書けなければ記録しない区切りのまま（保存する側へ倒れない）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 起動                       | ファイルの世代を読み、新しい通常の区切り（新しい ID）を **次の世代**（前の世代 + 1）で開き、書き戻す。前の起動で `private_open` が真なら、記録しない会話が終わったことを `NoticeSink` に渡す。書き込み・知らせの失敗は起動を止めない（通常の区切りに戻っていて、保存側へ倒れる要素がない）。欄が無ければ世代 1 から（書かない）。壊れていれば 1 から数え直して欄を書き直す                                                                                                                                                                                                                                                                                                           |
| 古い由来の拒否             | `originRejection`（domain の `storageOriginRejection`）。記録しない由来は、再起動の後は区切りの ID も世代も違うので `origin_private`（永続化しない）。世代の永続は、再起動をまたいで世代が戻らないことと、再起動の前に記録しない区切りが開いていたことを知るためにある                                                                                                                                                                                                                                                                                                                                                                                                               |
| 知らせ                     | 契約の `StorageBoundaryNotice`（`private_ended`・`core_restarted`）。終わった記録しない区切りの世代・戻った先の区切りの ID と世代・時刻だけ。`RetentionNotice` は広げず別の型にした（期限切れ・忘却の知らせの `items` と意味が違う）。`NoticeSink.publish` は両方を受ける。**1 回だけ渡し、再送・永続しない**（運搬と再送は UI-05 の判断。U40）。配信の失敗は起動の失敗にしない                                                                                                                                                                                                                                                                                                      |
| Live のゲート              | `VoiceControl` の `privateConversation`（保持者の値）。Live の受付の判定（`admitLiveStart` に今の値を渡す。1 段目・予約の後・2 段目の 3 回で今の値を読み直す）・入出力の状態の `private_conversation`・Live の入力の条件（`not_private_conversation`）が実値になった。記録しない会話の間は Live の開始が 0 回。真偽値だけでは「入って出た」を見逃すので、受付の開始時に**区切りの世代**（`storageBoundary`）を控え、1 段目・予約の後・2 段目・登録の後の判定で変わっていたら 409（`conflict`）で開かない（AO レビュー 2 回目の P2）                                                                                                                                                  |
| Live を閉じる              | 入るとき `closeForPrivateConversation()` が、開いている・開きかけの Live をすべて閉じ始める（閉じる要求の記録とサイドバンドへの `session.close`。終了の確認は待たず、確認できなければ他の閉じ方と同じく `close_unconfirmed` で予約を保持）。Live の記録（DB）を待つ間に入った場合（登録済みの接続だけを閉じるので取り損ねる）は、記録の後・provider への作成の前に今の値を確かめ、**provider へ何も送らずに**終了を確認できない状態で閉じ（理由 `private_conversation`）、拒否する（409）。送出意図は記録済みで予約は解放できない（ADR 0037）ので、15 秒の最低額で精算せず保持する。作成の呼び出しの後に入った場合はすでに送っているので、応答の後に閉じる（作成の途中の接続の扱い） |
| 書き込み結果が不確かな失敗 | 置き換えのあとの fsync の失敗のように、失敗の応答でもファイルには新しい値が入っていることがある。**出る**の書き込みが不確かに失敗したら、RAM は記録しない区切りに留まるので、ファイルを「その世代で記録しない区切りが開いている」状態へ書き直す（再起動の後の終了の知らせを失わない。AO レビュー 4 回目の P2）。**入る**の不確かな失敗は、入っていない状態（通常の区切り）へ書き直す（起きていない終了を知らせない）。書き直しは 3 回まで試し、できなければ記録を残して次の入る・出る・停止（`close()`）のたびに試す。新しい書き込みが成功したら古い書き直しは捨てる。書き込めない（`unavailable`）ときは何も書かれていないので書き直さない                                          |
| 命令の実行の失敗           | 状態は戻さない（記録しない側に倒した状態は RAM で確定済みで、戻すと保存する側へ倒れる）。失敗した命令は記録だけして次の命令へ進む                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## この PR に含めないもの（07a-2 の残り）

- **誰も `enterPrivate` を呼んでいない**。入る・出るの API（`POST /v1/sessions` が `private` を受ける）と、`TurnRequest` に端末が見ていた区切りの ID・世代・保存モードを足す契約の変更は次の段階。この段階の Live のゲートは、保持者を直接動かす試験でだけ効く（製品の経路から記録しない会話には入れない）。
- 保存先の書き込みを許可表（22 行）の行に結び付ける、キャンバス（一時／永続）・RAM を捨てる命令・区切りを開く命令の接続（保持者は `effects.run` に命令を渡すだけで、Core がつないでいるのは Live を閉じる命令だけ）。
- 独立した確認（最小の操作記録）の Core 側、処理の由来を後段（記憶の受付・遅着の結果）へ渡す経路、影モードのポート。
- `api-operations.ts`・`api-server.ts` の入出力の状態の安全側の既定値（音声の制御がないとき `private_conversation: false`）は変えていない（その値は入力不可の既定で、記録しない会話の表示には使わない）。

## 試験（模擬だけ）

期待値は手で書いた（世代の数、知らせの欄は手書き）。ファイルは一時ディレクトリ、鍵は模擬、Live は模擬の provider。実機の Mac mini・実際の Live・実 API・実請求は**未実施**。

- `apps/core/src/storage-gate.test.ts`（25 件）: 起動 8 通り（欄なし・通常の続き 3 → 4・記録しない区切りが開いたまま 3 → 4 と知らせ・古い由来の拒否 5 種・壊れた欄・ファイルなし・書き込み失敗・知らせの失敗）、入る・出るで世代を先に書いてから命令を domain の順に実行すること、書けない・場所がないときは状態も命令も動かず出られないこと、規則の拒否（すでに記録しない区切り・記録しない区切りでない・知らない出先）、入り直しても前の記録しない区切りの由来が拒否されること、同時の入るは 1 回、命令の失敗で戻らないこと、閉じた後は拒否。置き換えのあとの fsync の失敗（ディスクの中身を持つ模擬。出る・入る・書き直しの失敗と再試行・停止での書き直し・成功した書き込みが優先されること）、実ファイルで再起動・版や最終確認時刻を動かさないこと・掃除側の古い控えで世代が巻き戻らないこと・同時の保存 24 回で欄が落ちないこと・無い／壊れたファイルを作らない／直さないこと・壊れた欄 15 通りは読み替えないこと。

## 引き継ぎ

- 07a-2 の次の段階: `POST /v1/sessions` の `private`・`TurnRequest` の由来の欄（契約）・入る・出るの経路。入る経路は `StorageModeGate.enterPrivate()`、失敗の理由（`persist_unavailable`・`persist_failed`）は 503 に写す。出る経路は `exitPrivate()`。

- UI-05（U40・U149）: 終了の知らせの運び方と再送・永続の判断。
- B15: 実機の Mac mini での Core の再起動をまたぐ記録しない区切りの終了の確認、ファイルの rename・fsync の耐久。
