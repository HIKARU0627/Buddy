# UI-06 配置のエンジンとユーザーの操作の記録（AI が優先・棚・読む順・複数のモニターの設定）

[ADR 0032](../adr/0032-ui-canvas-stream-and-window-roles.md) の配置のエンジンとユーザーの操作（Issue #98、親 #92）の記録です。**製品の試験の合格ではありません。** 既定のデスクトップは今の 1 つの窓（従来の窓）で、開発用のフラグ（`--buddy-ui=canvas`）のときだけキャンバスの窓を使います。規則は [ADR 0032 の「UI-06 の配置のエンジンとユーザーの操作」](../adr/0032-ui-canvas-stream-and-window-roles.md)に先に書き、その後で実装しました。

記録は 3 つに分けます。

- **模擬**: Electron を起動しない試験（`pnpm test`）。127.0.0.1 の Core と main の部品の統合を含む。
- **撮影用の起動での描画**: ビルドした画面を、本物と同じ CSP の index.html で、画面に出ないブラウザ（Playwright の headless shell。本人のブラウザとは別の一時のプロセス）に読み込み、撮影用の模擬の限定 API で決まった記述を渡して撮った。main・OS の窓・物理の入力は通っていない。
- **未実施**: 確かめていないこと。

## 撮影用の起動での描画（2026-10-23）

ビルドした画面（`apps/desktop/dist/renderer`）を一時のディレクトリへ写し、撮影用の模擬の限定 API（キャンバスの窓として決まった状態欄とキャンバスの記述を返す）を読む index.html にして、127.0.0.1 から画面に出ないブラウザで開いた（CSP は本物の index.html の meta のまま。違反は 0 件）。幅 1920・1440・1280・1024・800・480 × ライト・ダーク、前に出したとき（選んだ物・ドラッグ中・入りきらない物・1 列）を撮った。入力バーとつまみの窓の場所は、撮影用の目印（赤の点線。製品の画面にはない）で重ねた。スクリーンショットはスクラッチの場所（リポジトリには入れない）。

- 格子（幅 1024 以上）: 焦点（今日の予定）が左上に大きく、その右に詳細（会議の資料）とまとまり（今日の用事・買い物）、焦点の下に見比べる 2 つ（旅行の案 A・B）が横に並び、順序（次にやること）は今日の用事の真下、周辺（ニュース・天気）は下の端。下の中央と右の端は空いている。棚は入力バーの左。
- 1 列（幅 800・480）: 読む順に上から並び、入りきらない物は棚の場所に「…」の札で並ぶ（幅 480 で 2 枚、800 で 3 枚が見える）。札を押すと、その物が見える場所に出て、ほかの物が札に回る（PR #121 のレビューで足した。縦の巻き取りは使わない）。
- 高さ 200（最小の 272 に満たない）: 物は置かず、棚は上の端の小さな帯（札だけ）。
- 焦点（今日の予定）は左の端の accent の線と大きさ、選んだ物は外周の輪で、形で区別する（PR #121 のレビュー）。
- 前に出したとき: 枠と Esc のキーの形（UI-02）。選んだ物にだけ閉じる・片付ける・大きさを変えるの印が出る。ドラッグ中の物は影が付き、マスに合わせて動き、ほかの物は並び直す。
