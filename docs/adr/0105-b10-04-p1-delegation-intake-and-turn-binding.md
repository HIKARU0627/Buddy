# ADR 0105: B10-04 P1 委譲の受付と、発話・版・workflow の対応（同じ発話への再委譲を二重に処理しない）と、返答文 reply_text の表示の境界（U217）

- 日付: 2026-11-14
- 状態: B10-04（親 #18、Issue #246）P1 の判断。Live の委譲の受付に、先の委譲との対応（発話の版と依頼の紐付け）を足す。実行と定型文は P2、つなぎ・背景化・遅着は P3。実音声・実 API・実請求・実機は未実施（B05-08・B05-09・B15 と本人の承認まで扱わない）。
- 根拠: 設計 10 §5・§5A-1・§5A-2、設計 09 X51・QA05、ADR 0052（B05-05）・0066・0090〜0092。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。
- 対象: `packages/domain/src/voice-live-input.ts`（`TurnBinding`・`resolveDuplicateDelegation`）、`packages/domain/src/reply-text.ts`（`admitReplyText`）、`apps/core/src/live-conversation.ts`、`scripts/delegation-binding.test.mjs`、`scripts/reply-text.test.mjs`、`apps/core/src/live-conversation.test.ts`、`docs/b00/contract-map.md`（U217 の解決・U250）。契約（`packages/contracts`）・マイグレーションは変えていない。

## 背景（main の状態）

- 委譲の受付・入力の確定（ready／partial／blocked）・保留・結果の届け先は B05-05（PR #169）で main にある。委譲は `offset_ms` の手前 2 秒の窓に重なる発話を対象にし、先の委譲が対象にした発話（`claimed`）は次の委譲の候補から外す。
- 外した結果、**同じ発話への 2 回目の委譲**（別の `delegation_id`。設計 09 X51 の「同じ発話を複数回委譲する」）は候補が 0 になり、5 秒の待ちの後に文字のない入力として扱われ、声で「うまく聞き取れませんでした」と言っていた。先の依頼は正しく答えているのに、本人には誤った聞き返しが出る。設計 10 §5A-1 は「同じ発話への複数委譲は同じ turn に結び付け、workflow・版・操作の種類で二重処理を除く」とする。

## 決めたこと

| 対象             | 決定                                                                                                                                                                                                                                                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対応の記録       | 委譲が発話を対象にして解釈に入るとき、`{ ordinal, workflow_id, text }`（`TurnBinding`）を Live の記録に残す。`text` はそのとき読んだ発話の文字で、発話の版を表す。`claimed` と同じ連番を持ち、Live の記録と同じ寿命。保存はしない（RAM のみ。記録しない会話でも新しい永続の値は増えない）                                  |
| 重複の判定       | `resolveDuplicateDelegation`（domain の純粋な規則）。窓の中に、まだどの委譲も対象にしていない発話が 0、窓の中の発話がすべて先の委譲に紐付き、**今の文字が先に読んだ文字と同じ**ときだけ、最も新しい発話の依頼と同じものとして返す。offset が不明・窓に発話がない・紐付けがない・文字が違うときは重複ではない（従来の経路） |
| 重複のときの扱い | 新しい依頼にしない。解釈・保存・声・画面のどれも 1 回も出さず、先の依頼の結果が唯一の答えになる（`live_delegation_duplicate` を理由だけログへ）。先の依頼が破棄・失効していても、再委譲で復活させない                                                                                                                      |
| 追記された発話   | 先の委譲が読んだ後に同じ発話へ断片が追記された（「…いや 16 時」）ときは、同じ版ではないので重複と見なさない。従来どおり自動では進めず、言い直しを頼む（訂正が到着中の入力から変更を始めない。設計 10 §5A-2）。追記後の全文を新しい依頼として自動で解釈し直すかは決めない（U250）                                           |
| 版の番号         | `request_revision` は、今の経路では依頼の保存時に `'1'` で固定のまま。訂正の確定は、保存前の旧依頼を失効させて新しい依頼にする（旧結果は存在しない）既存の規則で、同じ workflow の版を上げる形にはしない。保存後の訂正は照合と取消一覧の経路（設計 10 §5A-6）で、変えない                                                  |

### 返答文 reply_text の表示の境界（contract-map U217。本人決定 2026-11-14: (b)）

ADR 0090 は `reply_text`・`clarify_question` を検査して保持するだけにしていた（暫定 (a)）。本人が (b) を決めた: **`reply_text` だけを、文字で返す入力の smalltalk・general_question に限って吹き出しに表示する**。応答文をモデルに作らせない原則（ADR 0005・0070）の例外は、実行に関わらないこの 2 つの意図の文字表示だけに閉じる。境界は `admitReplyText`（domain の純粋な規則）に置き、表示の前に毎回検査する（モデルの値は信用しない）。

| 条件                                                                                           | 決定                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 意図                                                                                           | smalltalk・general_question 以外は表示しない（`intent_not_allowed`）。24 意図すべてについて、他の 22 意図が表示されないことを試験する                                                                                                                                                                                                                                                       |
| 入力の種類                                                                                     | 出力先が文字になる入力（②文字・③音声→文字。`voice_local`）だけ。声で返す入力（①`voice_live`）にはモデルの文を使わない（`voice_output`）。出力先は入力の種類だけで決まり（D14）、音声の接続が開いていても変わらない                                                                                                                                                                          |
| 平文                                                                                           | 改行以外の制御文字（タブ・DEL・C1 を含む）と、方向を変える制御・ゼロ幅・行区切り・BOM を除く。改行は                                                                                                                                                                                                                                                                                        |
| にそろえ、3 つ以上の連続は 2 つにする。前後の空白を除く。除いた後に空なら表示しない（`empty`） |
| 長さ                                                                                           | 除去後 400 文字（コードポイント）まで。超えたら**切らずに**表示しない（`too_long`。切ると意味が変わる）。400 は初期値で、変えるときは版（`REPLY_TEXT_POLICY_VERSION`）を上げて記録する                                                                                                                                                                                                      |
| URL・リンク                                                                                    | URL（`scheme://`・`www.`）、`mailto:`・`javascript:`・`data:`・`file:`・`tel:` などの scheme、Markdown のリンク、HTML のリンク・スクリプトの形を含む文は表示しない（`link_in_text`）。見えない文字で分けた URL も、除去の後に検査して拒否する。リンクの形のまま画面へ出さないので、リンクが実行や遷移になる経路を作らない。通常の文（`profile:`・`tel` という語・不等号・括弧）は拒否しない |
| 実行との関係                                                                                   | 表示してよい文は「実行した」の根拠にならない。実行の結果・完了は、コードの定型文だけが告げる。表示の有無は実行権限・承認・`effect_kind` に影響しない                                                                                                                                                                                                                                        |
| 聞き返し                                                                                       | `clarify_question` はコードの決まった文のまま（この規則の対象外）。(c)（両方表示）は B10-07 の評価の後に再検討する                                                                                                                                                                                                                                                                          |
| 表示できないとき                                                                               | 呼び出し側はモデルの文を出さず、コードの決まった文（未対応・画面への案内）にする。判定の呼出しを増やさない                                                                                                                                                                                                                                                                                  |

この PR は**規則と試験まで**で、判定の結果（`reply_text`）を Core の解釈の返り値へ通し、文字の発言の応答（`turn.reply_text`）と吹き出しへつなぐのは P2（ADR 0106）。つなぐまで、今の経路は `reply_text` を表示しない。

受付の前後・送る直前の再確認は、新しい経路でも省かない。重複の検査は、受付の条件の照会（非同期）が戻った後の `#await`（同期の区間）で行い、閉じた Live・失効した依頼・保留の破棄は従来どおり先に確かめる。重複と判定した依頼は、保留にも保存にも入らない。

## 試験（模擬だけ）

- `scripts/delegation-binding.test.mjs`（手書きの期待値）: 同じ発話・同じ文字は先の依頼として返る。文字が追記・変更されたら重複でない。窓に新しい未対象の発話がある・offset が不明・窓に発話がない・紐付けがない・対象にされていない、のどれも重複でない。窓に複数の発話があるときは、すべて同じ版のときだけ重複で、最も新しい依頼を返す。
- `scripts/reply-text.test.mjs`（手書きの期待値。見えない文字は文字コードから作る）: 表示は文字で返す 2 つの入力×2 つの意図だけ。24 意図のうち対象外の意図は、どの入力でも表示されない。声で返す入力は両方の意図で表示されず、リンクや空の文でも「声には使わない」が先に出る。空・空白・制御文字だけは表示されない。制御文字・方向を変える文字・ゼロ幅を除き、改行をそろえる。ちょうど 400 文字は表示し、401 文字は切らずに表示しない（サロゲートペアは 1 文字、除去した文字は数えない）。URL・scheme・Markdown と HTML のリンク・見えない文字で分けた URL は表示しない。語が似ているだけの通常の文は表示する。
- `apps/core/src/live-conversation.test.ts`: 答えの後の同じ発話への再委譲は、解釈 1 回・声 1 回・workflow 1 件で、聞き返しが出ない。入力の確定を待つ間に同じ発話へ 2 つの委譲が来ても、依頼は 1 件・答えは 1 回。追記された発話への委譲は重複にならず、解釈し直さずに言い直しを頼む。前の 2 件は旧コードで失敗することを確認した。

**模擬のみ**。実音声・実 API・実請求・実機は未実施で、合格扱いにしない。`tests/test-map.json` の X51 は、B10 の証拠をまとめる B10-08 で更新する（この PR では対応表・証拠の記録を変えない。ADR 0085）。

- P3: 1.5 秒のつなぎ・8 秒の背景化・遅着（閉じた接続への追記 0）・訂正と別件。

- U250: **本人決定（2026-11-14）で解決**。追記された発話への再委譲は、自動で解釈し直さず、言い直しを頼む（暫定を確定。上の決定のとおり）。聞き取りの遅れの頻度を実機（B05-09）で見て困るときは、改めて本人が決める。
