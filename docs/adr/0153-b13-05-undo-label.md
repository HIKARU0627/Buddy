# ADR 0153: B13-05 自動実行の取り消しの経路（ラベルを戻す補償の操作）

- 日付: 2026-11-26
- 状態: B13-05（親 #24）の Core の API の部分。取り消し（`POST /v1/auto-actions/{id}/undo`）の処理を、メールのラベルの変更（`label_mail`）について作る。下書き・用事・予定の補償、画面は未着手。実データ・実機・実 API は未実施。
- 根拠: 設計 03「取り消しと安全停止」、設計 07 §2・§3、設計 08 §1・§2・§9、J12、設計 06 B13、ADR 0009・0030・0074・0147・0152。原本の参照手順は `docs/design/README.md`。
- 対象: `packages/storage/src/operation-commands.ts`・`operation-store.ts`（押下の承認）、`safety-store.ts`（自動実行の一件の読み取りと取り消せる種類）、`packages/domain/src/approval.ts`（説明だけ）、`apps/core/src/api-auto-actions.ts`・`api-server.ts`・`api-operations.ts`・`core.ts`、それぞれの試験。契約（`packages/contracts`）とマイグレーションは変えない。

## 背景

ADR 0152 で自動実行の一覧と安全停止の解除を作り、取り消しは経路が無いので一覧で `unavailable` と見せていた。保存層には補償の操作の開始（`startUndo`）と結果の写し（`recordUndoOutcome`）が B13-03 からある。設計 03・J12 は、取り消しを新しい operation_id の補償の操作とし、一覧での本人の押下を確認とし（確認画面を足さない）、対象がその後に変わっていれば自動では戻さず差分を見せるとする。

## 決めたこと

| 対象           | 決定                                                                                                                                                                                                                                                                                                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 取り消せる種類 | 今はラベルの変更（`label_mail`）だけ。補償は逆向きのラベルの変更（足したラベルを外し、外したラベルを戻す）で、契約にある操作の種類（`mail.labels.change`）で作れる。下書き・用事・予定は契約に削除の種類が無いので取り消せない（U310）。提供元の読み書きの口が Core に無ければ、どの種類も取り消せるように見せない                                                             |
| 一覧の見せ方   | 取り消せる種類を Core が保存層へ渡し、その種類で有効な記録が無く期限内の行を `available` にする。他は ADR 0152 のとおり                                                                                                                                                                                                                                                        |
| 押下の承認     | 補償の操作を作る命令に押下（承認の ID と端末）を付け、同じ transaction で画面の承認として記録し、`approved` から始める。preview_id には取り消しの ID を使う（一覧の行が preview に当たる）。登録が無い・失効した端末は `device_not_registered` で何も書かない（U311）                                                                                                          |
| 対象の照合     | 補償を作る前に、実行した確定 intent を開き、提供元から口座と対象のメールを読み直す。足したラベルが残り、外したラベルが戻っていなければ同じとみなす。違う・メールが無い・口座が違うときは 409 `target_changed` で、補償を作らない。送出の直前には実行担当が対象と許可の版をもう一度照合する（ADR 0030）。読み直しは保存期限の掃除のゲートを確かめ、貸し出しを持って行う（U312） |
| 応答           | 受付は 202 の `CommandReceipt`（補償の操作の ID）。期限切れは 410 `undo_expired`。取り消し済み・取り消し中・この種類の補償が無いは 409 `conflict`。自動実行でない操作は 422（ADR 0023 の読み取り）。提供元の口が無い・読めない・掃除のゲートが閉じている・成否不明は 503。照合の後に失効した端末は 401                                                                         |
| 版の照合       | 経路の検査の `expected_revision` は、自動実行した操作の今の状態版と本文の `expected_state_revision` を比べる。同じ接続範囲・request_id の受付が既にあれば再送の判定に任せる                                                                                                                                                                                                    |
| 同じ要求の再送 | 補償の操作の ID を接続範囲と request_id から決まる値にする（命令の ID とは別の値）。同じ要求の再送は保存済みの受付を返し、送り直さない。内容が違えば 409。成否不明の後の送り直しも同じ操作になる                                                                                                                                                                               |
| 実行           | 保存の後に実行担当へ渡す。結果の記録と同じ transaction で取り消しの記録が `undone`・`failed`・`unknown` になる（B13-03）                                                                                                                                                                                                                                                       |
| エラーのコード | 契約にある `target_changed` と `undo_expired` を Core の応答のコードに足す                                                                                                                                                                                                                                                                                                     |

## 原本に決めがない項目

- 下書き・用事・予定の補償の操作（U310）。
- 押下を承認として残す形（U311）。
- ラベルの「対象が変わった」の判定（U312）。
- 補償の操作が止まったときの取り消しの記録と、安全停止の間の取り消し（U313）。

## 対象外

- 下書き・用事・予定の補償、照合で拒否した操作の後始末。
- 自動実行の一覧・安全停止・取り消しの画面（B13-05 の残り）。

## 試験（模擬だけ）

- `packages/storage/src/safety-store.test.ts`: 期待値はすべて手書き。取り消せる種類を渡したときの一覧の状態、自動実行の一件の読み取り（自動実行でない操作は null、形式の拒否）、押下つきの補償の操作（承認の行の中身、取り消しの記録、承認の命令なしで準備から結果まで進むこと、失効・未登録の端末、期限切れ、形式の不正）。
- `apps/core/src/api-auto-actions-undo.test.ts`: 合成の提供元で、提供元が無いときの 503、画面の操作と版の照合、受付・実行担当による送出・取り消し済み・押した端末の承認、再送の同じ受付、内容の違う再送の 409、取り消し済みの 409、ラベルが変わっていたときの 409 `target_changed`、期限切れの 410、自動実行でない操作の 422。

**模擬の期待値だけ**。画面・実データ・実機・実 API は未実施で、合格扱いにしない。
