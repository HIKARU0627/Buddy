# UI-02 窓の基盤の試作の記録（キャンバス・状態の層・入力バー）

[ADR 0032](../adr/0032-ui-canvas-stream-and-window-roles.md) の 3 つの窓（キャンバス・状態の層・入力バー）を、開発用のフラグで作る試作（Issue #94、親 #92、PR #104）の記録です。**製品の試験の合格ではありません。** 既定のデスクトップは今の 1 つの窓（従来の窓）のままです。

記録は次の 3 つに分けます。

- **模擬**: Electron を起動しない試験（`pnpm test`）。
- **実機**: この Mac で開発用の手順で起動して確かめたこと。OS への入力は Orca のコンピューター操作（CGEvent の合成の入力・アクセシビリティ）で送り、届いたかは自分で起動した Electron のページに付けたイベントの記録（Chrome DevTools Protocol）で確かめた。**物理のキーボード・マウスでの操作ではない。** CDP で送ったキー（`Input.dispatchKeyEvent`）は OS を通らないので、その旨を書く。
- **未実施**: 確かめていないこと。理由を書く。

### 役割の区別の仕方（決めたこと）

- 役割の正本は **main の対応表**（窓を作ったときの webContents の ID → 役割）。受付は送信元の webContents の ID でこの表を引き、表にない・閉じた窓は役割が分からないので拒否する。
- 送信元のフレームは、対応表で引いた窓の**今の主フレーム**（親がなく、processId と routingId が同じ）のときだけ信頼する。子フレーム・古いフレーム・破棄されたフレーム（`senderFrame === null`）・破棄した窓は拒否する（`senderFactsOf`）。
- preload へは窓を作るときの引数 `--buddy-window-role=<役割>` で渡す。preload と画面はこれを画面の切り替えと多重の防御にだけ使う。画面・preload の申告で受付を広げない（画面が別の役割の URL へ移っても、main は送信元の窓の役割で判断する）。
- 3 つの窓と従来の窓は、同じ sandbox・contextIsolation・preload・CSP（特権スキームの応答の見出しと画面の meta）を使う。違いは役割の引数だけ（試験で確かめる）。
- 役割に合わない要求の拒否の理由は `untrusted_sender`（ADR 0032 の 0014 の改め: 拒否の理由は増やさない）。
- 開発用のフラグと環境変数は、開発の起動（`app.isPackaged` が false）のときだけ受ける。配布版はどちらがあっても従来の窓（PR #104 のレビュー P2）。

### キャンバスを呼ぶ・戻す（本人の判断 2026-10-22）

キャンバスは普段はデスクトップの層に置き、アプリの後ろで見るだけにする。呼ぶと前に出て、カードを動かす・閉じるなどの操作ができる。

| 項目    | 決めたこと                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 呼び方  | 全体のショートカット（既定 `CommandOrControl+Alt+Shift+B`。IME・入力ソースの切り替えの ⌃Space・⌃⌥Space・⌘Space・Win+Space・Shift+Space を避け、修飾キーを 3 つ使う）、端のつまみの下のボタン、入力バーの右端のボタン（どちらも同じ 4 つの四角の記号と押せる縁）                                                                                                                                                                                                                                                                         |
| 戻し方  | Esc（修飾キーなし。IME の変換中の Esc は変換の取り消しで、戻さない）、ほかのアプリ・ほかの窓へ移る（キャンバスが前面でなくなる）、ロック・ロック状態が不明になる、窓を隠す操作                                                                                                                                                                                                                                                                                                                                                          |
| 状態    | main の `CanvasPresence`（後ろ・前）と、呼ぶ・戻すの手順 `CanvasSummoner`。二重に呼んでも状態は変えず、キャンバスへフォーカスを戻す。ロック中・不明は呼ばない（`device_locked`）。キャンバスの窓がなければ呼ばない。呼ぶときは、隠れている状態の層・入力バーを前面を奪わずに表示し直してから、最後にキャンバスを前に出してフォーカスする（前に出す途中の blur では戻さない）。`desktop.canvas_summon` はロック解除済みで、前面の窓（つまみ・入力バー）からだけ受け付ける（`screen_operation_required`）。キャンバスと従来の窓は使えない |
| macOS   | 前に出す: `setFocusable(true)` → `setAlwaysOnTop(false)`（通常の窓の段） → `show`・`focus`。戻す: `setAlwaysOnTop(true, 'normal', −2147483624)`（デスクトップの段） → `setFocusable(false)` → `blur`                                                                                                                                                                                                                                                                                                                                    |
| Windows | キャンバスは `focusable: false` で作る（後ろにある間はクリックしても前面に来ず、キー入力を受けない）。前に出す: `setFocusable(true)` → `setSkipTaskbar(true)` → `show`・`focus`。戻す: `setFocusable(false)` → `setSkipTaskbar(true)` → `blur`。Electron 44 の `setFocusable(true)` は内部でタスクバーに出す設定も呼ぶので、その後にタスクバーに出さない設定を当て直す（PR #104 の再確認）。重なりは「次の窓を前面にする」（`blur`）までとし、その後は OS の重なりに任せる（ほかのアプリを使えばキャンバスはその後ろになる。未実施）    |
| 見た目  | 前に出ている間は、キャンバスの縁に accent の枠（4px）と、右上に Esc のキーの形（キーの中は「Esc」だけ。HeroUI の `Kbd`。⎋ の記号は書体によって回転の矢印に見えるので使わない）を出す（文字の説明ではなく、枠で操作できること・キーの形で戻し方を示す）。端のつまみは、持ち手（左の縦の線）・状態の記号と数・縁のあるキャンバスのボタンを縦に並べ、押せるのは縁のあるボタンだけにする（PR #104 の再確認 P3）。ロック中・不明は中身を描かない                                                                                             |

## 実機（macOS 27.0.1、内蔵の 1 画面 1280 × 832 pt、Electron 44.9.0、2026-10-22・23）

起動: `apps/desktop` で `pnpm run build` の後、`electron . --buddy-ui=canvas --use-mock-keychain --user-data-dir=<一時ディレクトリ> --remote-debugging-port=<空きのポート>`。中枢には接続していない（未登録）。ほかに動いているデスクトップアプリ・Core には触れていない。窓の段・位置・共有の状態は CoreGraphics の `CGWindowListCopyWindowInfo` で読んだ。守った窓は道具で操作できないので、操作の確かめの一部は「守る設定だけを外した確認用の一時のコピー」（コミットしない。終わったら消した）で行った。

## ADR への影響（ADR 0032 に追記した）

- 後ろにあるキャンバスは、Finder のデスクトップの窓・ウィジェットより下にあり、入力を受けない見込み（未確認）。本人の判断（2026-10-22）で、普段は後ろで見るだけにし、呼んだときだけ前に出して操作を受けることにした。macOS は段とキー入力の可否を切り替えて前に出し、戻すときはデスクトップの段に戻す（実機で段が行き来すること・Esc とほかのアプリへの移動で戻ることを確かめた）。
- 状態の層がキャンバスから覆えないこと、画面共有（ScreenCaptureKit）から守る設定が効くこと（前に出した後も）を確かめた。
