# ADR 0166: 分類ごとの予算（家計簿 段階 2 の一部）

- 日付: 2026-11-26
- 状態: 家計簿の段階 2 の部分。本人が支出の分類ごとに月の予算を決め、家計簿の欄で、出している月の分類ごとの支出と予算を並べる。請求予定（請求のメールを支払い済みと分けること）は後の ADR で足す。**模擬の試験だけ**で、実データ・実機は未実施。
- 根拠: 本人の決定（段階 2: 定期の支出を見つけて固定費と予算を出す）、ADR 0003・0017・0158・0161・0162・0165。
- 対象: マイグレーション 0019、`packages/storage`（`sealed-blob.ts` の用途、`household-content.ts` の予算の暗号文、`household-store.ts` の `household.budget_get`・`household.budget_set`）、`packages/domain/src/household-budget.ts`、`packages/contracts`（`HouseholdBudget`・`HouseholdBudgetItem`・`HouseholdBudgetChangeRequest`・`HouseholdBudgetRevision`・`POST /v1/household/budget`、`HouseholdOverview.budget`、IPC の `desktop.household_budget`、`DesktopHouseholdView.budget`）、`apps/core/src/api-household.ts`、`apps/desktop`（橋渡しと画面の「予算」）。

## 決めたこと

| 対象         | 決定                                                                                                                                                                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 置き場所     | 1 行だけの表 `household_budgets`（版と時刻だけが平文）。分類ごとの予算の金額は暗号文（`sealed_blobs` の用途 `household_budget`。持ち主は予算の行、版は予算の版）に入れる。用途を足すために `sealed_blobs` を 0011・0016 と同じ方法で作り直す |
| 中身         | 支出の分類（18 個）ごとの月の金額（1 円以上の整数）。予算のない分類は持たない。収入・振替・全体の予算は持たない（U338）。同じ分類は二つ持たない。分類の表示の順にそろえて保存する                                                            |
| 変更         | 一覧を丸ごと差し替える（空なら予算なし）。版（`expected_budget_revision`）は保存層が同じ transaction で照合し、新しい暗号文を入れてから行を進め、古い暗号文を消す。古い版は 409、支出でない分類・同じ分類は 422                              |
| 読み方       | 月ごとの合計（`GET /v1/household/months`）が `budget`（版・一覧・合計）を返す。読めない・開けない（別のデータ鍵）ときは月ごとの合計も 503 で、予算を推測で見せない                                                                           |
| 比べ方       | 画面が domain の `householdBudgetUse` で、出している月の分類ごとの支出と予算を並べ、残り（負なら超過）を出す。超えたときの知らせは出さない（欄で見せるだけ）                                                                                 |
| 画面         | 家計簿の欄の「予算」。予算の合計と、分類ごとの「支出 / 予算（残り・超過）」。「予算を決める」で支出の分類ごとの入力欄を出す（全角数字とコンマを受け、1 円以上の整数でなければ保存させない）。保存できたら入力欄をしまう                      |
| 端末の経路   | IPC の `desktop.household_budget`（ロック解除済みの画面操作）。予算の版は main が持ち、画面へは一覧と合計だけを渡す。拒否・結果不明は送り直さずに読み直す                                                                                    |
| バックアップ | `household_budgets` は本人の決定なので含める（暗号文のまま）                                                                                                                                                                                 |

## 原本に決めがない項目

- U338: 予算の決め方と比べ方。

## 対象外

- 請求予定（請求のメールの取り込み）、予算を超えたときの知らせ、全体の予算、年の予算。

## 試験（模擬だけ）

- `packages/storage/src/household-store.test.ts`: 行がないときの版 0、暗号文の差し替えと古い暗号文の削除、分類の順、古い版の拒否、別の版として開けないこと、収入の分類・0 円・同じ分類を暗号化しないこと、版を飛ばす更新の拒否。
- `packages/storage/src/migrations.test.ts` ほか: DB の版 19、STRICT の表 63。
- `apps/core/src/api-household.test.ts`: 予算の変更と月ごとの合計の `budget`、古い版の 409、支出でない分類・同じ分類の 422、空にすること、別のデータ鍵の 503、データ鍵がないときの 503。
- `apps/desktop`: 橋渡し（読んだ版で送る・409・結果不明）、画面の状態（入力の読み方・保存と入力欄の開け閉め・拒否で残すこと）、欄（予算と支出の並べ方・超過・入力欄）。`desktop-ipc-cases.json` に受付 3 件。

**模擬の期待値だけ**。実データ・実機は未実施で、合格扱いにしない。
