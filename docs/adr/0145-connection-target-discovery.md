# ADR 0145: 取得対象の発見・表示名・画面からの新規追加

- 日付: 2026-11-23
- 状態: ADR 0142 の残件「対象の発見（未選択のカレンダー・フォルダー／ラベルの一覧と表示名）」と「カテゴリの一覧の表示（B09-05 の設計 06 の項目）」の回収。connector の列挙・Core の経路・契約・デスクトップの経路と画面と模擬試験まで。接続の作成・OAuth・トークン保存は B03-04（ADR 0144、並行作業）で、本 ADR では扱わない。実アカウント・実 API・Electron の実機は未実施。

## 決めたこと

| 対象               | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画面からの新規追加 | 本人が画面で選んだ対象を取得対象へ足せるようにする。設計 04 の「本人が接続時に選んだ」は、選ぶのが本人であることと、見つけた対象を自動で足さないことの規則と読み、追加の時点を接続の瞬間に限る規則とは読まなかった（設計 01 の接続・端末の主な操作に「対象選択」がある。ADR 0142 は発見の経路が無いために追加を閉じていた）。自動では足さず、足すのは本人の取得対象の変更（既存の PUT …/targets、許可版の CAS、範囲は設計の初期値が上限）だけ。原本の文言への反映は本人の確認が要る（残件）                                                                                                                                                                    |
| 表示名を保存するか | 保存しない。Core は求められたときに提供元から読んで返すだけ（`ConnectionSummary` と保存層は変えない）。表示名は本人の個人の内容になりうるうえ、保存すると名前の変更・削除の追随と忘却の対象が増える。保存済みの対象の表示名は、画面が発見の結果と照らして出し、読めていない・見つからない対象は ID のまま出す（推測で名前を作らない）                                                                                                                                                                                                                                                                                                                          |

## 設計の根拠が無い・不足する部分（最小の選択をしたもの）

- **追加の時点**: 上の「画面からの新規追加」。設計 04 の文言と設計 01 の操作の読み方の判断で、原本の文言は変えていない。原本への反映（「接続時に」の扱い）は本人の確認待ち。
- **Gmail の system ラベルの絞り込み**: SPAM・TRASH・SENT なども選択肢に出る。取得対象として不適切なものを除く設計の根拠が無いので絞らなかった（選ぶのは本人で、取得範囲の上限・期間の規則は変わらない）。
- **Outlook の子フォルダー**: `listMailFolders` は最上位のフォルダーだけを読む（ADR 0134 の connector のまま）。子フォルダーの列挙（childFolders）は設計に記述が無いため足していない。
- **Google の `primary` の別名**: 取得対象に `primary`（Calendar API の別名）が保存されている接続では、発見の結果の実 ID（メールアドレスの形）と一致しないため、画面では `primary` が「見つかりません」になり、同じカレンダーを実 ID で重ねて選べてしまう。どちらの ID を保存するかは接続の作成（B03-04）の決めで、本 ADR では別名を解決しない（推測で同一視しない）。
- **カテゴリの権限**: 設計 04 は既存カテゴリの表示に MailboxSettings.Read の明示追加を求める。権限が無い接続はカテゴリが rejected（または unavailable）になる。権限の追加（再認可）は B03-04。

## 残ること

- 原本（設計 04 取得する対象）の「本人が接続時に選んだ」の扱いを本人に確認し、必要なら原本へ反映する（本 ADR は画面からの追加を本人の明示の選択として許した）。
- B03-04（ADR 0144）との統合: 接続の作成が `CoreSyncOptions.tokenSourceFor`・`graphTokenSourceFor` を用意すれば、この経路も同じ出所で動く。B03-04 がトークンの出所の口を作り替える場合は `core.ts` の `createConnectionDiscovery` の配線を合わせる。Google の `primary` 別名の扱いと、カテゴリ表示のための MailboxSettings.Read・カレンダー一覧のための calendar.calendarlist.readonly の権限の要求は接続の作成側の決め。
- 同期の状態（最終取得・走査の状態）の表示は ADR 0142 の残件のまま。
- 実アカウントでの確認（Google・Microsoft の実接続での一覧・表示名・追加の保存）は B15 と本人の承認。Electron の実機での見た目・操作も未実施。
