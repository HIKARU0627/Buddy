# ADR 0167: 家計の記録の手入力（家計簿 段階 3 の一部）

- 日付: 2026-11-26
- 状態: 家計簿の段階 3 の部分。メールにも書き出しにもない支出（現金など）や収入を、本人が家計簿の欄から手で足す。レシートの写真・会話の一言からの補いと、突き合わせによる二重の登録の防止は後の ADR で足す。**模擬の試験だけ**で、実データ・実機は未実施。
- 根拠: 本人の決定（段階 3: メールの届かない支出の補い）、ADR 0158・0161・0162。
- 対象: `packages/contracts`（`HouseholdManualEntry`・`HouseholdEntryCreateRequest`・`POST /v1/household/entries`、IPC の `desktop.household_add`）、`apps/core/src/api-household.ts`、`apps/desktop`（橋渡しと画面の「記録を手で足す」）。

## 決めたこと

| 対象       | 決定                                                                                                                                                                                                                                                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 中身       | 向き・金額・日付・時刻（なくてもよい）・分類・店名・メモ・支払い手段。中枢は家計の記録の検査（向きと分類・長さ・制御文字・12 桁以上の数字の並び）をし直し、合わなければ 422                                                                                                                                                                                  |
| 出所       | 出所の種類は `manual`、出所の鍵は要求の `request_id` から作る（ADR 0158）。同じ要求の再送は二つ目を作らず、記録済みの記録を返す。ただし再送の中身が保存済みの中身と違えば 409（保存時に本人の規則で分類が当たった未分類の記録は、分類の違いを違いに数えない。保存後に直されて内容版が 1 より大きければ分類も比べる）。消した記録の要求の再送は作り直さず 409 |
| 店名の規則 | 店名があり分類が未分類でなければ、本人の規則として覚える（分類の変更と同じ）。未分類なら既にある規則を当てる                                                                                                                                                                                                                                                 |
| 重なり     | 利用通知・書き出しの記録とは突き合わせない（U339）。カードの利用を手でも入れれば二つになる                                                                                                                                                                                                                                                                   |
| 画面       | 家計簿の欄の「記録を手で足す」で欄を出す。向きを変えると分類の選択肢をその向きの分類にそろえる。金額（全角数字とコンマを受ける）・日付・時刻の形が違えば送らせない。足せたら、その記録の月を出す                                                                                                                                                             |
| 端末の経路 | IPC の `desktop.household_add`（ロック解除済みの画面操作）。拒否・結果不明は送り直さずに読み直す                                                                                                                                                                                                                                                             |

## 原本に決めがない項目

- U339: 手入力の記録の重なりと規則。

## 対象外

- レシートの写真・会話の一言からの補い、突き合わせ、記録の金額・日付・店名の変更。

## 試験（模擬だけ）

- `apps/core/src/api-household.test.ts`: 足した記録を返すこと、同じ要求の再送で増えないこと、規則を覚えて次の未分類に当てること、向きの違う分類と口座番号らしい店名の 422、消した後の再送の 409、データ鍵がないときの 503。
- `apps/desktop`: 橋渡し（入れたままの本文・足した記録の月を読むこと・422 と結果不明）、画面の状態（入力の読み方・送り方と欄の開け閉め・拒否で残すこと）、欄の表示。`desktop-ipc-cases.json` に受付 3 件。

**模擬の期待値だけ**。実データ・実機は未実施で、合格扱いにしない。

## 残ること

- レシートの写真・会話の一言からの補いと、突き合わせによる二重の登録の防止（段階 3 の残り）。
- U339 の本人の確認。
