## 決めたこと

| 対象                     | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 根拠の失効の遷移         | 設計 11 §4 の resolved の理由のうち、元情報が取得範囲から外れた・重複が解消したを遷移にした: `source_out_of_scope`・`overlap_resolved`。`new`・`seen`・`acted`・`snoozed` から `resolved` へ。`dismissed`・`resolved` は終端のままで受けない。ADR 0073 の遷移は変えない                                                                                                                                                                                                                                                    |
| 時間による遷移           | `candidateDueEvent(候補, now, zone)` が時計だけで起こす遷移を 1 つ返す。期限が過ぎたら `deadline_passed`、`snoozed` で再通知の時刻になったら `snooze_elapsed`。同時に起これば `deadline_passed` が先（過ぎた期限の候補を new に戻さない）。期限が無い・一意でない・暦にない候補は期限で動かない。`now`・`zone` が不正なら `ok: false`                                                                                                                                                                                      |
| 期限が過ぎたか           | 時刻付きの期限は、確定した UTC の時点（夏時間の終わりで 2 回ある現地時刻は後の回。U285）を**過ぎたとき**（ちょうどは過ぎていない）。現地の文字列では比べないので、時計が戻る時間帯でも「過ぎた」が戻らない。日付だけの期限は、その日が終わる（現地の翌日 0 時になる）とき。P1 の見出しと同じ判定を共有する                                                                                                                                                                                                                 |
| 初回取り込みの過去の期限 | 作った時刻にすでに過ぎていた期限の候補は、期限切れで自動に解決せず、本人が操作するまで折りたたみに残す（U274）。作った時にまだ過ぎていなかった期限は通常どおり解決する。作った時刻が読めない初回取り込みは解決せず残す側へ倒す                                                                                                                                                                                                                                                                                             |
| スヌーズ                 | 再通知の時刻は「いまより後の UTC 時刻」だけ受ける（`checkSnoozeUntil`。上限は原本にないので置かない）。時刻が欠けた・読めない `snoozed` は、隠れたままにせず `snooze_elapsed` で `new` に戻す（U276）。スヌーズでない候補の時刻は見ない                                                                                                                                                                                                                                                                                    |
| 根拠の取り直しの結果     | `evidenceDecision(状態, 観測)`。`available`: 変えない・有効。`revised`（新しい版）: 状態は変えず「作り直し要」にして資格を失効する。`temporarily_unavailable`: 状態は変えず「未確認」にして資格を失効する（保留。解決しない）。`out_of_scope`・`removed`: 活動中は `source_out_of_scope` で解決、終端はそのまま。いずれも根拠は「消えた」。U275                                                                                                                                                                            |
| 忘却                     | 状態の遷移にしない。`forgotten` は `purge: true`（題・抄録・識別子を忘却の計画で物理削除する。既存の `notification_candidate` の削除順）。解決して識別子だけ残す扱いにはしない                                                                                                                                                                                                                                                                                                                                             |
| 保持の段階               | `candidateRetentionPhase(状態, 状態を変えた時刻, now)`: 活動中は `active`、解決・却下から 7 日未満は `content_kept`、7 日以上 97 日未満は `identifier_only`（題・抄録を消し、`notification_key` と状態だけ残す）、97 日以上は `delete`。境界は掃除の規則と同じく「期限 ≦ いま」で期限切れ。注入された時計（`now`）が読めないときは段階を返さず拒否する（`now_invalid`。全行に共通で、倒すと全候補の内容が消えるため）。状態を変えた時刻（1 行の `changedAt`）が読めないときだけ、その行は内容を消す側（`identifier_only`） |
| 資格の引き継ぎ           | 根拠が `valid` のときだけ自動実行などの資格を引き継げる（設計 11 §5B 4・5）。`refresh_required`・`unconfirmed`・`gone` では引き継がない。資格の判定そのものは B13-02 と B11-04 が持つ                                                                                                                                                                                                                                                                                                                                      |

## 原本に決めがない項目

- 初回取り込みの過去の期限の寿命、新しい版・取り直せないときの状態、欠けたスヌーズの時刻は原本にない。U274〜U276 に記録し、暫定の置き方を試験で固定した。本人が決めたら変える。
- 取り直せない状態の長期の扱い（一定時間後に解決するか）は決めない。期限切れ・取得範囲外・本人の操作で終わるまで保留。

## 試験（模擬だけ）

- `node --test scripts/candidate-lifecycle.test.mjs`: 基準を 2030-10-09（水）12:00 JST に固定し、期待値は手で数えた。新しい 2 遷移が活動中の 4 状態だけで通ること、日付だけの期限が現地の 0 時（14:59:59Z と 15:00:00Z）で変わること、時刻付きの期限のちょうどと 1 秒後、期限が無い・暦にないものは動かないこと、終端の状態は動かないこと、初回取り込みの過去の期限と作った時刻が読めない場合、スヌーズの境界（ちょうど・1 秒前後・欠け）と期限が先に過ぎる場合、不正な時計とタイムゾーン、観測ごとの判断、保持の段階（7 日・97 日の 1 秒前後）を確かめた。境界の判定を変えると失敗することを、実装を一時的に壊して確かめた。
- `node --test scripts/candidate.test.mjs`: 遷移の列挙を新しい 2 つで更新した。既存の手書きの遷移・保持は変えていない。

**模擬の期待値だけ**。保存・一覧の画面・OS 通知・実データ・実機は未実施で、合格扱いにしない。
