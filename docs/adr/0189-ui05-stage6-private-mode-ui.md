# ADR 0189: UI-05 の段階 6 記録しないモードの UI と保存モードの切り替え

- 日付: 2026-11-27
- 状態: UI-05（#97、親 #92）の段階 6（ADR 0068 の段階の表）の判断と実装。切り替えの経路は ADR 0060（B06-07a-2 の 2b）の `POST /v1/stream/storage-mode`（U170 の (A)。**本人が 2026-11-03 に決定**）。Core は最小の変更だけ（切り替えの経路の検査を画面操作にした・流れの今の保存モードの読み取りを足した）。契約（JSON Schema・OpenAPI・生成型・fixture）、`packages/domain`（経路の検査・窓の役割の表）、`apps/desktop` の main（`storage-mode-bridge.ts`（新規）・`core-link.ts`・`operation-bridge.ts`・`status-bar.ts`・`device-controller.ts`・`electron/main.ts`）・preload・画面（`StorageMode.tsx`（新規）・`storage-mode-state.ts`（新規）・従来の窓の島と会話の欄・キャンバス表示の島とパネル）と、模擬の試験だけ。マイグレーションは足していない。記録しない区切りの間の発言・キャンバスの一時の記述（B06-07a-2 の 2c）は作っていない。実機の Mac mini・Windows・macOS の端末、実データ・実 API・実請求は未実施。
- 根拠: ADR 0045（記録しない会話の保存境界）、ADR 0059・0060（保存境界の保持者・発言の由来・流れの `POST /v1/stream/storage-mode`・入口の整理）、ADR 0068（段階 6 の範囲・U170）、ADR 0032（流れ・キャンバス・窓の役割、記録しない会話の区切り・要約をつながない）、ADR 0014（いつも見える状態・いつでも停止）、ADR 0024（色と記号・記号＋文言・1 画面の primary は 1 つ・コントラスト）、ADR 0181（上の中央の島・角の丸みの 4 段・共通の枠・島の役割とチャネル U391）、ADR 0187（知らせの運搬）、ADR 0188（表示のリース。同じ組み立ての作り方）。非公開の原本（設計 01・03・10）はこの環境になく、参照していない。決めのない点は、本人の「試験と見直しは後でまとめて行う」に従って聞かずに暫定で決め、`docs/b00/contract-map.md` の U475〜U479 に記録した。
- 番号: ADR は 0189、未決事項は U475〜U479。

### 拒否の文言

| 理由              | 文言（`desktop.storage_mode_change`）                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `core_rejected`   | 保存モードを切り替えられませんでした。中枢が受け付けなかったため、保存モードは変わっていません。少し待ってから、もう一度押してください。               |
| `outcome_unknown` | 保存モードが切り替わったか確かめられませんでした。自動では送り直しません。上の島と「保存モード」の表示を確かめてから、必要ならもう一度押してください。 |

## 契約

- `DesktopIpcChannel` に `desktop.storage_mode_change` を足した。`DesktopIpcRequest` に payload `{storage_mode: StorageMode}`（余分な欄は拒否）、`DesktopIpcResponse` に `{request_id, channel, outcome: "ok", storage_mode}` の分岐を足した。説明文に入口と受付の規則を足した。
- `StreamStorageModeView`（`{storage_mode}`）を足し、契約の根の `anyOf` に入れた（生成型に出す）。OpenAPI に `GET /v1/stream/storage-mode`（`getStreamStorageMode`）を足し、`POST` の `x-buddy-core-checks` に `screen_operation` と `InputOrigin` を足した。
- fixture: `api-cases.json`（`getStreamStorageMode` の応答と拒否 5 件、`postStreamStorageMode` の `voice_origin` の 403）、`desktop-ipc-cases.json`（受付 6 件: 画面操作・前面でない・ロック中・ロック不明・信頼しない送信元・停止中）、`schema-cases.json`（正しい形 3 件・拒否の形 6 件）。
- `StorageModeChangeRequest`・`StorageModeChangeResponse`・`StreamTurnResponse`・`DesktopStatusBar`・`StorageBoundaryNotice` の形は変えていない。

## 撮影（2026-11-27、Electron なし）

撮影の道具（スクラッチパッドの写し。製品のコードではない）に、記録しない間（`private`）と、通常から記録しないへ移った直後（`private-boundary`）の場面と、切り替えのチャネルの模擬を足し、Playwright の chromium で従来の窓（960 × 680・全体）・キャンバス表示の島（560 × 48 と広げた 560 × 104）・状態のパネル（440 × 900）・窓を重ねた見本（1440 × 900）を、ライト・ダークで撮って目で確かめた。島の札は記号と文字で読め、パネルの切り替えの欄は 8 項目の下に出る。従来の窓では、記録しない間の島の小さい形が 2 行に折り返す（U479）。ページの例外・CSP の違反はなかった。OS の窓の重なり・透明な窓の実際の描き方・Windows の見え方・実際の読み上げソフトは再現していない。

## 範囲の外と残り

- 記録しない区切りの間の発言の保持（RAM）・キャンバスの一時の記述・遅れて届いた結果の照合（B06-07a-2 の 2c）。2c の後に、記録しない間の発言とキャンバスの変更が通る。
- 段階 5（表示先の移動）・段階 2-ii（区切りの指示）。
- 別の端末の切り替えをすぐ届ける知らせ（U477）、音声の「記録しないで」の扱い（U475）。
- 実機（Mac mini の Core・Windows と macOS の端末）での確認、実際の読み上げソフトでの確認。
