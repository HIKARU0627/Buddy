## 決めたこと

| 対象           | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| つなぎ         | 委譲を受けた時点（依頼を登録した時点）から 1.5 秒（1500 ms。ちょうどで言い、手前では言わない）で結果がなければ、「確認しますね。」を**依頼ごとに 1 回だけ**声で追記する。入力の確定待ち（終了候補・300 ms の安定）の間も、結果を待つ時間に数える 。期限は、依頼を受けた時刻（`accepted_at`）からの**絶対の経過時間**で毎回判定する。タイマーが遅れて動いても、背景化の期限（8 秒）は遅れた分だけずれない。つなぎのタイマーが 8 秒を過ぎて初めて動いたときは、遅いつなぎは言わず、背景化だけを言う                                                                           |
| 背景化         | 8 秒（8000 ms）で結果がなければ、「少し時間がかかるので、できたら知らせます。」を 1 回だけ声で追記し、裏のジョブへ移す。移した後の結果の届け先は画面になり（`routeResultDelivery` の `backgrounded`）、声には載せない。声で言ってから移す（移した後は声で言えない）。つなぎが言えなかった（声で返せない）依頼でも、8 秒の判定は独立に行う                                                                                                                                                                                                                                   |
| 声で言える条件 | 言う直前に、結果の届け先を今の状態で決め直し、**声のときだけ**追記する（声で依頼され、接続が開いており、文字へ切り替えていない・読み上げを止めていない・世代と端末が有効）。閉じた接続・失効した依頼（訂正・取消・破棄）・終わった依頼には言わない（閉じた接続への追記 0） 。さらに、**入力の受付の条件（同意・Live が使える・予算など）の確認が通るまでは言わない**（確認に 1.5 秒以上かかり、後で拒否される委譲に「確認しますね」を言わない。見直しは 100 ms ごとに続け、確認が通った時点で受付時刻からの経過を判定し直す。Codex の P2 指摘）                             |
| 保留中の変更   | 新しい発話の確定を待つ保留中の変更は、結果を待つ処理ではないので、保留の間はつなぎも背景化もしない。ただし見直しは止めず（100 ms ごと）、**保留が解けた時点で受付時刻からの経過を判定し直す**: 再開した依頼が 1.5 秒を過ぎていればつなぎを 1 回、8 秒を過ぎていれば背景化だけを言う（保留の間に言えなかった分を、保留が解けた後に取り戻す。Codex の P2 指摘）。保留が解けずに破棄・失効した依頼、訂正で置き換わった旧い依頼は、タイマーを止めて何も言わない                                                                                                                 |
| 遅着           | 閉じた接続・背景化・読み上げの停止の後に返った結果は、従来どおり画面へ回し（失効した旧版だけ捨てる）、1 つの依頼として保存する。背景化した結果の理由は `backgrounded` で、画面の表示の配置者から区別できる。**完了の気づき（B11）と次回の文脈要約（B10-06）への反映は、それぞれの工程が `ScreenResult.reason === 'backgrounded'` の結果を使って行う**（この PR では気づき・要約を作らない） 。結果を届ける直前にも、受付から 8 秒を過ぎていれば背景化として扱う（保留が解けた直後に結果が戻り、次の見直しより先に配信される場合も、声に載せず画面へ回す。Codex の P2 指摘） |
| 訂正・別件     | 変えない（ADR 0052。新しい委譲だけを理由に古い処理を中止しない。訂正・取消が一意に確定したときだけ旧い依頼を失効させ、別件は別の依頼として進める）。つなぎ・背景化はこの規則と干渉しない（失効した依頼・保留中の依頼には言わない）                                                                                                                                                                                                                                                                                                                                          |
| 時計           | 時間は注入された時計（`timers`・`monoNow`）で数え、実時間を待たない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## 試験（模擬だけ）

- `apps/core/src/live-conversation.test.ts`:
  - X33: 結果が出ない依頼で、1499 ms までは何も言わず、1500 ms で「確認しますね。」を 1 回、7999 ms までは重ねず、8000 ms で背景化の発話を 1 回。結果が戻ると声ではなく画面へ（理由 `backgrounded`）回り、1 つの依頼として保存される。その後 10 秒たってもつなぎ・背景化を重ねない。
  - X33: 1.5 秒より前に結果が出る依頼には、つなぎも背景化も、その後も出ない。
  - X33/X29: つなぎの後に接続を閉じると、8 秒を過ぎても背景化の発話を追記せず（閉じた接続への追記 0）、遅れて戻った結果は画面へ回る。
  - X33/X27: 新しい発話で保留された変更には、9 秒たってもつなぎも背景化も出ない。訂正で置き換わった旧い依頼は何も言わず、訂正後の依頼の答えだけが出る。
  - X33/P3: つなぎのタイマーが 2 秒遅れて動いても（受付の 3500 ms）、背景化は受付の 8000 ms ちょうど（7999 ms では言わない）。つなぎのタイマーが 8 秒を過ぎて初めて動いたときは、背景化だけを 1 回言い、結果は画面へ。保留のまま 1.5 秒をまたいだ変更が別件の確定で再開すると、再開後につなぎを言い、受付から 8 秒で背景化する（背景化はちょうど 1 回、画面は `backgrounded`）。この 3 件は、固定の遅れで通知を数える旧い実装で失敗することを確認した。
  - X33/X46/P3: 受付条件の確認が 2 秒かかり、結果が同意なしの拒否のとき、1.5 秒を過ぎても何も言わず、解釈も保存もしない。確認が 2 秒後に通ると、通った後の最初の見直しでつなぎを 1 回言い、その後の答えを声で返す。X33/X27/P3: 受付から 9 秒まで保留した依頼が別件の確定で再開し、次の見直しより先に結果が戻っても（時計を進めずに解除）、結果は画面へ回り声に載らない。この 3 件は旧い実装で失敗することを確認した。
  - 既存の X51 の 3 件は、1.5 秒の待ちの間につなぎが 1 回入る期待値へ手で直した（仕様の変更による）。
- B05 の統合試験（`tests/integration/b05-cases-input.mjs`）の X51 のケースは、観測する値を変えず、答えを待つ条件を「声の追記の数」から「操作ができたこと」へ変えた（1.5 秒で入るつなぎが追記の数を変えるため）。手書きの期待値（`b05-expectations.json`）と B05 の模擬の証拠（`evidence-b05-simulated.json`）は**作り直さない**（ADR 0085: PR では証拠を作り直さず、記録は main の更新か工程の完了判定の PR で行う）。つなぎそのものは Core の試験で確かめる。
- 他の既存の試験は変更なしで通る。

## 残ること

- U253: 前面の委譲待ち中の無音終了 0 回（X29）は、端末の main が無音を判定する（ADR 0041）ため、中枢から端末へ委譲の状態（前面・裏・なし）を伝える経路が要る。今は `observeSilence` の規則だけがあり、端末の判定に接続されていない（端末の判定そのものが B05-08 の実機の作業）。経路の追加は契約の変更（音声の制御イベント）で、順番の指示が要る。
- U254: 調査（research）・思考レベル high の相談を最初から裏へ回し「受け付けました。終わったら知らせます。」と返す（設計 10 §5「裏のジョブ」）には、裏のジョブを受け付ける実行器（B12）と、実行中の状態の保存（`workflows.state` の `executing` は表にあるが、保存の型・遷移の経路は未実装）が要る。受付の文（ADR 0107 の `acceptedCommentary`）は用意済みで、**受け付けていない依頼には使わない**。今は従来どおり「未対応」の聞き返しのまま。
