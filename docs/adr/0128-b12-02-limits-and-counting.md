# ADR 0128: B12-02 公開 Web 調査の上限と数え方（3 検索・5 ページ・2MB・15 秒・3 リダイレクト）

- 日付: 2026-11-14
- 状態: B12-02（親 #27、Issue #264）の P2。契約と規則だけ。検索アダプター（B12-03）・取得（B12-04）・workflow（B12-05）は未着手。**実 API は呼んでいない**。
- 根拠: 設計 05「公開Web調査」（初期上限は 1 依頼 3 検索、参照本文 5 ページ、本文取得は 1 ページ 2MB・15 秒まで、リダイレクト 3 回まで。これは調査品質の保証ではなく、処理と費用の上限です。予算不足では範囲を減らすか保留します）、設計 05「費用の計算」、`docs/b12/search-service-comparison.md` §5、ADR 0077・0125。
- 対象: `packages/contracts/schemas/buddy.schema.json` の `WebSearchAttempt`・`WebSearchDenial`・`WebPageAttempt`・`WebResearchAttempts`、`packages/domain/src/web-research-limits.ts`、`packages/contracts/fixtures/web-research-attempts-cases.json`、`scripts/web-research-limits.test.mjs`。

## 決めたこと

| 対象               | 決定                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 上限（初期値）     | 検索 3 回・取得するページ 5 件・1 ページ 2MB・15 秒・リダイレクト 3 回（ADR 0077 の `WebResearchLimits` と同じ値）。設定の外へ出さない。品質の保証ではない                                                                                                                                                                                                                           |
| 数えるもの         | **試行**で数える。検索は「送った検索」（失敗も 1 回）、ページは「取得を試みた件」（読めない・会員限定・拒否・失敗も 1 ページ）。**送らなかった検索（上限・予算・検索語の拒否で断った）は数えない**（U295）。費用の予約（B07）は試行の数に合わせて B12-03 が行う                                                                                                                      |
| 受付の判定         | 3 回送った後の検索は拒否する（`webSearchAdmissionLimitErrors` → `search_limit`）。5 ページ試みた後の取得は拒否する（`webPageAdmissionLimitErrors` → `page_limit`）。検索で見つかった件数より多くは取得しない（`no_more_hits`）。断ったときは、その理由を記録に残す（`search_denials`・`page_limit_denials`）                                                                         |
| 範囲を減らす       | 上限や予算で断ったり、検索の一部が失敗したりしても、読めたページが 1 件以上あり要約が作れれば、**範囲を減らしたと明示して完了**にする（`scope_reduced`。ADR 0125）。読めたページが無ければ完了にしない（ADR 0129）。断ったことを隠さない                                                                                                                                             |
| 1 ページの上限     | 2MB・15 秒・3 リダイレクトは `WebPageAttempt` の schema の最大値にし、`too_large`（ちょうど 2MB で打ち切った）・`timeout`（ちょうど 15 秒）・`redirect_limit`（ちょうど 3 回）の記録は上限値と一致しなければ拒否する。上限を超えた取得を成功として残さない                                                                                                                           |
| 残さないもの       | 試行の記録（`WebResearchAttempts`）は、検索結果・URL・タイトル・スニペット・本文・検索語を持たず、件数と種類・ID・上限の数字だけを持つ（`additionalProperties: false`）。ADR 0077・0126 の「検索結果を永続保存しない」と衝突しない                                                                                                                                                   |
| 再開した調査の残り | 保留（`held`）から検索をやり直すときも、**同じ依頼の試行を引き継いで数える**（3 検索・5 ページの残りを使う）。再開で上限が戻らない。残りが 0 なら、検索の呼出しを拒否し、読めたページが無ければ失敗（`no_readable_page`）として終える。新しい依頼（新しい `request_revision`）は別の上限を持つ。記録は同じ依頼の `WebResearchAttempts` に追記する形で、引き継ぎの実装と試験は B12-05 |

## B07 の検索の枠との対応

- 検索は B07 の検索の枠（月 300 円）に計上する。170 円／米ドル・安全係数 1.2 では 1 検索 1.02 円で、1 依頼 3 検索なら最大 3.06 円。月 300 円で約 294 検索（約 98 依頼）。比較表 §4 のとおりで、実請求は未検証。
- 失敗した検索も請求されうるので、費用の予約は送る前に取り、失敗しても解放しない。精算の詳細は B12-03（B07 の予約・最大負担の区別に従う）。
- 取得（B12-04）は検索サービスの費用が無い。時間と接続先への負荷の上限として数える。

## 原本に決めがない項目

- 設計 05 は上限の数を決めるが、**何を 1 と数えるか**（試行か成功か）は書かれていない。成功だけを数えると、読めないページが続く限り取得が終わらないので、試行で数えた（U295、暫定）。代案は「読めたページだけを 5 と数える」で、時間の上限（15 秒 × ページ数）が別に要る。
- 保留からの再開で上限を戻すかは書かれていない。戻すと保留を繰り返して費用の上限を越えられるので、引き継ぐ側にした（U292 と同じく暫定）。
- 初期値（3・5・2MB・15 秒・3）は設計の初期値で、実測（日本語の調査品質・遅延・失敗率）はまだ無い。B15 と本人の承認の後に見直す。

## 試験（模擬だけ）

- `scripts/web-research-limits.test.mjs`: 検索 0〜3 回・ページ 0〜5 件と見つかった件数の境界、失敗・拒否・読めなかった試行が数に入ること、断った検索が数に入らないこと、記録に検索結果・URL・本文の欄が無いこと、上限ちょうどの打ち切りの記録を手で書いた fixture と照合した。
- 規則を壊す（読めないページを 0 件の扱いにする）と試験が落ちることを手元で確かめた。
- 実 API・実請求・実測は未実施。

## 残ること

- 検索の呼出し・費用の予約・上限を超える要求の拒否の実装は B12-03。取得の実装は B12-04。
- 失敗の区別と最終状態の決め方は ADR 0129。
