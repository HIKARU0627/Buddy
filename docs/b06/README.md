# B06 の完了判定

B06（#11）の保存期限・忘却・記録しない会話・復旧について、B06-09（#145）の模擬の統合試験と証拠を記録します。**親 Issue の完了条件 3 項目には、それぞれ模擬の観測が対応しました。ただし、未実装の経路（自動の抽出からの記憶の保存、発言からの忘却など）と、実機の Mac mini での実際のバックアップと鍵の復元（B15）が残るため、B06 を完了とはしません。** B06 全体を閉じるかは本人の判断です（下の「未実装・未実施」）。

根拠は設計 03（保存期限・忘却と再取り込み・バックアップ・復元・記録しない会話）、08 §4〜§6、09 の X15〜X17・X44・X59・QA34・T06、ADR 0008・0010・0016〜0019・0032・0036・0038 と B06 の ADR（下の表）、本人の判断（2026-10-24、#11 のコメント J1〜J6）と司令塔の判断（同日、#11 の 2 つ目のコメント）。この作業では原本（非公開の Notion）を新しく読んでおらず、既存の ADR と契約の fixture に取り込み済みの規則だけを使いました。既存の判断は変更していません。

## 目印の探し方

目印は試験の回ごとに作る合成の ASCII の文字列（`B06-SYNTH-<名前>-<seed>-<回>-<乱数>`）で、実データ・個人の値・内部の URL を含みません。製品と同じ形の封筒（AES-256-GCM、合成のデータ鍵）に封じて保存し、次の 2 つを探します（`tests/integration/b06-support.mjs` の `findResidue`）。

- **平文の目印**: DB・WAL・台帳の別ファイル・時計の状態ファイル・データディレクトリの全ファイル・バックアップの封筒・本人が残した写し・復号したバックアップの中身・ログ（Core と掃除の job と忘却の経路に渡した `log` を集めたもの）・知らせ・応答。どのケースでも 0 件でした。記録しない会話のケースは、応答は本人の画面への返事なので、記録しない会話の目印だけを応答から探します。
- **暗号文の目印**: 封筒の暗号文のバイト列そのもの。消した行の暗号文が DB と WAL（復元・バックアップでは復号した中身）に残っていないこと、消していない行の暗号文は見つかることを確かめます（陽性の対照）。記憶の一覧・保存した発言の本文を開いて、見える目印も確かめます。

Mac mini の SSD の削除の痕跡・OS のスワップ・同期フォルダーの写しは探していません（B15）。

## 実行器と証拠

- `pnpm run build` の後、`node --test tests/integration/b06.test.mjs` で全ケースを実行します（`pnpm test`・`pnpm run check` にも含みます。手元の Linux で約 21 秒）。

- 今回の証拠は手元の Linux（Node.js 24）で生成しました。通常の CI では macOS の shard 1 が生成して artifact `simulated-evidence-b06-<sha>` に残し、手動の `Simulated evidence (macOS)` でも作り直せます。`simulated` は記録した commit での観測を意味し、現在のソースでの再現・実機・実 API・実請求の合格を意味しません。
- 試験の感度: 次の欠陥を一時的に入れて（ビルド後の `dist` を書き換え、終わったら戻した。コミットしていない）、該当のケースが落ちることを確かめました。
