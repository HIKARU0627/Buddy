- 状態: B11-02（親 #23、Issue #204）の P1。`packages/domain` の純粋な規則だけ。保存（B11-03）・生成と一覧の経路（B11-04）・画面（B11-05）は未着手。実データ・実機は未実施。
- 根拠: 設計 11 §4（表示順・見出し・気づきの行に出すもの）、設計 04 気づきの作成、ADR 0073（B11-01）。原本の参照手順は `docs/design/README.md`。
- 対象: `packages/domain/src/candidate-order.ts`、`candidate-text.ts`、`scripts/candidate-order.test.mjs`、`docs/b00/contract-map.md`（U270〜U273）。

## 決めたこと

| 対象               | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入口               | `orderCandidates(items, { now, zone })`。時計とタイムゾーンは呼び出し側が渡す。`now` が UTC の時刻（末尾 Z）として読めない（タイムゾーンの無い時刻・暦にない日付を含む）・`zone` が IANA の名前として使えないときは `ok: false`（端末の既定のタイムゾーンへ黙って置き換えない）。入力は変えない                                                                                                                                                                                                                                                                                           |
| 見出し             | `today`（今日）・`tomorrow`（明日）・`this_week`（今週）・`later`（それ以降）・`unknown`（期限不明）・`initial_import_past`（初回取り込み（過去の期限））。この順に並べ、空の見出しは出さない。折りたたむのは `initial_import_past` だけ                                                                                                                                                                                                                                                                                                                                                  |
| 見出しの基準       | 「今日」は本人のタイムゾーンの現地の日付で決める（UTC の日付ではない）。時刻付きの期限は、確定した時点（UTC）を本人の `zone` の現地の日付に直して比べる（期限の `zone` の暦ではない。U287）。日付だけの期限は本人の暦の日付そのもの。今週は月曜始まりで、明日より後〜その週の日曜（U272）。日曜は今週が空になり、明日は翌週の月曜になる                                                                                                                                                                                                                                                   |
| 期限不明           | 期限が `unresolved`・`none` のものと、暦にない日付・不正な形のものは `unknown` へ入れる。隠さず、推測した日付で並べない                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 初回取り込みの過去 | `initial_import` が真で、時刻付きの期限は現地の「いま」より前、日付だけの期限は今日より前のもの。いまちょうどの時刻は過ぎていない。折りたたみの中は、いまに近い（新しい）期限から並べる（U273）                                                                                                                                                                                                                                                                                                                                                                                           |
| 期限切れの活動中   | 初回取り込みでなく期限が過ぎた活動中の候補は「今日」に置く（U271）。期限は `deadline_passed` で resolved になるまでの短い間だけ残る。見出し「期限切れ」は原本にないので足さない                                                                                                                                                                                                                                                                                                                                                                                                           |
| 並べ方             | 見出しの中で (1) 今日・明日の見出しの予定の重複を先頭、(2) 期限の近い順（期限不明は最後）、(3) 受信の新しい順、最後に `candidate_id` の昇順で決める。今週以降の予定の重複に先頭の扱いは無い。期限は UTC の時間軸で比べる（別のタイムゾーンの期限も同じ軸）。夏時間の終わりで 2 回ある現地時刻は**後の回**、存在しない時刻（隙間）は直後の時刻として扱い（U285）、過ぎたかも同じ時点との比較にするので、時計が進めば「過ぎた」が戻らない。日付だけの期限は、本人のタイムゾーンでその日が終わる時刻として、同じ日の時刻付きの期限の後に並べる（並べるためだけで、時刻には変換しない。U273） |
| 予定の重複の期限   | 予定の重複の候補は `deadline` に重複の始まり（`instant`）を入れて渡す。重複の判定そのものは B11-02 P3、候補を作るのは B11-04                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 一覧に出す状態     | `orderCandidates` は渡された候補だけを並べ、状態では絞らない。`snoozed` を既定の一覧に出すかは U270（未決。提案は出さない）で、B11-04 が決める                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 未返信の断定       | `candidateTitleErrors` は題が空・60 文字（コードポイント）超・未返信や未対応の断定（「未返信」「返信がありません」「まだ返信していない」「返信忘れ」など）のときに拒む。「参加可否の返信：10/7まで」のような依頼の題は通す。`candidateRowNotes` はメールの候補（期限・返信）に常に「対応済みかは未確認」を付け、一部未読なら続ける                                                                                                                                                                                                                                                        |

## 原本に決めがない項目

- 期限切れの見出し・週の始まり・日付だけの期限の並べ方・過去の期限の向き・`snoozed` の一覧は原本にない。U270〜U273 に記録し、暫定の置き方を試験で固定した。本人が決めたら変える。
- 日本語の断定の言い回しの網羅は、原本に表がない。ここで拒むのは代表的な言い回しだけで、題を作る側（B11-04）は材料（種類・期限・差出人の表示名）から定型で作り、モデルの文をそのまま題にしない。

## 試験（模擬だけ）

- `node --test scripts/candidate-order.test.mjs`: 基準を 2030-10-09（水）12:00 JST に固定し、期待値は手で数えた。見出しの境界（今日・明日・今週の日曜・翌週の月曜・それ以降）、現地の日付の変わり目（UTC では前日になる JST の 00:30、日曜に今週が空になる）、別のタイムゾーンの期限（現地の文字列でなく UTC の時間軸で並ぶこと、見出しは本人の暦で決まること）、夏時間で存在しない時刻、期限・受信・識別子の並び、予定の重複の先頭、初回取り込みの過去の折りたたみ（1 分前とちょうどの境界）、期限切れの活動中、不正な期限と時計・タイムゾーンの拒否、題の断定の拒否と注記を確かめた。

**模擬の期待値だけ**。保存・一覧の画面・OS 通知・実データ・実機は未実施で、合格扱いにしない。
