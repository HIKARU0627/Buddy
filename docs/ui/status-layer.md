# UI-04 状態と停止の層の記録（端のつまみ・スライドのパネル・停止のショートカット・確認の一覧）

[ADR 0032](../adr/0032-ui-canvas-stream-and-window-roles.md) の状態の層（Issue #96、親 #92）の記録です。**製品の試験の合格ではありません。** 既定のデスクトップは今の 1 つの窓（従来の窓。WorkPanel もそのまま）で、開発用のフラグ（`--buddy-ui=canvas`）のときだけ状態の層のパネルを使います。

記録は 3 つに分けます。

- **模擬**: Electron を起動しない試験（`pnpm test`）。127.0.0.1 の Core と main の部品の統合を含む。
- **実機相当の確認**: この Mac で自分で起動した Electron を CDP で操作した確認と、撮影用の起動での描画（OS の窓の撮影・物理の入力ではない）。
- **未実施**: 確かめていないこと。

### 確認の親（OS の確認ダイアログ）

- **決めたこと**: 3 つの窓の組み立てでは、パネルが出ている間だけ、状態の層の窓（パネル）を親にする。macOS はパネルに付くシート、Windows はパネルが持ち主のモーダルになる。パネルが出ていない（つまみだけ）なら確認を出さず、送らない（確認の入口はパネルだけ）。このときは「やめる」ではないので `screen_operation_required` を返す。手順は `runPanelConfirm`（status-panel.ts）にまとめ、main はダイアログを渡すだけにした（試験で守る）。
- **理由**: (1) 従来の窓と同じ「親付きの確認」の経路になり、ロック・停止・窓を隠す操作で確認を閉じる仕組み（AbortSignal、ADR 0026・0031）を同じ形で通せる。親のない確認はアプリのモーダル（macOS では親付きのシートと別の出し方）になり、閉じる仕組みが同じに働くかは確かめていない。(2) 確認が、押したパネル（内容を見せた場所）に付き、どの操作の確認かが位置で分かる。(3) UI-02 で親を付けなかった理由（つまみが小さくシートを付けられない）は、パネルの幅 440 で解ける。
- **パネルとの関係**: 確認を出している間は、確認（シート・モーダル）へフォーカスが移った blur でパネルをしまわない（ダイアログが例外を投げても終える）。確認の間にほかのアプリへ移っていたら、確認が終わった後（結果を返した後、150 ミリ秒の後）に窓が前面でなければパネルをしまう。パネルのショートカット・窓を隠す操作でパネルをしまうときは、先に確認を閉じて送らない（パネルなしで確認を残さない）。確認の後にパネルがしまわれていたら、承認として扱わない。
- **未実施**: シートがパネルの幅（440）より広いときの見え方・画面の右の端での位置、Windows のモーダルの位置（下の「未実施」）。

## 実機相当の確認（macOS 27.0.1、内蔵の 1 画面 1280 × 832 pt、Electron 44.9.0、2026-10-23）

- **パネルの出し入れ（実機の main）**: `apps/desktop` で `electron . --buddy-ui=canvas --use-mock-keychain --user-data-dir=<一時> --remote-debugging-port=<空きのポート>` で起動し（未登録・中枢なし）、状態の層のページへ CDP でつないだ。つまみのボタンを押す（ページの中のクリック）と、窓が 56 × 232・(1224, 315) から 440 × 803・(840, 29)（作業領域の右の端の上から下まで）になり、パネル（`aria-label="状態のパネル"`）が描かれた。CDP の Esc で 56 × 232 に戻った。つまみで出す → つまみでしまう、も同じ。全体のショートカット 3 つの登録の失敗のログは出なかった。OS の入力・物理の入力は使っていない。
- **描画**: 撮影用の起動（ビルド済みの画面を本物と同じ特権スキーム・CSP で、画面に出さない窓に読み込み、模擬の preload で決まった状態を返す。main は通らない）で、ライト・ダーク × つまみ・パネル・確認の欄・停止中・ロック中・専用の記号の状態にある、を撮った。CSP の違反は 0 件。スクリーンショットはスクラッチの場所（リポジトリには入れない）。

## 追記（B05-06、2026-10-25）: 音声の段と「音声を外部へ送っている」の印

[ADR 0050](../adr/0050-b05-desktop-voice-renderer-isolation-and-stop.md)。`--buddy-ui=canvas --buddy-voice=mock` のとき、パネルの入出力の段の下に音声の段を出す。1 段目は左から、マイクの記号・音声の状態（記号＋短い文言）・「音声を外部へ送っている」の印（つまみの専用の記号と同じ形）・「続ける」。2 段目は、印の列の右端にそろえて「同意を取り消す」（同意しているときだけ）。会話中は段の面を警告の色で塗る。ロック中・不明は位置だけを灰色の面で残す。知らせ（入力の中断・始められなかった）と拒否の文言は段のすぐ下に出し、理由のコード・送り先の名前は出さない。

- **「続ける」**: 押せるのは呼びかけ待ちで外部へ送っていないときだけ。初めてのときは main が、パネルを親にした OS の確認ダイアログを 1 回だけ出す（「やめる」が既定）。
- **印**: 開始の命令から、閉じる・停止の ACK を受けるか音声レンダラーを強制終了するまで on（停止した直後も ACK まで消さない）。会話中・読み上げ中・聞き取り中（文字で返す）を外部に数える（聞き取り中は③と KWS で確かめるまで送っている側）。8 項目の音声も同じ判定で、停止中は ■。押せない「続ける」は枠だけ、停止中は入出力の段の「再開」を主のボタンにし、取り消しの 2 段目の高さはいつも取っておく（PR #160 の見た目のレビュー）。
- **模擬**: `VoiceStrip.dom.test.tsx`、main の `voice-*.test.ts`。
- **スクリーンショット**: このマシンの Electron で、模擬のレンダラーと端末の中の模擬の中枢を使って撮った（ライト・ダーク。呼びかけ待ち・会話中・つまみ・停止中・同意の取り消し・再開・ロック。コミットしない）。OS の確認ダイアログは差し替えた模擬。
- **未実施**: 実際の音声・マイク・OS の確認ダイアログのクリック・Windows・読み上げソフト・Codex による見た目のレビュー。
