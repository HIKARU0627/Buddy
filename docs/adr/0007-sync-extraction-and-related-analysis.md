## 同期（F04）

`packages/domain/src/sync.ts` が持ちます。

- 同じ取得集合で有効な走査は 1 件だけです。走査中の要求はまとめて待たせ（pending）、全量照合の要求も失いません。全量照合は増分の要求も満たします。
- ページの保存・検証・公開の前に、有効な走査 ID・取得範囲の版・実行担当の世代（`ExecutorGeneration`）が一致するかを見ます。
- 公開は、開始時の公開世代・watermark・provider cursor との compare-and-swap です。一致しなければ拒否し、その走査だけを abandoned にします。active_scan_id の解放は自分の走査のときだけです。
- 差分ゼロでも照合を省かず、公開世代は進めず、watermark と完了時刻だけを更新します（QA36）。
- watermark は走査の開始時刻で、後退させません。開始時刻が保存済みの watermark より前なら開始を保留します（時計の後退）。
- token の失効・範囲の変更・TTL 超過では旧走査を abandoned にし、新しい走査で最初から取り直します。旧走査・旧担当の遅着ページや公開要求は保存も公開もしません。
- 差分のある公開の後は、その世代の解析計画が完了するまで候補起点の実行を始めません。

## 抽出と自動実行の判定

`packages/domain/src/extraction.ts` が持ちます。

- 根拠（`FieldEvidence`）は summary・kind・target・deadline・change の項目ごとに explicit / derived / missing / conflicting / unread を持ちます。explicit は位置の照合済みの引用、derived は規則 ID が必要です。位置は Unicode コードポイント単位で、end は含みません。
- 期限（`Deadline`）は instant / date / unresolved / none です。日付だけの期限は時刻を補わず、過去かどうかも受信日と日付どうしで比べます。
- 4 種類の自動操作に共通の検査: confidence が low でない、期限が未確定でない、根拠がすべて照合済み、引用内でない、未読・切り詰めがない、期限が受信時刻より前でない。
- 操作ごとの検査（11 §5、§5A D15）: 用事は依頼であること・本人宛て・自動配信でない・期限が日時か日付。予定はさらに日時・confidence high・本人所有のカレンダー。ラベルは割り当て済み。下書きは返信依頼・本人宛て・自動配信でない・下書きがない・予算がある。
- モデルの自己申告の confidence は観測値として残し、正答確率や承認権限に変換しません。宛先・自動配信の判定はヘッダーからコードが決めます。

## 関連解析と依頼の同一性（F05）

`packages/domain/src/analysis.ts` が持ちます。

- 関連集合は、同じ provider・アカウント・thread の公開メール群と、それに結び付く既存の依頼です。列挙が完了し（plan_complete）、必要なソースがすべて解析済みまたは規則 ID 付きで除外され、未解決の変更がなく、判定が現在の公開世代に対するものであるときだけ ready です。未読・失敗・予算待ちは完了に数えません。
- 取消・完了は `RequestChange` で表し、対象の依頼は根拠と一意性で Core が解決します。確定した取消・完了は、解析結果の到着順や配列順によらず同じ依頼の状態に反映します。曖昧な取消は状態を変えず、未解決の変更として ready を止めます。
- 自動作成は同じ依頼・操作種別・アカウント（予定はカレンダーも）につき一度だけです。取消・完了した依頼と、本人の取消で再作成を抑止した依頼からは作りません。
- 最終 transaction では、判定に使った関連解析の版（group_id・analysis_revision・source_set_hash・published_generation）が現在の版と同じで、かつ ready であることを確認します。

抽出した依頼・依頼 ID・気づきの候補の `request_revision` は、本人の依頼の版とは別の型 `RequestEntityRevision` です（ADR 0003 の U04）。
