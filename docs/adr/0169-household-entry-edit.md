# ADR 0169: 家計の記録の中身の変更（家計簿 段階 3 の一部）

- 日付: 2026-11-26
- 状態: 家計簿の段階 3 の部分。記録の金額・日付・時刻・店名・メモ・支払い手段・分類を、本人が家計簿の欄から直せるようにする。向きは変えられない（向きを変えたいときは削除して足し直す）。**模擬の試験だけ**で、実データ・実機は未実施。
- 根拠: 本人の決定（段階 3: 記録の金額・日付・店名の変更）、ADR 0158・0161・0162・0167。
- 対象: `packages/contracts`（`HouseholdEntryContentChangeRequest`・`POST /v1/household/entries/{entry_id}/content`、IPC の `desktop.household_edit`）、`apps/core/src/household-ledger.ts`・`api-household.ts`、`apps/desktop`（橋渡しと画面の「中身を直す」）。保存層は変えない（ADR 0158 の `household.update` をそのまま使う。マイグレーションはない）。

## 決めたこと

| 対象         | 決定                                                                                                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 直せる中身   | 金額・日付・時刻（なくてもよい）・店名・メモ・支払い手段・分類。形は手入力（ADR 0167）の `HouseholdManualEntry` と同じ                                                                                                               |
| 向き         | 変えられない。送られた向きが今の記録と違えば 422（今の中身を開いて確かめる）。向きを変えたいときは削除して足し直す（U341）                                                                                                           |
| 検査         | 中枢は家計の記録の検査（向きと分類・長さ・制御文字・12 桁以上の数字の並び・日付と時刻の形）をし直し、合わなければ 422。画面の入力の検査は送らせないためのもので、正本ではない                                                        |
| 内容版の照合 | 本文の `expected_content_revision` を保存層が同じ transaction で照合する。違えば 409、削除済みも 409。新しい中身は今の内容版の次の版で暗号化し、記録を所有者として差し替える。日付を直したら、記録の月も新しい日付の月に更新する     |
| 出所         | 出所の種類・出所の鍵・作成の日時は変えない。直しても、同じメール・同じ書き出しの行から作り直さない                                                                                                                                   |
| 店名の規則   | 支出の記録で、店名があり分類が未分類でなければ、本人の規則として覚える（分類の変更・手入力と同じ。U341）。収入・振替の記録からは覚えない（ADR 0175 で更新）。覚えられなくても中身の変更は済んでいる。未分類に直した場合は覚えない    |
| 失敗の写し方 | 内容版の違い・削除済みは 409、向きの違い・検査に合わない中身・ない記録・内容版の形の違いは 422、データ鍵が読めない・今の中身を開けない・保存の失敗・成否不明は 503（成功にも競合にも見せない）                                       |
| 経路の検査   | 分類の変更・削除と同じ（端末トークン・自宅判定・接続範囲・ロック解除・画面操作）。チャット・音声・システムの経路からは受けない                                                                                                       |
| 応答         | 直した後の `HouseholdEntry`（内容版は進んでいる）                                                                                                                                                                                    |
| 端末の経路   | IPC の `desktop.household_edit`（ロック解除済みの画面操作。payload は `{ref, entry}`）。main は読んだ内容版で照合して送り、受け付けたらその記録の月（日付を直したときは直した後の月）を読み直す                                      |
| 端末の失敗   | 409 は `preview_stale`、422 は `core_rejected`。どちらも送り直さず読み直す。結果不明（届いたか分からない・5xx・形の違う 2xx・送った後の世代の変化）は送り直さず `outcome_unknown` にし、その行を次の読み取りまで操作させない         |
| 画面         | 行に「中身を直す」を置く。押すと手入力と同じ入力欄を、今の値を入れて行の中に出す（向きは固定で、変えられないことを書く）。送れたら欄をしまい、拒否なら残して直させる。結果不明になった行・消えた行の欄はしまう。知らせは欄の頭に出す |

## 原本に決めがない項目

- U341: 記録の中身の変更で向きを変えられないことと、規則の覚え方。

## 対象外

- 向きの変更、複数の記録をまとめて直すこと、直した履歴の保存、レシートの写真・会話の一言からの補い。

## 試験（模擬だけ）

- `apps/core/src/api-household.test.ts`: 直した記録を返すこと、日付を直すと記録が別の月へ移ること、内容版が進み古い内容版の再送が 409 になること、店名の規則を覚えて次の未分類に当てること、未分類へ直したときは覚えないこと、向きの違い・検査に合わない中身・内容版の形の違い・ない記録の 422、削除済みの 409、データ鍵がない・別のデータ鍵・成否不明・保存の失敗の 503。
- `apps/desktop`: 橋渡し（読んだ内容版と入れたままの本文を送ること・直した月を読むこと・409 と 422・結果不明・世代をまたぐ変更・知らない参照）、受付（`household-link.test.ts`、`desktop-ipc-cases.json` に 3 件）、画面の状態（欄を開ける条件・一度だけ送ること・成功でしまうこと・拒否で残すこと・結果不明でしまうこと・世代の破棄）、欄の表示（今の値・向きの固定・送り中・結果不明の行）。
- 契約: `schema-cases.json`（正常 1・内容版なし・余分な項目）、`api-cases.json`（経路ごとの要求・応答・拒否・不正な本文）、経路と画面操作の数（`api-routes.test.ts`）、IPC のチャネルの数（`scripts/canvas.test.mjs`）。

**模擬の期待値だけ**。実データ・実機は未実施で、合格扱いにしない。
