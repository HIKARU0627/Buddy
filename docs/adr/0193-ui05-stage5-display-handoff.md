# ADR 0193: UI-05 の段階 5 流れの表示先の移動（「このPCに出す」）

- 日付: 2026-11-27
- 状態: UI-05（#97、親 #92）の段階 5（ADR 0068 の段階の表）の判断と実装。本人の決定（2026-11-01、U167 の (a)）に従い、流れ用の `POST /v1/stream/handoff` を作った。本文と応答は既存の `HandoffRequest` / `HandoffState` を再利用し、端末に会話・区切りの ID を見せない（UI-01）。Core（`apps/core/src/voice-control.ts`・`api-voice.ts`・`api-routes.ts`）、契約（OpenAPI・JSON Schema・生成型・fixture）、端末の main（`display-route-bridge.ts`・`core-link.ts`・`display-lease-keeper.ts`）、画面（状態の層のパネルの欄）と試験。**マイグレーションは足していない**（表示先は中枢の RAM だけ。U169 と同じ）。実機の複数の端末・実データ・実 API・実請求は未実施。
- 根拠: ADR 0188（表示のリース。「失う」の扱い・U473・U474）、ADR 0046（音声の所有の調停。リースの取消と交代の作り）、ADR 0032（キャンバス・表示の権限）、ADR 0068（段階の分け）、ADR 0187（知らせの配信）、ADR 0189・0190（記録しない間の扱い）。設計 07 §2・§5（呼び出した端末へ表示を移す。旧端末の退避か期限切れを確認するまで moving）。非公開の原本はこの環境になく、参照していない。決めのない点は、安全側の暫定を選び `docs/b00/contract-map.md` の U520〜U534 に記録した。
- 番号: ADR は 0193、未決事項は U520〜U534。

## 端末（main）

- `DisplayRouteBridge`（新規）: 中枢の流れの表示先を読み（接続・ロック解除・表示のリースの取れた・失った・移動の結果が分からなかった・拒否されたとき）、状態欄の `display_target` に載せる。読めなかったら前の値のまま（他の端末とみなさない）。表示先が未決定のときは、表示のリースを持っている間だけ「この端末」、持っていなければ null（U534）。移すときは直前に版を読み、画面操作として 1 回だけ送る。結果が分からなければ送り直さず読み直す。ロック・切断で値を捨て、世代をまたいだ結果と、後から始めた結果より古い読み取りの結果を反映しない。
- `DesktopCoreLink.handleDisplayHandoffIpc`: `desktop.display_handoff` を、信頼する送信元・前面・ロック解除済み・登録済みで中枢に接続中のときだけ受け付け、キャンバス表示（表示のリースを取る組み立て）でなければ `invalid_request`（従来の窓が表示のリースなしで他の端末の表示だけを消さない）。入出力の停止中は受け付けて中枢に判断させる。受け付けられたら表示のリースをすぐ取り直す。
- 通知: 状態欄の `display_target`（契約に既にある値）だけ。新しい通知は足していない。

## 契約

- OpenAPI に `getStreamHandoff`・`postStreamHandoff`。経路の検査は `postStreamHandoff` が画面操作（`expected_revision` の検査は付けず、経路の処理が版を照合する）、`getStreamHandoff` が読み取り＋ロック解除。
- `LeaseRenewalRejectReason` に `display_owned_elsewhere` を足した（契約の追加。端末は「失う」の扱いで処理する）。
- `DesktopIpcChannel`・`DesktopIpcRequest`・`DesktopIpcResponse` に `desktop.display_handoff`（要求の payload は null、成功の応答は `handoff_state`）。端末の ID・版・会話の ID は画面へ渡さない。役割の表は状態の層だけ（キャンバス・入力バー・島は使えない。従来の窓は全チャネルだが main が断る）。
- fixture: `api-cases.json`（`getStreamHandoff`・`postStreamHandoff` の正しい形・拒否・不正な本文）、`schema-cases.json`（9 件）、`desktop-ipc-cases.json`（受付 6 件）。生成型は生成した。

## 画面

- 状態の層のパネルに、保存モードの欄の上へ「表示先」の欄を足した（`DisplayHandoffControl`）。見出し「表示先」と、今の表示先の記号と文言（この端末は ●、他の端末は ○、未受信は記号なし）、ボタン「このPCに出す」。表示先がこの端末のときはボタンを出さず、入出力を止めている間は押せずに 1 文で理由を出す（U527）。ロック中・不明・中枢に接続していないときは何も描かない。押しても表示は変えず、状態欄の通知で変わる。拒否の文言は欄のすぐ下に出す。renderer は限定 API（preload 経由）だけを使い、端末の ID・版・会話の ID を持たない。
- 配色・形は既存の部品（`StatusText`・`InlineNotice`・`Button`）だけで、新しい色の組は作っていない。
