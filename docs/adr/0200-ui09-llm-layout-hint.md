# ADR 0200: UI-09 モデルが出す配置のヒントと、不正なヒントからコードの配置へ戻すこと

- 日付: 2026-11-28
- 状態: UI-09（Issue #101、親 #92）のうち、配置のヒントの契約・意味の検査・Core の当て方・プロンプトインジェクションの評価セット（模擬）・見た目の回帰の試験（配置のエンジンの出力と happy-dom の DOM）を作った。マイグレーションなし。**模擬の試験だけ**で、実 LLM・実 API・実請求・本物のブラウザ・Windows の実機・Codex の見た目のレビューは未実施。Issue の完了条件（評価セットの結果の記録・見た目の回帰がすべて通る・Codex の見た目のレビューに通る）のうち、最後の 1 つと Windows の実機の確認が残る。
- 根拠: ADR 0070（`ResponsePlan`。残ることに「UI-09 は ResponsePlan に配置のヒントを足す。この ADR はヒントの形を決めない」）、ADR 0032（AI が出すのは宣言的なキャンバスの記述だけ・UI-06 の配置のエンジンとユーザーの操作・AI が優先・記録しない間のキャンバス）、ADR 0066（文字の結果・保留を捨てた知らせの物）、ADR 0187（期限切れ・忘却でキャンバスの物を閉じる）、ADR 0190（記録しない区切りの一時の記述）、`docs/b00/contract-map.md` の ResponsePlan・キャンバスの記述・配置のエンジンの行。非公開の原本（設計 01・03・07・10）はこの作業環境に無く（`.local/design/notion/` が無い）、参照していない。原本の不足は推測で埋めず、決めていない点は暫定として U660〜U676 に記録した。
- 番号: ADR は 0200、未決事項は U660〜U670 と、見直しで足した U671〜U676。
- 追記（2026-11-28、見直し）: 見直しの指摘（重大 1・中 3・軽微 5）に対応した。守る物（コードが焦点にした物・文字の結果・保留を捨てた知らせ）を、周辺へ回す・読む順で後ろへ下げる・まとまりに入れる・入りきらなくする・小さくするのどれからも守る形に改めた。ヒントをその発言だけの上乗せにし、次の発言でコードの強調・まとまりへ戻す。まとまりの名前を g1〜g4 に付け直す。計画へ入れるのは形の検査を通ったヒントだけにする。下の表は改めた後の決定。
- 対象: `packages/contracts/schemas/buddy.schema.json`（`CanvasLayoutHint`・`CanvasLayoutHintGroup`・`ResponsePlan.layout_hint`）と生成型、`packages/contracts/fixtures/layout-hint-cases.json`（新規）・`response-plan-cases.json`（計画に `layout_hint: null`）、`scripts/check-contracts.mjs`・`scripts/contract-gate.test.mjs`、`packages/domain/src/canvas-layout-hint.ts`（新規）、`apps/core/src/canvas-stream.ts`（`admitLayoutHint`・`CanvasHub.applyHinted`・コードの値・記録・消えた物の名前、流れの経路の `layoutHint` の口）、試験（`scripts/layout-hint.test.mjs`・`apps/core/src/canvas-layout-hint.test.ts`・`apps/desktop/src/renderer/screens/canvas/CanvasBoard.hint.dom.test.tsx`、`scripts/response-plan.test.mjs` の計画）、`tests/test-map.json`（QA01・QA03）、`docs/ui/layout-hint.md`（記録）。

## プロンプトインジェクションの評価（模擬）

評価セットは `packages/contracts/fixtures/layout-hint-cases.json` の `evaluation`（31 例・34 の発言）。物の本文・メールの本文に入った合成の指示と、その指示に従ってしまった模擬のモデルが出すヒントを手で書き、各発言を `CanvasHub.applyHinted` に通した後の記述（強調・読む順・まとまり）と記録の理由のコードを手で書いた。結果は `docs/ui/layout-hint.md` に記録した（使う 11・ヒントなし 1・戻す 22。理由の内訳も同じ記録）。

- 配置の範囲の指示（メールを焦点にして先に読ませる・ほかを周辺へ回す）は、守る物に触れなければヒントとして使う。変わるのは強調・読む順・まとまりだけで、物の集合・見出し・データの参照・棚・ユーザーの置き場所・承認・実行は変わらない（U668）。次の発言では、ヒントで変わった強調・まとまりはコードの値へ戻る。
- 配置の範囲を超える指示（承認・実行・棚への片付け・読み上げ・見出しの書き換え）は、ヒントの形に表す項目がないので形の検査で戻る。承認の画面はキャンバスに置けず、承認のチャネルもキャンバスにない（ADR 0032）ので、ヒントで承認の画面に見せかける・押させることはできない。
- 守る物を目立たなくさせる指示は戻る: 重なりの確認を周辺へ回す・読む順の最後へ回す・周辺の物とまとめる、文字の結果を周辺へ回す、保留を捨てた知らせを最後へ回す、コードがその発言で足した文字の結果を周辺へ回す、重なりの確認があるときに 2 つを焦点にする。重なりの確認を焦点のまま残し、ほかの 1 つを焦点にするヒントは使う（確認の箱の位置と大きさはコードの配置と同じ）。
- 棚の物・ない物（コードの束が閉じた物を含む）・忘却で消えた物・記録しない区切りにだけあった物・古い版（記録しない区切りの間に作ったヒントを含む）も戻る。
- まとまりの名前に指示や会話の内容（例: `approve-now`・`dentist-at-3pm`）を入れても、記述には `g1` が入り、モデルの名前は記述・端末へ渡らない。画面はまとまりの名前を描かない（happy-dom に描いた DOM に名前が出ないことを確かめる）。

## 見た目の回帰

ピクセルの画像の比較の仕組みはリポジトリにないので、今の配置のエンジンの手計算の試験（`scripts/canvas-layout.test.mjs`）と、happy-dom に描く画面の試験（`CanvasBoard.dom.test.tsx`）と同じ形で足した（U669）。

- `apps/core/src/canvas-layout-hint.test.ts`: 評価セットの例を `CanvasHub` に通した後の `hub.document` を配置のエンジンで描く。1280 × 800 の格子で、ヒントなしはコードの配置（errands が列 2、mail が列 7 の 4 × 2）、ヒントありは mail が焦点（列 7 の 6 × 4）で errands が焦点の左（列 3）、ユーザーが置いた news は同じマス。600 × 800 の 1 列で、ヒントが読む順を変えると最後の news が入りきらない物になる（U670）。重なりの確認を焦点のまま残してほかを焦点にした例は、確認の箱がどの大きさでもヒントなしと同じ。戻した 1 発言の例は、ヒントなしで同じ手順を通した別の hub と、1920 × 1080・1280 × 800・600 × 800 で同じ出力。
- `CanvasBoard.hint.dom.test.tsx`: Core と同じ決め方（`decideCanvasTurnLayout`）で決めた束を当てた記述を CanvasBoard に描き、ヒントを使ったとき・捨てたとき・次の発言で戻したときのカードの位置・大きさ・強調の印・DOM の順（読み上げとキーボードの順）を手で書いた値と比べる。
