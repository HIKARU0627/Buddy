## 1. 忘却の transaction（`forget.apply`）

DB worker の新しい命令の組 `memory`（`executeMemoryOp`、DB worker のメッセージ `memory`、`DbWorkerClient.memory`）。忘却は次の順で 1 つの `BEGIN IMMEDIATE` の transaction で行う。

1. 計画を作ったときの台帳の世代（`previous_generation`）が今の世代と同じか（違えば `forgetting_generation_changed`）。対象（発言・記憶）があるか（元情報は行がなくても台帳に書いて再取り込みを止められるので、いつもある扱い）。
2. **計画を DB の今の系譜で作り直し、Core の計画と同じかを確かめる**（`forget_plan_stale`）。系譜（`derivations` と `memory_sources`）・会話・記憶・操作の状態を transaction の中で読み（`readForgetGraph`）、domain の `planForget` で作り直す。Core が `forget.graph` で読んでから適用するまでに派生物が増えていれば拒否し、Core が計画を作り直す（閉包の漏れを作らない）。HMAC は Core が鍵で求めて渡し（`source_hmacs`）、worker は鍵を持たない。計画に要る HMAC が渡されていなければ `source_hmac_missing`、形が違えば `source_hmac_malformed`。
3. 台帳の 1 件を `buildLedgerEntry` で組み立て、決まった順にそろえて連鎖の hash を求め、台帳の行（hash・項目の数）と項目を書く。系譜がまだなければ `ledger_id` を書く。
4. 計画の順（`FORGET_DELETE_ORDER`。参照する側から先）に物理削除する。種類ごとの消し方は下の表。消した物の系譜の辺（派生物としての辺）も消す。消した物を由来にする辺で、派生物が残るもの（送出禁止で残す操作の確定内容）は残す（ID だけ）。
5. 操作の確定内容: 終端（成功・取消・置換済み）の操作は暗号文を消す（hash・行・承認・試行は残す。J5 と同じ）。進行中・結果不明・未実行は**状態・承認・試行を変えずに**送出禁止の印だけを付ける。
6. 書いた台帳を DB から作り直して hash を照合する（ファイルを DB から作れることを、COMMIT の前に確かめる）。

| 種類（`ForgetNodeKind`）                                   | 消し方                                                                                                                                                                                                                                      |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `intent_shadow`・`async_guard`・`related_analysis`         | 行を消す（関連解析は `group_id` を派生物の ID にし、解析の版をまとめて消す）                                                                                                                                                                |
| `notification_candidate`                                   | 行と題・抄録の暗号文                                                                                                                                                                                                                        |
| `request_entity`                                           | その依頼から作った気づき・一度だけの記録（`request_entity_operations`。依頼を参照する）・依頼の行・要約の暗号文。元のメールは台帳の再登録の禁止で再抽出されない                                                                             |
| `session_summary`                                          | 会話の行は残し、要約の列を空にしてから暗号文を消す                                                                                                                                                                                          |
| `memory`                                                   | 由来（`memory_sources`）→ 行 → 本文・対象キーの暗号文                                                                                                                                                                                       |
| `turn`（対象の発言・「〇〇を忘れて」の発言・派生した発言） | 発言への応答（`turn_responses`。ID と決まった文だけ）を消し、入力の版（`input_snapshots.turn_id`）の結び付けを NULL にしてから、行と本文の暗号文を消す。この発言から作った本人の指示は閉包に入って先に消えている（U112。2026-10-29 に変更） |
| `user_directive`（本人の指示。U112）                       | 行と本文の暗号文（`directive.revoke` と同じ消し方）。発言より先に消す（`FORGET_DELETE_ORDER`）                                                                                                                                              |
| `source_item`                                              | 元サービスの ID（`remote_id`）が同じ行と本文の暗号文。アカウントをまたいで同じ ID があればすべて消す（閉じた側。U110）                                                                                                                      |
| `canvas_item`・`carried_summary`                           | まだ DB に表がない（UI-05 の永続のキャンバス・つないだ要約）。系譜の辺だけを消す                                                                                                                                                            |

- **「〇〇を忘れて」の発言**（司令塔の判断。ADR 0040）: `instruction_turn_id` を計画の対象に入れ、同じ transaction で消す。台帳には発言の ID だけが残る。影モードの記録（由来の記録がなく、入力の版から発言を引ける）も閉包の規則 D で消える。
- **進行中の操作を消さず、再送もしない**（08 §6）: 計画に操作の行の削除・取消・承認の失効・状態の変更の項目はない（ADR 0044）。送出禁止の印は操作の行の列で、操作の状態版（`state_revision`）も変えない。送出の境界を越えた操作は結果の記録を続けられ、成功を取り込んでも試行は増えない。印のある承認待ちの操作は、本人が取り消すまで進まない（勝手には取り消さない）。`operation-store.ts` は承認・準備・送出意図・LocalCommand の適用で印を先に見て `operation_send_blocked` で拒否する（DB の trigger が最後の保証）。
- **実行中の memory_forget の操作**（`executing_operation_id`）: この命令は `null` で計画を照合する。memory の操作（memory_save・memory_correct・memory_forget）はまだ契約の操作の種類（`OperationKind`）にも LocalCommand の適用の経路にもない。memory_forget の操作の適用（承認の使用・`succeeded` への遷移と、この忘却を同じ transaction で行い、その確定内容を消す）は、Core の経路を作る B06-07 で、`applyForget` を同じ transaction の中から呼ぶ形にする（`applyForget` は transaction を張らない関数として出してある）。

## 2. 台帳の別ファイルと DB の整合（U109）

**DB が正本で、ファイルは DB から作り直せる写し**にする。台帳の 1 件は本文を持たず、項目（ID と HMAC）・世代・記録の時刻・`entry_id` はすべて DB にあるので、ファイルは DB だけから同じ hash で作り直せる。

- **書く順序**: 忘却の transaction を COMMIT してから、Core がファイルを書く（`applyForgetAndSyncLedger`）。ファイルは SQLite の transaction に入れられないので、どちらかが先に進む瞬間は必ずある。DB を先にすると、物理削除と台帳の記録が同じ COMMIT で確定し、ファイルが遅れるだけになる（遅れは DB から埋められる）。ファイルを先にすると、ファイルだけが進んだ状態（DB は消していない）から再開するには計画をもう一度作る必要があり、計画が古くなる（採らない）。
- **ファイルの書き方**: 同じディレクトリの一時ファイルに書いて fsync し、rename で置き換えてからディレクトリを fsync する。途中で止まっても、ファイルは前の版か新しい版のどちらか。取り残された一時ファイルは次の同期で消す。追記だけの台帳を、全体を書き直す形で「追記」する（先頭を削らない・前の世代を変えないことは、hash の連鎖と下の照合で確かめる）。
- **再開の手順**（`syncForgetLedgerFile`。忘却の COMMIT の後と Core の起動時に呼ぶ）:

| DB とファイル                                                              | 扱い                                                                 |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 台帳もファイルもない                                                       | 何もしない                                                           |
| ファイルが DB より遅れている（COMMIT の後・書く前・rename の前に止まった） | DB の全件でファイルを書き直す                                        |
| 同じ head                                                                  | 何もしない                                                           |
| ファイルが DB より進んでいる・DB に台帳がないのにファイルに項目がある      | 書き換えずに拒否（`ledger_file_ahead`）。DB が古い状態へ戻された疑い |
| 同じ世代の hash が違う                                                     | 書き換えずに拒否（`ledger_file_diverged`）                           |
| 系譜が違う                                                                 | 書き換えずに拒否（`ledger_lineage_mismatch`）                        |
| ファイルが読めない・形が違う・連鎖が壊れている・追加の欄（本文）がある     | 書き換えずに拒否（`ledger_file_invalid`）                            |

- **拒否したとき**: Core は起動しない（`store_recovery_failed`、理由 `forget_ledger_file` と上の理由）。ファイルが進んでいるのに DB に合わせて書き直すと、忘れた内容を持つ古い DB で動き、新しい台帳の知識（再登録の禁止）を捨てることになる。復元の手順（段階 1 の台帳の確認・段階 3 の忘却の適用。B06-08）で台帳を当てるまで止める。壊れたファイルも、壊れる前に DB より新しい世代を持っていたかが分からないので、同じく止める（03 の「復元できるふりをしない」）。
- **限界**: hash の連鎖は真正性の証明にならない（ADR 0040 の「限界」のまま）。DB の台帳の行・項目は追記だけの trigger と項目の数で守り、ファイルの出力の前に hash を計算し直して DB の値と照合する（`forget_ledger_hash_mismatch`・`forget_ledger_items_mismatch`）。端末への複製（B06-07）は、このファイルを元にする。

## 3. 記憶の命令（`memory.*`）と指示の取り消し

| 命令                  | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `memory.save`         | 保存の直前の最後の保証として、transaction の中で台帳の全件と由来を照合する（domain の `ledgerRelationReasons`。ADR 0040 の「忘却の関連の判定」）。忘れた由来・再登録を禁じた元の発言・元情報（`source_forgotten`）、自動抽出の同じ内容（`content_forgotten`）、台帳の欠番・巻き戻り、由来がない（`provenance_unknown`）、HMAC がない・形が違う、由来がもうない・期限を過ぎた（`source_expired`。U118: 発言は `expires_at`、元情報は本文が保存期限の中にある行、記憶は行と見直し待ちの削除の期限を transaction の中の今の値で判定し、ちょうどは期限切れ。掃除がまだでも拒否する）は保存しない。関係のない忘却で世代が進んだだけなら保存する。同じ内容（`memory_duplicate`）は保存しない。見直し日は保存から 90 日で、別の記憶から作った記憶は由来の見直し日より後にしない。由来は `memory_sources` に書く |
| `memory.start_review` | 見直し日を過ぎた記憶を見直し待ちへ。削除の期限は見直し日から 30 日                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `memory.continue`     | 見直し待ちの明示継続（継続した時点から次の 90 日。ADR 0008 U14）。削除の期限を過ぎた見直し待ちは生き返らせない（`delete_due`）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `memory.delete_due`   | 見直し待ちのまま期限を過ぎた記憶の物理削除（由来・派生物としての辺・暗号文）。**期限切れは忘却ではない**ので台帳に書かず、再登録を禁じない（ADR 0008・0040）。この記憶を由来にする辺は残す（存在しない由来は期限切れとして扱う）。派生物が残っていれば、この記憶の由来の辺を ID だけで `derivations` に残し、派生物がなくなったら消す（U110。下の「レビューへの対応」）                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `directive.revoke`    | 本人の指示の取り消し。行と暗号文を消す（U112）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

- 時刻は呼び出し側の `now` を信じる（DB は時計を持たない）。期限の命令（`memory.start_review`・`memory.delete_due`）は、d1 の `sweepPlan` の時計の判定を通してから呼ぶ（`budget.purge_month`・`retention.*` と同じ）。
- **同じ種類・同じ対象キーで内容が違う記憶**（J15。両方を見直し待ちにする）は、保存せずに `memory_conflict_review_required` で知らせる（U111）。0001 の CHECK（見直し日は作成より後、削除の期限は見直し日より後）では、「今から見直し待ち」の新しい記憶と、見直し日が先の既存の記憶の削除の期限（今から 30 日）を表せない。見直し待ちの起点は原本に決めなし。

## 4. 移せない用事を本人が決着する命令（ADR 0051 の引き継ぎ）

`retention` の組に 2 つ足した。

- `task.unmigrated_list`: 暗号文を持たない用事（0010 までの用事で、確定 intent を開けずに移せなかったもの）を `task_id` の順に読む。本文を持たず、知らせ（UI-05）と決着の画面の材料。
- `task.resolve_unmigrated`: 本人の決着。`discard` は用事を消す（中身を取り出せないので、本人が手放すと決めた）。`replace` は本人が入れ直した題名・期限・本文を、Core が用事を所有者にして暗号化した値（`task_content`、版 0）で結び付ける（0011 の trigger が所有者・用途・一度だけを照合する）。どちらも、書き込み済みで結び付けていない暗号文（移行の途中で止まって読み戻しが合わなかったもの）を先に消す。決着の後、その用事の操作は J5 の本文の削除・90 日の削除の対象に戻る（試験で確かめた）。

## 5. 復元の後の保留を DB に書く（ADR 0047 の引き継ぎ。U113）

- **書く時点**: 復元は、取り出した別の DB（作業用の DB）で段階 2〜5 を行い、最後に今の DB と差し替える（ADR 0040）。`applyRestoreAftermath` は、**差し替える前の作業用の DB に**、ADR 0047 の取り直しを 1 つの `BEGIN IMMEDIATE` の transaction で書く。差し替えの後に書くと、書く前に止まったときに、承認が生きたまま・隔離の印がないまま・端末が有効なままの DB が今の DB になる。作業用の DB に書いてから差し替えれば、今の DB はいつも「取り直しの済んだ DB」か「元の DB」のどちらか。ファイルの rename は SQLite の transaction に入れられないので、指示の「差し替えと同じ transaction」はこの読みにした。
- **書くもの**（計画は domain の関数。ここは読む・書く・読み戻すだけ）:

| 取り直し（`RESTORE_RESETS`）                  | 書き込み                                                                                                                                                                                                                     |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 承認の失効・操作の隔離（J3）                  | 有効な承認をすべて `revoked`。`quarantineRestoredOperations` の状態と印（`restore_unverified_at`）を書き、状態版を 1 つ進める。実行中の試行は、送出意図の前を `superseded`、後を `unknown_held` にする（どちらも再送しない） |
| 端末の失効（U78）・接続範囲の失効             | `restoreDevicePlan` の端末に復元の時刻で `revoked_at`。接続範囲はすべて失効                                                                                                                                                  |
