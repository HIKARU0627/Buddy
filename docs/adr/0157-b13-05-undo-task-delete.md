# ADR 0157: B13-05 自動で登録した用事の取り消し（用事の削除）

- 日付: 2026-11-26
- 状態: B13-05（親 #24）の部分。U310 のうち用事を本人の決定で (a) にし、Buddy が登録したままの（開いている）用事を取り消しで削除する。予定は ADR 0153 の暫定 (b) のまま。**模擬の試験だけ**で、実データ・実機・実 API は未実施。
- 根拠: 設計 03「取り消しと安全停止」、J12、設計 07 §2、設計 08 §3・§9、ADR 0030・0051・0075・0153・0155・0156。原本の参照手順は `docs/design/README.md`。
- 対象: 契約（`OperationKind`・`OperationStepKind`・`TaskDeleteOperationIntent`）、`packages/domain/src/connectors.ts`、`packages/storage`（命令 `operation.delete_local`、照会 `task_state`）、Core の実行担当と取り消しの経路、端末の文言。マイグレーションは足さない。

## 背景

ADR 0153 では、契約に用事の削除の種類が無く、原本も用事の取り消しの方法を書いていないため、自動で登録した用事は取り消せない（`unavailable`）と見せた（U310 の暫定 (b)）。ADR 0156 で下書きの削除を足した後、本人に確かめ、用事も削除で取り消すと決まった。消してよいのは、Buddy が登録し、その後に変わっていない用事だけとする。

## 決めたこと

| 対象                   | 決定                                                                                                                                                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作の種類             | `task.delete`（LocalCommand、工程は `delete_task`、照合は `local_transaction`）。target は用事の id、action は用事を登録した操作と内容版（`created_by`）。外部の相手へは送らず、提供元・アカウントを持たない。`created_by` が自分自身を指せば意味検査の誤り（`created_by_self`）            |
| 使える場面             | 自動実行の取り消しの補償だけ。取り消しに結び付かない作成は保存層が `undo_only_kind` で拒否する（`mail.draft.delete` と同じ一覧）。方針の自動承認では作らない。ADR 0075 の「完全削除の種類を作らない」は、取り消しの補償の二つの種類だけを除いて続く                                         |
| 「変わっていない」     | 用事の内容（題名・期限・本文）を編集する命令は今は無く、暗号文は差し替えられない（0011 の `tasks_content_fixed`）。そこで、元の操作が登録した用事で、まだ開いている（完了していない）ことを「変わっていない」とする。完了した・消えた・別の操作の用事は 409 `target_changed` で消さない     |
| 取り消しの押下の時     | 元の操作の作成物の id（試行の `external_id`）で用事の状態を読む（照会 `task_state`。用事を作った操作と開いているかだけを返し、内容は返さない）。合えば押下を画面の承認として補償を承認済みで作る（ADR 0153 と同じ）                                                                         |
| 適用                   | 実行担当が `operation.delete_local` を出し、DB worker が一つの transaction で、取り消しの記録が結ぶ元の操作の用事で開いていることを確かめ直し、成功の試行・用事の行・用事の暗号文の削除・承認の使用・最終状態・取り消しの記録の更新を書く。合わなければ何も書かず、補償は承認済みのまま残る |
| 命令の取り違え         | 用事の登録の命令（`operation.apply_local`）は `task.create` の操作だけ、削除の命令は `task.delete` の操作だけに使える（違えば `operation_kind_mismatch`）                                                                                                                                   |
| 取り消せるように見せる | 取り消しの口（データ鍵・契約）を渡したときは、用事の行を取り消せると見せる。端末は取り消せる行に「取り消すと、Buddy が登録したタスクを削除します。」と添える（同じ欄の行の見出しが「タスクの登録」なので、語をそろえた）                                                                    |

## 原本に決めがない項目

- U310: 下書き（ADR 0156）に続き、用事も本人の決定で (a)。予定は暫定 (b) のまま。
- U317: 押下の後、適用の前に用事が完了・削除されたときも、暫定 (a) と同じく適用せず承認済みのまま残す。本人が操作の画面で取り消すと、ADR 0155 の規則で取り消しの記録が外れる。

## 試験（模擬だけ）

- `packages/storage/src/safety-store.test.ts`: 取り消しに結び付かない用事の削除は `undo_only_kind` で作らないこと。別の操作の用事・完了した用事・無い用事は `target_changed` で消さず承認済みのまま残ること。登録の命令では削除の操作を適用しないこと。開いている用事は行と暗号文が消え、取り消し済みになり、もう一つの用事は残ること。
- `packages/storage/src/operation-store.test.ts`・`operation-retention.test.ts`: 登録の命令の試験の操作を `task.create` にそろえた。
- `apps/core/src/api-auto-actions-undo-task.test.ts`（3 件）: 自動で登録した用事が押下で作った補償で削除され、取り消し済みになること（同じ要求の再送は二つ目を作らない）。完了した・消えた用事は 409 `target_changed`。純粋な判定（用事の登録だけを読む）。
- `apps/core/src/api-auto-actions-undo-draft.test.ts`: 取り消せる種類に用事が加わったこと。
- `scripts/contracts.test.mjs`・`scripts/operation-kinds.test.mjs`・`scripts/approval-required-operations.test.mjs`: 新しい intent の正誤の例（提供元を持つ・照合が外部・`created_by` が無い・用事の id が無い）と意味検査、種類と intent の対応、完全削除の除外が取り消しの二つの種類だけであること。
- 端末の `AutoActionsPanel.test.tsx`: 取り消せる用事の行だけに削除の説明が出ること。

**模擬の期待値だけ**。実データ・実機は未実施で、合格扱いにしない。

## 残ること

- U310（予定）・U313〜U317 の本人の確認。
- 用事の編集・完了の命令を足すときに、「変わっていない」の判定を内容の版で見直すこと。
- 承認済みのまま残った補償を、自動実行の欄から取り消せるようにするか（ADR 0156 と同じ）。
