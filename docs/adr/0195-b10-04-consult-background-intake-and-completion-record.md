# ADR 0195: B10-04 相談（consult）を最初から裏のジョブへ回す口と、完了条件ごとの判定の記録

- 日付: 2026-11-27
- 状態: B10-04（親 #18、Issue #246）の残りの判断。P1〜P5（ADR 0105〜0109・0135）と、調査の裏のジョブの製品配線（B12-05、ADR 0141）は main にある。ここでは、相談を裏へ回す**受付の口**と、X29・X33・X36・QA05 の模擬の観測の記録、完了条件ごとの判定表を足す。**製品の起動（`core.ts`）は相談の口を渡さないので、製品の相談は従来どおり「未対応」のまま**（U254 の暫定を維持）。実音声・実 API・実請求・実機は未実施。
- 根拠: 設計 10 §5「裏のジョブ」、contract-map U254・U560〜U564、ADR 0005（結果の表）・0052・0066・0090〜0092・0105〜0109・0135・0141・0190（記録しない会話の RAM の経路）、`docs/b10/model-routing.md`（相談は思考 high の profile に固定）。非公開の原本（`.local/design/notion/`）はこの作業の環境になく、原本の不足を推測で埋めていない。設計が決めていない点は、安全側の暫定として U560〜U564 に記録した。
- 対象: `apps/core/src/turn-ports.ts`（`ConsultJobAcceptance`・`BackgroundJobAcceptor.acceptConsult`・模擬の解釈）、`apps/core/src/api-turns.ts`（`planBackground`）、各試験（`api-turns.test.ts`・`live-conversation.test.ts`・`private-conversation.test.ts`）、`tests/test-map.json`、`tests/integration/evidence-b10-04-simulated.json`、`docs/b10/b10-04-completion.md`、`docs/b00/contract-map.md`、`docs/handoff.md`。契約（`packages/contracts`）・マイグレーション・`core.ts`・候補（B11-04）の経路は変えていない。

## 決めたこと

| 対象                 | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 裏へ回す条件（U560） | 思考レベルの信号を契約へ足さない。意図が `consult` と判定されたこと自体を「思考レベル high の相談」とみなし、最初から裏へ回す（モデルの振り分け表で相談のジョブは思考 high に固定される）。雑談・一般の質問は別の意図で、これまでどおり返答文（U217）の経路。思考レベルの信号を契約へ足す案（b）は、短い相談を同期で答える経路が必要になったときに本人が決める                                                                                                   |
| 受付の口（U561）     | `BackgroundJobAcceptor` に省略できる `acceptConsult(job)` を足す。項目は調査と同じ 5 つだけ（`workflow_id`・`intent: 'consult'`・`query`・`session_id`・`dedupe_key`）で、発言の全文・本人の情報・端末の情報は渡さない。契約も調査と同じ（冪等・受け付けていないのに `accepted` を返さない・例外は `unavailable`）。調査の口（`acceptResearch`）は相談を受け取らない。口がなければ「未対応」。製品の受付器（B12-05）は口を持たないので、製品の相談は未対応のまま |
| 受け付けない条件     | 調査と同じ順: 主題（`query`）が空・空白だけ → 足りない情報の聞き返し／口なし → 未対応／確定前の入力（Live の `unverified`）→ 今は進められません／掃除のゲート（検索・クラウドへの送信・自動利用のどれかが閉じている間）→ 今は進められません／受付器が `unavailable`・例外・不正な ID → 今は進められません。記録しない会話では口を呼ばず、保存もせず、決まった文で断る（U562）。受付の文は受け付けたときだけ使う                                                  |
| 応答（U563）         | `status: 'background'`、`reply_text` は「受け付けました。終わったら知らせます。」（`acceptedCommentary()` と同じ定型文）。`result_view` の種類は意図の表のまま `speech_bubble`、状態は `preparing`、`item_refs` なし。表示の計画の意味検査（`responsePlanErrors`）と食い違わない。モデルの返答文（`reply_text`）は相談では使わない。依頼は `executing` で、操作は作らない                                                                                        |
| Live の届け方        | 変えない（ADR 0135）。`status: 'background'` は結果の画面回しを作らず、声で返せるときだけ受付の文を 1 回だけ追記する。閉じた接続・背景化済み・世代違い・失効した依頼では何も足さない。受付の前後と送る直前の再確認は、調査と同じ共通の経路（`commitLive` と `#deliver`）を通る                                                                                                                                                                                   |
| 完了条件の判定       | `docs/b10/b10-04-completion.md` に、Issue の完了条件ごとに、観測する試験と未実施の範囲を表で書いた。X29・X33・X36・QA05 の `product_test` は、新しい `tests/integration/evidence-b10-04-simulated.json` の記録で `simulated_partial` にした（U564）。X49・X51・QA34 は既存の記録のまま                                                                                                                                                                           |

## 試験（模擬だけ）

- `apps/core/src/api-turns.test.ts`: 相談の受付（`background`・`speech_bubble`・`preparing`・受付の文・5 項目だけ・調査の口は呼ばない・依頼 `executing`・操作 0・意味検査と一致）、同じ `request_id` の再送で受付 1 回、受付器の `unavailable`・例外・不正な ID は「今は進められません」で受付の文も実行中の依頼もなし、調査の口だけ・受付器なしは「未対応」で調査の口を呼ばない、主題が空は聞き返しで受付器を呼ばない、掃除のゲートが閉じている間は受け付けず開けば受け付ける、モデルの自由文を使わない。
- `apps/core/src/live-conversation.test.ts`: 声の相談の受付の文が 1 回だけで、つなぎ・背景化を重ねず `ScreenResult` を作らない・同じ委譲の再送で増えない／受付が閉じた接続の後なら追記 0・画面 0・依頼は `executing`／確定前の入力からは受け付けず受付器を呼ばない／調査の口だけの受付器では「未対応」。文字の依頼は、遅くても（10 秒）つなぎ・背景化を声に載せず、文字の相談の受付の文も声に載せない（X49・QA34）。同じ Live の 2 つの依頼が同じ `session_id` の 2 つの発言として保存される（X36）。
- `apps/core/src/private-conversation.test.ts`: 記録しない区切りでは、相談の口があっても呼ばず、DB に触れず、決まった文で断る。
- 期待値は手で書いた。時計・タイマーは注入し、実時間を待たない。

**模擬のみ**。相談の実行器（B12）・実音声・実 API・実請求・実機は未実施で、合格扱いにしない。

## 残ること

- 相談の実行器・受付の保存・完了の気づき（B11）・次回の文脈（B10-06）への受け渡し。製品が相談の口を渡すのは、B12 の相談の実行器ができてから（調査の ADR 0141 と同じ順）。
- 受付と発言の記録が別の transaction であることによる孤立したジョブの照合（ADR 0135 の残件。調査では B12-05 が実装し、相談は実行器と合わせる）。
- 完了条件のうち「結果は次回の文脈へ」は B10-06 が実装するまで観測できない（U564）。
- 実音声・実 API・実機（B05-08・B05-09・#132・#133・B15）。
