# ADR 0185: 忘却の計画の「消える指示」の本文を画面に出す（U433）

- 日付: 2026-11-27
- 状態: U433 の判断と実装。Core の計画の応答・保存層の系譜の読み取り・デスクトップの main の中継・忘却の画面・契約（JSON Schema・OpenAPI・fixture）、模擬の試験と撮影だけ。**忘却の公開ゲートは閉じたまま**（`FORGET_PUBLIC_GATE_OPEN = false`）で、製品の組み立てでは計画は 503 のまま。マイグレーションは足していない（DB の版は 23 のまま）。実機の Mac mini・Electron の実画面・Windows／macOS の実機・実データ・実 API・実請求は**未実施**。

## 決めたこと

### 経路（U433 の (b)）

- 忘却の計画の応答（`POST /v1/memory/forget-plans`、`ForgetPlanView`）の `removed.directive_ids` を `removed.directives` に置き換えた。消える指示ごとに、指示 ID・範囲（`this_time` 今回だけ／`from_now_on` 今後ずっと）・本文（1〜200 文字、読めなければ `null`）を ID の順に返す。指示を一覧する経路（(c)）は作らない。指示の一覧は設定画面（03）と一緒に決める。
- 本文を返すのは**消える本人の指示だけ**。記憶の本文は今までどおり記憶の一覧の経路が返し、計画には入れない。元の発言の ID・元サービスの生の ID・台帳の HMAC・内容の HMAC・対象キーは返さない（`additionalProperties: false` と fixture で確かめる）。
- 検査は既存の計画の経路のまま変えない: 端末トークン・自宅・接続範囲・ロック解除・本人の画面操作の起源（`Buddy-Input-Origin` が screen）。計画は要求した端末に結び付き、別の端末は実行できない（409）。ゲートが閉じている間は 503 で、系譜も読まない。

### 本文の読み方

- 保存層の `forget.graph` が、系譜（`readForgetSubgraph`）と**同じ読み取りの transaction の中で**、系譜の辺にある指示（`user_directive` の節点）の行と封筒を読む（`ForgetGraphValue.directives`）。計画に出す指示の本文を、計画を作った系譜と同じ時点の値にするため。封筒は所有者（`user_directives`・指示 ID・用途 `directive_text`）が合う行だけを返し、合わなければ `null`。
- Core（`ForgetService.plan`）は、計画で消える指示の封筒だけを、計画のたびに読むデータ鍵（保持しない）で開く（`openSealedText`。記憶の一覧の `api-memory.ts` と同じ処理を `sealed-text.ts` に分けて共有した）。消える指示がない計画では、データ鍵を読まない。
- 上限は契約の `UserDirective.text` と同じ 200 文字（コードポイントで数える）。

### 開けないとき（U460）

- 指示ごとに、封筒がない・所有者が違う・別の鍵・別の指示の封筒の差し替え・UTF-8 でない・空・200 文字を超えるときは、その指示を「読めない指示」（本文 `null`）として**計画に残し**、件数に入れる。計画から外すと本人が知らない指示が消え、計画を作らないと壊れた指示 1 件でその記憶を忘れられなくなる（U439 と同じ問題）ため。
- 消える指示があるのに**データ鍵を読めない**（ない・例外）ときは、計画を作らない（`directive_text_unavailable`、HTTP は 503 dependency_unavailable）。全部を「読めない指示」と見せると、壊れていない指示まで見せずに消すことになるため。このとき同じ端末の前の計画は捨てない。
- 計画の指示が、同じ読み取りの指示の行にない（材料の食い違い）ときは `plan_unavailable`（503）。

### main の中継

- 中枢の計画（指示 ID を含む）は main が持つ。画面へは、計画ごとに main が作る参照（`ref`）と範囲と本文（`null` を含む）だけを渡す（`DesktopForgetPlanView.removed.directives`。`directive_count` を置き換えた）。指示 ID は画面・IPC・ログに出さない。同じ計画を見ている間は参照を変えない。
- 中枢の応答が契約に合わない（指示に余分な欄・201 文字・空の本文）ときは、計画を見せない（`core_rejected`）。

### 画面（U461）

- 右の「消える指示」は、件数だけの文と「指示の本文は、この画面ではまだ見られません」の注記をやめ、次の形にした。
  - 見出し「消える指示」と件数（読めない指示も数える）。
  - 「この記憶の元の発言から作った、本人の指示です。忘れると、これらの指示も消えます。」
  - 共通の枠（`FRAME_CLASS`。箱の丸み 12px）の中に区切り線で行を並べる。行は本文（省略せずに折り返して全部出す。空白のない長い英字も枠の中で折り返す `break-words`）と、その下に範囲（「今後ずっと守る指示」「この会話の間だけの指示」）。
  - 読めない指示の行は、warning の ⚠（読み上げない記号。`tones.ts` の対応表）と「本文を読めない指示」を太字で、その下に「中枢がこの指示の本文を開けませんでした。忘れると、この指示も一緒に消えます。」と範囲。
  - 指示がなければ「消える指示はありません。」
- 確認の帯の「指示 n 件」は、読めない指示も数える。

### OS の確認ダイアログ（U462）

- 指示の本文は書かない（最大 1000 件・各 200 文字でダイアログが読めない長さになるため。本文は画面で見せる）。指示の数は今までどおり書き、読めない指示があるときだけ「本文を読めない指示: n 件（これも一緒に消えます）」の行を足した。

### 既存の判断のうち、変えたもの

| 既存の判断                                                                                               | この ADR での扱い                                                                                                     |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| U388・ADR 0180「計画は消える指示の ID を返す。本文は出さない」                                           | 消える指示だけ、本文と範囲を返す（`directive_ids` を `directives` に置き換えた）。記憶の本文・HMAC などは出さないまま |
| ADR 0183・U433 の暫定 (a)「画面は本人の指示 n 件と『指示の本文は、この画面ではまだ見られません』を出す」 | 本文の行を出す（上の「画面」）                                                                                        |
| U434「確認には記憶と指示の数」                                                                           | 読めない指示の数の行を足した（U462）                                                                                  |

## 公開ゲート（U431）

ゲートは開けていない。U112 の条件のうち「消える指示を本人に見せる画面」はこの ADR で満たした（暫定）。ゲートを開く前に残るのは、U385（台帳の鍵がないとき）・U383（画面の経路の忘却の後の流れの区切り）と、実機での確認。開くかは本人の判断のまま。

## 見直しでの修正（2026-11-27）

読むだけの見直しで、直すべき指摘はなかった。軽微な指摘を次のように扱った。

- 画面に渡す本文の整形: main（`memory-bridge.ts`）は、OS の確認ダイアログと同じ `displayText` で、制御文字・書字方向の制御文字・ゼロ幅の文字を空白に置き換え、続く空白を 1 つにまとめてから画面へ渡す。除いた結果が空になった本文は、読めない指示（`null`）と同じ扱いにする。試験は `memory-bridge.test.ts` に足した（期待値は手で書いた）。
- 開けない理由の区別: 鍵違い・改ざん・UTF-8 でない・空・200 文字を超えるは、どれも同じ `null` になる。本文を出さない理由のコードをログに残すかは、指示を保存する経路を作るときに決める（残り）。
- 計画の 503 のときの main の扱い: main は前の計画の参照を捨てるので、画面からは前の計画を実行できなくなる。Core に残った前の計画は、期限（ADR 0180 の 10 分）で消える。
