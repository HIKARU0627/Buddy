# 家計簿の実機・実データでの確かめ（未実施）

家計簿（外部の家計簿サービスの代わりに Buddy の中に持つ家計簿。[ADR 0158](../adr/0158-household-ledger-store.md)）の段階 1〜3 は、模擬の試験だけで確かめています。**実在のメール・実在の書き出し（CSV）・実機の画面では、まだ何も確かめていません。** この文書は、本人が自分の環境で確かめるための手順と、結果を残す記録の枠です。模擬の試験の成功を、実データ・実機の合格として扱いません。実 API の呼び出しと実請求は、この手順では行いません。

根拠は ADR 0158〜0168・0171 と、契約台帳（[contract-map.md](../b00/contract-map.md)）の U318〜U340・U343〜U346 です。各 ADR の「試験（模擬だけ）」と「残ること」に書かれた、実データで確かめる項目をこの文書に集めました。

## 公開してよい情報の決まり

この文書と repo には、次のものを書きません（[情報管理と公開前確認](../public-release.md)）。記録の欄にも書かないでください。

- 実在のメールの本文・件名・差出人、書き出しの中身、金額、店名、カード番号・口座番号の一部。
- 本人のメールアドレス、端末名、内部 URL、データディレクトリの実際の場所、トークン・鍵。
- 画面や端末の記録（ログ）をそのまま貼ること。

気づいたことは、「項目名の一覧が違った」「日付の書き方が違った」のように、**何が違ったかの種類だけ**を書きます。詳しい内容が必要なときは、本人の手元（repo の外）に残します。表記が足りないと分かったときは、実データから写さず、合成の例を作って試験へ足します。

## 前提

1. 検査するコミット、Node.js 24.19.0・pnpm 12.11.2、端末の OS を控えます。`pnpm install --frozen-lockfile` と `pnpm run build` を通します。
2. Core を起動します。方法は [apps/core/README.md](../../apps/core/README.md) を参照してください。試験用のデータディレクトリを使うか、本番の DB で確かめるかは、先に本人が決めます。どちらでも、接続した実際の Gmail のメールを読みます。模擬の鍵保護（`--mock-key-protection`）で作った DB は実機の鍵では開けません（逆も同じ）。
3. 端末（デスクトップ）を起動し、Core とつなぎます。方法は [apps/desktop/README.md](../../apps/desktop/README.md) を参照してください。ロックを解除した状態で、家計簿の欄を開けること。
4. Gmail のアカウントを Buddy に接続し、メールの同期が動いていること。Outlook は対象外です（U329。本文を読む口がありません）。
5. 対象のカード会社の会員サイトで、**利用通知メールを有効にします。** 本人がすることは、これだけです。現在の送信元の一覧は、ビューカード・楽天カード・三井住友カード・JCB です（ADR 0159）。
6. 書き出しの取り込み（項目 D）には、マネーフォワード ME のアプリで書き出した入出金履歴の CSV を、本人の手元に用意します。ファイルを repo へ置かないでください。

## 確かめの進め方

- 項目 A〜I の順で進めるのが自然です。A で初回の基準ができた後に、B の停止と再開を確かめます。D の後に E〜H を確かめると、記録が十分にあります。
- 各項目は、手順と期待する結果の表、そして記録の表で成り立っています。実施日・結果（期待どおり／期待と違う／実施できず）・気づいたことを、種類だけ書きます。
- 期待と違ったときは、自動で直さず、まず種類を記録します。設計の意味が変わる判断は、契約台帳へ記録して設計判断として解決します（既存の判断を黙って変えません）。

## A. 利用通知メールの取り込み（ADR 0159・0160）

利用通知メールの取り込みは、Gmail の同期が対象を公開した直後に自動で始まります（本人の操作は要りません。U326）。一度に新しい順に 50 件まで読み、残りは次の同期の後に読みます。

| 手順 | 操作                                                                                                                                         | 期待する結果                                                                                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1   | 取り込みを有効にして**初めて**同期を行い、家計簿の欄を読み直す                                                                               | 過去のメールの利用は記録されない（初回の基準。U327）。過去の分がないのは不具合ではなく、書き出しの取り込み（項目 D）で補う                                             |
| A2   | 基準の後に、対象のカードを実際に使う（少額）。同期を待って、家計簿の欄を読み直す                                                             | 使った利用が、支出・未分類・支払い手段にカード会社の名前で 1 件記録される。日付・金額・店名が通知と合う。同じ利用が 2 件にならない                                     |
| A3   | 速報と確定の二度の通知を送る会社で A2 を行い、確定の通知が届いた後も確かめる（U323）                                                         | 確定の通知の分だけが記録され、二重にならない。速報と確定で金額が違う場合（割引・為替など）は、記録が確定の金額になっている。**この食い違いがあったかどうかを記録する** |
| A4   | 各社の通知で、利用日・利用先・金額の項目が読めているか確かめる                                                                               | 日付・時刻・金額・店名が読めている。読めない通知があれば、**項目名の一覧のどの表記が足りないか**を種類だけ記録する                                                     |
| A5   | 一通に複数の利用が入るカード会社があれば確かめる                                                                                             | 一通の中の複数の利用が、別々の記録になる                                                                                                                               |

## D. 書き出しの取り込み（ADR 0164）

書き出しの日付・金額の書き方と文字コードは、公式の案内では確かめられていません。**ここで実在の書き出しを使って確かめ、受け方を一つに決めるかどうかを判断します（未決事項 U336）。**

| 手順 | 操作                                                                                                     | 期待する結果                                                                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1   | 「ファイルを選んで取り込む」でファイルを選ぶ                                                             | OS のファイル選択が出る。画面にパスや中身は出ない。16 MB を超えるファイルは受け付けない                                                                          |
| D2   | **文字コードを確かめる（U336）。** 実在の書き出しが UTF-8 か Shift_JIS かを控えて取り込む                | どちらの文字コードでも文字化けなく読める。どちらでもないときは、読めないと表示される。実在の書き出しの文字コード（と BOM の有無）を記録する                      |
| D3   | **日付の書き方を確かめる（U336）。** 実在の書き出しの日付が YYYY/MM/DD か YYYY-MM-DD かを控える          | 日付が正しい日に入る。**この二つ以外の書き方（月日だけ・和暦など）が出たら、その種類を記録する**                                                                 |
| D4   | **金額の書き方を確かめる（U336）。** 桁区切りのコンマ・先頭の符号・全角か半角かを控える                  | 支出は負、収入は正で読まれ、向きが逆にならない。金額の列の見出しの括弧が全角でも半角でも読める。**金額が読めない行があれば、その種類を記録する**                 |
| D5   | 見出しの名前（計算対象・日付・内容・金額（円）・保有金融機関・大項目・中項目・メモ・振替・ID）を確かめる | 見出しの名前で列が探せる。見出しの名前が違う・足りないときは、画面に出る理由の種類を記録する                                                                     |
| D6   | 取り込んだ行と取り込まなかった行の数を見る                                                               | 取り込まなかった行（計算対象が 0・金額 0・日付や金額や ID が読めない行）の数が出る。内訳が書き出しの実際の行と合う                                               |

| D8   | 利用通知で記録済みの利用が書き出しにも入っているときを確かめる（U335）                                   | 同じ日・同じ金額の利用通知の記録がある支出の行は取り込まれず、一つの通知に一つの行だけが突き合わされる。**同じ日・同じ金額の別の利用が落ちていないかを記録する** |
| D9   | 大項目の名前が分類に引けるか確かめる                                                                     | 大項目が分類の表示名で引ける。引けない行は未分類になる。引けなかった大項目の種類を記録する（分類の一覧の見直しの手がかり。U319）                                 |
| D10  | 取り込みの途中でファイル選択をやめる、Core を止める、を試す                                              | 送り直さずに止まり、「止めた」と表示される。取り込み直すと、記録済みの行は増えない                                                                               |
