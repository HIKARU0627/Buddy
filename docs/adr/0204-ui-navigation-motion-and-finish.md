# ADR 0204: 画面を機能ごとのページに分け、動きと質感をそろえる

- 日付: 2026-11-28
- 状態: 実装済み（`apps/desktop` の UI レンダラーと、窓の作り方）。模擬の試験と、ビルドした画面を Chromium で描いた確認だけで、**実機（macOS・Windows の Electron の窓）での確認は未実施**（下の「確かめたこと・確かめていないこと」）。
- 根拠: 本人の依頼（2026-11-28）。使った感触として次の 3 点が挙がった。
  1. 動きが付いている所と付いていない所があり、使っていて楽しくない。入力バーを押すと欄が急に大きくなる。入力欄に限らず UI 全体で、Dynamic Island のように滑らかに動かしてほしい。
  2. 通常のウィンドウは、すべての機能が 1 つの画面に集まっていて使いにくい。タブなどで機能を構造化・階層化してほしい。
  3. UI 全体に高級感がない。Windows や macOS の純正アプリと比べてチープに見える。よく調べて改善してほしい。
- 関係する判断: ADR 0024（画面の骨格とデザインの約束）、ADR 0181（上の中央の島・角の丸みの 4 段・動きの時間）、ADR 0032・0067（3 つの窓・入力バーの大きさ）。
- 対象: `apps/desktop/src/renderer/`（`styles.css`、`app/AppShell.tsx`、`components/Fluid.tsx`・`NavIcons.tsx`・`Section.tsx`・`AppFooter.tsx`・`StatusBand.tsx`、`screens/canvas/InputBar.tsx`・`CanvasIsland.tsx`、`screens/device/DeviceScreen.tsx`、`App.tsx`、`state/use-role-window-state.ts`）、`apps/desktop/src/main/window-roles.ts`、`apps/desktop/src/main/electron/main.ts`、`scripts/renderer-shape.test.mjs`。

## 調べたこと

純正アプリの数値は、Microsoft の Windows 11 の設計の文書（書体・形・層・動き）、Fluent 2 のトークン、WinUI の配色の資源、Apple の Human Interface Guidelines と WWDC（Designing Fluid Interfaces、Animate with springs）、Electron 45 の文書で確かめた。要点は次のとおり。

- **書体**: Windows 11 の本文は 14px・行の高さ 20px、強調は太字ではなく Semibold。macOS の本文は 13pt。書体は Segoe UI Variable（和文は Yu Gothic UI）と San Francisco（和文は Hiragino Sans）。
- **層**: 純正アプリは区切り線を並べず、地（窓の地）と、その上の面（カード）の明るさの差でまとまりを示す。枠線は黒の 6% ほどの薄い線。
- **影**: 地に置いた物は影を持たず、浮いた物（フライアウト・ダイアログ）だけが影を持つ。影は近い影（輪郭）と遠い影（高さ）の 2 層。
- **動き**: 現れる物は速く出て静かに止まる（Windows 11 の Fast-In は `cubic-bezier(0, 0, 0, 1)` で 167〜333ms）。形の伸び縮みはばね。Apple は「まず行き過ぎのないばねから始め、勢いのある動きだけ少し弾ませる」とし、SwiftUI の既定のばねは減衰比 0.825。
- **安っぽく見える原因**（経験則）: 濃い区切り線の多用、大きすぎて太さの差がない文字、押した手応えのないボタン、既定のスクロールバー、指のカーソル、選択できてしまう操作の部品の文字、一律の時間と曲線の動き、OS の枠のままのタイトルバー。
- **Electron の窓**: 窓の大きさを滑らかに変える指定（`setBounds` の animate）は macOS だけ。Windows で毎フレーム大きさを変えると、古い描画や黒い面が見える。透明な窓は OS の影を持てない。

## 決めたこと

### 1. 機能をページに分ける（依頼 2）

登録済みの端末の画面は、左のサイドバーでページを切り替える。

| ページ     | 中身                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| 会話       | 記録しない会話の確認、会話、確認が必要な操作・処理中・終わった操作                                                 |
| 気づき     | 気づきの欄                                                                                                         |
| 自動実行   | 自動実行の欄                                                                                                       |
| 家計簿     | 家計簿の欄                                                                                                         |
| 記憶       | 保存してよい記憶の種類、記憶と忘却                                                                                 |
| 端末と接続 | 中枢との接続（中枢の画面なら、端末の登録・登録済みの端末・連携アカウント・自宅のネットワーク）、電源とロックの記録 |

- **いつも見える物は変えない**（設計 01）: 状態帯（上の中央の島と項目の行）と、今やること（登録の知らせ・停止中の帯）は、どのページでも右の上に出す。状態帯はスクロールしない。閉じる・終了はサイドバーの下に置く。
- **選んでいないページも描いたまま隠す**。入力の途中の内容や開いている欄を、ページを切り替えても失わない。
- **ページを切り替える操作**: 島の「確認が必要な操作を見る」は会話のページへ移ってから確認の欄の見出しへ移る。会話からの家計の記録の候補を開くと、家計簿のページへ移る。会話のページの名前の横に、確認が必要な操作の数を出す。
- **狭い窓**（幅 768px 未満）では、サイドバーを記号だけの細い列にする。名前は読み上げと `title` が持つ。
- **ページを出さない画面**: 登録の画面、ロック中・ロック状態不明（島とフッターだけ）、画面を開けないときは、今までどおり 1 列。
- 部品は HeroUI の Tabs（縦）。キーボードの矢印でページを移れ、選ばれた印がばねで移る。

### 2. 動きをそろえる（依頼 1）

- **動きの時間と曲線**（`styles.css`）: 時間は 3 段（`--motion-move` 180ms・`--motion-panel` 280ms・`--motion-island` 520ms。ADR 0181 の 150・180・320ms を改めた）。曲線は 3 つ（`--ease-settle`: 現れる物・移る物、`--ease-spring`: 形の伸び縮み、`--ease-island`: 島の行）。ばねは減衰比 0.82 のばねの応答を CSS の `linear()` で写した（行き過ぎは 1% ほど）。動きを減らす設定では、今までどおり時間を 0 にする。
- **形の伸び縮み**（`components/Fluid.tsx` の `FluidBox`）: 上の中央の島（キャンバス表示・従来の窓）は、中身の大きさを測り、外側の形の幅と高さを数値で指定して、ばねで補間する。文言が変わって幅が変わるときも、行が足されて高さが変わるときも、同じように滑らかに伸び縮みする。畳むときは、行が薄れる間だけ前の行を残す（`usePresence`。動きの時間が 0 なら残さない）。
  - 大きさの指定は要素の `style` プロパティ（CSSOM）で行う。CSP の `style-src 'self'` が止めるのは style 属性と style 要素で、CSSOM は止めない（ビルドした画面で、CSP の違反が出ないことを確かめた）。ADR 0024 の「実行時に style 要素を差し込まない」は守る。
- **入力バー**: 角は島の丸み（28px）のまま、高さだけを 56 と 176 の間でばねで動かす（高さ 56 では錠剤の形に見える）。入力欄は小さい形でも広がった形でも同じ TextArea にし、置き換えない（フォーカスも入力の途中の変換も失わない）。
- **窓の大きさと見える形を分ける**: 島と入力バーの窓は透明なので、**窓は先に広げ、後で縮める**。入力バーは、前面に来たら main が窓をすぐ広げ、画面が見える形をばねで伸ばす。前面でなくなったら画面がすぐ見える形を縮め、main は 560ms 待ってから窓を小さくする（`INPUT_BAR_COLLAPSE_DELAY_MS`）。島は、中身の高さが小さい形を超えたら main が窓を広げ、縮み終わったら戻す（今までの `preferred-size-changed` の仕組みのまま）。窓の大きさを毎フレーム変えない（Windows で崩れるため）。
- **現れる物**: 知らせ（Alert）・ページ・状態のパネル・島と入力バーの最初の表示に、同じ調子の現れ方（少し動いて現れる）を付けた。ボタンの押した手応え・入力欄の枠・開閉する欄・Tabs の印の時間と曲線もそろえた。

### 3. 質感（依頼 3）

- **層**: 欄（`Section`）は「見出し＋地より 1 段明るい面（角は箱の丸み）」にした。区切り線を並べる代わりに、面の明るさの差でまとまりを示す。
- **影**: 浮いた面（上の中央の島・入力バー）だけに、2 層の影（`shadow-float`）を付ける。Tabs の選ばれた印は、地から少しだけ浮いた面（`shadow-raised`）。地に置いた物（カード・欄）は影を持たない。島と入力バーの窓は透明で OS の影を持てないので、窓を見える形より大きく作り、その余白に影を描く（`FLOAT_SHADOW`: 左右 16・島の下 16・入力バーの上 16。キャンバスの配置のエンジンが周りに空ける幅と同じで、窓の余白がカードの置き場所に重ならない）。見える形の位置は変えていない。
- **タイトルバー**: 従来の窓は、macOS と Windows でタイトルバーを隠し、画面の上端を窓を動かせる帯にする。窓の操作のボタン（信号機・最小化など）は OS が描き、画面はタイトルバーの領域の環境変数で重ならない余白を空ける。その他の OS は OS の枠のまま。窓の初めの大きさは 1040 × 720（サイドバーの分を広げた）。
- **書体**: 純正アプリと同じ書体を先に置く（Segoe UI Variable・Yu Gothic UI、San Francisco・Hiragino Sans）。本文は 14px・行の高さ 20px、欄の見出しは 14px の Semibold。
- **細部**: 操作の部品の文字を選択させない。カーソルは矢印のまま（指のカーソルはリンクだけ）。スクロールバーを細くし、地になじませる。選択の色をアクセントの薄い面にする。

## 既存の判断のうち、この ADR で変えるもの

| 既存の判断                                                                                        | 変えたこと                                                                                                                                 |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| ADR 0024 の骨格「状態帯 → 今やること → 本体 → 詳細 → フッター を 1 列」                           | 登録済みの端末の画面は、サイドバーとページにした。状態帯と今やることは、どのページでもいつも出す。1 列の骨格は、登録の画面・ロック中に残す |
| ADR 0024 の約束 6「一覧・記録・接続の欄は見出しと区切り線の Section」                             | 見出しと、地より 1 段明るい面の Section にした                                                                                             |
| ADR 0024・0181「影は使わない」（U393）                                                            | 浮いた面（島・入力バー）と Tabs の選ばれた印に限り、影を使う。カード・欄は影を持たないまま                                                 |
| ADR 0024 の UI レビュー 2 回目「Tabs の選ばれた印は境界線で示す」                                 | 地から少しだけ浮いた面（薄い影）にした                                                                                                     |
| ADR 0181 の動きの時間（150・180・320ms）                                                          | 180・280・520ms にした。名前と、動きを減らす設定で 0 にすることは同じ                                                                      |
| ADR 0181 の段階 4「窓の動きは付けない。入力バーは小さめがカプセル（完全な丸）、入力中は島の丸み」 | 窓の大きさは今までどおり一度に変えるが、縮めるときは見える形が縮み終わるまで待つ。入力バーの角は島の丸みのまま（高さ 56 では同じ錠剤の形） |
| ADR 0067 の入力バーの窓の大きさ（560 × 56・560 × 176）                                            | 見える入力バーの大きさは同じ。窓は影の余白を足した 592 × 88・592 × 208                                                                     |
| ADR 0181 の島の窓の大きさ（560 × 48・560 × 104）                                                  | 見える島が入る領域は同じ。窓は影の余白を足した 592 × 72・592 × 128                                                                         |

変えていないもの: 色とコントラスト（ADR 0024 の表のまま。色の上書きは足していない）、角の丸みの 4 段、ボタンの形（完全な丸。本人の決定 2026-11-27）、状態を色だけでなく文言と記号で示すこと、読み上げの領域、IPC・受付の規則（main が正本）、CSP。

## 確かめたこと・確かめていないこと

- **模擬**: `pnpm test`（形の約束の試験 `scripts/renderer-shape.test.mjs`、コントラストの試験、画面の部品の試験、窓の作り方の試験）。
- **ビルドした画面を Chromium で描いた確認**（合成の状態を返す模擬の限定 API。Electron の窓ではない）: 従来の窓の各ページ（ライト・ダーク、幅 620〜960）、登録の画面、ロック中、状態のパネル、島、入力バー。入力バーの高さが 56 → 176 → 56 を途中の値を通って動くこと、島の幅と高さが途中の値を通って動くこと、CSP の違反が出ないことを測った。
- **未実施**: macOS・Windows の実機の Electron の窓での確認。特に、(1) タイトルバーを隠した窓の操作のボタンの位置と余白、(2) 透明な窓の影の余白の見え方と、余白がポインターを受けること、(3) 入力バーの窓を遅らせて縮める間の見え方、(4) 和文の書体の見え方（U740）。

## 残したこと

- 状態のパネルをしまうときの動き（窓は main が一度に隠す。U741）。
- 窓の地の素材（Windows の Mica・macOS の vibrancy）。地が透けると文字のコントラストを決められないので、今回は入れていない（U742）。
- キャンバス表示の物（カード）の動きと質感は、今回の対象の外（キャンバス表示は開発用のフラグの試作）。
