# ADR 0197: 記録しない会話の独立した確認を画面に出して承認を受ける経路（U503）

- 日付: 2026-11-28
- 状態: U503 の判断と実装（B06-07a-2 の 2d の続き、Issue #143 の一部、親 #11）。ADR 0192 で作った Core の口（`PrivateConfirmationDesk`）に、確認の一覧・承認・断るの契約と経路（OpenAPI・JSON Schema・生成型・fixture・経路の検査）、Core の経路（`apps/core/src/api-private-confirmations.ts`）、端末の main（`apps/desktop/src/main/private-confirmation-bridge.ts`・`core-link.ts`・`admin-confirm.ts`）と画面（状態の層のパネルと従来の窓の欄、島の数え方）をつないだ。**製品の口 `PRIVATE_CONFIRMATION_SCREEN_OPEN` は false のまま**（開くかは本人の判断。忘却の公開ゲートと同じ扱い。下の「口を開く条件」）。そのため製品の挙動は変わらず、記録しない間の外部の変更は今までどおり決まった文で断る（U483）。**マイグレーションは足していない**（確認・受付の控えは Core の RAM だけ）。試験の組み立てだけが口を開き、端末の画面から承認して最小の操作記録ができ、外部の変更が 1 回だけ行われるまでを模擬で通した。実機の Mac mini・Windows・macOS の端末、実際の Gmail などの実 API・実請求は未実施。
- 根拠: ADR 0045（独立した確認の中身・確認の ID と承認の結び付け・U64〜U67）、ADR 0040（最小の操作記録の確定内容の暗号文は完了から 7 日、hash とレシートは 90 日）、ADR 0192（Core の口・U502〜U508）、ADR 0031（承認の画面と OS の確認ダイアログ・入出力の停止中の承認）、ADR 0181（島は確認が必要な操作と結果だけ自動で広げる。U391）、ADR 0189（記録しない間の印）、設計 07 §3（受付と再送）。設計 03 の原本の要約（ADR 0045 の「原本に書いてあること」）: 外部変更は、会話本文を保存せず、必要な操作記録を残す独立した確認画面へ切り出し、その記録内容を示して一度承認を得る。非公開の原本はこの環境になく、新しく参照していない。原本と ADR に決めのない点は、安全側の暫定を選び `docs/b00/contract-map.md` の U600〜U611 に記録した。
- 番号: ADR は 0197、未決事項は U600〜U611。

## 端末

- main（`PrivateConfirmationBridge`、新規）: 一覧を中枢から読み（接続・ロック解除・保存モードの変化・保存モードの知らせ・記録しない間の発言の後・承認と断るの後）、画面へは参照（ref）と表示用の値だけを渡す（確認の ID・内容版・内容の hash は main の中だけ）。中枢の流れの保存モードが private と読めている間だけ画面に出す（記録しない会話の外・不明なら出さず、送らない）。承認は OS の確認ダイアログを 1 回挟み（U606）、ダイアログの間に確認が変わった・消えた・ロック・切断・入出力の停止があれば送らない。断るはダイアログを挟まない。送るのは画面操作として 1 回だけで、本文は内容版と内容の hash（断るは空）と、`@buddy/client` が足す `request_id`・接続範囲だけ。入出力の停止中は承認を受け付けず、断るは受け付ける（U603）。ロック・切断で一覧・参照・保留を捨てる。
- 限定 IPC: `desktop.private_confirmation_decide`（`{ ref, decision: approve | decline }`）。本人の画面操作（ロック解除済み・前面）だけ。状態の層のパネルと従来の窓だけが使え、キャンバス・入力バー・島は使えない（役割の表）。接続の状態（`DesktopConnectionView`）に `private_confirmations`（`DesktopPrivateConfirmationEntry` の配列。接続していて全部見えるときだけ）を足した。
- 画面: 状態の層のパネルと従来の窓の「確認が必要な操作」の上に欄「記録しない会話の確認」を置く（U607）。見出しの横に記録しない間の印（記号と文言。ADR 0189 の `PrivateModeMark`）、1 行目に「会話の内容は保存しません。承認すると、この変更の最小の記録だけを残して実行します。」。行は種類・対象の件名と差出人・付ける／外すラベルと、「断る」「承認する」（primary）。送っている間・結果を確かめている間・入出力の停止中・対象を確かめられない行では承認を押せず、理由の 1 文を出す（断るは押せる）。結果は欄の下に 1 つだけ出す（承認・断ると行は一覧から消えるので。U608）。
- 島: 承認を待つ確認の数を、確認が必要な操作の数に足して広げる（ADR 0181 の既定のまま。島から承認しない。パネルを出すだけ）。外部の変更の結果は、通常の操作と同じく操作の一覧と島（操作の状態の移り）で示す（U608）。

## 口を開く条件（`PRIVATE_CONFIRMATION_SCREEN_OPEN`、U610）

口を開くかは本人の判断とし、false のままにした。開くと、記録しない会話の間のラベルの変更が実際の外部の変更（Gmail などへ送る）になる。開いてよいのは、次をすべて確かめた後とする。

1. 実機の Mac mini の中枢と、実機の Windows・macOS の端末（状態の層のパネル・従来の窓の両方）で、記録しない会話の間のラベルの変更が確認になり、頼んだ端末の画面にだけ出て、OS の確認ダイアログの後の一度の承認で最小の操作記録（`private_minimal`）が 1 件だけでき、外部の変更が 1 回だけ行われること（他の端末・ロック・断る・出る・入り直すの後は何も起きないこと）。
2. 実際の Gmail（または使う提供元）の試験用の口座で、ラベルの変更が 1 回だけ届き、結果不明のときに自動で送り直さず、本人の照合で確かめられること（B15 の実 API）。
3. データディレクトリ（DB・WAL）・ログ・バックアップに、記録しない会話の発言・応答・確認の ID・区切りの ID が残らないこと、最小の操作記録の暗号文が完了から 7 日で消えること（J5、ADR 0040）を、実機のデータで確かめること。
4. 確認の画面と OS の確認ダイアログの文言（記録しない会話であること・会話の内容は保存しないこと・残る記録と期間）を本人が見て、承認の入口として足りると判断すること（U606・U607）。
5. U600〜U611 の暫定（特に頼んだ端末だけ・他の端末のロックでも取り下げる・画面に世代を出さない）を本人が見直し、変えるものがあれば変えた後であること。

開くときは、この定数を true にするだけで、経路・画面・試験は変えない（試験は口を開いた組み立てで通している）。開いた後の B06 の模擬の統合（X17）に、確認と承認の観測を足す。

## 試験（模擬だけ）

期待値は手で書いた値（状態・件数・文・理由・応答の欄）。内容の hash は試験の中でキーを並べ替えた区切りのない JSON と `node:crypto` の SHA-256 で別に求め、実装の関数から作っていない。

- `apps/core/src/private-confirmation-api.test.ts`（3 件、新規。製品の Core の HTTPS・合成の読み書きの provider・口を開いた組み立て・2 台の端末）: 一覧は頼んだ端末の確認だけで、画面で承認に要る値だけ（世代・操作の ID を含まない）。他の端末からの承認・声の起点（403）・内容の hash の違い・古い内容版・本文で端末を名乗る（422）は通らず、記録も外部変更も作らない。頼んだ端末の画面操作の承認で `private_minimal` の操作が 1 件でき、承認の端末は認証した端末、外部の変更は 1 回だけ。同じ要求の再送は同じ応答、別の `request_id` の二重の承認は最初の結果、同じ `request_id` で内容が違えば 409、承認した確認は断れない、他の端末の二重の承認も通らない、出た後の承認は 409。断る（他の端末からは 409、再送は declined、後の承認は 409）、ロック中は一覧も承認も 403・ロックで取り下げた確認は解除後も 409、出て入り直した後の古い確認は 409、どれも操作の記録は増えず外部へも送らない。口が閉じていれば一覧は空で承認・断るは 409。
- `apps/desktop/src/main/private-confirmation-bridge.test.ts`（5 件、新規。模擬の接続）: 記録しない会話の間だけ出し、確認の ID・hash を画面へ渡さない。読めなかったら前の一覧のまま。承認は OS の確認ダイアログの値・送る本文・画面操作の印・送り先を手書きの値と比べ、二度押しでは送らない。対象を確かめられない確認は承認させない、停止中は承認しない（断るは送る・ダイアログなし）。ダイアログの間の確認の変更・ロック・停止・「やめる」では送らない。結果不明は送り直さず、読み直すまで保留、拒否では読み直す。

- `apps/desktop/src/renderer/components/PrivateConfirmations.dom.test.tsx`（5 件、新規）: 見出しと記録しない間の印と保存しない旨、行の値、ボタンの読み上げの名前、押すと参照と決定で 1 回呼ぶ、送っている間・保留・停止中・対象を確かめられない行の扱い、結果の文言、何もなければ描かない、店の送り方と世代、島を広げる数え方。

### 感度

次の欠陥を一時的に入れて（ビルド後の `dist` を書き換え、終わったら戻した。コミットしていない）、該当の試験が落ちることを確かめた。

- 承認の経路で頼んだ端末の照合を外す → Core の 1 件目の試験が落ちる（他の端末の承認が通る）。
- 一覧の経路で頼んだ端末の絞り込みを外す → Core の 1 件目の試験が落ちる（他の端末の一覧に出る）。
- main で記録しない会話の間だけ出す判定を外す → main の 1 件目の試験が落ちる。

## 範囲の外と残り

- 口を開くこと（本人の判断。上の条件）。
- 返信の下書きを切り出すか（U502 のまま）。
- 実機の Mac mini・Windows・macOS の端末、実際の Gmail などの実 API・実請求（B15）。
- 記録しない会話から作った操作の一覧の行の見出し（通常の承認済みの操作と同じく、読めていなければ操作の種類）を、承認のときの表示用の値で埋めるか（U608 のまま見出しは通常と同じ）。
