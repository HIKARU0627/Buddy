# ADR 0091: B10-03 P2 Core の解釈への接続（モデルを使う Interpreter・Gemini の codec・失敗の区別）

- 日付: 2026-11-03
- 状態: B10-03（親 #18、Issue #200）P2 の判断。Core の解釈の差し込み口（`Interpreter`）に、`packages/ai` のアダプターを使う実装を足す。影モードの記録は P3。実 API・API キー・実請求・実機は未実施（B15 と本人の承認まで扱わない）。
- 根拠: 設計 10 §5・§5A・§6・§6A、設計 09 X58・QA01〜QA04、ADR 0004・0005・0029・0052・0070・0080〜0082・0090。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。
- 対象: `packages/ai/src/gemini-codec.ts`、`apps/core/src/model-interpreter.ts`、`turn-ports.ts`・`api-turns.ts`・`live-conversation.ts` の最小の変更、`apps/core/package.json`（`@buddy/ai` への依存）。契約（`packages/contracts`）は変えていない。

## 決めたこと

| 対象               | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 既存の経路         | 会話の操作の照合（X58）、`input_kind` の確認、partial のときに参照と聞き返しまでしか進めない規則、保留中の変更の関係の解決（`relation`・`target_workflow_id`）は main にあり、変えない。この PR は**解釈の中身**だけを足す                                                                                                                                                                                                                 |
| 会話の操作の位置   | `api-turns.ts` は照合表に当たった発話を解釈より前に処理する。モデルを使う解釈には**届かない**ので、モデルの前にコードで照合される。「終わりの時間を教えて」のような依頼は照合に当たらず、解釈へ回る。試験で、操作の発話ではアダプターを呼ばず、依頼の発話では 1 回呼ぶことを確かめた                                                                                                                                                       |
| 解釈の実装         | `createModelInterpreter` が `Interpreter` を実装する。入力の検査（空・長すぎ）→ 予算の口の受付 → 1 回の判定（ADR 0090）→ 精算の順。返す値は信用されず、Core が意図表・契約（`IntentArgs`）・意味検証で再び確かめる。モデルは承認・実行権限・処理状態・`effect_kind` を決めない                                                                                                                                                             |
| 失敗の区別         | `InterpreterReply` に `failed`（原因の種類と `retryable`）を足す。拒否・打ち切り・形式/意味の不正・timeout・利用不可・予算・中断を「意図が不明」と混ぜない（QA02・QA03）。聞き返しの文は 2 種類: 形式/意味の不正・拒否・打ち切りは「うまく読み取れませんでした。言い換えてお願いします」、timeout・利用不可・予算・中断・失効は「今は判定できませんでした。少し待ってからお願いします」。どちらも依頼・操作を作らず、実行へ進まない        |
| 未知の種類・型違い | schema の列挙・型で `invalid_schema` になり、聞き返しになる（QA01）。実行へ進まない                                                                                                                                                                                                                                                                                                                                                        |
| 文脈不足           | 必須の引数が足りない出力は通し、既存の `checkIntentArgs` による聞き返し（意図を保つ）になる。対象の候補が空のメール操作は、候補にない ID を作らせず、`candidate_not_offered` で拒否する                                                                                                                                                                                                                                                    |
| 依頼の候補（QA04） | `InterpretationContext.open_workflows` を足す。テキスト会話は依頼の保留を持たないので省略、Live は保留中の変更（この委譲自身を除く）を渡す。モデルは渡された依頼の中からだけ `target_workflow_id` を選べ、渡していない依頼は `invalid_semantics`。対象が決まらない取消（`target_workflow_id: null`）は通し、Live の既存の規則（`resolveHold`）が聞き返しにする                                                                             |
| 対象の候補         | 目印は一覧の順番（`メール1`）だけを渡す。provider のメール ID・件名・差出人・本文は渡さない（U216 の暫定）                                                                                                                                                                                                                                                                                                                                 |
| 診断               | `onJudged` に、結果の種類・失敗の種類・理由コード・usage・経過時間を渡す。発話の本文・引数の値・モデルの自由文は含めない                                                                                                                                                                                                                                                                                                                   |
| 予算の口           | `ModelCallGuard`（受付→精算）を注入する。拒否・例外なら送らない。アダプターが例外を投げたときは送った可能性があるので `settle(null)`（usage 不明として予約を保持）で、再送しない。usage が分かる失敗は精算する。**B07 の `BudgetGate` を使う実装は別の子で足す**（この PR では偽の口で試験した）                                                                                                                                           |
| Gemini の codec    | `generateContent` の形式で、固定部分を `systemInstruction` に、変わる部分を `contents` に置く。`thinkingLevel` を必ず指定し、`temperature` は指定せず、構造化出力は `responseJsonSchema`（契約の schema から `$ref` を展開し、`pattern`・`format`・注釈を落とした部分集合）で受ける。認証ヘッダーは持たない。usage の出力は思考を含み、cached は入力の内数。終了理由の拒否・打ち切りを区別し、想定外の封筒・状態・終了理由は利用不可にする |
| 実 endpoint        | wire 形式・usage の欄・終了理由・モデルの名前は**模擬の HTTP でだけ確かめた**。実 endpoint での確認は B15 と本人の承認まで行わない。Core の起動時の設定（endpoint・認証・profile の読み込み）は、実 API の承認まで既定では配線しない（既存の模擬の解釈が既定のまま）                                                                                                                                                                       |
| 依存方向           | `apps/core` は `@buddy/ai` に依存する（`packages/ai` は Core・保存・Electron に依存しない）。デスクトップの main・renderer が `@buddy/ai` を読むことは既存の lint が禁止している                                                                                                                                                                                                                                                           |

## 試験（模擬だけ）

- `packages/ai/src/gemini-codec.test.ts`: 送る schema から `$ref`・`pattern`・`format` が消え、形（必須・列挙）が残ること。リクエストの形（`systemInstruction`・`thinkingLevel`・`maxOutputTokens`・`temperature` なし・認証ヘッダーなし）。usage の対応（思考込みの出力・cached の内数）。拒否・打ち切り・思考の要約・usage の欠落・想定外の封筒/状態/終了理由・timeout・利用不可を区別し、いずれも送信が 1 回であること。
- `apps/core/src/model-interpreter.test.ts`: 判定が intent の返答になり usage を 1 回精算すること。候補が中立の目印だけで送られること。QA04: 渡した 2 候補のうち 1 つを指す訂正は通り、渡していない依頼は拒否、対象を決めない取消は通ること。拒否・打ち切り・途中の JSON・timeout・利用不可・中断・未知の意図・型違い・渡していない候補が `failed` になり、再送されないこと。予算の拒否・例外で送らないこと。入力の検査が予算より先であること。アダプターの例外で usage 不明として保持すること。HTTP の経路で、X58（会話の操作ではアダプターを呼ばない／似た言い回しの依頼は 1 回呼ぶ）、QA01〜QA03（失敗が聞き返しになり依頼・操作を作らない）、必須の引数の不足（意図を保った聞き返し）、同じ要求の再送でモデルを再度呼ばないこと。
- 既存の `api-turns`・`live-conversation`・`draft-save` の試験（75 件）が通ること。

**模擬のみ**。実 API・実請求・実機・実 endpoint の能力確認・モデルの採否は未実施で、合格扱いにしない。

## 残ること

- 影モードの記録（比較・300 件の上限・保存期限・既定 OFF）は P3。
- `BudgetGate` を使う `ModelCallGuard`、Core の同時数（枠 A は 1 本）の受付、起動時の profile・endpoint・認証の設定は、実 API の承認（B15）に合わせて別の子で行う。
- `reply_text`・`clarify_question` の表示は B10-04（U217）。
