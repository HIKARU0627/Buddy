# ADR 0175: 店名の規則を覚えるのを支出の記録だけにする（家計簿の不具合の修正）

- 日付: 2026-11-26
- 状態: 家計簿の不具合の修正。本人が分類を直す・手入力する・中身を直すときに、収入・振替の記録の店名が、同じ店名の支出の規則を上書きして消していた。覚える記録を支出に限って直した。**模擬の試験だけ**で、実データ・実機・実 API は未実施。
- 根拠: ADR 0158（店名の規則は向きと分類が合うときだけ当てる）、0161（分類の変更の副作用）、0167（手入力）、0169（中身の変更）、0174（収入の候補。U353 で、この動きを見直すと書いた）。原本（非公開 Notion）に家計簿の決めはない（U318 以降と同じ）。
- 対象: `packages/domain/src/household.ts`（`householdRuleLearnable` を追加）、`apps/core/src/household-ledger.ts`（`changeHouseholdCategory`・`changeHouseholdContent`）、`apps/core/src/api-household.ts`（手入力 `createEntry`）。契約（JSON Schema・OpenAPI）・保存の形・マイグレーションは変えない。

## 不具合

規則は店名の HMAC ごとに一つで、「店名 → 分類」を持つ（`household.rule_set`、出どころ `user`）。本人が分類を直す・手入力する・中身を直すと、店名があり分類が未分類でなければ、その店名の規則を書いていた。規則を当てるときは記録の向きと分類の向きが合うときだけ当てる（`householdRuleApplies`）。

収入の分類は「収入」、振替の分類は「振替」の一つずつなので、収入・振替の記録に店名が入っていると「店名 → 収入（振替）」を書く。同じ店名の支出の規則（たとえば「メルカリ → 日用品」）はこれで上書きされて消える。収入の規則は支出の記録には当たらないので、次のメルカリの支出は未分類に戻る。

再現（模擬の試験で確かめた）: 支出の記録の分類を日用品に直して「店名 → 日用品」の規則を覚えさせる。同じ店名の収入の記録を手入力する（または収入・振替の記録の分類・中身を直す）。規則を読むと「収入」（振替）に変わっており、`rule_learned` が true で返る。

## 決めたこと

| 対象             | 決定                                                                                                                                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 規則を覚える条件 | 記録の向きが支出で、分類が支出の分類であり、未分類でないときだけ（`householdRuleLearnable`）。分類の変更・手入力・中身の変更の三つが同じ判定を使う。ただし分類の変更で支出を未分類へ直すときは、下の「支出の記録」の行のとおり規則を未分類で上書きする |
| 収入・振替の記録 | 店名があっても規則を覚えない。同じ店名の支出の規則を書き換えない。収入・振替だけの店名にも規則を作らない                                                                                                                                               |
| 応答             | 収入・振替の記録の分類の変更・中身の変更では `rule_learned` は false になる（形は変えない。覚えなかった理由を別に出さない）                                                                                                                            |
| 支出の記録       | 動きは変わらない。分類の変更は今までどおり覚え、支出を未分類へ直したときも、その店名の規則を未分類で上書きする（覚えた分類を本人が取り消す手段。ADR 0158 からの動き）。手入力・中身の変更は、未分類のときは覚えない                                    |
| 当てる側         | 変えない。利用通知（`recordHouseholdEntry`）は `householdRuleApplies` で向きが合うときだけ当てる。書き出しの取り込み（`importHouseholdRows`）は、もともと支出で未分類でない行だけを `import` の規則として覚える                                        |
| 保存済みの規則   | 消さず、移し替えない。すでに「店名 → 収入（振替）」が保存されていても、支出の記録には当たらないので害はない。本人が支出の分類を直せば、本人の規則で置き換わる                                                                                          |

## 確かめたこと

- 振替の分類の向き（ADR 0158・U321）: 分類「振替」の向きは `transfer`。収入・振替の記録に支出の分類は付けられない（`category_direction_mismatch`、422）ので、向きと分類は常に合っている。振替は集計から外れ、規則で分類を決める意味がない。
- U322（データ鍵の作り直しでの店名の規則）: 保存の形を変えないので影響しない。
- U319（分類の一覧）・U321: 変えない。U339・U341・U353 の暫定の文に、この ADR で規則を覚えるのを支出だけにしたことを書き足した。
- 利用通知・書き出しの取り込み: 取り込みの記録は支出（利用通知は支出のみ、書き出しは `direction === 'expense'` の行だけ規則を覚える）なので、動きは変わらない。

## 退けた案

| 案                                                                   | 退けた理由                                                                                                                                                                                                                         |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (b) 規則を店名の鍵と向きの組で持つ                                   | 保存の形の変更・マイグレーション・規則の鍵の作り直し（U322）の見直しが要る。収入・振替の分類は一つずつなので、向きごとに規則を持つ意味がない（収入の店名から分類を選ぶ余地がない）。収入や振替の分類が増えたときに決め直す（U355） |
| (c) 今のまま、収入の規則だけ別の欄に書く                             | (b) と同じ保存の形の変更が要り、使い道がない                                                                                                                                                                                       |
| 収入・振替の記録の店名から規則を覚えず、覚えなかった理由を結果に出す | 契約（`HouseholdCategoryChangeResult`・`HouseholdEntry`）の変更になる。`rule_learned` の false で足りる。理由を出す必要が出たら別に決める                                                                                          |
| 保存済みの「店名 → 収入（振替）」の規則を消す                        | 本人の規則を黙って消すことになる。害がなく、移し替えの根拠もない                                                                                                                                                                   |

## 原本に決めがない項目

- U355: 店名の規則を覚える記録の範囲（支出の記録だけ。この ADR）。U339・U341・U353 の暫定の文も更新した。

## 試験（模擬だけ）

期待値は手で書いた。直す前に次の 4 件が失敗することを確かめた（支出の記録からの規則は直す前も通る）。

- `apps/core/src/household-ledger.test.ts`（3 件）: 収入・振替の記録の分類の変更で `rule_learned` が false で、支出の規則が残り次の支出に当たること。収入・振替の記録の中身の変更で支出の規則が残り、収入だけの店名に規則ができないこと。支出の記録の中身の変更は今までどおり覚え、未分類へ直したときは覚えないこと。
- `apps/core/src/api-household.test.ts`（2 件）: 収入・振替の手入力が支出の規則を上書きせず、収入・振替だけの店名に規則を作らないこと（同じ経路の支出の手入力は覚える）。収入・振替の記録の中身の変更・分類の変更（`rule_learned` が false）で支出の規則が残ること。
- `scripts/household.test.mjs`（1 件）: `householdRuleLearnable` の判定（支出の分類・未分類・収入・振替・向きの違う分類・知らない分類）。

実データ・実機・実 API・実際の端末の画面は未実施で、合格扱いにしない。

## 残ること

- 保存済みの誤った規則（過去に上書きされて消えた支出の規則）は戻らない。本人が支出の分類を直せば覚え直す。
- U355 の本人の確認。
