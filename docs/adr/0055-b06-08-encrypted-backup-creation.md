## 守ること（含めないもの）

- 生音声・記録しない会話・OAuth トークン・API キーは DB の表にも封筒にも入らない。封筒の `excluded_data` に 4 つを必ず記録し、`included_storage_modes` は `normal`・`extended` だけ（`private` を入れない）。封筒を書く前に契約の Schema と domain の意味検査（`backupManifestProblems`）に通す。
- 含めない表 10 とその表が持つ暗号文は写しから消す（ADR 0047 の U73）。未知の表がある DB は取らない（`unknown_table`）。
- 復旧キー（256 ビット）は CLI のプロセスが作り、端末の画面（標準エラー）に 1 度だけ出す。Core・制御チャネル・HTTP・イベント・ログ・DB・バックアップ・標準出力の JSON に出さない（試験で確かめた）。
- 結果・ログには ID・件数・理由コードだけを入れる。鍵・復旧キー・置き場所のパス・本文は入れない（制御チャネルの状態の応答もパスを返さない）。

## 判断が要る点（司令塔）

1. **U127**: 設定をやり直すと復旧キーが新しくなり、古い復旧キーで包んだ古い封筒は古いキーで開く。この仕様（推奨 (a)）でよいか。バックアップがあるときの再設定を禁じる (b)・包み直す (c) もある。
2. **U126**: 台帳の系譜を「最初の忘却」ではなく「バックアップの設定」でも付ける（ADR 0054 の系譜の付け方を広げた）。
3. **U128〜U130**: 復元 CLI の復旧キーの入力（推奨: 端末の標準入力だけ）、U109 の手での復旧の手順（推奨: 復元の段階 1 の台帳の確認を使い、退避してから DB から作り直す）、復元先でのデータ鍵の導入（推奨: KeyStore に鍵がないときだけ `data-key-v1` に置く）。

## 既知の限界・未実施

- 本体はメモリに全体を読んで暗号化する。DB が大きくなったら分割の AES-GCM にする（B15 で実測）。
- 作業用の写しは平文の SQLite だが、DB 自体が暗号文（sealed_blobs）を含む設計で、機微な欄はもともと暗号化されている。写しは本人だけのディレクトリに置き、成否によらず消す。SSD の痕跡までは保証しない。
- Windows ではディレクトリの fsync を省略している（ADR 0054 の P2-5 と同じ）。初期の中枢は Mac mini。
- 設定の途中で止まったときに KeyStore に使われない鍵が残り得る（次の設定は新しい ID の鍵を作る）。
- 使えない同期フォルダー（判定できない独自の同期）は警告が出ない。
- 忘却の台帳の端末への複製（B06-07）が入るまで、復元の段階 1 の材料は中枢のファイルと封筒の台帳だけ。

## 後続への引き継ぎ（段階 2）

- 復元は `readPreRestoreState`（今の DB）→ 作業用の DB に段階 2〜5 → `applyRestoreAftermath` → 作業用の DB を閉じる → `installRestoredDatabase` → 起動、の順（ADR 0054）。封筒は `readBackupFileHeader`・`readBackupPayload`・`decryptBackupPayload`・`unwrapBackupKey` で開ける（この PR で用意した）。
- 封筒の `payload.sha256` と長さを開く前に照合する（段階 2 の `backup_unreadable`）。
- `ledger_hmac_key_id` は DB の `schema_meta` に記録済み。復元で鍵を入れるときの `keyInstallPlan`。
- `backup-state.json` の `first_seen`（初めて見た時刻）は掃除が記録している。復元で別の機器の封筒を開いたとき、`first_seen` がないときの期限の起点は ADR 0047 のとおり。
