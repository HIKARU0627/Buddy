- 日付: 2026-11-14
- 状態: B13-01（親 #24）の契約と規則。判定表の実行・保存・画面は未着手。実データ・実機は未実施。
- 根拠: 設計 08 §1・§5・§9、設計 11 §5・§5A、設計 09 X21・X23・X24・X40・X65、J10・J12、ADR 0010・0027・0047。原本の参照手順は `docs/design/README.md`。

## 決めたこと

| 対象                   | 決定                                                                                                                                                                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 方針による承認         | 自動実行の操作は、承認レコードの経路を `policy_auto` とし、使った方針の版・規則 ID・内容版・内容の hash・承認時刻を残す。古い方針の版で判定した承認を新しい内容へ流用しない                                                                               |
| 判定表の範囲           | 自動実行の対象は、用事の登録・自分だけの予定の作成・既存ラベルの付与・返信下書きの保存の 4 種類だけ。共通検査（安全停止・初回取り込み・許可版・根拠・未読・関連解析・鮮度）を通らない候補は自動実行せず、気づきだけにする。メール本文の指示を起点にしない |
| 自動実行の既定         | 4 種類はすべて既定 **OFF**。`AutoExecutionPolicy` の未設定・初期値は false で、T10 の合格後に本人が有効化する（D6）。下流の B13-02〜04 は、この契約を通らない有効状態を作れない                                                                           |
| 安全停止の件数         | 自動承認の時間窓は **10 分間に 20 件**を初期値とし、窓の開始時刻・件数・上限・分数を `SafetyStopCounters` に持つ。自動承認の記録と同じ transaction で数え、上限に達した時点で以後の自動承認を拒否する。値は T10 の結果で調整する（U178）                  |
| 停止の扱い             | 停止前に自動承認済みで送出前のものは保留にし、送出済みのものは通常の照合を続ける。停止の理由は既存の `rate_exceeded`・`same_target_repeated`・`compensation_failures`・`restored_from_backup` を使い、解除は登録済み・ロック解除済みの画面からだけにする  |
| 取り消し               | 取り消しは補償操作として新しい `operation_id` で扱い、元の操作を取り消し済みに書き換えない。対象の内容版と hash を `UndoTarget` に残し、実行の直前に現在値と照合する。変わっていれば自動で補償せず、差分を表示する                                        |
| 取り消しの期限         | 自動実行の完了から **30 日**までを取り消しの期限とする。期限を過ぎた・対象が変わった・補償が失敗した場合は `undo_state` を `expired`・`target_changed`・`unavailable` にし、成功として扱わない                                                            |
| 取り消しの再作成の抑止 | 取り消した操作と同じ候補・同じ内容版から、自動実行をやり直さない。再度実行するのは本人が明示的に依頼した場合だけとし、元の候補は `acted` のまま保つ                                                                                                       |
| 一覧                   | 既存の `AutoActionList`（安全停止の状態と自動実行の項目）を使う。項目は本文を含めず、操作 ID・種類・方針の版・状態の版・完了時刻・取り消しの状態と期限・取り消しの対象版だけを持つ                                                                        |
| 保存                   | 承認・自動実行・安全停止の件数・取り消しの記録は、B13-03 の同じ transaction で残す。この ADR はマイグレーションを追加しない                                                                                                                               |

## 原本に決めがない項目

- 安全停止の初期値は設計 08 §9 の「10 分間に 20 件」を仮の値とし、T10 で調整する（U178）。
- 自動実行の既定は D6（2026-11-01、本人の決定）で 4 種類すべて OFF。契約の既定値も OFF にし、T10 の合格後に本人が有効化する（U180）。
- 取り消しの再作成の抑止は、設計 08 §9 の「取り消しは補償操作」から導いた判断で、抑止の単位（候補・内容版・操作種別）をこの ADR で決めた（U179）。

## 契約の形

- `PolicyApprovalRecord` は `policy_auto` の承認だけを表し、画面承認の `ApprovalRequest` と混ぜない。トークン・ヘッダー・本文を持たない。
- `SafetyStopCounters` は `SafetyState.auto_approvals` にだけ置く。停止の判定は `autoApprovalAllowed` が持ち、窓が過ぎていれば新しい窓として数え直す。
- `AutoActionItem.undo_target` は取り消す対象の内容版と hash。対象がない・期限切れのときは null か `undo_state` で表す。
- 契約の列挙と domain の値は `scripts/policy-approval.test.mjs` が照合する。
