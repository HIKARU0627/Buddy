# ADR 0181: UI を上の中央の島（Dynamic Island 風）に合わせてそろえる（段階 0・1）

- 日付: 2026-11-27
- 状態: 段階 0（判断の記録）と段階 1（見た目の土台）。段階 1 は `apps/desktop` の UI レンダラーの角の丸み・動きの時間・共通の枠のクラス・色の規約に外れた 3 か所・停止のボタンの重さを直した。島そのもの（段階 2）・各画面の部品の置き換え（段階 3）・キャンバス表示の島の窓と入力バーのカプセル（段階 4）は**未着手**。試験は模擬（ソースの静的な検査・ビルドした CSS の検査・サーバー描画と DOM の試験）と、撮影用の起動（画面に出ないブラウザ）での撮影だけ。Electron の実画面・実機（macOS・Windows）・実際の読み上げソフトは**未実施**。
- 根拠: 本人の依頼（2026-11-27）「UI を Dynamic Island 風にして統一感のある UI にしてください」と、その場の質問への本人の回答（下の「本人の決定」）。ADR 0014（いつでも停止できる）、ADR 0024（HeroUI・色と記号・角丸・読み上げの約束）、ADR 0032（3 つの窓・端のつまみ・UI-04 の状態と停止の層）、ADR 0067（入力バーの大きさ）。
- 対象: `apps/desktop/src/renderer/styles.css`（角の丸みの 4 段・動きの時間）、`apps/desktop/src/renderer/shapes.ts`（形の対応表・共通の枠のクラス。新規）、画面のソース 11 ファイル、`scripts/renderer-shape.test.mjs`（新規）、`scripts/contrast.test.mjs`、`apps/desktop/src/main/renderer-build.test.ts`、`docs/b00/contract-map.md`（U390〜U400）。

## 本人の決定（2026-11-27）

1. **島の置き場所**: 画面の上の中央に新しく島を置く。これは ADR 0032 の「画面の端のつまみ」と、UI-04 の「4 つ目の窓は作らない」を、本人の決定として変える。
2. **統一**: 全体を島に合わせて改める。角の丸みを全体で 4 段（6px・12px・28px・完全な丸）にそろえる。
3. **島の色**: 配色に合わせる。ライトでは明るい面、ダークでは暗い面（黒で固定しない）。
4. **自動で広げる**: 承認待ちと操作の結果のときだけ広げる。それ以外は小さな島のままにする。

## 段階 1 で決めたこと（実装済み）

### 角の丸みの 4 段

`styles.css` の `@theme` に定め、画面のソースで使えるクラスを 4 つに限る（`scripts/renderer-shape.test.mjs` が確かめる）。

| 段       | クラス           | 値   | 使う場面                                                                                                             |
| -------- | ---------------- | ---- | -------------------------------------------------------------------------------------------------------------------- |
| 小       | `rounded-part`   | 6px  | 箱の中の小さな面（つまみの専用の記号の枠・音声の外部送信の印・予定の帯）、HeroUI のチェックボックス                  |
| 箱       | `rounded-box`    | 12px | カード・Alert・確認のダイアログ・ツールチップ・キーの形・入力欄・枠・状態のタイル・引用の段・キャンバスの物の外枠    |
| 島       | `rounded-island` | 28px | 上の中央の島が広がった形と、島に準じる大きな浮いた面（段階 2 以降で使う。段階 1 では HeroUI の大きな段の行き先だけ） |
| 完全な丸 | `rounded-full`   | —    | ボタン・札・Tabs・閉じるボタン・ダイアログの記号・円の印・細い棒（進み具合）。高さの決まった物だけ（箱には使わない） |

- **HeroUI の段の寄せ方**: HeroUI の部品は中で `rounded-xs`〜`rounded-4xl`・`rounded-field`・`calc(var(--radius) * n)` を使う。`@theme` で `--radius-xs`・`sm`・`md` を小、`lg`・`xl`・`field` を箱、`2xl`・`3xl`・`4xl` を島に寄せ、`--radius`・`--field-radius` を箱にした。そのうえで、画面で使う部品（Card・Alert・AlertDialog・Tooltip・Kbd は箱、Button・Chip・CloseButton・AlertDialog の記号・Tabs・ProgressBar は完全な丸）は components 層で値を明示した（HeroUI の内部の段の使い方が変わっても見た目が動かないように）。`calc(var(--radius) * 2.5)` など、4 段の外になる計算を使う HeroUI の部品（ColorPicker・DatePicker・Table・Avatar）は今の画面で使っていない。使うときは components 層で 4 段のどれかを明示する。
- **キャンバスの物**: 外枠（フォーカスの輪・ドラッグの範囲）は `rounded-3xl` で、中の Card（`--radius-lg`）と丸みが合っていなかった。どちらも箱（12px）にした。

### 動きの時間

- `:root` に `--motion-move`（150ms。キャンバスの物の位置・大きさ）・`--motion-panel`（180ms。パネルの滑り込み）・`--motion-island`（320ms。島の伸び縮み。段階 2 以降で使う）を置き、`@media (prefers-reduced-motion: reduce)` ではすべて `0s` にする。動きの曲線 `--ease-island` も `@theme` に置いた（段階 2 以降で使う）。
- クラスの側も二重に止める: 位置・大きさを動かす `transition-[…]` には `duration-(--motion-*)` と `motion-reduce:transition-none` を付け、`animate-*` は `motion-safe:` を付ける。時間を数で書いた `duration-150` などは使わない（静的な検査で確かめる）。
- パネルの滑り込みは `motion-safe:animate-status-panel-in`（`--animate-status-panel-in` を `@theme` に置いた）にし、時間を `--motion-panel` にした。macOS の窓の `setBounds` の動き（main。UI-04）は今までどおり OS の「視差効果を減らす」で付けない。島の窓の伸び縮みも同じにする（段階 2・4）。

### 共通の枠のクラス（`shapes.ts`）

HeroUI の部品を使わず Tailwind のクラスで描いていた枠・入力欄・札が、画面ごとに `rounded-md`・`rounded-lg` と境界の色がばらばらだったので、定数にまとめた。

| 定数                 | クラス                                                                                         | 使う場面                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `FRAME_CLASS`        | `rounded-box border border-separator`                                                          | 一覧の行・編集の欄・引用の段（家計簿・気づき・確認が必要な操作の候補） |
| `FRAME_DANGER_CLASS` | `rounded-box border border-danger-soft-foreground`                                             | 取り消せない操作（削除）の確認、安全停止の欄（記号と文言は中に置く）   |
| `FIELD_CLASS`        | `rounded-box border border-field-border bg-transparent px-2 py-1 text-sm text-foreground`      | HeroUI の入力欄を使わない select・日付・数の欄（家計簿）               |
| `BADGE_CLASS`        | `inline-flex h-5 items-center rounded-full border border-separator px-2 text-xs font-semibold` | 小さな札（気づきの種類・予算の種類）                                   |

### 色の規約に外れていた箇所

意味（どの状態か）は変えず、`tones.ts` の色と記号の対応に合わせた。

- **家計簿の入力の誤り（追加の欄・予算の欄）**: `text-danger` の文字だけだった。`--danger` は塗りのボタンの面の色で、ダークの面の上の文字としては 3.45:1（ADR 0024 UI レビュー 2 回目 3）。`StatusText` の danger（⚠ ＋ `--danger-soft-foreground`）にした。ライブ領域にはしない（入力のたびに読み上げない。今までどおり）。
- **家計簿の予算の超過の金額**: `text-danger` の文字だけだった。⚠ ＋ `--danger-soft-foreground` にした（文言「n 円の超過」は変えない）。
- **家計簿の select・数の欄の境界**: `border-separator`（区切り線の色。入力欄の境界としての 3:1 は測っていない）だった。ADR 0024 で 3:1 を測った `--field-border`（`FIELD_CLASS`）にした。
- **状態の層のパネルの停止**: `variant="danger"`（塗り）を `danger-soft` にした（上の表）。`danger-soft` の文字と面は ADR 0024 の表で 4.5:1 以上（ライト 6.80:1・ダーク 5.12:1）。

## 段階 2 以降の設計（計画。未実装）

### 島の形と色

- **小さな形**: 上の中央のカプセル（完全な丸）。入出力の記号、承認待ちの数、プライバシーと権限の専用の記号 3 つ（UI-04 のつまみと同じ順・同じ形の区別）、停止（U396）を置く。
- **広がった形**: 島の丸み（28px）。下へ広がり、上の端の位置は変えない。中身は承認待ちの 1 行（件数と、確認の入口のパネルを開くボタン）か、操作の結果の 1 行。
- **色**: 配色に合わせる（本人の決定 3）。面は HeroUI のテーマの変数で、縁取りは影の代わりの線（U398）。キャンバスのカードと同じ面の色でも、形と線で区別する。

### 自動で広げる・読み上げ（本人の決定 4）

- **広げるのは 2 つだけ**: 承認待ち（確認が必要な操作が増えた）と、操作の結果（承認・取消・照合・停止・再開の結果が届いた）。それ以外（接続・音声・保存モードの変化など）は小さな形の記号だけを変える。
- **フォーカスを奪わない**: 広げても前面・キー入力を取らない（UI-04 のつまみと同じく、状態の層は前面を奪わずに出す）。
- **読み上げ**（ADR 0024 約束 8 を改める。暫定 U394）: 承認待ちは件数が増えたときだけ `role="status"`（polite）で「確認が必要な操作が n 件あります」を読む。操作の名前・宛先・時刻は入れない（時刻が変わる値をライブ領域に入れない約束 8 は保つ）。操作の結果は、成功は `role="status"`、失敗は `role="alert"`（UI レビュー 3 回目 2 のまま）。押した行の下に同じ結果が出ている（パネル・従来の窓の欄が見えている）ときは、島の行はライブ領域にせず、同じ文を 2 回読ませない。
- **縮める**: 暫定（U395）。一定の時間で縮め、ポインター・キーボードのフォーカスが島にある間は縮めない（WCAG 2.2.1）。承認待ちの件数は小さな形に残る。
- **動きを減らす設定**: 大きさを一度に変え、中身を滑り込ませない（`--motion-island` が 0s）。main の窓の動きも付けない。

## 試験

- `scripts/renderer-shape.test.mjs`（新規）: 画面のソース（試験を除く。コメントを除く）の丸みのクラスが 4 つだけであること、`rounded-full` が高さの決まった物（同じ並びに `h-数`・`size-数`、または高さを入れた同じファイルの定数）だけにあること、位置・大きさを動かす transition が `duration-(--motion-*)` と `motion-reduce:transition-none` を持ち、時間を数で書かず、`animate-*` に `motion-safe:` があること、`shapes.ts` の 4 つの定数（手で書いた値）、`styles.css` の 4 段の値と HeroUI の段の寄せ方（手で書いた表）、`styles.css` のすべての `border-radius` が 4 段のどれかであること、動きを減らす設定で `--motion-*` がすべて `0s` になること、検査そのものが `rounded-3xl`・`rounded-md`・`rounded`・`rounded-[10px]`・`rounded-t-lg`・`md:rounded-lg`・高さのない `rounded-full`・数で書いた時間を見つけること。
- `apps/desktop/src/main/renderer-build.test.ts`: ビルドした CSS に 6px・12px・28px の値、`--radius-3xl` の寄せ先、カードと Alert が箱・ボタンと札が完全な丸、動きを減らす設定の 0s が出ていること。
- `scripts/contrast.test.mjs`: 共通の上書き（色を含まない）の一覧に `--field-radius` と `--motion-*` を足した（手で書いた一覧）。色の値は変えていないので、測った比は ADR 0024 の表のまま。
- 既存の試験（renderer の試験すべてと、main の `renderer-build`・`window-roles`・`status-panel`。StatusPanel・CanvasBoard・parts・家計簿・気づき・予算・確認が必要な操作・登録の画面などを含む 435 件）は、期待値を変えずに通った。

## 撮影での確認（模擬）

撮影用の起動（ビルドした renderer を画面に出ないブラウザで開き、模擬の状態を渡す。Electron の実画面ではない）で、従来の窓（端末・登録）、状態の層のつまみとパネル、入力バー（小さめ・入力中・聞き返し）、キャンバス（後ろ・前・ロック中）をライトとダークで撮り、変更前と見比べた。

- 変わった点: カード・Alert・入力欄の角が 12px になった。ボタンが錠剤型、キーの形（全体の停止のショートカット）が 12px、入力バーの右のボタン・つまみの下のボタン（記号だけのボタン）が円になった。パネルの停止が塗りから薄い面（状態帯と同じ重さ）になった。状態のタイル・音声の欄は 12px、つまみの専用の記号の枠・予定の帯は 6px。
- 崩れ: 見つからなかった（文字のはみ出し・重なり・行の折り返しの変化はない）。CSP の違反・ページの例外は 0 件。
- 見ていないもの: 家計簿・気づき・自動実行の欄の中身（撮影用の起動では「まだ取得できていません」。枠・札・入力欄の変更はサーバー描画と DOM の試験だけで確かめた）、中枢の画面（Tabs・閉じるボタン）、フォーカスの輪の形、文字の拡大（200%）、ハイコントラストの設定。

## 読み取り（レビュー対象）

- **ボタンを錠剤型に戻した**（U390）: ADR 0024 の UI レビュー 1 回目で錠剤型をやめたのは、角丸を 1 段にそろえるためだった。この ADR は 4 段の 1 つに「完全な丸」を持ち、島（カプセル）と同じ形をボタンにも使うほうが、本人の「統一」に合うと読んだ。
- **島の段（28px）は段階 1 では画面で使っていない**: HeroUI の大きな段（`2xl`〜`4xl`）の行き先としてだけ置いた。今の画面でこの段を使う部品（Drawer・Modal など）はない。
- **入力の誤りの文の色**: 家計簿の 2 文は FieldError（記号なし）と同じ扱いにもできるが、`tones.ts` の danger の行（⚠）に合わせた。登録の画面のコードの誤り（`PairingPanel` の記号なしの 1 文）は段階 3 で同じ形にそろえる。
- **静的な検査の限界**: クラスの文字列を読む検査で、実行時に組み立てるクラス（別のファイルの定数を埋め込むなど）までは追わない。`rounded-full` の高さの判定は、同じファイルの `const` だけを展開する。
