# ADR 0102: B10-05 P3 抽出前フィルターと判定の記録・抽出の入口

- 日付: 2026-11-14
- 状態: B10-05（親 #18、Issue #244）P3 の判断。抽出前フィルターの規則（domain）と、フィルター → 予算の受付 → 抽出 → 精算の入口（Core）だけ。関連集合の計画と実行直前の照合は P4。判定の記録の保存（DB）・診断画面・候補の生成は未着手。実 API・API キー・実請求・実メールは未実施（B15 と本人の承認まで扱わない）。
- 根拠: 設計 11 §2・§3・§5B、設計 09 X38・X62・QA10・QA45、ADR 0007・0070・0100・0101。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。

## 決めたこと

| 対象               | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外す条件           | **条件 A（自動配信）と条件 B（期限・依頼・変更の手がかりがない）の両方**を満たすときだけ LLM の解析から外す（`skip_automated`、規則 ID `prefilter_automated_no_cue_v1`）。どちらか一方だけなら外さない                                                                                                                                                                                                                                                                                                                                                                                                              |
| 条件 A             | `Auto-Submitted`（`no` 以外。`;` 以降のパラメーターは見ない）、`Precedence`（bulk・list・junk）、`List-Unsubscribe`、送信者のローカル部が no-reply・noreply・donotreply・mailer-daemon・notification(s)・newsletter のいずれか。大文字小文字を区別しない。ローカル部は完全一致（部分一致で人を自動配信にしない）                                                                                                                                                                                                                                                                                                    |
| 条件 B             | 件名・本文（**引用の行を除く**）・許可範囲内で選んだ添付の抽出テキストのすべてに、日付表現・期限語・依頼語・変更語（設計 11 §2 の語）がない。語は広めに拾う（含んでいれば手がかりあり。外しすぎない側）。設計 11 §2 の一覧より広げ、年なしの「11/30」「20日」「11月」と、英語の月名と日・曜日・相対語（tomorrow・next week・EOD など。月名は日の数字と組み合わさったものだけ）も日付の手がかりにする（U246）。本文が未取得、許可対象の添付が未取得・読取失敗・抽出が途中までなら**条件 B は未確定**で、期限なしとして外さず解析する（`cue_undetermined`）。許可範囲外の添付は見ない・取得しない・未確定にも数えない |
| 例外               | 本人が「このメールを見て」と頼んだ（`user_requested`）、同じスレッドに依頼候補・抽出待ち・自動実行履歴がある（`thread_activity`、U244）、設定でフィルターが OFF（`filter_disabled`）は、条件に関係なく解析する。`text/calendar` の招待は LLM に送らず予定はカレンダー連携で扱う（`handled_elsewhere`）。本人が頼んだ招待は解析する（U245）                                                                                                                                                                                                                                                                          |
| 宛先・自動配信     | `addressed_to_me`（To に本人のアドレスがある。CC だけは false）と `from_automated_sender`（条件 A）は、ヘッダーから Core が決める（`deriveMessageFacts`）。モデルへアドレスを渡さず、入力の型にアドレスの欄を持たない                                                                                                                                                                                                                                                                                                                                                                                               |
| 判定の記録         | 本文なしのメタデータ（アカウント・メッセージ・版・判定・理由・規則 ID・時刻）。件名・本文・宛先を持たない。**診断用の別の口**（`PrefilterRecordSink`）に渡し、候補（気づき）の保存先には渡さない。記録の失敗で解析を止めない。診断の件数（解析済み・自動配信のため未解析・招待は別経路）は、同じメッセージ・版の最後の判定だけを数える                                                                                                                                                                                                                                                                              |
| 抽出の入口         | 判定 → 記録 →（解析する場合だけ）入力の検査 → 予算の受付 → 抽出（1 回）→ 精算。**外したメールは予算の受付も LLM の呼出しもしない**。入力が組み立てられないメールも受付しない。受付の拒否・口の失敗は送らず、`pending`（予算待ち。空の成功にしない）。アダプターが例外を投げたときは、送った可能性があるので usage 不明（`settle(null)`）で予約を保ち、再送しない                                                                                                                                                                                                                                                    |
| 関連解析への写し   | 外したメールは、**規則 ID 付きの除外**（`excluded`）。招待は `prefilter_calendar_invite_v1`。解析したメールは P2 の `analysisStateOfExtraction`（analyzed・pending・unread・failed）。規則 ID なしの除外・未読の空の結果で ready にならない                                                                                                                                                                                                                                                                                                                                                                         |
| 添付の抽出の切詰め | 添付の抽出テキスト自体が途中までのとき（`extraction_truncated`）、送った分に収まっても切詰めとして記録する（P1 の入力に追加）。**空・空白だけの抽出テキストでも、抽出が途中までだった添付は切詰めとして記録する**（送るものが無くても、読めていない範囲が残る。読めた集合として ready にしない）。この ID も切詰めの一覧に載るので、入力の枠の見積り（付加部分）に数える                                                                                                                                                                                                                                            |

## 試験（模擬だけ）

`scripts/extraction-filter.test.mjs`・`apps/core/src/mail-extraction.test.ts`（手書きの期待値）:

- X38: 自動配信で手がかりのないメールは LLM 呼出し 0 回・予算の受付 0 回で、規則 ID 付きの除外になる。自動配信でも「10月7日までに」があれば解析する。本人の依頼があれば手がかりなしでも解析する。診断の件数は記録に従い、記録に本文を含めない。
- X62: 本文が「添付参照」だけで、期限が選択した添付にあるときは解析し、根拠は添付の位置に一致する。添付の抽出失敗・未取得・途中までのときは外さず解析し、結果は未読で関連解析が ready にならない。許可範囲外の添付は見ず、取得もしない。自動配信への用事・下書きの既存の制限は残る（P2）。
- 条件 A の各ヘッダー・ローカル部の単独成立、`no` の許容、部分一致の否定。条件 B の各語（大文字小文字）、引用の中だけの語は手がかりにならない。
- スレッドの履歴・フィルター OFF・招待の扱い。宛先の判定（CC だけは本人宛てでない）、モデルへ渡す入力にアドレスがないこと。
- 予算の拒否・口の失敗は送らず `pending`。成功は usage を 1 回精算。例外は usage 不明で精算。読める内容のないメールは受付しない。
- 判定の要点（未確定を外さない・スレッドの履歴・本人の依頼・切詰め・許可範囲）を壊した実装で試験が失敗することを確認した。

**模擬のみ**。実 API・実メール・実請求・実機は未実施。削減効果（設計時の仮定は 3〜5 割）は実データで測るもの（T08）で、未測定。
