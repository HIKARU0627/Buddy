# ADR 0181: UI を上の中央の島（Dynamic Island 風）に合わせてそろえる（段階 0〜4）

- 日付: 2026-11-27
- 追記（2026-11-27、段階 2）: 従来の窓（配布版の標準の画面）の上の中央に島を作った（下の「段階 2 で決めたこと」）。U390〜U400 は本人の確認を待たずに暫定の案のまま進める（本人は試験と見直しを後でまとめて行う）。U395 の時間を決めた（結果 6 秒・確認が必要な操作 8 秒）。
- 状態: 段階 0（判断の記録）と段階 1（見た目の土台）。段階 1 は `apps/desktop` の UI レンダラーの角の丸み・動きの時間・共通の枠のクラス・色の規約に外れた 3 か所・停止のボタンの重さを直した。段階 2 で従来の窓の島を作った。段階 3 で各画面の部品を置き換え、段階 4 でキャンバス表示の島の窓と入力バーのカプセルを作った（下の「段階 3 で決めたこと」「段階 4 で決めたこと」）。試験は模擬（ソースの静的な検査・ビルドした CSS の検査・サーバー描画と DOM の試験）と、撮影用の起動（画面に出ないブラウザ）での撮影だけ。Electron の実画面・実機（macOS・Windows）・実際の読み上げソフトは**未実施**。
- 根拠: 本人の依頼（2026-11-27）「UI を Dynamic Island 風にして統一感のある UI にしてください」と、その場の質問への本人の回答（下の「本人の決定」）。ADR 0014（いつでも停止できる）、ADR 0024（HeroUI・色と記号・角丸・読み上げの約束）、ADR 0032（3 つの窓・端のつまみ・UI-04 の状態と停止の層）、ADR 0067（入力バーの大きさ）。
- 対象: `apps/desktop/src/renderer/styles.css`（角の丸みの 4 段・動きの時間）、`apps/desktop/src/renderer/shapes.ts`（形の対応表・共通の枠のクラス。新規）、画面のソース 11 ファイル、`scripts/renderer-shape.test.mjs`（新規）、`scripts/contrast.test.mjs`、`apps/desktop/src/main/renderer-build.test.ts`、`docs/b00/contract-map.md`（U390〜U400）。

## 本人の決定（2026-11-27）

1. **島の置き場所**: 画面の上の中央に新しく島を置く。これは ADR 0032 の「画面の端のつまみ」と、UI-04 の「4 つ目の窓は作らない」を、本人の決定として変える。
2. **統一**: 全体を島に合わせて改める。角の丸みを全体で 4 段（6px・12px・28px・完全な丸）にそろえる。
3. **島の色**: 配色に合わせる。ライトでは明るい面、ダークでは暗い面（黒で固定しない）。
4. **自動で広げる**: 承認待ちと操作の結果のときだけ広げる。それ以外は小さな島のままにする。

## 段階 1 で決めたこと（実装済み）

### 角の丸みの 4 段

`styles.css` の `@theme` に定め、画面のソースで使えるクラスを 4 つに限る（`scripts/renderer-shape.test.mjs` が確かめる）。

| 段       | クラス           | 値   | 使う場面                                                                                                             |
| -------- | ---------------- | ---- | -------------------------------------------------------------------------------------------------------------------- |
| 小       | `rounded-part`   | 6px  | 箱の中の小さな面（つまみの専用の記号の枠・音声の外部送信の印・予定の帯）、HeroUI のチェックボックス                  |
| 箱       | `rounded-box`    | 12px | カード・Alert・確認のダイアログ・ツールチップ・キーの形・入力欄・枠・状態のタイル・引用の段・キャンバスの物の外枠    |
| 島       | `rounded-island` | 28px | 上の中央の島（小さい形と広がる形。段階 2）と、島に準じる大きな浮いた面。HeroUI の大きな段の行き先                    |
| 完全な丸 | `rounded-full`   | —    | ボタン・札・Tabs・閉じるボタン・ダイアログの記号・円の印・細い棒（進み具合）。高さの決まった物だけ（箱には使わない） |

- **HeroUI の段の寄せ方**: HeroUI の部品は中で `rounded-xs`〜`rounded-4xl`・`rounded-field`・`calc(var(--radius) * n)` を使う。`@theme` で `--radius-xs`・`sm`・`md` を小、`lg`・`xl`・`field` を箱、`2xl`・`3xl`・`4xl` を島に寄せ、`--radius`・`--field-radius` を箱にした。そのうえで、画面で使う部品（Card・Alert・AlertDialog・Tooltip・Kbd は箱、Button・Chip・CloseButton・AlertDialog の記号・Tabs・ProgressBar は完全な丸）は components 層で値を明示した（HeroUI の内部の段の使い方が変わっても見た目が動かないように）。`calc(var(--radius) * 2.5)` など、4 段の外になる計算を使う HeroUI の部品（ColorPicker・DatePicker・Table・Avatar）は今の画面で使っていない。使うときは components 層で 4 段のどれかを明示する。
- **キャンバスの物**: 外枠（フォーカスの輪・ドラッグの範囲）は `rounded-3xl` で、中の Card（`--radius-lg`）と丸みが合っていなかった。どちらも箱（12px）にした。

### 動きの時間

- `:root` に `--motion-move`（150ms。キャンバスの物の位置・大きさ）・`--motion-panel`（180ms。パネルの滑り込み）・`--motion-island`（320ms。島の伸び縮み。段階 2 以降で使う）を置き、`@media (prefers-reduced-motion: reduce)` ではすべて `0s` にする。動きの曲線 `--ease-island` も `@theme` に置いた（段階 2 以降で使う）。
- クラスの側も二重に止める: 位置・大きさを動かす `transition-[…]` には `duration-(--motion-*)` と `motion-reduce:transition-none` を付け、`animate-*` は `motion-safe:` を付ける。時間を数で書いた `duration-150` などは使わない（静的な検査で確かめる）。
- パネルの滑り込みは `motion-safe:animate-status-panel-in`（`--animate-status-panel-in` を `@theme` に置いた）にし、時間を `--motion-panel` にした。macOS の窓の `setBounds` の動き（main。UI-04）は今までどおり OS の「視差効果を減らす」で付けない。島の窓の伸び縮みも同じにする（段階 2・4）。

### 共通の枠のクラス（`shapes.ts`）

HeroUI の部品を使わず Tailwind のクラスで描いていた枠・入力欄・札が、画面ごとに `rounded-md`・`rounded-lg` と境界の色がばらばらだったので、定数にまとめた。

| 定数                 | クラス                                                                                         | 使う場面                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `FRAME_CLASS`        | `rounded-box border border-separator`                                                          | 一覧の行・編集の欄・引用の段（家計簿・気づき・確認が必要な操作の候補） |
| `FRAME_DANGER_CLASS` | `rounded-box border border-danger-soft-foreground`                                             | 取り消せない操作（削除）の確認、安全停止の欄（記号と文言は中に置く）   |
| `FIELD_CLASS`        | `rounded-box border border-field-border bg-transparent px-2 py-1 text-sm text-foreground`      | HeroUI の入力欄を使わない select・日付・数の欄（家計簿）               |
| `BADGE_CLASS`        | `inline-flex h-5 items-center rounded-full border border-separator px-2 text-xs font-semibold` | 小さな札（気づきの種類・予算の種類）                                   |

### 色の規約に外れていた箇所

意味（どの状態か）は変えず、`tones.ts` の色と記号の対応に合わせた。

- **家計簿の入力の誤り（追加の欄・予算の欄）**: `text-danger` の文字だけだった。`--danger` は塗りのボタンの面の色で、ダークの面の上の文字としては 3.45:1（ADR 0024 UI レビュー 2 回目 3）。`StatusText` の danger（⚠ ＋ `--danger-soft-foreground`）にした。ライブ領域にはしない（入力のたびに読み上げない。今までどおり）。
- **家計簿の予算の超過の金額**: `text-danger` の文字だけだった。⚠ ＋ `--danger-soft-foreground` にした（文言「n 円の超過」は変えない）。
- **家計簿の select・数の欄の境界**: `border-separator`（区切り線の色。入力欄の境界としての 3:1 は測っていない）だった。ADR 0024 で 3:1 を測った `--field-border`（`FIELD_CLASS`）にした。
- **状態の層のパネルの停止**: `variant="danger"`（塗り）を `danger-soft` にした（上の表）。`danger-soft` の文字と面は ADR 0024 の表で 4.5:1 以上（ライト 6.80:1・ダーク 5.12:1）。

### 島の形と置き場所

- **置き場所**: 窓の上端の細い帯（「Buddy」と画面の役割）の下、本文の列の上の中央。スクロールしても窓の上（上から 8px）に貼り付いて残る（停止がいつも見えて 1 回で押せる）。上端の細い帯は窓の題（h1 と画面の役割）として残した（計画では島にまとめるとしていたが、島に入れると 960 の窓の本文の列（720）に 1 行で収まらないため）。
- **小さい形**（いつも出す。U396）: 「入出力:」と入出力の記号＋文言（ライブ領域。状態帯から移した）、「中枢:」と中枢との接続、停止のボタン（`danger-soft`・錠剤型。止まっていないときだけ。横に全体の停止のショートカットのキーの形）。未受信・ロック中・ロック状態不明では、内容を隠した旨（ライブ領域）と停止だけ。確認が必要な操作の件数は小さい形に入れない（従来の窓では同じ画面に一覧があり、島の幅を増やさないため。キャンバス表示の島は段階 4 で決める）。
- **広がる形**: 小さい形の下に区切り線を引き、1 行を足す。確認が必要な操作のときは、右に「確認が必要な操作を見る」（同じ画面の「確認が必要な操作」の見出しへフォーカスを移す）。承認・取消のボタンは島に置かない。承認は今までどおり行の「内容を確認」から OS の確認ダイアログで 1 回。
- **色と縁**: 面は `--surface`、縁取りは `--border`（U398 の暫定 (a)）。影は使わない。文字と記号は ADR 0024 の表で測った組み合わせ（カードの面の上の文字・記号）だけを使う。
- **項目の行**（U397 の暫定 (a)）: 中枢が正本の 5 項目と「（— は中枢から未受信）」を、島の下に中央寄せで小さく並べる（畳まない）。

### 何を出すかの優先の順（`islandView`）

1. 内容を隠している（未受信・ロック中・ロック状態不明）なら、広げない（届いた知らせも出さない）。
2. 失敗の結果（行の知らせが拒否、または結果を待っていた操作が「結果を確認できませんでした」になった）。6 秒。
3. 確認が必要な操作が増えた（承認待ち・結果不明・届いたか分からない保留。WorkPanel の「確認が必要な操作」と同じ数え方）。8 秒。件数が減ったら畳む。
4. 成功・中立の結果（承認を送った・取消を依頼した・完了した・実行されなかった・取り消した など）。6 秒。
5. どれもなければ小さい形のまま。

- **島に出す「操作の結果」の範囲**: 確認が必要な操作（WorkPanel）の、(a) 行の知らせ（本人が押した承認・取消・照合・再試行・状態の確認の受付と拒否）と、(b) 結果を待っていた操作（承認待ち・承認済み・準備中・実行中・照合中・届いたか分からない保留）が結果の状態（完了・結果不明・実行されなかった・取り消した）へ移ったこと。内容の更新で使われなくなった（superseded）は含めない。初めて見た操作（起動・接続し直し・ロック解除の直後）は前の状態が分からないので結果にしない。停止・再開の結果は入出力の行（ライブ領域）と停止の帯が出すので、島では広げない。中枢の画面の申請の承認・拒否・失効の結果は、その欄の知らせのまま（島に出さない）。
- **時間（U395 の暫定の値）**: 結果は 6 秒、確認が必要な操作は 8 秒（件数と行き先のボタンを読めるよう長めにした）。ポインターかキーボードのフォーカスが島にある間は畳まない（触れ始めた時点で広がっていたものだけ。触れても閉じたものは開き直さない）。時刻は 1 秒ごとの画面の時刻で比べるので、畳むのは最大 1 秒遅れる。
- **数え始め**: 確認が必要な操作の件数は、見せられない間（ロック中・切断中・未登録）は 0 とみなす。ロック解除・接続し直しの後に確認が必要な操作があれば、一度だけ広げて読む。

### 島の窓（U391 の暫定 (b)）

- **役割とチャネル**: 新しい役割 `island`。使えるのは、状態の取得（`desktop.get_state`・`desktop.get_connection`・`desktop.get_voice`）、停止（`desktop.io_stop`）、パネルを出す（`desktop.status_panel`）だけ。承認・取消・再試行・照合・再開・登録・失効・終了・発言・キャンバスを前に出す・キャンバスの物の操作と中身は使えず、main の役割の検査で `untrusted_sender` になる。受ける通知は状態欄・接続の状態・音声の状態だけ（電源とロックの記録・キャンバスの記述は受けない）。
- **「状態の取得」に 3 つを入れた理由**: 島の小さな形は、確認が必要な操作の数（接続の状態の中の操作の一覧から数える）と、専用の記号の「音声を外部へ送っている」（音声の状態）を出す。どちらも読むだけのチャネルで、ロック中・不明は main が内容を隠す。窓を開いた直後の値を取るために、通知だけでなく取得の要求も要る。
- **島からは確認を出さない**: 確認が必要な操作で広がったときの「確認が必要な操作を見る」は、パネルを出す要求（`status_panel` の `open: true`）だけを送る。OS の確認ダイアログの親はパネルのまま（UI-04 の確認の親の決め方を変えない）。
- **窓の作り方**: 作業領域の上の中央（上端から 8）、560 × 48。枠なし・最前面（`floating`）・タスクバーに出さない・すべてのデスクトップに出す・画面共有から守る（状態の層と同じ）。前面を奪わず、キー入力も受けない（`focusable: false`。U401）。macOS はパネル型。
- **島の窓の大きさ**: 画面が描いた島の中身の高さを、main が `webContents` の `preferred-size-changed`（`enablePreferredSizeMode`）で受け取り、48 を超えれば 560 × 104、そうでなければ 560 × 48 にする（`islandExpandedFor`）。上の端は固定し、下へ伸ばす。新しいチャネルは作らず、画面は 2 つの決まった大きさのどちらかを選ばせるだけ（位置と大きさの値は main が決める）。窓の動きは付けない（窓は透明で、見える伸び縮みは画面が描く。動きを減らす設定では画面も動かさない）。
- **島の中身**: 小さい形は、入出力の記号と文言（ライブ領域）、状態のパネルを出すボタン（中に確認が必要な操作の数・専用の記号 3 つ・パネルの記号。読み上げの名前に要約と専用の記号の状態を入れる）、停止（`danger-soft`。見える文字は「■ 停止」、読み上げの名前は「入出力を停止」。止まった後は出さない）。未受信・ロック中・ロック状態不明では、内容を隠した旨（ライブ領域）、パネルを出すボタン（記号だけ）、停止だけ。広がる形は段階 2 と同じ優先の順と時間（結果 6 秒・確認が必要な操作 8 秒。ポインターが島にある間は畳まない）で 1 行を足し、長い行は 1 行で切る（全文は読み上げとパネルで分かる）。
- **島に出す結果の範囲**: 島の窓には行の知らせ（パネルの `WorkOperations` が持つ）がないので、結果は「結果を待っていた操作が結果の状態へ移った」ことだけ。本人がパネルで押した承認・取消などの受付と拒否は、押した行のすぐ下の知らせ（パネル）だけに出る。
- **ライブ領域**: 入出力の 1 行のライブ領域を、パネル（`StatusPanel` の `role="status"`）から島へ移した。パネルの入出力の 1 行は見せるだけ（島とパネルの両方が表示されている間に、同じ文を 2 回読ませない。U394）。

### 状態の層のパネル（U392 の暫定 (a)）
