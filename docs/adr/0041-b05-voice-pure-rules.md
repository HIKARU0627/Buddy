## 判断が要る点（原本に決めなし。本人の確認待ち）

`docs/b00/contract-map.md` の U28・U30〜U37 に同じ内容を記録した。

1. **再生停止の ACK が返らないときの全停止の理由（U30）**: ADR 0038 の「原本に決めがない項目」を、新しい理由を足さず既存の `device_io_stop`（local）で解いた。音声レンダラーは応答しないので強制終了で止め、端末は画面で明示再開するまで再開しない（安全側）。理由の名前が実態（再生停止の障害）と違うので、別の理由を足す案（表・Schema・fixture の変更）に異論があれば直す。
2. **「ちょっと待って」の 1 回（U33）**: 「言うたびに、次の 1 つの無音の区間だけ 60 秒（重ねない）」と読んだ。接続ごと・会話ごとに 1 回に絞る案もある。
3. **世代の進め方（原本に決めなし）**: Live の開始・再接続・端末交代はすべて audio と session を 1 つずつ進める（前の接続の結果・音声を新しい接続へ付け替えないため）。停止時の端末の世代は、stop_playback と close が output、suspend_io が io と output（原本は stop_playback の output_epoch だけを明記）。
4. **時計の整合の許容（U31）**: 単調時計と壁時計の進みの差 1000 ms を仮置き（T04・T07 の実測まで。合格値ではない）。
5. **無音の判定の主体（U32）**: 設計 10 §3（v0.5）に従い main だけが判定する。`voice.set_silence_timeout` は main が音声レンダラーへ今の猶予を知らせる値として残し、契約は変えない。
6. **通知の制限中の気づき（U35）**: 待ちの列に残して次の読み上げにまとめる（画面通知は別経路で常に出る）。
7. **ASR の比較の規則（U36）**: 初期の規則で、4 種類以外の差は検出しない。名前のかな書きと漢字書きは聞き返す側に倒す。宛先は名前だけで比べ、敬称の違いは同じ人とする。
8. **方式 C と handoff_screen（U37）**: `admitMethodC` は 4 操作だけを進め、`handoff_screen` は全文の確定へ戻す。`intents.ts` の表（handoff_screen の `liveTranscript` は true）は変えていない。どちらに揃えるか決めてほしい。
9. **予算失敗時にサイドバンドが使えない（U34）**: 伝える相手がいないのですぐ閉じて③へ。
10. **「まだ接続中」の効果音の閾値**: 原本は「目標 1.5 秒、許容 3 秒。超えたら」と書くだけなので、許容（3 秒）を超えたら、と読んだ。

## 解決しなかったこと

- **サイドバンド接続済みの音声レンダラーへの伝え方（U28 の残り）**: `evaluateLiveStartGate` は main が持つ事実（session.started・サイドバンド接続済み）から送信トラックを有効にしてよいかを返すだけで、renderer への伝え方（7 つ目の IPC か start の再送か）は決めていない。契約は 6 つの IPC のまま。
- 設定 `voice.same_connection_playback_resume` の置き場所（ADR 0038 が B05-02 に残した項目）。実行時の設定の読み込みを作る作業で決める。
- 実際の音声・時計・スリープ・ACK の時間・Live の offset と端末の sample の対応・ASR の精度は、すべて未実施（T04・T08、実機・実 API の 2 段階の試験）。

## 試験（模擬のみ）

`scripts/voice-rules.test.mjs`（ビルド後の domain）と、`packages/contracts/fixtures/` の `voice-lease-clock-cases.json`・`voice-epoch-cases.json`・`voice-stop-timing-cases.json`・`voice-silence-cases.json`・`voice-reservation-cases.json`・`voice-notification-rate-cases.json`・`voice-start-gate-cases.json`・`voice-segment-cases.json`・`voice-method-c-cases.json`・`voice-asr-compare-cases.json`。`session-control-phrases.json` には表の意味検査と解決の例を足した。期待値は手書きで、実装から生成していない。

- 拒否の側: 世代の逆行、遅着の ACK・リースの応答、使えない時計、期限ちょうどと 1 ms 前後（リース・ACK・無音・予算の閉じ・通知の間隔・60 秒のリング・15 秒のつなぎ・サイドバンドの 3 秒・300 ms の安定）、同時（同じ言い回しの重ね、同じ時刻の画面操作と判定、発話の終わりと予算の閉じ）、時計の戻り（リース・無音・通知・停止・予算の閉じ）。
- 全ての組を試すもの: 世代の大小、停止の理由ごとの手順と停止の表（`audio.ts`）との整合、要求から 0〜400 ms の各時点、接続開始の門の 16 通り、全ての意図の方式 C への分類、使用秒数 0〜20 秒の精算。
- **変異試験**: domain の `dist` に 52 通りの変異（境界の比較を 1 つずらす・時計の検査を外す・15 秒の下限を外す・条件の分岐を外す・照合表の検査を外す等）を入れて試験を走らせ、全て失敗することを確かめた（最初は生き残った 2 通り（質問の言い回し「ですか」の単独・通知のまとめの境界）の fixture を足して全て失敗させた）。変異を戻して通ることを確かめている。試験で実装の誤り 1 件（「メール」をひらがなへそろえた後の宛先の取り出し）を見つけて直した。
- 実際の音声・実 API・実機・実請求の試験は**未実施**。契約 CI の成功を製品の試験の合格として扱わない。`tests/test-map.json` は、X13・X25・X30・X34・X35・X51・X54・X55・X58・QA05・QA06・QA08・QA41・QA43 の契約 fixture を足した（`product_test` は `not_run` のまま。X35・X55・QA08 は `specified` から `contract_fixture`）。
