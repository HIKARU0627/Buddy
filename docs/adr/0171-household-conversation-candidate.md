# ADR 0171: 会話の一言からの家計の記録の候補（家計簿 段階 3 の一部）

- 日付: 2026-11-26
- 状態: 家計簿の段階 3 の部分。メールの届かない支出（現金の支払いなど）を、Buddy との会話の一言（「コンビニで 500 円使った」）から補う。一言を決まった規則で読み、家計簿の欄の手入力の入力欄（ADR 0167）に値を入れて開くところまでを作った。記録を作るのは、本人が入力欄で中身を確かめて「足す」を押したときだけ。**模擬の試験だけ**で、実データ・実機は未実施。
- 根拠: 本人の決定（段階 3: メールの届かない支出を会話の一言から補い、本人の手間を減らす）、ADR 0004・0005・0031・0158・0162・0167・0168。原本（非公開 Notion）に家計簿の決めはない（U318 以降と同じ）。
- 対象: `packages/domain/src/household-utterance.ts`（一言の読み方）・`household.ts`（店名だけの検査 `householdMerchantErrors`）、`apps/desktop` の renderer（`state/household-candidate.ts`・`work-state.ts`・`household-state.ts`、`screens/work/WorkPanel.tsx`・`screens/household/HouseholdPanel.tsx`・`App.tsx`）。契約（JSON Schema・OpenAPI・IPC）、Core、保存層、マイグレーションは変えない。

## 背景

手入力（ADR 0167）で現金の支出を足せるが、家計簿の欄を開き、向き・金額・日付・店名を一つずつ入れる手間がある。本人は会話の一言で済ませたい。一方で、LLM とクライアントは承認・実行権限・処理状態の正本にならず（AGENTS.md）、分類の変更・削除はチャット・音声の経路から受けない（U332）。会話から家計の記録を直接作る口は作れない。

会話の仕組みを調べた結果は次のとおり。

- 発言は `desktop.turn_submit` → `POST /v1/turns` → 意図の判定（模擬か、`packages/ai` の LLM による判定。ADR 0091）→ 意図表（`INTENT_POLICIES`）と契約（`IntentName`・`IntentArgs`・`ResultView`）の検査 → 経路の分け、の順に進む。意図を足すには、契約の列挙・引数・結果の種類、意図表、LLM の判定の入出力と評価、影モードの比較まで変える必要がある。
- 結果の表示（`ResultView`）は「本文を複製しない」形で、金額や店名を画面へ返す欄がない。
- `ExtractionResult` v2 は同期したメールからの抽出の形で、会話の発言には使わない。
- 標準の窓では、会話の欄（`WorkPanel`）と家計簿の欄（`HouseholdPanel`）が同じ renderer にあり、どちらもロック解除済みで中枢に接続している間だけ内容を持つ。手入力は `desktop.household_add`（画面操作）で送り、要求ごとに新しい `request_id` を付け、出所の鍵は `request_id` から作る（ADR 0167）。

## 決めたこと

| 対象           | 決定                                                                                                                                                                                                                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 読み方         | LLM は使わず、domain の `readHouseholdUtterance` が決まった規則で読む（U343）。結果は「読まない」（支出の話でない）、「候補にしない」（理由つき）、「候補」の三つ                                                                                                                                                                                                           |
| 読む範囲       | 支出だけ。支出を表す言い方（使った・払った・買った・かかった・購入した）と、円・¥・通貨の言葉がそろったときだけ読む。問い（「使ったっけ」「？」で終わる）・仮定（「使ったら」）は読まない（U345）                                                                                                                                                                           |
| 金額           | 円の正の整数を一つだけ（「500 円」「1,280 円」「¥500」「1 万 2000 円」「3 千円」。全角の数字もそろえて読む）。上限は記録と同じ 9,999,999,999 円。取り消し・返金の言葉、円以外の通貨、負の金額、二つ以上の金額、0 円・11 桁以上・3 桁ごとでないコンマ、読めない金額（漢数字・小数）は候補にせず、理由を会話の欄に出す（家計簿の欄から入れるように書く）                      |
| 日付           | 「今日」「昨日」「おととい」を端末の今日の日付から数える。日付の言葉がなければ今日。読めない日付の言葉（「3 日」「先週」）や違う日付の言葉が二つあれば、日付を空にして本人に入れさせる（空のままでは送れない）。今日の基準は端末の時計（U344）                                                                                                                              |
| 店名・支払い   | 店名は金額のすぐ前の「〜で」の部分（読点か文の頭まで。頭の「今日は」などの時の言葉を除く）。記録に入れられない店名（100 文字を超える・制御文字・12 桁以上の数字の並び）は入れない（中枢と同じ検査の `householdMerchantErrors`）。支払い手段は「現金」「カード」「クレジットカード」「クレカ」「電子マネー」だけを読む。分類は読まず未分類にする（中枢が店名の規則を当てる） |
| 候補の置き場所 | renderer のメモリーだけ（会話の状態の `householdCandidate`）。保存せず、中枢へも送らない。ロック・切断で会話と一緒に捨てる。受け付けられた発言の分だけ出し、次に受け付けられた発言で置き換える（拒否された発言では変えない）                                                                                                                                                |
| 出す場所       | 標準の窓の会話の欄の、会話の履歴の下（U346）。「家計簿の入力欄で開く」と「閉じる」。読めなかったときは理由と「閉じる」だけ                                                                                                                                                                                                                                                  |
| 発言の扱い     | 発言は今までどおり中枢へ送る（本文だけ。候補の値は送らない）。中枢の解釈・保存は変えない                                                                                                                                                                                                                                                                                    |
| 入力欄で開く   | 家計簿の欄の手入力の入力欄に、向き「支出」・金額・日付・店名・支払い手段・分類「未分類」を入れて開き、金額の欄へフォーカスを移す。欄の頭に「会話の一言から読んだ値を入れました。まだ記録していません。…」。開けたら会話の候補はしまう（同じ候補から二度開かない）                                                                                                           |
| 開けないとき   | 家計簿を読めていない・送り中・手入力の欄を開いている（本人が入れている途中の値を書き換えない）ときは開かず、ボタンを押せなくして理由を書く                                                                                                                                                                                                                                  |
| 確定           | 本人が入力欄で「足す」を押したときだけ、既存の `desktop.household_add`（`POST /v1/household/entries`、出所 `manual`、要求ごとの `request_id`。ADR 0167）で送る。中枢は今までどおり中身を検査し直す。結果不明は送り直さず読み直す（ADR 0167 と同じ）                                                                                                                         |
| 変えないこと   | 会話（チャット・音声）から記録を作る・直す・消す口は作らない（U332）。分類の変更・削除は画面操作だけ                                                                                                                                                                                                                                                                        |

## 退けた案

| 案                                                                  | 退けた理由                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 意図の一つ（家計の記録の候補）として LLM に抽出させる               | 契約（`IntentName`・`IntentArgs`・`ResultView`）、意図表、LLM の判定の入出力・評価・影モードまで変える大きな変更になる。LLM が出す金額・日付は信用できず、結局は本人の確かめが要る。結果の表示は本文を複製しない形で、候補の値を返す欄も足す必要がある。決まった規則で足りない言い方が実際の使い方で多ければ、改めて検討する（U343） |
| 中枢が LLM の前に決まった規則で照合する（会話の操作の照合表と同じ） | 応答の契約（`TurnResponse`）に候補の値を足す必要があり、当たった発言を LLM へ回さないと、規則の誤りで本人の依頼が届かなくなる。値は端末が送った本文から読めるので、中枢を通す利点がない                                                                                                                                              |
| `ExtractionResult` v2 の抽出に乗せる                                | メールの同期からの抽出の形で、会話の発言の経路にない                                                                                                                                                                                                                                                                                 |
| 会話から直接記録を作る（確かめの画面だけ出す）                      | LLM・会話の経路を記録の作成の正本にしない境界に反する。手入力と同じ経路（本人の画面操作と `request_id`）だけで作る                                                                                                                                                                                                                   |
| 候補を中枢の DB に置く                                              | 置く理由がない（候補は手入力の欄に入れるまでの値）。置くなら暗号文にする必要があり、期限・忘却の扱いも増える                                                                                                                                                                                                                         |

## 原本に決めがない項目

- U343: 会話の一言からの補いの読み方と、記録を作る経路。
- U344: 会話の一言の「今日」「昨日」を数える基準の日付。
- U345: 会話の一言から読む範囲（支出だけ・円だけ・金額は一つ・日付の言葉・店名と支払い手段の読み方）。
- U346: 会話の一言からの候補を出す場所（標準の窓の会話だけ）と、発言を今までどおり中枢へ送ること。

## 対象外

- 収入（「給料が入った」）・振替の候補、時刻・分類・メモの読み取り、複数の支出をまとめた一言。
- キャンバスの入力バー・音声の会話からの候補（家計簿の欄がない窓・経路。U346）。
- LLM による読み取り、レシートの写真からの補い、突き合わせによる二重の登録の防止（段階 3 の残り）。

## 試験（模擬だけ）

## 残ること

- 画面の見た目と操作（候補の欄から家計簿の欄へのフォーカスの移り方を含む）は Electron の実機で未確認。手順は `docs/household/README.md` の項目 I。
- U343〜U346 の本人の確認。決まった規則で読めない言い方が多ければ、LLM の意図にするか（U343）を改めて決める。

## 追補（2026-11-26）: 金額でない「円」・日付の言葉・店名の前の時の言葉の見直し

見直しで確かめられた誤りの修正。**模擬の試験だけ**で、実データ・実機は未実施。

- 「100円ショップで買った」「1000円札で払った」「500円引きで買った」が、100 円・1000 円・500 円の支出として読まれた。
- 「さきおととい500円使った」が 2 日前（「おととい」）になり、「昨夜」「昨晩」「去年」「昨年」「今月」「今週」「先々週」などでは日付が今日になった。
- 「朝コンビニで」「昨夜コンビニで」の店名に時の言葉が残り、「おとといと昨日で」は店名が「と昨日」になった。

| 対象                   | 決定                                                                                                                                                                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 金額でない「円」       | 数の直後の「円」に「ショップ」「均」「札」「玉」「引き」「off」「オフ」（大文字・小文字・全角を問わず。「円」の前後の空白は許す）が続くときは、その数を金額に数えない。「100円ショップで500円使った」は 500 円で、店名は「100円ショップ」。「100円ショップで買った」のように金額がほかになければ `amount_missing`                          |
| さきおととい           | 3 日前にする（「おととい」と読み間違えない）                                                                                                                                                                                                                                                                                               |
| 昨夜・昨晩             | 昨日の日付にする。0 時を過ぎた話でも昨日にするので、本人が入力欄で確かめて直す                                                                                                                                                                                                                                                             |
| 日付を決められない言葉 | 先々週・先々月・今週・今月・来週・来月・再来週・去年・昨年・今年・来年を、先週・先月などと同じく日付を空にする言葉に足した                                                                                                                                                                                                                 |
| 店名の前の時の言葉     | 日付の言葉・今朝・今夜・夕方などは助詞がなくても店名の前から除く。「朝」「昼」「夜」は、助詞（は・に・の）が続くか、次がカタカナ・英数字・空白のときだけ除く（「朝コンビニ」）。次が漢字・ひらがなの「朝日食堂」「夜景の見えるバー」は店名の一部として残す。「と」「や」は、次も時の言葉のときだけ除く（「昨日とんかつ屋」の「と」は残す） |
| 日付の言葉が二つ以上   | 違う日付の言葉が二つ以上あれば日付を空にし、除いた後に店名が残らなければ店名も空にする（「おとといと昨日で500円」は日付も店名も空）                                                                                                                                                                                                        |

試験: `scripts/household-utterance.test.mjs`。
