## 本人の決定（2026-10-22）

- **キャンバス**: アプリの後ろに、デスクトップの代わりとして 1 枚だけ置く。画面ぴったりの大きさ。使わない物は下の棚へ片付ける。タイトルバー・サイドバー・固定の入力欄は極力なくす。
- **会話**: 会話という単位をユーザーに見せず、ずっと続く 1 本の流れにする。この方針は変えない。
- **AI の配置**: AI はカードとフローティングウィンドウを自由に作って置く。ユーザーも動かす・閉じることができるが、配置は AI が優先する。
- **状態と停止**: 画面の端のつまみ（記号と承認待ちの数）とトレイで、いつも見せる。つまみを押すとパネルがスライドして出る。
- **入力**: 画面の下の小さなバー。入力するときだけ大きくする。将来は OS の音声入力（AquaVoice など）から入力できるようにする。
- **複数のモニター**: 設定で変えられる。既定は主の画面だけ。
- **UI の原則**: 文字ではなく、レイアウトで説明する。

## 決めたこと（設計の骨子）

### 窓を 3 つに分け、窓ごとに使えるチャネルを分ける

| 窓（役割）          | 大きさ・置き場所                                                 | 描くもの                                                   | 使える要求のチャネル（`DESKTOP_ROLE_CHANNELS`）                                                                                                                 | 受ける通知                                                                                       |
| ------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| キャンバス `canvas` | 主の画面ぴったり。macOS はデスクトップの層、Windows は最大化の窓 | AI が置くカード・フローティングウィンドウと、下の棚        | `desktop.get_state`・物のユーザーの操作の `desktop.canvas_user_op`（UI-06。前に出ている間だけ）                                                                 | `desktop.state_changed`・`desktop.canvas_changed`（UI-03。キャンバスの記述はキャンバスの窓だけ） |
| 状態の層 `status`   | 画面の端のつまみと、押すとスライドで出るパネル。トレイ           | いつも見える状態・停止・再開・確認の一覧・接続・登録・終了 | 発言を除くすべて（停止・再開・承認表示の準備・承認・取消・照合・再試行・状態の確認・失効・登録・ウィンドウを閉じる・終了・パネルを出す／しまう（UI-04）を含む） | 状態・電源とロックの記録・接続の 3 種                                                            |
| 入力バー `input`    | 画面の下の小さなバー。入力するときだけ大きくなる                 | 文字の入力と、聞き返しの質問                               | `desktop.get_state`・発言の `desktop.turn_submit`・`desktop.canvas_summon`                                                                                      | `desktop.state_changed`                                                                          |

- AI の部品はキャンバスの窓の外に出られない。キャンバスは承認・停止・再開・取消・登録・失効・終了のチャネルを持たないので、AI の部品が状態や停止を隠すことと、承認の画面に見せかけることを、構造で防ぐ。状態の層はキャンバスより前に置き、キャンバスから覆えない（UI-02 で確かめる）。
- 承認・取消・再試行は、これまでどおり main の OS の確認ダイアログで 1 回行う（ADR 0026・0031）。状態の層のパネルはその入口で、承認そのものではない。
- sandbox・contextIsolation・CSP・送信元の検査（ADR 0015）は弱めない。main は今の送信元の検査に加えて、送信元の窓の役割で受付を絞る（UI-02 で接続する。`admitDesktopRequest` の今の振る舞いは変えない）。
- B04-05（PR #91）の 7 チャネルは次のとおり割り当てた: `desktop.turn_submit` は入力バー、`desktop.operation_preview`・`operation_approve`・`operation_cancel`・`operation_retry`・`operation_reconcile`・`operation_check` は状態の層。キャンバスには割り当てない。表の試験（`scripts/canvas.test.mjs`）は、全チャネルがどこかの役割にあることを確かめる。

### AI が出すのは宣言的なキャンバスの記述だけ

- AI（と UI-03 の模擬の配置者）が出すのは `CanvasOpBatch`（操作の列と版）だけ。コード・HTML・CSS・ピクセルの座標・色を出させない。描画は HeroUI で作った決まった部品で行う（ADR 0024）。見出しを含む文字列は**プレーンテキストとしてだけ描く**（React の文字列の子として渡し、HTML として解釈しない・リンクにしない・`dangerouslySetInnerHTML` を使わない）。
- 操作は `add`・`update`・`move`・`close`・`relayout` の 5 つ。物（`CanvasItem`）は種類（`card`・`float`）、部品（`list`・`table`・`schedule_timeline`・`mail_card`・`compare`・`progress`・`chart`・`source_list`・`text`）、見出し、強調（`low`・`normal`・`high`）、まとまり（`group`）、関係（`compare`・`sequence`・`detail_of`）、12 列の格子のヒント、置き場所（`canvas`・`shelf`）、データの参照を持つ。
- データは参照だけ（`item_refs` は 50 件まで、残りは `more_count`）。本文は描くときに許可範囲内で取る（ResultView と同じ考え）。
- 版は `canvas_revision`。Core が変更の束ごとに 1 進め、端末は描いている版を発言に添える（`expected_canvas_revision`）。`request_revision`・`content_version`・`state_revision` とは別の版。
- 配置は AI が優先する。ユーザーが動かした・閉じた・棚に片付けたことは、次の束の前の状態として Core に返す（返し方は UI-06 で決めた。下の「ユーザーの操作（AI が優先）」）。

### 「文字ではなくレイアウトで説明する」を仕組みにする

- 物は説明文の項目を持たない（`description`・`note`・`caption`・本文の項目がない。Schema の `additionalProperties: false` で拒否する）。関係・順序・まとまりは、関係・読む順・格子のヒントで表す。
- 見出しは 24 文字（コードポイント）まで・1 行。制御文字・改行・双方向の上書き・埋め込み・分離・方向の印は拒否する（Schema と domain の両方）。空白だけの見出しは domain で拒否する。
- 見出しにマークアップ・URL を入れない（Schema と domain の両方。add と update の両方）。規則（PR #102 の再確認で整理し直した）:
  - **タグ**: 次の形だけを拒否する。閉じたタグ（`<` ＋ 英字で始まる名前 ＋ 任意の属性 ＋ `>`。名前の直後の `/` も区切りとし、`<br/>`・`<img/src=x>` も拒否する）、終わりのタグ（`</名前>`）、`<!`・`<?`、属性の形（`<名前 空白か / 属性名=`。`>` がなくても拒否）。名前は ASCII の英字で始まる英数字・`:`・`-`。`A<B の比較`・`A < B`・`A < B > C`・`2<3 と 5>4` は通す。`A<B>C` は閉じたタグの形なので拒否する（許容する）。
  - **URL**: スキームの名前（`http`・`https`・`javascript`・`vbscript`・`data`・`file`・`ftp`・`blob`・`mailto`）の直前が ASCII の英数字でない（または先頭である）ときに、`スキーム名 ＋ 空白（任意）＋ :` を拒否する。`-https:`・`+https:`・`.https:` は拒否し、`metadata:` は通す。`www.` も直前が ASCII の英数字でないときに拒否する。
  - **大文字・小文字**: `/i` を使わず、ASCII の文字集合（`[Hh][Tt]…`）で明示する。Schema（`CanvasHeading` の `not.anyOf`）と domain（`CANVAS_HEADING_MARKUP_PATTERNS`）は同じパターンの文字列を同じ `u` フラグで使い、一致を試験で確かめる。`ſ`（U+017F）は `s` とみなさず、`K`（U+212A、ケルビンの記号）は ASCII の英数字でないので直後の `http:` を拒否する。
  - **通してよいもの**: `＜script＞`（全角の山かっこ）・`https%3A%2F%2F`（符号化した URL）・`java script:`（空白で割ったスキーム）は通す。描画はプレーンテキストだけで、HTML として解釈せずリンクにもしないので、これらは文字として見えるだけになる。
  - 「3/5 の予定」「A > B の比較」「比較: A と B」「http の設定」「www の話」「＜予定＞」のような普通の見出しも通す。描画がプレーンテキストだけでも、見出しにスクリプト・リンクを紛れ込ませない（多重の防御）。
- `text` 部品は 1 回の答え（1 つの束）につき 1 つまで。足す `text` に加え、中身（見出し・データ）を変える既存の `text` も数える（`applyCanvasBatch` が今のキャンバスを見て数える）。強調・まとまり・関係だけの更新は数えない。
- 見える物は 24 個まで（棚を含めて 48 個まで）。1 回の変更は 12 個まで。
- 読む順（`reading_order`）は見える物をちょうど 1 回ずつ含む。読み上げソフトとキーボードの移動はこの順に従う（UI-06・UI-07）。

### 会話の単位をなくし、流れ（stream）と自動の区切り（segment）にする

- ユーザーには 1 本の流れだけを見せる。発言は `POST /v1/stream/turns` で送り、会話の ID・区切りの ID・保存モードを送らない。区切りは Core だけが選ぶ。
- Core は次のときに新しい区切りを始める（`SegmentBoundaryReason`）。

| 理由                   | いつ                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------- |
| `stream_started`       | 流れの最初の発言                                                                       |
| `idle_timeout`         | 前の発言から 30 分、やりとりがない                                                     |
| `date_changed`         | 本人の時間帯（設定のタイムゾーン）で日付が変わった                                     |
| `private_started`      | 記録しない会話（`StorageMode` の `private`）に入った                                   |
| `private_ended`        | 記録しない会話から出た                                                                 |
| `storage_mode_changed` | それ以外の保存モードの変更（`normal` ⇔ `extended`）                                    |
| `user_requested`       | 区切りの指示（「話を変える」などの照合表の言い回しと画面の操作。照合表の追加は UI-05） |
| `forget_requested`     | 忘却の指示                                                                             |

- **要約をつなぐ**: 新しい区切りには、前の区切りの要約だけをつなぐ（`carried_summary`。由来の区切りの ID と期限を持ち、本文は持たない）。流れの最初・忘却の指示・記録しない会話に入る・出るときはつながない。記録しない区切りは要約を作らず、ほかへも持ち込まない。
- **保存期限**: 今の規則（設計 03）を区切りの上で保つ。期限は発言ごとに生成から計算し（`normal` 7 日・`extended` 30 日）、区切り・流れの継続で伸ばさない。保存モードは区切りごとに 1 つで、途中で変えるときは区切りを分ける。
- **要約の由来と期限**（PR #102 のレビュー）: 要約は由来（材料にした区切り）と期限を引き継ぐ。規則は次の 2 つで、`nextCarriedSummary`（D:canvas.ts）が決める。
  1. 要約の期限は、**由来の発言のうち最も早い期限**。その時に要約全体を捨てる（一部の由来だけを残さない）。同じ区切りでも発言ごとに期限が違うので、最後の発言ではなく最も早い発言に合わせる。
  2. 要約し直すときは、**期限内の材料だけ**を使う。期限の切れた前の要約と期限の切れた発言は材料にしない。期限内の前の要約を材料にしたら、その由来と期限も引き継ぐ。何回区切りをまたいで要約し直しても、同じ規則を当てる（期限は伸びない）。
  - 由来が 256 区切りを超えるなら、つながない（Core は期限内の発言だけから作り直す）。区切りの始まりより前に期限が来た要約・自分の区切りを由来に含む要約は、`StreamSegment` の意味の検査で拒否する。
- **忘却**: 忘却の指示は新しい区切りを始め、前の要約をつながない。忘れた対象は、期限内でも文脈・要約から外す（設計 03 のまま）。
- **記録しない会話**: 区切りの単位で始めて終える。発言・要約を永続保存せず、区切りの終わりで一時文脈を捨てる。Live は開かない（設計 01・03・10 のまま）。
- **記録しない間のキャンバス**（PR #102 のレビュー）: 記録しない区切りの間の変更は、新しく足した物だけでなく、既存の物の `update`・`move`・`close` を含めて、すべて一時の記述（RAM だけ）に当てる。保存してよい記述（DB・スナップショット・イベントの記録に書くのはこれだけ）は記録しない区切りに入る前のまま変えない。区切りが終わったら一時の記述を捨てて、入る前の記述に戻す（版は一時の記述の版より 1 進め、端末が新しい記述として受け取る）。D:canvas.ts の `beginPrivateCanvas`・`applyCanvasBatchToStore`・`canvasForDisplay`・`endPrivateCanvas` がこの規則を表す。記録しない間のキャンバスの変更（見出しを含む）は、保存するスナップショット・イベントの記録（outbox）・ログに残さない。端末へは接続中の WSS でだけ送り、切断の後の復元は Core の RAM の一時の記述から返す（07 §4 の「記録しない会話の発言のイベントは永続化しない」と同じ扱い）。Core が止まれば一時の記述は失われ、入る前の記述に戻る。
- **「今回は」の指示と聞き返し**: 「今回は」の指示（一時の指示）は区切りの終わりで捨てる。聞き返しの待ち（5 分）も区切りをまたがない。
- **表示のリース・端末の移動**: 内容を見せる権限は、今の表示のリース（ハートビート・リース・中枢の起動 ID・端末・接続範囲・入出力の世代への結び付け。設計 07 §5）のまま。キャンバスの物は、リースが切れる・ロック・停止で隠す（ADR 0014 のまま）。表示の移動は会話ではなく流れの表示先を移す（経路は UI-05 で決める）。

### 複数のモニター・状態の見せ方・OS ごとの窓

- **複数のモニター**: 既定はキャンバスを主の画面だけに置く。ほかの画面にも置くかは設定で変えられる（UI-06 で設定の形と main での扱いを作った。下の「保存と複数のモニター」）。キャンバスは画面ぴったりで、棚に片付けられる。
- **状態**: 端のつまみ（記号と承認待ちの数）とトレイで常に見せ、つまみを押すとスライドで出るパネルに詳細（ADR 0024 の状態帯の項目・確認の一覧・接続）を出す（UI-04）。ロック中・不明は今と同じく内容を隠す。
- **OS ごとの窓**: macOS はデスクトップの層の窓、Windows は最大化の窓にする。どちらも試作で確かめる（UI-02）。macOS は試作した（下の「UI-02 の試作の結果」。デスクトップの層の入力に見直しが要る）。Windows は**未実施**。

### UI-02 の試作の結果（2026-10-22 追記）

記録は [docs/ui/window-prototype.md](../ui/window-prototype.md)（模擬・実機・未実施を分けた）。実機は macOS 27.0.1 の 1 画面だけで、入力は OS への合成の入力。Windows は未実施。

- **役割の区別**: 役割の正本は main の対応表（窓を作ったときの webContents → 役割）。preload へは `--buddy-window-role=<役割>`（`additionalArguments`）で渡し、画面の切り替えと多重の防御にだけ使う。対応表にない・閉じた窓、役割の表にないチャネル、窓の今の主フレームでない送信元（子フレーム・古い processId／routingId・破棄されたフレーム・破棄した窓）は `untrusted_sender` で拒否する（拒否の理由は増やさない）。従来の 1 つの窓は UI-02 より前の全チャネル・全通知を使う（`legacy`。`desktop.canvas_summon` は使わない）。

- **前提の見直し**: macOS のデスクトップの段（`type: 'desktop'`）のキャンバスは、通常の窓より下にあるだけでなく、**Finder のデスクトップの窓（画面全体）とウィジェットよりも下**にある。デスクトップのアイコン・ウィジェットがキャンバスの上に描かれ、キャンバスの位置のクリックは Finder が受けると見込む（Electron の文書も「desktop の窓はフォーカス・キーボード・マウスのイベントを受けない」とする。直接の確かめは未実施）。「デスクトップの層ではキー入力を受けにくい」という見込みは、**マウスも受けない見込み**に広げる。これを受けて、本人が次の「キャンバスを呼ぶ・戻す」を決めた。

#### キャンバスを呼ぶ・戻す（本人の判断 2026-10-22、UI-02 で試作）

- キャンバスは**普段はデスクトップの層**に置き、アプリの後ろで見るだけにする（後ろにある間はキー入力を受けない: `focusable: false`）。**呼ぶと前に出て**、カードを動かす・閉じるなどの操作を受ける。**Esc**（修飾キーなし。IME の変換中の Esc は変換の取り消しで戻さない）・**ほかのアプリ（ほかの窓）へ移る**・ロック・窓を隠す操作で後ろへ戻る。
- 呼び方は 3 つ: 全体のショートカット（既定 `CommandOrControl+Alt+Shift+B`。IME・入力ソースの切り替えのキーを避ける。登録できなければログを出してほかの 2 つで呼ぶ）、端のつまみ、入力バーのボタン。つまみと入力バーからは `desktop.canvas_summon`（状態の層と入力バーだけ。ロック解除済みの画面操作だけ。キャンバスと従来の窓は使えない）。
- 前に出ているかは main の状態（apps/desktop/src/main/canvas-presence.ts の `CanvasPresence`）。二重に呼んでも何もしない。ロック中・不明は呼ばない（キャンバスの中身を出さない）。前に出ている間にロック・不明になったら戻す。
- macOS は、前に出すときに `setFocusable(true)`・通常の窓の段（`setAlwaysOnTop(false)`）・`focus`、戻すときにデスクトップの段（`setAlwaysOnTop(true, 'normal', −2147483624)`）・`setFocusable(false)`・`blur`。Windows も、キャンバスを `focusable: false` で作り、前に出すときだけ `setFocusable(true)`・`focus`、戻すときに `setFocusable(false)`・`blur` にする。Electron 44 の `setFocusable(true)` は内部でタスクバーに出す設定も呼ぶので、どちらのときも `setFocusable` の後に `setSkipTaskbar(true)` を当て直す（後ろにある間はクリックしても前面に来ず、キー入力を受けない）。Windows の重なりは「次の窓を前面にする」までとし、その後は OS に任せる（未実施。PR #104 の再確認）。
- 呼ぶときは、隠れている状態の層・入力バーを前面を奪わずに表示し直してから、最後にキャンバスを前に出してフォーカスする（すべての窓を隠した後にショートカットで呼んでも 3 つの窓が戻る。前に出す途中の blur では戻さない。PR #104 の再確認）。
- 前に出ている間は、キャンバスの縁に accent の枠と、右上に Esc のキーの形（キーの中は「Esc」だけ）を出して、操作できることと戻し方を示す（文字の説明ではなく枠とキーの形で伝える）。端のつまみは、持ち手・状態の記号と数・縁のある「キャンバスを前に出す」ボタン（入力バーと同じ 4 つの四角の記号）を縦に並べ、押せるのはボタンだけにする（PR #104 の再確認。**UI-04 で改めた**: つまみの上の部分を、パネルを出すボタンにした）。
- 実機（macOS 27.0.1）で確かめたこと: 入力バーのボタン・つまみ・ショートカットで段が 0 になって前面の窓になる、Esc とほかのアプリへの移動で段がデスクトップの段に戻る、前に出しても画面共有から守る設定（共有の状態 0）は保たれる、CSP の違反は 0 件。前に出した窓にクリック・キー入力・IME が届くことは、同じ操作の最小の確認用のアプリで確かめた（Buddy の起動では道具が入力バーを前面に戻すため未確認）。ロックで戻ること・物理の入力・Windows は未実施（記録は docs/ui/window-prototype.md）。
- 前に出すと、Finder のデスクトップのアイコン・ウィジェットもキャンバスが覆う（段の観察）。戻すとまたキャンバスの上に描かれる。
- Esc で戻した後は Buddy が前面のアプリのまま（キー入力を受ける窓がない）になる。直前のアプリへ戻す方法は Electron にないので、本人の確認で使い勝手を判断する。
- **入力バーの内容**: 「打てるか」と「内容を出せるか」を分け、ロック中・状態が不明のときは打った文字を描かず、捨てる（解除しても戻さない）。止めただけなら文字は残り、打てない（PR #104 のレビュー）。
- **確認のダイアログ**: 3 つの窓の試作では、承認・失効・自宅の登録の OS の確認ダイアログに親を付けない（状態の層のつまみが小さく、シートを付けられない）。出し方は UI-04 で決める（**UI-04 で決めた**: パネルが出ている間だけパネルの窓を親にする。下の「UI-04 の状態と停止の層」）。

### UI-03 の最小の縦断（2026-10-23 追記）

- **流れへの発言**: Core は会話（`createSession`）を 1 つだけ持ち、それを今の区切りにする（流れの最初の発言で作る。理由は `stream_started`、要約はつながない。区切りの ID は会話の ID）。発言は既存の発言の処理（`postTurn`。模擬の解釈・意味検証・承認待ちの操作の作成・同じ要求の再送）を**関数として呼ぶ**だけで、その中身は変えない。経路の検査（端末トークン・自宅・接続範囲・ロック解除）は会話への発言と同じ。端末の声の入力（`voice_local`）は今の発言の処理と同じく受け付けない（B06）。応答は区切り・文字の結果・キャンバスの変更（なければ null）。Core が再起動すると区切りと記述は作り直す（UI-03 の記述は Core の RAM にだけ置く。保存は UI-05）。
- **端末の `expected_canvas_revision`**: 今は束の元の版に使わない（Core は自分の今の版から束を作る）。版の食い違いを端末へ返す・ユーザーが動かした／閉じたことを前の状態として返す仕組みは UI-06（**UI-06 で決めた**: 下の「`expected_canvas_revision` の照合」）。端末が古い版を添えても発言は受け付ける（試験で確かめた）。
- **模擬の配置者（コードの規則）**: 予定の照会（`query_schedule`）の結果だけを配置する。用事の list のカード 1 枚（物の名前 `errands`、見出し「今日の用事」、格子は 2 列目から 4 列分・3 行分）を、なければ `add`、あれば中身（強調・データ）だけ `update`（本人が棚へ片付けていれば棚のまま・読む順も増やさない）。参照は予定の ID（`calendar_event`）を 50 件まで（残りは `more_count`。50 件に満たないときは 0）。重なる予定があるとき（確認が要る）は強調（`high`）する。聞き返し・雑談・承認待ちの操作（承認の画面）・読み取りでない発言は何も置かない（承認・停止はキャンバスに置かない）。LLM・端末は配置を決めない。模擬の解釈には「今日の用事を見せて」を足した（「今日の予定を見せて」と同じ意図）。
- **当てる前の検査**: Core は束を Schema（`CanvasOpBatch`）と domain（`applyCanvasBatch`。読む順・参照の件数・版の連続・対象の有無・text の数など）で検査し、当てた後の記述も Schema で検査する。どれかに反すれば何も当てず、前の版が残る（発言の文字の結果だけを返す。`canvas` は null）。同じ要求の再送はもう一度配置しない（前の束はキャッシュに 256 件まで残る。下の「配置済みの判定」）。
- **版の知らせ**: 束を当てたら、開いている購読へ版だけを送る（本文・見出し・参照を含めない。イベントの記録 cursor・保存の対象にしない。購読は受け付けた直後の同期の処理で登録するので、端末が開いた後に取る `getCanvas` より後の変更は必ず届く）。端末は届いた版が手元より新しければ取りに行く。
- **読み取り**: `GET /v1/canvas`（`getCanvas`）は `CanvasDocument` を返す。検査は `unlocked` まで（読み取りで、接続範囲は求めない）。ロック中・不明は 403。
- **main の取得**: 接続（`live`）・ロック解除・版の知らせ・発言の応答（`canvas` が null でないとき）で、`GET /v1/canvas` を取る。取った記述は **Ajv（`CanvasDocument`）と domain（`canvasDocumentErrors`）の両方**を通ったものだけを使い、どちらかに反すれば捨てて前の版を残す（ログは `canvas_document_rejected` だけ。中身を出さない）。同じ世代の中で版は戻さず、同じ版は渡し直さない。取得は後に始めたものだけが有効（古い応答で新しい記述を戻さない）。
- **不透明な参照**: 画面へ渡す前に、表示対象の参照（予定の ID）は main が作った参照（UUID v4 の形、記述ごとに作り直す）に置き換える。中枢の識別子は main の中にだけ持つ（物を開くときの解決は UI-07）。画面の記述は別の Schema（`DesktopCanvasView`。`ref` の項目だけが `CanvasData` と違う）で検査する。
- **キャンバスの窓だけに通知**: 新しい通知 `desktop.canvas_changed`（`{canvas: DesktopCanvasView | null}`）を足した。役割の表（`DESKTOP_ROLE_NOTIFICATIONS`）ではキャンバスの窓だけが受け、状態の層・入力バー・従来の窓には送らない（preload の表・main の宛先の判定も同じ）。キャンバスの窓が使えるチャネルは `desktop.get_state` だけのまま（UI-06 で物のユーザーの操作 `desktop.canvas_user_op` だけを足した）（承認・取消・再試行・停止・再開・発言・キャンバスを前に出すチャネルを持たない。統合の試験で全チャネルを確かめた）。
- **世代の照合**: ロック・不明・切断・接続のやり直し・登録のやり直しで世代が進むと（`#bumpGeneration`）、記述と参照を捨て、キャンバスの窓へ空（`canvas: null`）を通知する。進行中の取得は各 `await` の後に世代・取得の順・ロック状態を照合し、またいだ応答は何も変えない。ロック中に届いた版の知らせは取りに行かず、解除したときに取り直す。発言は、送った後に世代が変わったら内容を画面へ返さず結果不明（`outcome_unknown`）にする（ADR 0031 と同じ。自動では送り直さない）。画面（renderer）も、ロック中・不明の状態の通知を受けたら main の通知を待たずに記述を捨て、描かない。
- **停止でも隠す**（PR #109 のレビュー。入出力の停止の状態・`io_epoch` が実際に変わったときだけ破棄・取り直しを行い、中枢の最終確認の時刻だけが変わった状態の通知では取得を増やさない）: 入出力の停止・`io_epoch` の変化でも、ロックと同じく記述と参照を捨てて空を通知する（`CanvasBridge.ioChanged`。Electron の層が状態の通知のたびに `ioStateChanged` を呼ぶ）。停止中は取得も版の知らせの処理もしない。取得は前後で停止の状態と `io_epoch` を照合し、またいだ応答は渡さない。再開したら取り直す。画面（renderer）も、キャンバス専用の表示の条件（解除済みで停止していない。`canvasContentShown`）で、停止中は描かない（入力バーの下書きの条件とは別）。
- **通知を取り逃したとき**: キャンバスの窓は購読を始めてから `desktop.get_state` を取る。main はキャンバスの窓のその取得を「通知を受け取る準備ができた」合図にして、今の記述を送り直す（なければ取り直す。`canvasResendAfter`・`canvasSubscribed`）。読み込み直しの通知が購読より先に来ても、次の変更まで空のままにならない。
- **配置済みの判定**（PR #109 のレビュー）: 同じ要求の再送で再配置しないかを、応答の束のキャッシュ（256 件）とは切り離し、発言の ID（`turn_id`。再送は保存済みの同じ発言を返す）で覚える（Core の RAM に上限なしで持つ。配置を試みた発言だけで、聞き返しは入れない。再送の判定と保持期限に結び付けて保存するのは UI-05。Issue #97）。キャッシュから消えた後の再送は配置せず、`canvas` は null で返す。
- **入力バー**: Enter（IME の変換の確定は除く）で `desktop.turn_submit` を送る。答えが返ったら入力欄を空にし、聞き返し・拒否・通信の失敗・結果不明では文字を残して入力欄の枠（無効の枠）で知らせる（説明文は置かない。聞き返しの表示は UI-08）。送っている間は記号を回転にして重ねて送らない。
- **キャンバスの窓の描画**: 12 列の格子（読む順の DOM）に、格子のヒント（列・幅・行数）から決めたクラスで HeroUI の `Card` を置く。見出しは React の文字列の子としてだけ渡す（プレーンテキスト。HTML として解釈せず、リンクにしない）。記述は参照だけで本文を持たないので（本文は開いたときに許可範囲内で取る設計。UI-07）、行は順番の数と空の帯、残りは「+数」の札、強調は accent の枠で示す。説明文は置かない。list 以外の部品・フローティングウィンドウ・棚は UI-06・UI-07（今は同じカードで描く。**UI-06 で**格子のクラスをやめ、配置のエンジンの位置で描くようにし、棚を作った）。

- **OS の確認ダイアログの親（UI-02 の持ち越しを決めた）**: パネルが出ている間だけ、**状態の層の窓（パネル）を親にする**（macOS はパネルに付くシート、Windows はパネルが持ち主のモーダル）。パネルが出ていなければ確認を出さず、送らない（確認の入口はパネルだけ）。このとき「やめる」ではないので `confirmation_declined` ではなく `screen_operation_required` を返す（main の確認が `not_shown` を返し、core-link が読み替える。UI-04 のレビュー P3-c）。理由は、従来の窓と同じ「親付きの確認」の経路になり、ロック・停止・窓を隠す操作で閉じる仕組み（AbortSignal。ADR 0026・0031）を同じ形で通せること（親のない確認はアプリのモーダルになり、閉じる仕組みが同じに働くかは確かめていない）、確認が内容を見せたパネルに付いて位置で対応が分かること、UI-02 で親を付けなかった理由（つまみが小さい）がパネルの幅で解けること。手順は `runPanelConfirm`（status-panel.ts。main はダイアログを渡すだけで、試験で守る）: 確認を出している間は、確認へフォーカスが移った blur でパネルをしまわない（例外でも終える）。パネルをしまう・窓を隠すときは先に確認を閉じて送らず、確認の後にパネルがしまわれていたら承認として扱わない。確認の間にほかのアプリへ移っていたら、確認が終わった後（結果を返した後、フォーカスが落ち着いてから）に窓が前面でなければパネルをしまう（P3-b）。シートの見え方は**未実施**。
- **全体の停止のショートカット**: 既定 `CommandOrControl+Alt+Shift+X`（macOS ⌘⌥⇧X、Windows Ctrl+Alt+Shift+X）。トレイの「入出力を停止」と同じ `DesktopDeviceController.stopFromMain`（UI-03 までの `stopFromTray` を改名）を呼ぶ。パネルの停止（`desktop.io_stop`）も同じ状態の遷移（`io_stop`）を通り、同じ状態欄を通知し、同じ値を保存する。安全に関わるので、**既定の従来の窓（配布版を含む）でも登録する**（本人に代わる司令塔の判断 2026-10-23、UI-04 のレビュー）。パネル `CommandOrControl+Alt+Shift+P`・キャンバス ⌘⌥⇧B は 3 つの窓の組み立てのときだけ。登録は `registerGlobalShortcuts`（停止を先に。登録できない・例外でもログを出して続ける）。既定値は修飾キー 3 つと英字 1 つで、IME・入力ソースの切り替えと、取り違えると困る OS の操作（強制終了・ログアウト・画面のロック・タスク マネージャーなど）を避ける（`RESERVED_ACCELERATORS`。手で書いた一覧で網羅ではない）。停止を登録できなければ、トレイの停止の項目に ⚠ を付け（登録できればショートカットを右に出す）、パネルと従来の窓の停止のボタンの横のキーの形に打ち消しの線と ⚠ を重ねる（説明文に頼らない。P3-d。画面へは窓を作るときの引数 `--buddy-stop-shortcut` で渡し、受付には使わない）。パネルのショートカットで出すときは、macOS で `app.focus({ steal: true })` で Buddy を前面にしてから窓にフォーカスを渡す（P3-a）。
- **専用の記号（プライバシーと権限）**: つまみの中に、音声を外部へ送っている・記録しないモード・安全停止中を、決まった順と位置で縦に並べ、いつも見せる。形で分ける（UI-04 のレビュー P2-3）: その状態にある（on）は塗った面と濃い記号、ない（off）は線だけ（実線の枠と記号）、値がまだない（音声は B05、記録しないモードは UI-05、安全停止は中枢が配るまで）は点線の枠と薄い記号、ロック中で隠すときは記号のない灰色の面。点線の枠の意味は、つまみとパネルの 8 項目のどちらでも「未受信」だけにした（P3-f）。
- **なりすましの試験**: キャンバスの窓は承認・取消・停止・パネルのチャネルを使えない（既存の役割の表に `desktop.status_panel` を足した）。外部の内容（予定の題名・用事の題名・キャンバスの見出し）に「承認しました」「ここを押して承認」があっても、キャンバスへは参照だけが届き（見出しは文字として描くだけ）、状態の層のボタンは main が渡す操作の一覧（参照）からだけ決まった文言で作る。127.0.0.1 の Core と main の統合で、状態の層から承認すると OS の確認（模擬の `confirmAdmin`）がちょうど 1 回だけ出ることを確かめた。

### UI-06 の配置のエンジンとユーザーの操作（2026-10-23 追記）

意味（強調・まとまり・関係・格子のヒント）から位置を決める配置のエンジンと、ユーザーの操作（動かす・大きさを変える・閉じる・棚へ片付ける・棚から出す）、複数のモニターの設定を作った（Issue #98）。規則を先にここへ書き、その後で実装した。記録は [docs/ui/canvas-layout.md](../ui/canvas-layout.md)。

#### 配置のエンジン（`layoutCanvas`、D:canvas-layout.ts）

- **純粋な関数**: DOM・Electron・Node 専用 API に依存しない。入力は、記述（物・読む順）・ユーザーの操作の記録（`user_pins`）・守る物（ドラッグ中・送信中の物の位置。画面だけが持つ）・キャンバスの大きさ（幅と高さ）・作業領域の外の幅（`insets`。macOS のメニューバー・Dock）。出力は、各物の位置と大きさ（ピクセルと格子のマス）・読む順・棚の場所と中身・入りきらない物・空けた場所（入力バー・状態の層）。決まった入力からは決まった結果を出す（乱数・時刻・前回の結果を使わない。同点は行、次に列の小さい方）。
- **強調の読み替え**: 契約の `emphasis` の `high` を**焦点**、`normal` を**補助**、`low` を**周辺**として扱う（契約の値は変えない）。
- **空ける場所**: 作業領域（キャンバスの大きさから `insets` を除いた範囲）の右の端の幅 72（端のつまみ 56 と余白）を**状態の層**のために空け、下の中央の幅 592・高さ 88（入力バー 560 × 56 と余白。UI-02 の `INPUT_BAR_SIZE`・`INPUT_BAR_MARGIN`）を**入力バー**のために空ける。カードは、この 2 つと重ならない。下の帯（作業領域の下の高さ 88）にはカードを置かない。`insets` は画面（renderer）が `window.screen` の `availLeft`・`availTop`・`availWidth`・`availHeight` と窓の位置から求める（IPC を足さない）。
- **棚**: 下の帯の、入力バーの左（幅 160 以上あるとき）に置く。高さ 56 の横 1 列で、棚の物（`placement` が `shelf`）を記述の順に並べ、入りきらなければ横へ送る（棚の中だけ）。左の幅が 160 に満たないときは、入力バーの上に作業領域の幅で置き、カードの範囲をその分だけ縮める。
- **並べ方の切り替え**: カードを置ける幅（作業領域の幅 − 余白 24 × 2 − 状態の層の 72）が 720 以上なら**格子**、720 未満なら**1 列**（読む順に上から並べる）。
- **格子**: 12 列。列の幅は置ける幅から間 16 × 11 を引いて 12 で割る。行の高さは 72（間 16）で固定し、置ける高さに入る数だけ行を作る（画面からはみ出さない。キャンバスを巻き取らない）。位置と大きさは格子のマスを整数のピクセルに丸めて出す。
- **置く順**（先に置いた物が場所を取る）:
  1. **守る物**（ドラッグ中・送信中の物）を、その位置にそのまま置く。
  2. **ユーザーが置いた物**（`user_pins`）を、読む順に、記録したマスにそのまま置く（はみ出す・先の物と重なるなら、同じ大きさで最も近い空きへ）。
  3. **焦点**を読む順に置く。
  4. **補助**、その後に**周辺**を置く。それぞれの中では、関係を持つ物を先に（相手の隣を、関係のない物より先に取る）、その中は読む順に置く。関係の相手（`target`）がまだ置かれていない物は、相手の後に回す（循環していれば読む順のまま）。
- **大きさ**（格子のヒントの幅・行数から）: 焦点は幅を 6 以上・行数を 4 以上に広げる（大きく目立つ）。補助はヒントのまま。周辺は幅を 4 以下・行数を 2 以下に縮める。ユーザーが置いた物と守る物は記録の大きさのまま。行数は作れる行の数までに収める。
- **望む位置**（格子のヒントの列は、意味の規則と食い違わない範囲で使う）。関係 → まとまり → 強調 の順に、最初に当てはまるもので決める（焦点・周辺でも、相手の置かれた関係があれば関係に従う）:
  - 焦点: 1 行目、ヒントの列（はみ出すなら左へ寄せる）。
  - 関係（最初の関係で、相手が置かれているもの）: `detail_of` は親の右隣（同じ行。右に幅がなければ左隣）、`compare` は相手の右隣（同じ行。右に幅がなければ左隣。行数を相手にそろえる）、`sequence` は相手の真下（同じ列）。
  - まとまり（`group`。関係がないとき）: 同じまとまりの置いた物を囲む範囲に接するマス（下の「範囲からのすき間」）。
  - 補助（関係・まとまりがないとき）: 最初の焦点に接するマス（右・下のどちらでも。範囲からのすき間）。焦点がなければ 1 行目のヒントの列。
  - 周辺: 最後の行に下端をそろえ、ヒントの列（周辺へ寄せる）。
- **関係の隣を先に試す**: 関係の物は、まず相手の隣を同じ行で試す（`compare`・`detail_of` は右、なければ左。どちらも空いていなければ幅を 2 まで 1 ずつ縮めて右・左の順に試す。`sequence` は真下の同じ列・同じ幅）。入らなければ次の「重なりを解く」で望む位置に最も近い空きへ置く。
- **重なりを解く**: 空いているマスの中から、望む位置に最も近い場所を選ぶ（距離は 行の差 × 3 ＋ 列の差 × 2。まとまり・補助は位置ではなく範囲からのすき間の行 × 3 ＋ 列 × 2 で、接していれば 0。同点は上、次に左）。どこにも入らなければ、行数を 1 まで、次に幅を 2 まで減らして探し直す（周辺は幅を減らさない）。それでも入らない物は**入りきらない物**（`overflow`）として棚の場所に並べる（記述は変えない。AI の次の答えか、ユーザーがほかの物を閉じる・片付けると戻る）。重なりは置き方で起きない（試験で確かめる）。
- **1 列**: 読む順に上から、置ける幅いっぱいで並べる。高さは、焦点が 3〜4 行、補助が 1〜3 行（ヒントの行数）、周辺が 1 行。下の帯に届く物から後ろは、読む順を保ったまま入りきらない物にする。ユーザーが置いた物・守る物のマスは使わない（1 列では動かす・大きさを変えるを受けない）。
- **読む順**: 出力の読む順は記述の `reading_order` のまま（置いた物と入りきらない物）。読み上げとキーボードの移動（DOM の順）は置いた物をこの順に並べ、入りきらない物は棚の場所（DOM では置いた物の後）に同じ順で並べる。位置が読む順と違っても並べ替えない（読む順の正本は記述）。

#### ユーザーの操作（AI が優先）

- **操作の種類**（S:CanvasUserOp）: `move`・`resize`（どちらも置く先のマス `cell`: 列・行・幅・行数）、`close`、`shelve`（棚へ片付ける）、`unshelve`（棚から出す）。マスはエンジンが出した格子のマスで、ピクセルは送らない。
- **キャンバスが前に出ている間だけ**操作できる。画面は前に出ているときだけ、選んだ物・ポインターを重ねた物に閉じる・片付ける・大きさを変えるの印を出し（見出しの帯を掴んで動かす。狭いカードでも見出しを隠さないよう、ほかの物には出さない）、main は `CanvasPresence` が前に出ていることと、キャンバスの窓が前面であることを確かめる（そうでなければ `screen_operation_required`）。ロック中・不明は `device_locked`、入出力の停止中は `input_stopped`。
- **キーボード**: Tab で読む順に物を選ぶ。矢印で 1 マス動かす、Shift ＋ 矢印で大きさを 1 マス変える（← → は幅、↑ ↓ は行数）、Delete・Backspace で閉じる、Alt（Option）＋ ↓ で棚へ片付ける。棚の物は Enter・Space で棚から出す。
- **記録**: 操作は main を通して Core に送る（`desktop.canvas_user_op` → `POST /v1/canvas/user-ops`。承認・停止のチャネルとは別）。Core は操作を記述に当て（版を 1 進める）、`move`・`resize` は物の**ユーザーの置き場所**（`user_pins`。マス）として持つ。格子のヒントは AI の意味として残す。`close` は物を消し、`shelve` は棚へ移して読む順から外し、`unshelve` は見える物に戻して読む順の最後に足す（見える物が 24 個なら `conflict`）。操作の記録は Core の RAM に 64 件まで持つ（保存は UI-05）。
- **AI が優先**: Core は記録を次の配置者の入力にする（模擬の配置者は、ユーザーが最後に置いた大きさを、同じ物を置き直すときの格子のヒントにする）。AI の束が物を `move`・`close` する、`relayout` する、棚へ移すと、その物のユーザーの置き場所を消す（AI の置き方に従う）。中身だけの `update` では消さない。
- **ドラッグの間は守る**: ドラッグしている物は、画面がエンジンの「守る物」として、その位置に置き続ける（新しい記述が届いても、AI がその物を動かしたことを画面に反映しない）。ほかの物は新しい記述で並べ直す。届いた記述にその物がない（AI が閉じた・片付けた）ときは、ドラッグをやめる。落とした後、Core が当てた版が届くか拒否されるまでは、送った位置を同じく守る（送信中）。Esc・ほかのアプリへの移動（キャンバスが後ろへ戻る）・ロック・停止・切断でドラッグと選択と送信中の位置を捨てる。
- **`expected_canvas_revision` の照合**:
  - **操作**: 操作は画面が描いている版を添える。Core は、版が今と同じなら当てる。古い版でも、**その物の置き場所・存在がその版より後に変わっていなければ**当てる（AI が中身だけを変えた・ほかの物を動かしただけなら、ユーザーの操作を捨てない）。その物が後から追加・移動・閉じる・置き直し（`relayout`）・片付け／出す の対象になっていた、物がない、Core の版より新しい版（Core の再起動など）なら `409 conflict` で捨てる（main は `canvas_conflict` を返し、記述を取り直す。自動では送り直さない）。物ごとに「置き場所が最後に変わった版」を Core が持つ。同じ `request_id` の再送は保存した同じ結果を返す。
  - **発言**: 発言（`postStreamTurn`）は、版が古くても受け付ける（言葉を捨てない）。配置者は Core の今の記述から束を作る（AI が優先）。添えた版は配置者の入力（本人が見ていた版）として渡す。
- **ロック・停止で捨てる**: ロック・不明・停止・切断では、main は記述と参照を捨て（UI-03 のまま）、送信中の操作は世代が変わったら結果不明（`outcome_unknown`）にする。画面はドラッグ・選択・送信中の位置を捨てる。

#### 保存と複数のモニター

- **端末に保存してよいのは配置の設定だけ**: 複数のモニターの設定（S:DesktopCanvasDisplaySettings）だけを、main がユーザーのデータの場所（`canvas-display.json`）に保存する。読み込みは Schema（`additionalProperties: false`）で検査し、反していれば既定（主の画面）にする。キャンバスの本文・見出し・参照・ユーザーの置き場所・操作の記録は端末に保存しない（Core の RAM。画面は `localStorage`・`sessionStorage`・IndexedDB・cookie を使わない。試験で確かめる）。
- **複数のモニターの設定**: `{ schema_version: 1, target: "primary" }`（既定）か `{ schema_version: 1, target: "display", display_id }`。main は設定と今の画面の一覧から、キャンバス・状態の層・入力バーを置く画面を 1 つ選ぶ（`resolveCanvasDisplay`）。選んだ画面がなければ主の画面にする（設定は書き換えない）。選んだ画面の大きさと作業領域を読める。画面の追加・取り外し・大きさの変更では選び直し、3 つの窓をその画面へ置き直す。すべての画面を 1 枚につなぐ形は作らない。設定を変える画面は後の Issue（今は設定の形・保存・読み込み・main での扱いだけ）。

## 設計原本の改訂案（要約）

原本の本文は写さず、どの節の何をどう変えるかだけを書く。原本への反映は本人が判断する。

### 01 体験・画面・初期版の機能境界

- **画面構成**: 「左のナビ・中央の対象・必要なときの根拠と変更確認」の 3 部構成と「カードを並べず一覧行と区切りを基本」を、キャンバス・状態の層・入力バーの 3 つの窓に置き換える。8 つの画面（気づき・会話・用事と処理状況・記憶・接続と端末・設定と運用・変更確認）は、キャンバスに置く物の部品と状態の層のパネルへ配り直す。会話の画面の「明示終了」の操作は、区切りの指示に置き換える。
- **いつも見える状態**: 上部の細い状態欄を、端のつまみ（記号と承認待ちの数）・トレイ・スライドのパネルに置き換える。項目・日本語の文言・色だけで区別しないこと・ロック中は内容を隠すことは変えない。
- **主要な流れ C（端末を移る）**: 「同じ会話を引き継ぐ」を「同じ流れの表示先を移す」に改める。機密の表示の退避は変えない。
- **承認画面**: 必須の内容と「登録済み・ロック解除済みの PC の画面だけで承認する」は変えない。承認の画面はキャンバスに置かず、状態の層から開く main の確認に置くことを足す。
- **停止・取消・終了**: 「会話を終わる」を「区切る」（文脈の利用を区切る）に改める。無音で音声の接続だけを切る規則は変えない。記録しない会話は区切りの単位で始めて終える。

### 03 データ・承認・記憶・復旧

- **データの分離**: sessions／turns に、流れの区切り（区切りの ID・保存モード・始めた理由・つないだ要約の元）を足す。発言ごとの期限は変えない。「今回は」の指示は「区切りの終わりで捨てる」に改める。
- **保存期限**: 日数は変えない。保存モードは区切りごとに 1 つで、途中で変えるときは区切りを分けることを足す。つないだ要約は由来と期限を引き継ぎ、由来の発言のうち最も早い期限で捨てること、要約し直すときは期限内の材料だけを使うことを足す。
- **忘却と再取り込み**: 忘却の指示で新しい区切りを始め、前の要約をつながないことを足す。
- **記録しない会話の境界**: 「会話の終了時に捨てる」を「区切りの終わりに捨てる」に改め、要約を作らない・前後の区切りへ持ち込まないことを足す。

### 07 通信契約・端末状態・再接続

- **§1 識別子**: session_id（会話）に並べて、流れの区切りの ID と、キャンバスの版（`canvas_revision`）を足す。キャンバスの版は依頼・内容・状態の版と別にする。
- **§2 認証と最小 API**: `POST /v1/stream/turns` を足す。`POST /v1/sessions` と会話への発言は、流れへの移行が終わるまで残す（移行の手順は UI-05）。限定 IPC は窓の役割ごとに絞ることを足す。
- **§4 イベントとスナップショット**: スナップショットに今のキャンバスの記述と区切りの保存モードを足す（本文は持たない）。記録しない区切りの発言のイベントは今と同じく永続化しない。
- **§5 端末移動と停止**: 表示のリースは変えない。キャンバスの物もリース・ロック・停止で隠すことを足す。表示の移動を流れの単位にする。

### 10 音声経路・委譲・会話文脈

- **§1 音声プロセスの配置**: UI レンダラーを 3 つの窓（キャンバス・状態の層・入力バー）に分けることを足す。音声レンダラー（隠し窓）と、その限定 IPC は変えない。
- **§1A 停止理由と再開**: end_conversation を「区切る」に改める（session_id を閉じる代わりに区切りを閉じる）。外部処理を一括で取り消さないことは変えない。
- **§3 無音・休止**: 音声の接続を閉じても流れは続く。「明示終了でだけ閉じる」を「区切りの規則（30 分・日付・保存モード・指示）で区切る」に改める。「続ける」の操作は入力バーに置く。
- **§4 会話文脈**: 文脈を区切りごとに持ち、前の区切りの要約だけをつなぐことを足す。要約の更新は「区切りの終わりに」に改める。
- **§5A 発話の確定**: 会話の操作の照合表に、区切り・忘却の言い回しを足す（UI-05）。聞き返しの待ちが区切りをまたがないことを足す。
- **§6・§6A テキスト会話と結果の表示**: 結果の種類と画面の部品の対応表を、キャンバスの部品（`CanvasComponent`）の対応表に置き換える。聞き返しは入力バーの上に出す。雑談の吹き出しは `text` 部品（1 回の答えにつき 1 つ）にする。
- **§8 端末移動**: 引き継ぎの提案のバナーを、状態の層に出すことに改める。

## 読み取り（レビュー対象）

原本・本人の決定に明記がなく、この ADR で決めた点です。

- **記録しない会話から出た区切り**: 前の（記録しない会話に入る前の）区切りの要約もつながない（`private_ended` はつながない）。記録しない会話の前後を 1 本の文脈にすると、記録しない間の話題の推測を残し得るため、安全側にした。
- **30 分の数え方**: 前の発言（本人か Buddy のどちらか）の受付から数える。音声の接続の 10 秒の切断や、端末内の文字起こしのモデルの 30 分の解放とは別の規則。
- **棚を含めた上限 48**: 本人の決定は「見える物 24」。棚が無制限に増えないよう、棚を含めて 48 にした。
- **more_count**: 参照を 50 件並べたときだけ残りの件数を持つ（50 件に満たないのに残りがある形を拒否する）。
- **relayout は引数なし**: 置き直しの計算は配置のエンジン（UI-06）が読む順とまとまりで行い、AI は座標を出さない。1 つの束に 1 回まで。
- **update で置き場所を変えない**: 置き場所は `move` だけで変える（棚への片付けをユーザーの操作と同じ操作にそろえるため）。
- **入力バーのチャネル**: `desktop.get_state` と発言の `desktop.turn_submit`（B04-05）だけ。UI-02 でキャンバスを前に出す `desktop.canvas_summon` を足した（状態の層も使える）。
- **キャンバスの `get_connection`**: 接続の表示には承認・取消に使う参照が含まれるので、キャンバスには渡さない。
- **要約の期限の数え方**: 期限は UTC のミリ秒で比べ、期限ちょうどの時点で切れたとみなす。発言のない区切りでも、期限内の前の要約はそのまま引き継ぐ。
- **記録しない間の版**: 一時の記述の版は保存してよい記述の版から続けて進め、終わったら一時の記述の版より 1 進める。端末から見て版は戻らない。
- **最終確認が古い（UI-04）**: 45 秒（購読の生存の時間切れ）より古ければ警告の形にする。
- **パネルの出し方（UI-04）**: 4 つ目の窓を作らず、状態の層の窓を広げる。画面は窓の幅でパネルを描き、出しているかの状態を持たない。幅は 440（承認の確認の変更の前後の表が読める幅）。
- **ロック中のパネル（UI-04）**: パネルは出せる（停止へ届く）。中身は隠す。
- **OS の確認ダイアログの親（UI-04）**: パネルの窓。パネルが出ていなければ確認を出さない（上の「UI-04 の状態と停止の層」）。
- **全体のショートカットの既定値（UI-04）**: 停止 ⌘⌥⇧X・パネル ⌘⌥⇧P（Windows は Ctrl+Alt+Shift）。停止はどの組み立てでも（既定の従来の窓・配布版を含む）登録し、パネル・キャンバスは 3 つの窓の組み立てのときだけ（本人に代わる司令塔の判断 2026-10-23）。
- **音声を外部へ送っている状態（UI-04）**: 音声の状態のうち、会話中（`conversation_live`）と聞き取り中（`listening_text_reply`）を「外部へ送っている」とみなす（Live の接続へ音声を送る状態）。読み上げ中は含めない。B05 で確かめ直す。
- **強調の読み替え（UI-06）**: エピックの「焦点・補助・周辺」を、契約の `emphasis` の `high`・`normal`・`low` に当てた（契約の値は変えない）。
- **ユーザーの置き場所を格子のヒントと分ける（UI-06）**: ユーザーが動かしたマス（行を含む）は `user_pins` に持ち、AI の意味（格子のヒント）は書き換えない。格子のヒントには行がなく、ユーザーの置いた位置を表せないため。AI が `move`・`close`・`relayout`・棚へ移すとユーザーの置き場所を消す（AI が優先）。
- **古い版への操作（UI-06）**: 版が今と同じでなくても、その物の置き場所・存在が添えた版より後に変わっていなければ当てる（AI が中身だけを変えた・ほかの物を動かした間の操作を捨てない）。発言は版が古くても受け付ける。
- **入りきらない物（UI-06）**: 記述は変えず、棚の場所に「…」の印の札で並べる（押しても動かない）。AI の次の答えか、ユーザーがほかの物を閉じる・片付けると戻る。
- **行の高さは固定（UI-06）**: 72（間 16）で固定し、画面の高さに入る数だけ行を作る（行を引き伸ばさない。キャンバスを巻き取らない）。1 列の切り替えは、カードを置ける幅 720（画面の幅 840）。
- **操作の印（UI-06）**: 閉じる・片付ける・大きさを変えるの印は、選んだ物とポインターを重ねた物にだけ出す（狭いカードで見出しを隠さない。すべてに出すと画面が記号で埋まる）。
- **操作の記録の上限（UI-06）**: Core の RAM に 64 件（保存は UI-05）。模擬の配置者は、同じ物を置き直すときに最後のマスの列・幅・行数を格子のヒントにする。
- **複数のモニターの設定（UI-06）**: 3 つの窓を同じ画面に置く。選んだ画面がないときは主の画面にし、設定は書き換えない（画面をつなぎ直せば戻る）。設定を変える画面は後の Issue。
- **つまみを押せる範囲（UI-04）**: つまみの上の部分（記号・数・専用の記号）全体をパネルを出すボタンにした（本人の決定「つまみを押すとパネルがスライドして出る」）。PR #104 の再確認の「押せるのは縁のあるボタンだけ」を改めた。
