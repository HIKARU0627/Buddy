# ADR 0190: B06-07a-2 の 2c 記録しない区切りの RAM の保持と保存境界の命令の結び付け

- 日付: 2026-11-27
- 状態: B06-07a-2（Issue #143 の一部、親 #11）の**段階 2c** の判断と実装。ADR 0059・0060 の「引き継ぎ」に書いた 2c の範囲（保存境界の保持者の命令を Core の保存先へ結び付ける・記録しない区切りの発言を RAM で受けて出るときに捨てる・結果の由来を処理の開始時に控えて保存の直前に照合する・`postTurn` の 503 を RAM の経路へ置き換える）。`apps/core` の `private-turns.ts`（新規）・`api-turns.ts`・`canvas-stream.ts`・`core.ts`・`turn-ports.ts`、`apps/desktop` の main の注記と試験、B06-09 の X17 の実行器と期待値、模擬の試験だけ。**契約（JSON Schema・OpenAPI・生成型・fixture）は変えていない**。マイグレーションは足していない（0012 のまま）。2d（独立した確認の Core の経路と最小の操作記録）は範囲外。実機の Mac mini・Windows・macOS の端末、実際の Live・実 API・実請求は未実施。
- 根拠: ADR 0045（許可表の「禁止（RAM）」の行・保存先の分類・由来と遅れて届いた結果・U63〜U67）、ADR 0059（保存境界の保持者と命令）、ADR 0060（発言の由来・流れの `POST /v1/stream/storage-mode`・2b の実装）、ADR 0032（記録しない間のキャンバスは一時の記述・区切りの終わりで一時文脈を捨てる・要約をつながない）、ADR 0068（自動の区切りの 30 分・日付の変更）、ADR 0187（知らせの運搬と流れの表示の後始末）、ADR 0189（記録しないモードの UI・U478）、ADR 0180（忘却の経路）、契約の `ConversationContext`（直近の発言の上限 6 件、記録しない会話では RAM だけ）。非公開の原本（設計 03・10）はこの環境になく、参照していない。決めのない点は、本人の「試験と見直しは後でまとめて行う」に従って聞かずに暫定で決め、`docs/b00/contract-map.md` の U480〜U485 に記録した。
- 番号: ADR は 0190、未決事項は U480〜U485。

## 端末

- 従来の窓は記録しない間に流れの経路へ送る（ADR 0189）ので、Core が答えると、そのまま会話の欄に結果が出る（`storage_notice` は付かない）。main の注記を直し、`storage-mode-link.test.ts` の記録しない間の発言を「断られて読み直す」から「答えが出て、表示は記録しないのまま」に直した。画面の部品は変えていない。
- キャンバス表示は、記録しない間の結果を一時の記述に置き、終えると版の知らせで入る前の記述に戻る（端末は版の知らせと `getCanvas` で収束する）。

## 契約

変えていない。`InterpretationContext.recent_turns` は Core の中の差し込み口（`turn-ports.ts`）の型で、ワイヤ契約ではない。応答は既存の `TurnResponse`・`StreamTurnResponse`（区切りの `storage_mode` が `private`）のまま。

## 試験（模擬だけ）

期待値は手で書いた値（状態・件数・文・版・理由・境界の時刻）。実装の関数から作っていない。

- `apps/core/src/private-turns.test.ts`（5 件、新規）: 直前のやりとりの 6 件の上限（3 回のやりとりでちょうど 6 件、4 回目で最初の 2 件が落ちる、返事の文がない応答は 1 件）、最後のやりとりから 29 分 59.999 秒は残りちょうど 30 分で捨てる・本人の時間帯の 23:59 の後の 0:00 で捨てる、応答の控えの 64 件の上限（65 件目で最も古い要求が落ちる）・照合値の違いは conflict・別の区切りの控えは見えない、捨てた後は前に始めた結果を持たない、別の記録しない区切りへ結び付けると前の中身を捨てる。
- `apps/core/src/private-conversation.test.ts`（6 件、新規。製品の Core と、DB に触れると数える偽物の保存先）: 記録しない間の発言が 200 で答えること（予定の照会は一時の記述にカードを置く・目印を含む発言は聞き返し・直前のやりとりが解釈の入力に添えられる・同じ要求の再送は解釈を呼ばずに同じ発言・照合値が違えば 409・用事の登録は決まった文で断る）、DB の 12 の保存先の行が増えないこと、合成の目印がデータディレクトリの全ファイル（DB・WAL・時計の状態ファイル）とログにないこと（停止の前と後）、終えると RAM を捨てキャンバスが入る前の記述に戻り版が進むこと、終えた後の再送は 409 で保存しないこと、終えた後の発言は保存されること（陽性の対照）。遅れて届いた結果: 記録しない間に始めた発言の解釈の間に終えると 409 でキャンバスにも RAM にもない、通常の区切りの発言の解釈の間に記録しないへ入ると 409 で保存しない。直前のやりとりの上限（5 回目の入力は直前 3 回の 6 件・29 分 59.999 秒後は残る・その 30 分後は空）。ロックの申告と忘却の知らせで捨て、記録しない区切りのまま一時の記述を閉じ直し、次の発言は前の文脈なしで始まり、その後に終えても前の要求の再送は保存されない。再起動で RAM を失い通常の区切りに戻り、目印がどこにもない。記録しない区切りの間は発言の処理が DB に触れず、用事・ラベル・調査は provider・裏の受付に触れずに断り、予定の照会は provider の読み取りだけ、古い世代・別の区切りの由来は 409、Live の委譲は DB に触れずに 409。
- `apps/core/src/canvas-stream.test.ts`: 2b の試験の記録しない間の発言の期待値を 503 から 200（区切りは private）へ直した（2 件）。偽物の発言の処理を使う 1 件は注記だけ直した。
- `apps/desktop/src/main/storage-mode-link.test.ts`: 記録しない間の従来の窓の発言が答えとして画面へ返り、記録された印が付かず、表示は記録しないのまま、中枢の RAM に 1 件あること。
- `tests/integration/b06-cases.mjs`・`b06-expectations.json` の `X17-private-conversation-not-saved`: 記録しない間の発言が 200（区切りは private・聞き返し）で発言の行が増えない、同じ要求の再送は同じ発言、RAM の件数（応答の控え 1・直前のやりとり 2・一時のキャンバス）、終えると RAM が空で理由は `private_ended`、終えた後の再送は 409 で行が増えない、を足した。証拠（`evidence-b06-simulated.json`）は実行器で作り直した。
- 実装を壊して新しい試験が落ちることを確かめた（下の「感度」）。

### 感度

次の欠陥を一時的に入れて（ビルド後の `dist` を書き換え、終わったら `tsc` で作り直して戻した。コミットしていない）、該当の試験が落ちることを確かめた。

- 処理の後の区切りと `epoch` の照合（`postPrivateTurn`）と、RAM に持つ時の照合（`PrivateConversationRam.hold`）の両方を外す → 遅れて届いた結果の試験が落ちる（終えた後に結果が RAM に残る）。応答は流れの経路の照合で 409 のままなので、片方だけ外しても落ちない（重なった守り）。
- 記録しない区切りの控えを捨てるときに、流れの受付の対応も捨てる → 終えた後の再送が新しい要求として通常の区切りに保存され、1 件目の試験が落ちる（200 になる）。
- `discard_private_ram` の命令で発言の RAM を捨てない → 1 件目の試験（終えた後の件数）と B06-09 の X17（seed 3 個とも）が落ちる。
- 通常の区切りの保存の直前の照合を外す → 記録しないへ入った後に、入る前に始めた通常の発言が保存され、遅れて届いた結果の試験が落ちる（200 になる）。

## 範囲の外と残り

- **2d**: 独立した確認の Core の経路と最小の操作記録（`record_minimal_operation`。ADR 0045・U42・U64・U67）。それまで記録しない間の外部の変更は断る。
- 記録しない会話での記憶の保存の拒否（X59）は、memory_save の Core の経路（U389・U436）が未実装のため観測していない。記録しない間の `memory_save` の意図は上の決まった文で断る。
- 直前のやりとりを判定・返事に使うこと（U481）。ロックの申告を Core へすぐ運ぶこと（U482）。再起動の後の再送（U484）。
- 実機の Mac mini・Windows・macOS の端末、実際の Live・実 API・実請求、OS のスワップ・SSD の痕跡（B15）。
