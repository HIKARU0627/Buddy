## 画面（状態の層のパネル）

説明の文章を置かず、並べ方で伝える。項目は「種類の札・枠の表示名・予算月・期限」の 1 行と、その下の発生した日時・用途・モデルの名前の小さな行、金額を大きく並べた行、金額の関係の帯、右寄せのボタン。超過枠の承認は最大負担と超過枠の残りを左右に置き、最大負担が占める割合の帯と「承認する（primary）」「見送る」。M 超過は最大負担・実費・超過（+ 付き、危険の色）を並べ、最大負担の分と超えた分を別の色の帯で見せ「確認する」。不明な費用は最大負担の下に、照合 ID の欄（`manual:` を最初から入れる）と実費の欄と「精算する」。結果不明は ⚠ と「結果不明」だけ（ボタン・欄なし）、期限切れは赤い「期限切れ」だけ、入出力停止中は承認・確認のボタンを出さない。理由のコード・API の名前・ID は画面にも読み上げにも出さない。帯の幅は 5% きざみのクラスの表から選ぶ（CSP の style-src 'self' で style 属性を使えない）。状態の「予算の保留」は 8 項目の 1 つで、`budget_held` が true なら ⚠ の塗り、false なら「なし」、不明なら点線の枠。

## 試験（模擬のみ）

- `apps/core/src/api-budget.test.ts`（Core の HTTPS・DB worker・模擬の provider）: 4 経路すべてで未登録・失効した端末は 401、ロック 403、画面操作でなければ 403、古い接続範囲 410。利用状況の形と承認待ち・期限切れの除外。承認のない超過枠の使用が 0 回（pending・見送り・期限切れ・別の依頼・自発の処理）、承認の二度押し（同じ命令・別の命令・逆の決定）で承認が 1 件、M・予算の要求が違えば 409、承認は 1 回だけ使える。M 超過の確認（版が古い・見た値が違う・予約がない・再送）と受付の再開。手での精算（元の月に一度だけ・`manual:`・版が古い 409・クレジットの区分と provider の照合 ID の形は 422・同じ照合 ID の別の予約は 409）。個人の金額（XTS 以外の通貨）が契約の例にないこと。
- `apps/desktop/src/main/budget-bridge.test.ts`（模擬の接続）: 項目の順・ID を画面へ渡さない・予算保留の読み方・確認の 1 回・確認の前に送らない・確認の最中の期限切れ・項目の消失・M の変化・停止・io_epoch の変化・結果不明の保留と解除・409 と他の拒否・形の違う 2xx・世代の変化。`budget-link.test.ts`（実際の Core と DesktopCoreLink）: 承認から超過枠の使用まで、同時の二度押しで確認 1 回・送信 1 回・承認 1 件、やめれば何も送らない、確認の最中に失効、停止中、ロックで項目を捨てる、M 超過の確認と手での精算と予算保留の変化。
- 画面: `budget-state.test.ts`・`BudgetItems.test.tsx`（種類ごとの並べ方・帯・ボタン・停止中・結果不明・期限切れ・欄の問題・理由のコードと説明の文章を出さない）、`admin-confirm.test.ts`（3 つのダイアログの文言）、`device-controller.test.ts`（予算保留を接続中だけ出す）。契約: schema-cases（項目・要求・応答・意味検査）、desktop-ipc-cases（受付）、`scripts/budget-money.test.mjs`（金額の表示・入力と、契約の例が XTS だけ）。
- スクリーンショット（コミットしない）: 状態の層のパネルの確認の一覧（超過枠の承認・M 超過の確認・不明な費用・入力の問題・結果不明と期限切れ・停止中）と予算保留の記号を、ライト・ダークで撮った。ビルド済みの画面を画面に出さない窓で描いた模擬の preload の撮影で、Electron の main・OS の窓・OS の確認ダイアログは通っていない。CSP の違反 0 件。データはすべて合成（XTS）。

## 判断が要る点

1. **承認の期限 10 分**: 原本に決めがないので置いた値。長くすると、放置した承認で後から支出できる窓が延びる。短くすると、離席で失効しやすい。
2. **見送りは確認なし**: 承認を増やさない操作なので OS の確認を挟まない。本人の画面操作（前面・ロック解除済み）は要る。確認を挟むなら `budget_overage_decide` の reject も確認の対象にする。
3. **読み取りの間隔 30 秒**: 中枢が予算の変化（月替わり・上限到達・M 超過）を知らせるイベントを持たない。パネルを出したときにも読み直す。イベントを足すなら、読み取りを減らせる。
4. **手での精算のクレジット区分**: B07-07 まで初期の規則だけ。クレジットを使った請求の精算は、B07-07 の後に画面の入力を足す。
