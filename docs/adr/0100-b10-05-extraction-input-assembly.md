# ADR 0100: B10-05 P1 メール抽出の入力の組立て

- 日付: 2026-11-14
- 状態: B10-05（親 #18、Issue #244）P1 の判断。件名・本文・選択した添付からモデルへ送る入力と、未読・切詰めの確定だけ。モデルの呼出し・根拠の照合は P2、抽出前フィルターは P3、関連解析は P4。実 API・API キー・実請求・実メールは未実施（B15 と本人の承認まで扱わない）。
- 根拠: 設計 11 §3（入力・根拠の対応付け・未読と切詰め）・§5B、設計 09 X39・X62・QA10・QA11、ADR 0007・0070・0090。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。
- 対象: `packages/ai/src/extraction-input.ts`・`extraction-input.test.ts`・`index.ts`、`packages/domain/src/extraction-source.ts`・`index.ts`、`docs/b00/contract-map.md`（U240・U241）。契約（`packages/contracts`）は変えていない。

## 決めたこと

| 対象                 | 決定                                                                                                                                                                                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入力                 | 件名・本文（引用は残す）・許可対象の添付の抽出テキスト・受信日時・本人の名前だけ。**送信者・宛先のアドレスは入力の型に欄を持たない**（宛先と自動配信の判定はヘッダーからコードが決める。設計 11 §3）                                                                                                             |
| source_id と版       | `subject`・`body` は予約語。添付は呼び出し側の添付 ID を source_id にし、予約語・空・重複は入力の誤りで送らない。件名と本文の版はメッセージの版。添付は添付ごとの版                                                                                                                                              |
| 送ったテキスト       | モデルへ**実際に送った**テキストを `ExtractionSource` として返す。根拠の照合（P2）はこの text に対して行い、送っていない部分への引用を一致にしない。切詰めは先頭からの切り出しなので、位置は元の抽出テキストと同じ。区切りの記号は、どのソースの本文にも現れないものを選び、本文を書き換えない（位置を変えない） |
| 位置の単位           | Unicode コードポイント、end は含まない（QA11）。UTF-16 の長さや書記素の数ではない。切詰めはサロゲートペアの途中で切らない                                                                                                                                                                                        |
| 上限                 | 入力全体 6,000 トークン、うち添付は最大 2,000（設計の初期値。実測で調整）。割り当ては、件名 → 添付（合計 2,000 かつ全体の残りまで）→ 本文（残り）の順に枠を決める。本文が短ければ余った枠は使わない。トークン数はコードポイント数で数える暫定の見積り（U240）                                                    |
| 未読                 | 本文が未取得、許可対象の添付が未取得・読取失敗のとき `unread_source_ids` に入れる。**入力を組み立てるコードが確定し、モデルの出力で変えない**。未読の内容を推測しないよう、モデルへ読めなかったソースを伝える                                                                                                    |
| 切詰め               | 上限を超えて切り捨てたソースを `truncated_source_ids` に入れる。予算が尽きて 1 文字も送れなかったソースは、送っていないので切詰めとして記録し、「入力に使った版」（`source_revisions`）には入れない                                                                                                              |
| 範囲外の添付         | 許可範囲外の添付は取得も送信もせず、未読にも数えない（取得範囲を広げない。設計 11 §2・§3）。診断のために ID だけ `out_of_scope_ids` に残す                                                                                                                                                                       |
| 引用                 | 行頭（空白・全角空白を除く）が `>` の行を、本文の引用の範囲（コードポイント）として記録する。HTML・転送の見出しは判定しない（U241）。P2 でモデルの `in_quoted_text` と合わせ、どちらかが引用なら引用として扱う                                                                                                   |
| 読める内容がないとき | 件名・本文・添付のどれにも読める内容がなければ、組み立てずに入力の誤り（`nothing_readable`）にする。空の入力でモデルを呼んで「依頼なし」を成功にしない（設計 11 §5B）                                                                                                                                            |
| 指示文               | 固定部分（`EXTRACTION_SYSTEM_MESSAGE`、版は `EXTRACTION_PROMPT_VERSION = '1'`）と変わる部分を別の message にする。固定部分にメールの中身・本人の名前を入れない。メール・添付の指示には従わない旨を固定部分に置く。文面は仮置きで、変えたら版を上げる。モデルの採否は B10-07、調整は B15 以降                     |

## 試験（模擬だけ）

`packages/ai/src/extraction-input.test.ts`（手書きの期待値）:

- 変わる部分の書式を手書きの文字列と照合。固定部分はメールの中身を含まず、指示めいた本文はブロックの中にそのまま入る。
- 区切りの記号が本文と衝突しても本文を書き換えない。引用の範囲をコードポイントで数える（絵文字を含む）。
- 範囲外の添付は送らず未読にも数えない。未読・読取失敗は `unread_source_ids` に入り、モデルへ伝える（QA10）。
- 6,000／2,000 の上限（本文・添付・件名の組み合わせ）、予算が尽きた添付は送らず切詰めに記録、サロゲートペアの途中で切らない。
- 入力の誤り（予約語・重複・暦にない受信日時・読める内容なし）は組み立てない。

**模擬のみ**。実 API・実メール・実請求・実機・tokenizer の実測は未実施で、合格扱いにしない。

## 残ること

- 呼出し・schema 検証・根拠の照合・`ExtractionResult` への変換は P2。
- 抽出前フィルターと判定の記録は P3。関連集合の解析計画と実行直前の照合は P4。
- U240・U241 の最終判断は B10-07 の評価と B08・B09 の本文の変換で行う。
