# B05 の完了判定（下書き）

B05（#15、音声入出力・停止保証・文字応答への切替）について、B05-07（#131）の模擬の統合試験と証拠を記録します。**親 Issue の完了条件 5 項目のうち、1〜4 は模擬の範囲で観測できました（既知の未了・制約が 3 つあります。下の「未実施・残る判断」）。5（日本語品質・停止時間・費用の実測）は未実施です。** 実機（#132）・実 API（#133）・実請求はすべて未実施で、模擬の時間（`voice_stop_ms` など）は手で進める時計の値であり T04 の実測ではありません。B05 全体を閉じるかは本人の判断です。この文書は判定の材料までを書きます。

根拠は設計 07 §5（リース）、10 §1〜§6A（停止の 3 層・世代・無音・結果の届け先・入出力のモード）、06 B05、09 の QA41・QA43・X13・X14・X25・X27・X30・X49・X51・X58・QA24・T04・T08、ADR 0005・0006・0037・0038・0041・0046・0049・0050・0052、本人の判断（2026-10-23、#15 のコメント）。原本は新しく読んでおらず、既存の ADR・契約の fixture・契約台帳に取り込み済みの規則だけを使いました。既存の判断は変更していません（新しい未決事項は契約台帳 U151 に記録しました）。

## 突き合わせの規則と感度

- 規則 `findings`（`tests/integration/b05-support.mjs`）は、端末が実際に送った命令（`voice.start` などの `io_epoch`・`output_epoch` が後退しない・存在しない Live を開始しない・世代が Live の行と同じ）と、Core の Live・予約の行（SQL で直接読む）と、provider 自身の真の使用時間（作成から閉じる要求まで）から、実装の判定とは別に数えます: 使用秒数が provider と同じ・精算の金額が最低 15 秒を含めて一致・確認済みなのに未精算でない・開いたままの Live が精算済みでない・送出意図のある予約を使用秒数の確認なしに解放しない・音声の枠の使用量が上限以内。毎回すべての世界で確かめ、この規則自体が不正な記録を検出できることは `b05-support.test.mjs`（手作りの記録）で確かめます。
- 期待値は [b05-expectations.json](../../tests/integration/b05-expectations.json) の手書きです。時刻は手で進める時計の相対 ms（IPC の片道は 1 ms）、会話の予約は合成の 1 秒 1 単位（通貨は合成の XTS、最低 15 秒）から、設計・ADR の規則と契約の fixture で手計算した値で、実装（端末の音声の制御・中枢・DB worker・予算の門）の処理から作っていません。固定の文は設計の定型文です。
- 感度は、製品のコードに一時的に欠陥を入れて確かめました（コミットしていません）: 端末の停止（`suspend_io` の送出）を外すと全ケースが失敗、制御接続の期限を 6001 ms にすると X25、ACK の期限を 1 ms ずらすと X30（固まる・ACK なし）、再生の停止を外すと QA43、端末の再生停止イベントの処理を外すと X58（2 ケース）、入力の安定時間を 300→200 ms にすると X51 が失敗しました。
- 待ち合わせは、手で進める時計と、条件が満たされるまで時計を進めつつ中枢の保存（DB worker）に追いつく待ち（条件が満たされたらすぐ抜ける）で行い、固定の sleep の合格判定は使いません。

- **既知の未了 1（U70・U91）**: 端末が進めた `io_epoch` を中枢へ報告する経路がありません。端末の停止（OS のロックなど）の後に画面で再開しても、中枢は次のリースを `unknown_io_epoch` で拒否し、会話を始め直せません（`X13-io-epoch-sync-before-restart` が現状を記録しています）。拒否は安全側で新しい許可を生みませんが、「停止の後に再開して音声を使える」は、この経路ができるまで成り立ちません。実機の試験の前に決める作業です。
- **既知の未了 2（ADR 0050）**: 中枢から届く停止のイベント（`suspend_io`・全体停止・来客モード）を、端末が止めに使う経路がありません。端末はリースの更新の拒否（次のハートビート、2 秒以内。リースの期限 6 秒以内）で止まります（`X14-global-stop-reaches-the-other-device`）。他の端末の ACK の経路（U70）も未実装です。
- **既知の制約（U151、本人の判断待ち）**: 会話の操作に使った発話は委譲の対象の候補から外れないため、直後（2 秒以内）の依頼は聞き返しになります（実行はされない。安全側）。契約台帳に選択肢・推奨（外す）を記録しました。挙動は変えていません。
- **U120（文字の結果・破棄の知らせの画面への配信）は未了**です。UI-08（#100）の別 PR で行います。それまでは、声に出せなかった文字の結果は理由だけをログに残し、案内は声の定型文だけです。承認の対象を作らないので、表示の欠落から実行権限は生まれません。
- 模擬の音声レンダラーは発話を作らないので、10 秒の無音で閉じる判定（main の純粋な規則。`scripts/voice-*.test.mjs`）はこの統合を通していません。モデルの発話の終わり・読み上げ（定型句なしの効果音）・呼びかけ（sherpa-onnx の語の指定）は実機の工程です。
- B04・B07 の対象のソースは変更していません（証拠の作り直しは不要）。
- B05 の完了の判定（材料）: 親 Issue の完了条件 1〜4 は模擬の範囲で観測でき、5 は未実施です。上の既知の未了 2 つと U151、U120 を別の Issue に残して「模擬の範囲で 1〜4 を満たした」として #15 の子を閉じ、5 と実機の確認を #132・#133 に残すか、実機の前に U70・U91 の経路を作るかは、本人の判断です。参考までに、実機で停止時間を測る前に U70・U91（世代の報告）と ADR 0050 の停止イベントの経路を先に作ると、T04 の測定が「リースの拒否で止まる」ではなく設計の経路になります。
