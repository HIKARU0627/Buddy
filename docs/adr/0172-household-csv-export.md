# ADR 0172: 家計の記録の CSV への書き出し（家計簿 段階 3 の一部）

- 日付: 2026-11-26
- 状態: 家計簿の段階 3 の部分。本人が、画面の操作で、家計の記録を月の範囲で CSV ファイルに書き出し、表計算ソフトなどで見られるようにする。**模擬の試験だけ**で、実機（保存先の選択・表計算ソフトでの開き方）・実データは未実施。
- 根拠: 本人の決定（U318: 外部の家計簿サービスを Buddy で置き換え、家計の正本を Buddy の中に置く）、ADR 0158・0161・0162・0164。正本を Buddy に置くなら、本人が自分の記録を取り出せなければならない。原本（非公開 Notion）に家計簿の決めはない（U318 以降と同じ）。
- 対象: `packages/domain/src/household-export.ts`（CSV の組み立て・範囲・ファイル名）、`packages/contracts`（IPC の `desktop.household_export`、`DesktopHouseholdView.last_export`、`desktop-ipc-cases.json`）、`packages/domain/src/desktop.ts`、`apps/desktop`（`main/household-bridge.ts` の `exportCsv`、`main/household-export-file.ts`、`main/electron/main.ts` の保存先の選択、`main/core-link.ts`、`preload`、画面の「記録の書き出し」の欄）。

## 背景

ADR 0158 で記録の正本を Buddy の中（暗号化した保存）に置き、ADR 0161・0162 で端末から読む経路と画面を作った。取り込み（ADR 0164）で外部の家計簿サービスの書き出しを入れる向きはあるが、Buddy から取り出す向きがなかった。取り出せない正本は、本人が自分の記録を自由に使えない。

## 調べたこと（新しい API を足すか）

| 案                                                            | 内容                                                                                                            | 判断                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 案 1（採用）: main が既存の読み取りを月ごとに呼んで組み立てる | `GET /v1/household/months/{month}`（ADR 0161）を、範囲の月の数だけ古い月から順に呼び、端末の main で CSV にする | 契約・認可・OpenAPI・Core に変更がない。読み取りは「端末トークン・自宅・ロック解除」で既に守られている。全期間は選べないが、月の範囲（120 か月まで）は選べる。1 か月の応答に打ち切り（`truncated`）と読めない記録の数（`unreadable`）が付いているので、欠けたことを検出できる |
| 案 2（退けた）: Core に書き出し専用の経路を足す               | 全期間または範囲の記録を一度に返す                                                                              | 全期間を選べる。しかし、金額・店名・メモをまとめて返す新しい経路が増える。認可（接続範囲・画面操作・チャットからの拒否・U332）、契約、意味検査、応答の大きさの上限、再送の扱いをそろえて作り直す必要があり、同じ内容の読み取りが既にあるのに表面積だけが増える                |
| 案 3（退けた）: Core が CSV の文字列を作って返す              | Core が列・並び・引用符を決める                                                                                 | Core が平文の CSV を作ることになり、Core のログ・メモリーに全記録の平文の塊が出る。CSV の形は端末の保存の都合（保存先・文字コード・表計算ソフトの癖）に近く、表示の細部を Core の契約にすると、書式の直しのたびに契約を変えることになる                                       |

月の数だけ読む回数が増えるのが案 1 の代償である。1 回の読み取りは月 1 つ分で小さい。一方、Core には認証した端末ごとの頻度の上限（既定は 1 分に 300 回。ADR 0020 の仮の値。`api-server.ts`）があり、120 か月の書き出しは 120 回で収まるが、画面の他の読み取り（予算の自動の読み取りなど）と重なると上限（429）に当たることがありうる。その場合は「読めなかった」として扱い（欠けたファイルは作らない）、本人は少し待ってやり直す。実際の中枢で 120 回続けたときの時間と、上限に当たるかどうかは未確認である。

## 決めたこと

| 対象           | 決定                                                                                                                                                                                                                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 受け付ける入口 | 本人の画面の操作（ロック解除済み・前面）だけ。IPC の `desktop.household_export` を、取り込み（ADR 0164）と同じ「画面操作を求める」一覧に入れる。チャット・音声・システムの経路からは受けない（U332 と同じ）。キャンバス・入力バーの窓は使えない。ロック中・不明は拒否する。入出力の停止中は、中枢へ書き込まず読むだけなので受け付ける（取り込みと同じ） |
| 範囲           | 月の範囲（`from`・`to`。両端を含む。2000〜2099 年。120 か月まで）。画面は「今出している月だけ」「直近 12 か月」「直近 36 か月」「直近 10 年（120 か月）」から選ぶ（既定は 12 か月）。全期間を一度には選べない（U347）。範囲の誤りは中枢へ何も送らずに `invalid_request`                                                                                 |
| 読み方         | main が古い月から順に `GET /v1/household/months/{month}` を 1 つずつ読む。応答は契約で検査し、月の食い違い・記録の日付が月の外・同じ記録の重なり（月をまたいでも、同じ月の中でも）は読み取りの失敗にする。読んだ記録は関数の中の変数だけに持ち、画面の表示（今出している月）には混ぜない                                                                |
| 欠けるとき     | 打ち切られた月（`truncated`）が 1 か月でも、読めない記録（`unreadable`）が 1 件でも、読めなかった月がある、または記録の不整合があるときは、**ファイルを作らない**。保存先の選択も出さない。画面に、月の数・記録の数・打ち切られた月の数・読めない記録の数と理由を出す（U348）                                                                           |
| 保存先         | すべて読めたときだけ、main が OS の保存先の選択（確認ダイアログと同じ親の窓）を出し、本人が選んだパスにだけ書く。ファイル名の候補は `buddy-household-2030-11.csv`・`buddy-household-2029-12_2030-11.csv`（ASCII）。選ぶ前にやめたときは何も書かず、結果も残さない（前の結果は消える）                                                                   |
| 書く処理       | 新しいファイルの権限は本人だけ（0600）。一時ファイルは作らず、選ばれたパスへ直接書く。書けなかったとき（容量不足・権限など）は、書きかけのファイルを消して失敗として返す。ログには `household_export_read_failed`・`household_export_write_failed` のコードだけを出し、パス・中身は出さない                                                             |
| ロック・切断   | 読んでいる間・保存先を選んでいる間にロック・切断（世代の交代）があれば、何も書かず、読んだ記録を捨てて `not_connected` を返す。保存先が決まった後、書く直前にも世代を確かめ直す                                                                                                                                                                         |
| 画面           | 画面は期間（月の範囲）だけを送る。パス・ファイルの中身を渡さない・受け取らない。結果（`last_export`）は、結果の種類（書けた・欠けるので作らなかった・読めなかった・書けなかった）と件数だけで、パスも中身も入らない                                                                                                                                     |

## 平文になること（暗号化との関係）

家計の金額・店名・メモなどは、保存では暗号文（ADR 0158）である。**書き出したファイルは暗号化されず、金額・店名・メモ・支払い手段がそのまま入った平文になる。** これは本人が自分の記録を表計算ソフトで見るための機能で、避けられない。守りは次のとおり。

- 書くのは、本人が OS の保存先の選択で選んだパスだけ。一時ファイル・ログ・画面（renderer）の記憶域・IPC の応答には、CSV の中身もパスも出さない。読んだ記録と CSV の文字列は、main の関数の中の変数だけに持ち、書いたら捨てる。
- 画面に、ファイルが暗号化されないことと、書き出したファイルの保管は本人の責任であることを書く。
- 同じ Buddy のバックアップ・復元・忘却（ADR 0158 以降）の対象外である。書き出したファイルは Buddy の管理から離れる。本人が忘却の依頼をしても、書き出し済みのファイルは消えない（画面の注意に含める）。
- 新しいファイルの権限は本人だけにするが、すでにあるファイルを本人が上書きすると選んだときは、その権限を変えない。保存先が同期フォルダ（クラウド）のときの扱いは本人に任せる。

## ファイルの形（U349）

| 対象               | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 列                 | 先頭の 10 列は取り込み（ADR 0164）と同じ見出しと意味: 計算対象（常に 1）・日付（YYYY/MM/DD）・内容（店名）・金額（円）（支出は負、収入と振替は正の整数）・保有金融機関（支払い手段）・大項目（分類の表示名）・中項目（空）・メモ・振替（振替なら 1）・ID（`buddy:` に記録の ID）。後ろに 時刻（HH:MM）・向き（支出・収入・振替）・出所の種類（利用通知メール・書き出しの取り込み・手入力）を足す。取り込みは見出しの名前で列を探すので、足した列は取り込みに影響しない |
| 並び               | 日付の古い順。同じ日は時刻の早い順（時刻なしが先）、それも同じなら作った順                                                                                                                                                                                                                                                                                                                                                                                             |
| 文字コード         | UTF-8、先頭に BOM（U+FEFF）を付ける。BOM がないと、日本語環境の表計算ソフト（特に Windows の Excel）が UTF-8 と判断せず、文字化けすることが多い。BOM があれば、Excel・LibreOffice・Numbers・Google スプレッドシートはいずれも UTF-8 として開ける（実機では未確認）。取り込み（ADR 0164）は BOM の有無を問わない。BOM の不都合は、UTF-8 を前提にしない古い道具で先頭に余計な文字が見えることだけで、開きやすさを優先する                                                |
| 区切り・改行       | コンマ区切り、行末は CRLF（RFC 4180）                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 値の中の特別な文字 | コンマ・二重引用符・改行（CR・LF）・前後の空白を含む値は、二重引用符で囲み、中の二重引用符は二つにする。取り込みの読み取り（`splitHouseholdCsv`）で戻ることを試験で確かめた                                                                                                                                                                                                                                                                                            |
| CSV 注入           | 店名・メモ・支払い手段（本人や外部の文字）が、表計算ソフトで式として解釈されうる文字（`=`・`+`・`-`・`@`・タブ・復帰・全角の `＝`・`＋`・`－`・`＠`。先頭の空白を飛ばして判定）で始まるときは、先頭に `'` を付けて文字として開かせる（OWASP の対策）。金額の負の符号は Buddy が作った数字なので守らない。代償: 守りの `'` は、取り込み直すと店名の先頭に残る（取り込みは元に戻さない。ADR 0164 は変えない）                                                            |
| 取り込みとの往復   | 空の Buddy へ書き出しを取り込むと、向き・金額・日付・分類・店名・メモ・支払い手段・ID が戻る（試験で確かめた）。戻らないもの: 時刻、出所の種類（取り込みは `csv_import` になる）、内容版、作成・更新の時刻、規則、守りの `'`。**同じ Buddy へ取り込み直すと、ID が元の出所の鍵と違うので二重の記録になる**（画面の注意に含める）                                                                                                                                       |

## 原本に決めがない項目

- U347: 書き出しの経路と範囲（案 1・全期間を選べない点）。
- U348: 打ち切られた月・読めない記録があるときの扱い（作らない）。
- U349: ファイルの形（列・BOM・注入対策・平文・往復で戻らないもの）。

## 対象外

- 全期間を一度に書き出すこと（U347）。10 年より前の記録は、範囲を前へずらして書き出す。
- 暗号化した書き出し、パスワード付きの圧縮、クラウドへの送信、メールで送ること。
- 予算・固定費・分類の規則の書き出し（記録だけ）。
- 書き出したファイルの取り込み直しで二重にならない仕組み（同じ Buddy への取り込みは対象外）。
- 取り込み（ADR 0164）の読み取りの変更。

## 残ること

- 実機で確かめる: OS の保存先の選択、Windows・macOS の表計算ソフトでの文字化けのなさ（BOM）、`'` で始まる値が文字として開くこと、書き出したファイルを空の Buddy へ取り込んで戻ること、120 か月を読む時間。手順の表は `docs/household/README.md` へ足す（本 ADR では足していない）。
- U347〜U349 の本人の確認（全期間を一度に書き出したいか、読めない記録があるとき書き出せなくてよいか、列の足し方）。
