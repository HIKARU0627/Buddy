# ADR 0109: B10-04 P4 委譲の状態（前面・裏・なし）を端末へ知らせる（U253。X29）

- 日付: 2026-11-14
- 状態: B10-04（親 #18、Issue #246）P4 の判断。本人決定（2026-11-14）: **U253 は (a)**（音声の制御イベントで委譲の状態を端末へ知らせ、端末は委譲を前面で待つ間に会話を無音で終えない）。**契約の変更を含む**（`VoiceEvent.event_type` に `delegation_finished` を足す）。実音声・実 API・実請求・実機は未実施。
- 根拠: 設計 10 §3・§5（つなぎ・即時ジョブの上限）・§5A-7（前面の委譲の待ちと背景化）、設計 09 X29・X55、ADR 0041（無音の判定は端末の main だけが行う）・0052・0108、contract-map U32・U253。非公開の原本は権限のある接続で読み取りだけを行い、全文を写していない。
- 対象: `packages/contracts/schemas/buddy.schema.json`（`VoiceEvent.event_type`・説明）・`src/generated.ts`・`fixtures/voice-contract-cases.json`、`packages/domain/src/voice-silence.ts`、`apps/core/src/live-conversation.ts`・`voice-control.ts`、`apps/desktop/src/main/voice-controller.ts`、各試験、`tests/test-map.json`（X29 の fixture の対応）、`docs/b00/contract-map.md`（U253）。マイグレーションは変えていない。

## 決めたこと

| 対象             | 決定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 契約             | `VoiceEvent` には、委譲の状態を表す `delegation_processing`（前面で結果を待つ）・`delegation_backgrounded`（8 秒を超えて裏へ移した）が**すでにあり、どこからも出されても使われてもいなかった**（B05 の契約）。新しい項目（`delegation_phase`）は足さず、**終わりを表す `delegation_finished` だけを足す**（待つ委譲がなくなった。`none`）。状態は event_type で読み取り、既存の項目（本文・文字起こしを載せない）の形を変えない。既存の意味検証（`silence_extension_ms` は `silence_extension` だけ）も変えない |
| 中枢の集計       | 1 つの Live の状態は、結果を待つ依頼（受付条件の確認が通り、失効・終了していないもの。**新しい発話で保留された変更も含める**: 待ち続ける側へ倒し、端末が処理中の会話を無音で閉じない）から決める。前面で待つ依頼が 1 つでもあれば前面、なければ裏に移したものがあれば裏、どちらもなければ none（`aggregateDelegationPhase`）。別の依頼が裏にあっても、新しい依頼が前面で待つ間は前面                                                                                                                            |
| 通知             | 状態が**変わったときだけ**、依頼の受付（条件の確認が通った時点）・背景化（8 秒）・依頼の終了で、1 度だけ送る。受付条件の確認で拒否された委譲・閉じた接続には送らない。イベントは今の接続の `live_session_id`・`audio_epoch`・`control_epoch` を持ち、本文・文字起こし・候補 ID を載せない                                                                                                                                                                                                                       |
| 端末             | 中枢のイベントの形・宛先・今の接続の世代を確かめた後（古い世代・別の接続・別の端末のイベントは今までどおり捨てる）、状態を保持して変わったときだけ `onDelegationPhase` で知らせ、`delegationPhase` として読めるようにする。接続を開くたびに none から始め、接続がないときは none として扱う。**前面の間は、無音の判定（domain の `observeSilence` の `delegation` 入力）が会話を閉じない**（既存の規則。前面では 60 秒待っても閉じず、裏へ移した時点から 10 秒で閉じる）                                        |
| 届かなかったとき | イベントが届かない・古い世代で捨てられたときは、状態は none のままで、従来の無音の判定になる（会話が早く閉じる側。実行の権限は動かない。X29 の「閉じた接続では読み上げ 0 回・結果は画面」は ADR 0108 のまま）                                                                                                                                                                                                                                                                                                   |
| 実行権限         | 状態は表示と無音の判定にだけ使い、承認・実行権限・処理状態の正本にしない（端末・LLM は正本にならない）                                                                                                                                                                                                                                                                                                                                                                                                          |

## 試験（模擬だけ）

- `scripts/delegation-phase.test.mjs`（手書きの期待値）: 状態とイベントの対応（読み戻しも）、他のイベント・未知の値・大文字小文字違い・空は状態を変えない、前面が 1 つでもあれば前面、無音の規則（前面では 60 秒待っても閉じない・裏へ移した時点から 10 秒で閉じる・none では 10 秒で閉じる）。
- `packages/contracts/fixtures/voice-contract-cases.json`: 3 つの状態のイベントが妥当（`tests/test-map.json` の X29 から参照）、`delegation_finished` に無音の延長の値を付けると意味検証で拒否、未知の種類 `delegation_phase` は拒否。
- `apps/core/src/live-conversation.test.ts`: すぐ答える依頼は processing → finished を 1 回ずつ（今の接続の世代・本文なし）。遅い依頼は 8 秒の手前まで processing だけ、8 秒で backgrounded、結果で finished（変わったときだけ）。裏の依頼があるときに新しい依頼が来ると processing に戻り、終わると backgrounded、最初の依頼が終わって finished。受付条件で拒否された委譲は何も送らない。接続を閉じた後は、結果が戻っても送らない。
- `apps/desktop/src/main/voice-controller-control.test.ts`: 状態の保持・変わったときだけ通知・接続ごとに none から。別の端末・別の接続・古い世代・未知の項目を足した形・接続なしは無視。

**模擬のみ**。実音声・実 API・実請求・実機は未実施で、合格扱いにしない。

## 残ること

- 端末の main に無音の判定の本体（タイマー）はまだない（`observeSilence` は domain の規則と試験だけで、`apps/desktop` から呼ぶ所は未実装。B05-08 の実機の作業）。この PR は、判定へ渡す状態（`delegationPhase`）を端末に用意するところまでで、前面の待ちで実際に閉じないことの確認（実機）は未実施。
- B05 の模擬の証拠（`evidence-b05-simulated.json`）は作り直していない（ADR 0085）。X29 の `product_test` は変えない（X29 は `not_run` のまま。実機・統合の証拠は B10-08 と B05 の完了判定）。
